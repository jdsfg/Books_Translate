**Q7.** 为你的代码库配置一份 `CLAUDE.md`（或 `AGENTS.md`），规定：提交信息约定、PR 约定、测试约定、代码库风格指导。以 §4.6 Carmen 的示例为起点结构；适配你的代码库。

提示

文件应针对你的代码库，不要泛泛而谈。

**答：** 合理结构（按需适配）：

    # 供 AI 智能体遵循的项目约定

    ## 提交信息约定
    Use Conventional Commits.
    Allowed types: feat, fix, refactor, test, docs, chore, perf.
    Allowed scopes: <list from your codebase>.
    Subject line ≤ 50 chars. Body wrapped at 72.

    ## PR 约定
    One atomic change per PR. Target main; do not branch off feature branches.
    Use the template at .github/pull_request_template.md.
    Behind a feature flag if user-visible. Flag name follows `<scope>_<feature>_<verb>`.

    ## Testing
    Framework: <pytest / vitest / jest / etc>.
    Use the existing fixtures in <fixtures path>; do not introduce new test frameworks.
    Cover happy path, at least one error path, and at least one boundary case.

    ## Style
    Match the surrounding file. Do not reformat existing code.
    Linter: <eslint / ruff / etc>. Run before committing.
    Imports: <grouped by stdlib / local / third-party in that order>.

    ## 应避免的反模式
    - Do not introduce a new HTTP client; the codebase uses <existing client>.
    - Do not introduce a Singleton; use the existing DI container.
    - Do not catch the base Exception type; catch specific exceptions only.

    ## 首先看哪里
    - Tests are in <tests path>.
    - Domain models are in <models path>.
    - Entry points are in <entry points path>.

该文件应入版本库，约定变更时审查。智能体会话开始时读取；团队 onboarding 时也读。它同时服务两个受众。
