#### 应用问题

**Q5.** 一个月内追踪团队各模块的三个债务指标（前置时间、缺陷、on-call）。识别表现最差的模块。对其债务应用四象限分析；提出补救计划。

提示

分析是一半；计划是另一半。

**答：** 这是开放练习。有代表性的结果：

* 最差模块：payments。前置时间 11 天；缺陷 6/月；on-call 3/月。
* 象限分析：60% 无意-审慎（代码库已学到更多）；25% 未经审查的可信度（AI 生成、审查弱）；10% 蓄意-审慎（已知捷径仍正确）；5% 蓄意-鲁莽（近期压力下的工作）。
* 计划：对无意-审慎部分做 Q2 重构（第 11 章规模）；对未经审查的可信度部分重置审查纪律（应用线索 C checklist）；对蓄意-鲁莽部分做关于 Q1 压力的团队对话。

计划是多方面；单一干预无法解决所有债务。下季度追踪指标以验证改善。

**Q6.** 识别代码库中一段未经审查的可信度代码（AI 生成、审查弱）。现在应用线索 C checklist。原始审查漏了什么？

提示

回顾性审查常暴露缺口。

**答：** 这是开放练习。常见发现：原始审查漏了未测试的边界情况（谎言 1）、不一致的风格（谎言 3）、或过度 mock（第 7 章）。回顾性审查现在抓住这些；团队可以更新原始 PR 或开后续修复。

更深教训：回顾性审查是有用的债务管理工具。定期抽样审查旧 AI 生成代码（而非穷尽）的团队能在这些问题变成事故前抓住缺口。

**Q7.** 与团队进行一次债务分类练习。识别五个债务项；对每个按象限分类；商定回应。比较团队成员的分类；有分歧的地方讨论原因。

提示

分歧常揭示对当时已知内容的不同假设。

**答：** 这是开放练习。常见模式：

* 团队成员对最明显的案例达成一致（明确的蓄意-审慎、明确的无意-鲁莽）。
* 团队成员对中间案例有分歧（这是蓄意还是无意？审慎还是鲁莽？）。
* 分歧揭示对团队历史的不同假设（2023 年团队在这里的理解是什么？）。
* 讨论分歧产生共享理解和更好的未来分类。

这个练习的价值在于讨论本身，超过具体分类。团队对债务的校准变成共享技能。
