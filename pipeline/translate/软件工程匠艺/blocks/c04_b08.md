### 3.7 一个完整示例：二分一次回归

以下 bisect 是 Trellis 一次虚构事故的完整示例，用于展示这项纪律。

Bug：从上周二起，线索评分 API 对大约 0.3% 的请求返回 500 错误，全部来自 EU 区域账户。

第 1 步：写一个能复现 bug 的失败测试。

    // src/scoring/__tests__/regression.test.ts
    test('EU account scoring should not 500', async () => {
      const account = await createAccount({ region: 'EU', plan: 'enterprise' });
      const response = await api.score(account.id);
      expect(response.status).toBe(200);
      expect(response.body.score).toBeDefined();
    });

该测试在 `HEAD` 上失败。

第 2 步：确认它在已知好提交上通过。两个月前的发布标签 `v2.18.0` 被怀疑是最后一个好版本。

    $ git checkout v2.18.0
    $ npm install
    $ npm test -- regression.test.ts
    # passes
    $ git checkout main

第 3 步：bisect。

    $ git bisect start
    $ git bisect bad HEAD
    $ git bisect good v2.18.0
    $ git bisect run npm test -- regression.test.ts

Git 在大约 240 个提交中二分查找，约 8 步，每步 30–60 秒。6 分钟后，输出：

    abc1234 is the first bad commit
    commit abc1234
    Author: Priya Mehta
    Date: 6 weeks ago
        feat(scoring): use cached region-tax-rate for performance

        Cache region tax rates for 5 minutes. Reduces tax-table
        lookups by ~80% for batch scoring jobs.

        Refs: TRELLIS-2018

第 4 步：读提交。缓存键按 region；缓存失效跑在 5 分钟定时器上。仔细检查后发现：EU 税率表在最近一次 ETL 任务中更新了，而缓存会把过期税率保留 5 分钟。对 0.3% 的请求（恰好在错误时刻命中缓存），过期税率导致下游乘法溢出，触发 500。Bisect 找到了引入者；读提交找到了原因；修复是在税率更新时做缓存失效。

总时间：约 20 分钟工程师时间，其中 6 分钟是自动化 bisect 本身。对比“在代码库里滚动找变化”的替代方案，那是数小时注意力，还不保证有结果。
