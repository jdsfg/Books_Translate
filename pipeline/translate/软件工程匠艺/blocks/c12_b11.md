**Q5.** 为代码库里一个已累积债务的子系统提出六个月重构计划。包括：目标架构、并行路径设计、金丝雀阶段、成功指标、删除里程碑。

提示

用 §11.7 作为模板。

**答：** 这是开放练习。一个假设的“OrderProcessing”子系统的合理计划：

* **目标架构**：把 OrderProcessing 拆成 Validator、Calculator、Persister 三个独立类；用当前 ORM 惯用法替换遗留数据库查询层；移除三个已弃用支付方式处理器。
* **并行路径设计**：把 OrderProcessing 抽象到 `IOrderProcessor` 接口后面；旧实现在 `LegacyOrderProcessor`，新在 `OrderProcessorV2`。开关 `order_processing_v2_enabled` 路由；开关 `order_processing_v2_shadow` 启用比较。
* **金丝雀阶段**：staging 100% shadow，然后生产 canary 1% / 10% / 50% / 100%。每阶段一周；每次推进由指标把关。
* **成功指标**：错误率与基线相同（0.1% 内）；延迟相同（5% 内）；第 3 阶段 shadow 不匹配率 < 0.01%。
* **删除里程碑**：新路径 100% 运行且连续两周无事故后，开删除旧路径的 PR；开关在同一 PR 中移除。

按具体子系统调整；结构可迁移。

**Q6.** 为代码库里一个函数实现一个小型并行路径抽象。用功能开关路由。写测试覆盖两条路径。演示拨动开关会改变实现。

提示

原型中开关服务可以是一个简单的 `os.environ` 查询。

**答：** 这是开放练习。最小原型：

    class FeatureFlag:
        @staticmethod
        def is_on(name):
            return os.environ.get(f'FLAG_{name.upper()}', '0') == '1'

    class Calculator:
        def __init__(self, legacy, modern):
            self._legacy = legacy
            self._modern = modern
        def compute(self, x):
            if FeatureFlag.is_on('modern_calculator'):
                return self._modern.compute(x)
            return self._legacy.compute(x)

测试：

    def test_default_uses_legacy():
        os.environ.pop('FLAG_MODERN_CALCULATOR', None)
        calc = Calculator(LegacyCalc(), ModernCalc())
        assert calc.compute(5) == LegacyCalc().compute(5)

    def test_flag_routes_to_modern():
        os.environ['FLAG_MODERN_CALCULATOR'] = '1'
        calc = Calculator(LegacyCalc(), ModernCalc())
        assert calc.compute(5) == ModernCalc().compute(5)

原型展示了模式。生产版本会使用真实开关服务（LaunchDarkly 等）并包含 shadow-read 比较；抽象形状相同。
