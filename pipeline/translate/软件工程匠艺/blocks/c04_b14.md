* **测试：** Bisect 要求测试套件足够可靠，能充当二元判定 oracle。因此 Git 匠艺*需要*测试套件匠艺；二者一起复利。第 6 章的变异测试让测试套件成为更锋利的判定 oracle，让 bisect 更快。
* **重构：** 原子提交是重构的促成者。Fowler 重构（第 9 章）最安全地以小、可审查、可回退的步骤应用；原子提交是每个步骤的自然粒度。没有原子提交，重构就危险，因为提交级回退的粒度错误。
* **命名：** 提交信息本身就是一种命名行为。写祈使、具体、原子的信息所锻炼的技能，与给函数和类型起好名字相同。提交信息写得好的人，函数名也往往起得好；两项技能高度相关。
* **代码审查：** 包含 7 个原子提交的 PR 是 7 次小审查；一个巨大提交的 PR 是一次大审查。审查工程师的认知负荷（第 15 章）在原子提交下显著降低；Git 匠艺纪律因此是团队审查能力的礼物。
* **ADRs：** 一条解释*为什么*改动的优质提交信息就是一个微 ADR（第 17 章）。对不够重要、不需要完整 ADR，但又不能空信息的决策，提交信息是唯一持久化的解释。Git 匠艺因此是轻量级决策文档赖以生存的基底。

复利是多向的：Git 匠艺启用其他纪律，其他纪律也以其累积价值回报 Git 匠艺。同时投资它们的人会在第二年看到复利；只投资一项的人回报平缓。


### 本章总结

本地 Git 匠艺是本书大部分内容站立的基底。原子提交纪律（§3.1）是基础：后续每项技术（bisect、审查、回退）在原子提交加持下更强，没有则更弱。Rebase 与 merge 是不同工作的工具（§3.2）；反对任何一方的教条都是错的。`git bisect`（§3.3）把小时级调试变成分钟级，但前提是提交原子、测试确定；reflog（§3.4）是破坏性操作可恢复的安全网；interactive rebase（§3.5）是把工作草稿提交变成定稿文章的叙事工具。

2026 年 AI 智能体提交（§3.6），纪律通过 `CLAUDE.md / AGENTS.md`（第 22 章）明确指定给智能体，并在 push 前由人类 rebase 强制执行来扩展。阅读智能体的提交历史本身就是捕捉线索 C 谎言的工具：一连串 fixup 信号是谎言 #5 和 #6，仅一致性的多文件提交信号是谎言 #2 和 #3。

第 4 章把这些本地技能提升到团队层面：分支信条、Conventional Commits、语义化版本、特性开关（feature flags）、agent-PR 工作流。本地技能在团队采用它们时复利；团队技能在本地技能已就位时复利。阅读旧代码（第 2 章）因 `git blame` 和 `git log` 工作而更容易；在测试保护下重构（第 10 章）因 bisect 能找到重构引入的回归而更安全；纪律层层叠加。这是本书回报最高的投资之一。
