#### 概念检查

**Q1.** 一位入行三年的朋友向你寻求诚实建议：“我想在接下来 5 年里投资于成为更好的工程师。时间有限；每周大概能在工作之外投入 4 小时。七种复利纪律（§23.1）中我应该先投资哪个、第二、第三？为什么对入行三年的人要按这个顺序？”

提示

有些纪律是其他纪律的前提。有些回报更快。你朋友带宽有限；顺序很重要。

**答：**

对每周 4 小时、入行三年的工程师，建议顺序：

**第一：读旧代码 + 代码审查纪律（约 3 个月）。** 这是基础技能（第 2 + 15 章）。入行三年的人读代码比写代码多；投资阅读能力在每次他们审查的 PR 和每次探索的新模块上复利。练习：每周挑一个开源代码库读 30 分钟；日常工作中，对每个 AI 生成的 PR 应用线索 C checklist（附录 D）。回报立竿见影：审查更好、心智模型更好、更少“这段代码在干嘛？”的时间。

**第二：测试即 spec + 测试下重构（约 3 个月）。** 一旦阅读能力更 sharp，下一个技能就是安全改动的前提。练习：每个新函数先写 failing test（即使团队是 test-after）；对遗留重构工作，在改之前先写特征化测试。这两项相互复利；更好的测试让重构更安全；更安全的 refactor 教会你写更 sharp 的测试。

**第三：ADR + 命名即设计（约 3 个月）。** 此时工程师读够多、改够多，知道哪些决策重要。练习：每季度为团队做过的一个决策写一份 ADR；在每个 PR 里重命名一个误导名字。这两项比前六个月回报慢——杠杆体现在未来读者身上，而不是今天干活的你自己——但正是它们区分第五年的工程师和只有同样工时的第三年工程师。

**第四：AI 协作 + 版本控制匠艺（约 3 个月并持续）。** 这两项与其余五项一起复利；没有基础就先做，会产生数量没有质量。到第 10 个月，你的审查和重构本能能跟上 AI 工作流的速度，你的 commit 历史也能支持让团队其他人生活更轻松的纪律化 Git 工作。

顺序是**阅读 → 测试 → 决策推理 → AI 协作**。每一步建立在前一步之上。要避免的错误：先投资 AI 协作（它最闪亮、最现代、最快“看，我发布了东西”）。没有基础，AI 协作会产生未经审查的可信度债务（第 19 章）；快速产出你无法维护。有了基础，AI 协作是耐久技能的乘数。

到第 8 年，你的朋友会回头发现：早期投资的纪律已经像反射；推迟的纪律仍然像苦活。这个观察本身就是复利。
