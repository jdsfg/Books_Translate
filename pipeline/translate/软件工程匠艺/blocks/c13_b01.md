2026 年初，Helix 一位初级工程师问 Aki 设计模式是否还重要。“GoF 的书是 1994 年的，” 他说，“这些模式假设的 Java 惯用法现在没人写了。而且，我不能直接问 AI 应该用什么形状吗？” Aki 的回答后来成了她标准入职演讲的一部分：“有些模式过时了。下一章会讲。但有六个模式一直有用，因为它们描述的是跨语言、跨十年反复出现的设计动作。它们不是 Java 惯用法；它们是你反复会做动作的*词汇*。AI 从训练数据里知道这些模式。如果你不知道，你就无法识别 AI 什么时候用得好、什么时候用得差。所以，是的，你得学。”

本章讲授 Gang of Four《Design Patterns》（1994）里历经三十年语言和工具演变仍存活的六种模式：Strategy、Adapter、Decorator、Observer、Iterator、Command。每种都用 2026 年的惯用法而非原 Java 示例展示；每种都匹配它解决的问题和触发信号。第 13 章讲没有存活下来的模式。


### 12.1 Strategy（策略）

Strategy 模式让你通过在共同接口后把每个行为封装成自己的对象，在运行时交换算法行为。


#### 定义：Strategy

Strategy 模式定义一族可互换的算法，每个算法都在实现共同接口的自己的类里。客户代码持有接口引用，可以切换具体策略而不改变自己的代码。

直白地说：当你有许多做同类事情的方式，并想在运行时选择其中一种，Strategy 就是这个形状。


#### 2026 年示例

一个 pricing 服务按不同客户等级用不同规则计算价格。朴素实现用条件判断：

    def price_for(customer, product):
        if customer.tier == 'free':
            return product.list_price
        elif customer.tier == 'pro':
            return product.list_price * 0.9
        elif customer.tier == 'enterprise':
            return negotiated_price(customer, product)

Strategy 版本：

    from typing import Protocol

    class PricingStrategy(Protocol):
        def price_for(self, customer: Customer, product: Product) -> Decimal: ...

    class ListPricePricing:
        def price_for(self, c, p): return p.list_price

    class TenPercentDiscountPricing:
        def price_for(self, c, p): return p.list_price * Decimal('0.9')

    class NegotiatedPricing:
        def __init__(self, negotiator): self._n = negotiator
        def price_for(self, c, p): return self._n.lookup(c, p)

    # 用注册表把等级映射到策略
    PRICING_STRATEGIES = {
        'free': ListPricePricing(),
        'pro': TenPercentDiscountPricing(),
        'enterprise': NegotiatedPricing(negotiator),
    }

    class PricingService:
        def __init__(self, strategies):
            self._strategies = strategies
        def price_for(self, customer, product):
            strategy = self._strategies[customer.tier]
            return strategy.price_for(customer, product)

收益：每个定价规则可单独测试；增加新等级只需加策略，不用修改条件；`PricingService` 小而稳定。
