### 附录B — 12 种重构速查卡

第 9 章 12 种重构的速查卡。代码审查时用它；可以贴在墙上。

| # | 名称 | 信号 | 机械动作 |
|---|---|---|---|
| 1 | Extract Function | 函数超过 30–50 行；被注释分隔成听起来像函数名的段落 | 把该段落提为命名函数；传入它使用的输入；返回调用者需要的东西 |
| 2 | Inline Function | 函数相对其正文没有语义价值；只调用一次；名字没有让调用点更清晰 | 用正文替换调用；删除该函数 |
| 3 | Rename | 名字误导、泛化或过时（`data`、`info`、`Manager`、`handle`） | 用 IDE 的重命名工具（或智能体）——确认改动纯粹机械，不跨系统 |
| 4 | Move | 函数放错文件；使用另一个模块的数据多于当前模块 | 移动函数；更新 imports；运行测试 |
| 5 | Replace Conditional with Polymorphism | 对一个类型标签有很长的 if/elif/switch，并在多处重复 | 定义协议；每个 case 一个类实现它；通过注册表分发 |
| 6 | Replace Magic Number with Constant | 字面量出现且没有明显含义 | 把它提到使用处附近的命名常量；并非每个字面量都需要命名——只有含义不明晰的 |
| 7 | Extract Class | 类的方法明显分成几组，每组使用类字段的不同子集 | 把类按职责拆成一个一个；如调用者依赖原公共 API，保留薄 facade |
| 8 | Replace Inheritance with Composition | 类继承另一个类是为了*共享实现*，而不是因为它*is-a*父类 | 把父类变成成员而不是基类；或用 trait/mixin/dataclass 方式 |
| 9 | Introduce Parameter Object | 函数有 5+ 参数，其中一些概念上成组 | 把内聚参数组成 dataclass；传入对象 |
| 10 | Replace Loop with Pipeline | 循环通过过滤和转换中间累积量来构建列表 | 转成 comprehension、`filter`/`map`，或语言提供的流式集合 API |
| 11 | Combine Functions into Class | 多个函数取同一数据并以相关方式操作 | 围绕数据构建类；函数变方法；数据只存在一处 |
| 12 | Decompose Conditional | 条件逻辑与分支动作缠在一起；读者必须同时理解两者 | 把条件提取为命名谓词；把每个分支提取为命名动作 |

**刻意练习规则**：前二到三个月把这张卡放在显眼处。每个 PR 都找信号；应用对应重构；把它作为单独的原子 commit（第 3 章）。一季度后，清单会进入脑海，卡片就不再需要。

**AI 层规则**：智能体擅长全部十二种的机械执行。它们在识别*何时*适用以及*粒度*上不可靠（智能体倾向于过度提取小 helper 和过度应用多态）。2026 工作流是*人类识别、智能体执行、人类审查*（第 9 章 §9.13）。
