#### 常见误解

一个常见误解是“童子军规则给范围蔓延找理由。” 错误在于把*小改进*和*无边界重构*混为一谈。修三行 bug 的 PR 包含 300 行重构，不是童子军；是范围蔓延。审查者会（正确地）反对；工程师应拆分。

纪律是*小且对齐*：改进足够小，能在 PR 范围内，且与 PR 正在做的事对齐。修日期计算 bug 的 PR 可以修复一条相关误导注释；它不应该重构整个日期模块。


### 20.2 AI 辅助下的童子军规则

2026 年，AI 智能体可以快速识别和应用小改进。童子军纪律随 AI 扩展：智能体可以扫描你正在编辑的文件，寻找改进机会，机械应用，然后呈现给审查者。


#### 工作流

  1. 人类打开文件修 bug 或加功能。
  2. 人类问 AI：“你在这个文件里，找出三个与我们当前工作一致的小童子军改进。”
  3. AI 提出改进及理由。
  4. 人类审查并接受合适的（通常三个中两个；一个常常是越界）。
  5. AI 在 PR 内作为单独 commit 应用它们。
  6. 审查者看到实质性改动和童子军改进作为不同 commit，易于评估。

人类成本很小；代码库成本为负（变干净）；审查者成本很小（每个 commit 可见且易于评估）。


#### CLAUDE.md 纪律

一条捕捉童子军规范的 CLAUDE.md 条目：

    ## Boy Scout improvements

    When working on a file, identify small adjacent improvements:
    - Renaming misleading variables.
    - Deleting dead conditionals.
    - Extracting small helpers.
    - Updating stale comments.
    - Deleting stale TODOs.

    Apply these as separate commits within the PR. Do not include
    improvements unrelated to the substantive change; those belong
    in separate PRs.

指令设定规范；AI 遵循；团队童子军率提高，无需每位工程师都记住应用纪律。


### 20.3 绞杀者无花果模式

绞杀者无花果模式由 Martin Fowler 于 2004 年命名，是通过逐步用新系统替换旧系统来迁移的技术，两者同时存在。


#### 定义：绞杀者无花果

绞杀者无花果模式通过让新系统围绕旧系统生长、逐步把功能从旧重定向到新，直到旧系统完全被替换并删除。迁移是增量的；两个系统在迁移期间共存；迁移在新系统中没有剩余功能时完成。

直白地说：不要重写；逐步替换，每次一小块，旧系统全程作为安全网。
