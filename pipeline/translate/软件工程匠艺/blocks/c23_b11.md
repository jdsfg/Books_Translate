#### 概念检查

**Q1.** 一位队友已经用了 3 年 AI。他描述自己的工作流：“我写一个函数头，然后写注释 `# what this should do`，Copilot 就一行一行自动补全主体。我按 Tab 之前会审查每条建议。有时建议错了，我就手动修。” 他问这是不是“agent mode”。请走一遍他的工作流与 2026 agent mode 的区别：各擅长什么、各有什么风险、何时各是正确选择。

提示

逐步批准（自动补全）vs 自主多步执行（agent mode）。各有位置。

**答：** 队友的工作流是**带每步人类批准的自动补全**，不是 agent mode。两者都有用；适合不同工作。

**他的工作流属性：**

* 人类在每条建议落地前审查并接受/拒绝。
* 失败模式：错误建议立即被拒；没有下游影响。
* 周期：每条建议（几秒到一分钟）。
* 最适合：人类心智模型完整的小段、熟悉代码；AI 产出的不是下一个决策，只是下一行。

**Agent mode 属性：**

* 人类设定目标（常是 failing test）；智能体自主读文件、写代码、运行测试套件、迭代，完成后报告。
* 失败模式：错误实现可能连同正确实现一起落地；人类在*最后*审查，而非每步。
* 周期：每个任务几分钟到几小时。
* 最适合：目标可精确表述（测试即 spec、跨多文件的机械重构、应用已知模式）的、范围明确的多步工作。

**权衡是*完成速度与每步控制*。** 自动补全按任务更慢，但人类立即捕获错误；agent mode 更快，但人类审查集中在最后，若审查肤浅则坏代码会发布。

**何时各是正确选择：**

* **自动补全** 胜在：
    * 工作新颖或在陌生代码中（人类正在建立心智模型）。
    * 触碰到敏感代码（安全、支付、数据），每行都重要。
    * 智能体训练数据在该领域弱（罕见语言、内部框架）。
* **Agent mode** 胜在：
    * 工作机械且目标可精确指定（failing tests、具名重构动作）。
    * 工作跨多文件且一致（重命名 87 个调用点；在模块 Y 应用模式 X）。
    * 人类是审查者；spec 清晰；“测试 → 智能体 → 审查”循环比手打实现更快。

多数工作工程师两者都用。队友的自动补全用得不错；他可能在 spec 足够精确的那类工作中加入 agent mode。两者不互相替代；纪律是按任务选择。

**Q2.** 什么是 spec 驱动工作流？为什么它比提示驱动工作流产出更好结果？

提示

Spec 可验证；提示可解释。

**答：** Spec 驱动指人类写描述期望行为的 failing tests；智能体的工作是让测试通过。提示驱动指人类写自然语言指令；智能体解释并产出代码。
