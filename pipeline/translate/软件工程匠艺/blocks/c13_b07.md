#### 2026 年示例

一个后台作业系统异步处理命令：

    from dataclasses import dataclass
    from typing import Protocol

    class Command(Protocol):
        def execute(self) -> None: ...

    @dataclass
    class SendEmailCommand:
        to: str
        subject: str
        body: str
        def execute(self):
            email_service.send(self.to, self.subject, self.body)

    @dataclass
    class ProcessRefundCommand:
        order_id: str
        amount_cents: int
        def execute(self):
            refund_service.refund(self.order_id, self.amount_cents)

    class CommandQueue:
        def __init__(self):
            self._queue = []
        def submit(self, command: Command):
            self._queue.append(command)
        def process_all(self):
            while self._queue:
                cmd = self._queue.pop(0)
                try:
                    cmd.execute()
                except Exception:
                    log.exception(f'Command failed: {cmd}')

    # 用法
    queue = CommandQueue()
    queue.submit(SendEmailCommand(to='alice@example.com', subject='Refund', body='...'))
    queue.submit(ProcessRefundCommand(order_id='ord_123', amount_cents=5000))
    queue.process_all()

收益：命令是数据；可以序列化、记录日志、持久化到数据库以便重试、回放调试。执行层可以跨所有命令统一实现重试、死信和可观测性。


#### 何时 Command 是正确模式

* **你需要把动作排队**以便稍后执行（后台作业、批处理）。
* **你需要记录动作**用于审计或回放（事件溯源、撤销-重做）。
* **你需要用调用方不必知道内部的操作来参数化调用方**。
* **你需要对许多不同动作应用统一横切行为**（重试、日志、指标）。


#### 何时 Command 是错误模式

如果你调用函数并想立即得到结果，Command 不必要；函数调用更简单。Command 在调用被*延迟*或*转换*时才闪耀；同步直接执行会增加无价值的层。

2026 年，Command 是大多数后台作业系统（Celery、Sidekiq、BullMQ、RQ）的基础：作业就是命令；队列就是命令队列；worker 就是执行器。该模式在基础设施而非应用代码中实现，但形状相同。


### 12.7 AI 层：LLM 何时恰当地、何时错误地伸手拿模式

2026 年的 LLM 从训练数据中知道所有 GoF 模式。当提示与模式的信号匹配时，它们会伸手拿模式。伸手有时对，有时错；人类的工作是识别哪一种。


#### LLM 伸手拿得好的时候

* **Strategy** 用于数据驱动的算法选择：LLM 正确识别“按等级不同行为”并提议 Strategy。提议通常形状良好。
* **Adapter** 用于 vendor 集成：让 LLM 集成两个 SDK 时它会提议 adapter。形状通常对；名字有时需调整。
* **Iterator** 是自动的；LLM 默认使用语言原生迭代，无需提示。
* **Command** 用于后台作业：让 LLM 设计异步作业处理时它会提议 Command。提议通常与团队的作业框架匹配。
