**Q3.** 一位 Staff 工程师审查 AI 生成代码时征求你的判断。AI 为一个分页遍历 5000 万行（50M）数据库表的设计提议如下：

    class UserPaginator:
        def __init__(self, db, page_size=1000):
            self._db = db
            self._page_size = page_size
            self._cursor = 0
        def has_next(self) -> bool: ...
        def next(self) -> list[User]: ...
        def reset(self) -> None: ...

审查者说：“这是 Iterator 模式。Strategy 和 Adapter 我们接受；Iterator 应该拒绝，因为是过度工程。用 generator。” 审查者对吗？2026 年什么时候显式 Iterator 类是正确的形状，什么时候 generator 严格更好？

提示

Generators*就是* iterators；差别在于实现成本和状态可见性。

**答：** 审查者部分对。模式（Iterator）是正确的设计动作——把遍历与集合存储分离。1995 年 Java *实现*（带 `hasNext`/`next` 的类）已经过时；2026 年 Python 惯用法是 generator 函数：

    def paginate_users(db, page_size=1000):
        cursor = 0
        while True:
            page = db.query("SELECT * FROM users WHERE id > %s ORDER BY id LIMIT %s",
                            (cursor, page_size)).fetchall()
            if not page:
                return
            yield page
            cursor = page[-1].id

Generators*就是* iterators；语言原生支持该模式；显式类增加样板，并暴露可变状态（`self._cursor`），而 generator 把它藏在局部作用域里。

**显式类什么时候对：**

* 迭代器需要 `next()` 之外的*操作*：`reset()`、`seek_to(cursor)`、`current_position()`。这些可以实现在类上；无法在 generator 函数上实现。
* 调用方需要检查*状态*的迭代方式（例如进度报告、可观测性）。
* 语言老旧或 generator 能力弱（旧 Java 版本、嵌入式 C 环境）。

**Generator 什么时候严格更好：**

* 调用方只想迭代，可能用 `break`/提前退出。
* 状态纯粹内部，调用方不需要检查。
* 代码库是 Python 3.10+、现代 JS、Rust 等（典型的 2026 后端）。

在提议代码中，`UserPaginator` 类有 `next()`、`has_next()` 和 `reset()`。如果调用方真用 `reset()`，这个类就合理。如果不是（类是因为 AI 在教程里见过才加的），拒绝它；用 generator。用问题回推：“给我看一个使用 `reset()` 的调用方。如果没有，简化成 generator 函数。” AI 的默认反映训练数据；团队的*信号驱动*纪律会过滤它们。
