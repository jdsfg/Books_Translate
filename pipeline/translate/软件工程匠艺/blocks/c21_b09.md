**一般规则**：问*迁移的决策点在哪里*。外部 HTTP 边界、消息队列边界、任何跨网络或进程的事物？用绞杀者无花果——路由请求。应用内部接口？用 Branch by Abstraction——在接口后路由操作。大型迁移可跨多种边界结合；如果迁移跨越多个边界类型，不必强选一种。

**Q4.** 何时机会主义重构（童子军）足够，何时团队必须安排专门重构？

提示

§20.5 的信号。

**答：** 机会主义足够当：

* 债务分散在许多文件；没有热点。
* PR 吞吐量足够高，小改进能复利。
* 指标稳定或改善。

安排式必要当：

* 债务集中在一两个大子系统。
* 代码库有结构性债务，需要协调变更。
* 指标在恶化。
* 即将到来的变更需要先处理债务。

大多数团队以混合模式运作：持续童子军，每季度一两次安排式重构处理较大项。混合平衡取决于团队情况；纪律是两者都用。
