### 9.12 重构 12：分解条件表达式

**信号**：*什么*（条件）和*如何*（分支动作）纠缠在一起；读者必须同时理解两者。

**之前 / 之后**：

    # 之前：条件逻辑 + 分支逻辑混在一起
    def schedule_refund(order, current_date):
        if (order.status == 'completed' and
            (current_date - order.completed_at).days < 30 and
            not order.has_been_refunded and
            order.payment_method != 'gift_card'):
            refund = order.total - (order.partial_refund_amount or 0)
            if order.customer.tier != 'enterprise':
                refund = refund * 0.95
            return process_refund(order, refund)
        return None

    # 之后：命名谓词、命名动作
    def schedule_refund(order, current_date):
        if not is_eligible_for_refund(order, current_date):
            return None
        return process_refund(order, compute_refund_amount(order))

    def is_eligible_for_refund(order, current_date):
        return (order.status == 'completed'
                and (current_date - order.completed_at).days < 30
                and not order.has_been_refunded
                and order.payment_method != 'gift_card')

    def compute_refund_amount(order):
        base = order.total - (order.partial_refund_amount or 0)
        return base * 0.95 if order.customer.tier != 'enterprise' else base

条件和动作各得一个名字；两者都可独立测试；`schedule_refund` 变成清晰的三步流程。

**AI 层**：智能体这个重构做得好。风险是过度分解；简单的 `if x > 0` 不需要命名谓词。
