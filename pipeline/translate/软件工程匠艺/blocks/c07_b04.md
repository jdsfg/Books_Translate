#### Shrinking

当属性失败时，工具会向*最小失败示例*方向 *shrinks*。shrinker 尝试删除列表元素、数字折半、简化字符串；每次简化后重新测试，如果仍失败，则用更简单的输入替换原输入。最终报告的是能展示该 bug 的最小输入。

Shrinking 让基于属性的测试可用。一个 200 字符、混合 Unicode 的随机字符串上失败很难调试；shrunk 到 3 字符字符串后就很直接。


### 6.4 变异测试：思想

变异测试回答*覆盖率无法回答*的问题：测试是真的在测试，还是仅仅执行？

技术：变异测试工具以机械方式小改生产代码（把 `<` 改成 `<=`、删除 return 语句、替换常量），产生代码库的多个*变异体*。对每个变异体运行测试套件。如果套件失败（抓住了变异体），该变异体被*killed*；如果套件通过（没抓住），该变异体*survives*。变异分数是杀死的变异体百分比。


#### 定义：变异分数

变异分数是测试套件杀死的生成变异体比例。80% 变异分数意味着 80% 对生产代码的机械改动被测试检测到；20% 没有，意味着这些改动可能不经失败测试就上线。

直白地说：变异测试模拟 bug 并问测试能否抓住。高覆盖但低变异分数意味着测试执行了行但没有检查行；套件是覆盖率填充。


#### 示例

    def is_eligible(age, has_consent):
        return age >= 18 and has_consent

假设测试套件包含：

    def test_eligible_adult_with_consent():
        assert is_eligible(25, True) == True

    def test_ineligible_minor():
        assert is_eligible(15, True) == False

覆盖率：100%。变异测试引入变异体：

变异体 | 变异 | 测试结果 | 是否杀死？  
---|---|---|---  
M1 | `age >= 18` → `age > 18` | `test_eligible_adult` 通过（25 > 18 为 True）；`test_ineligible_minor` 通过（15 > 18 为 False）。套件通过。 | **Survived**  
M2 | `age >= 18` → `age <= 18` | `test_eligible_adult` 失败（25 <= 18 为 False，函数返回 False）。套件失败。 | Killed  
M3 | `and` → `or` | `test_eligible_adult` 通过（25>=18 or True 为 True）；`test_ineligible_minor` 通过（15>=18 为 False，True 为 True，False or True 为 True。于是函数对 (15, True) 返回 True，而测试期望 False）。套件失败。 | Killed  
M4 | `return age >= 18 and has_consent` → `return True` | `test_ineligible_minor` 失败（对 (15, True) 返回 True）。套件失败。 | Killed  

有趣的结果是 M1。两个测试都通过，因为没有一个测 age 18 这个边界。M1 survive。变异分数是 3/4 = 75%；测试套件在边界有缺口。修复：添加 `assert is_eligible(18, True) == True`。

这就是核心洞见。变异测试发现覆盖率发现不了的缺口。
