### 17.8 完整示例：Drizzle vs Prisma 的 ADR

2025 年初，Helix 的 Aki 团队考虑把 Drizzle 换成 Prisma。这个决策意义重大（会触及数百个文件），因此开了一个 RFC，讨论两周，最终被拒绝。RFC 被归档；现有决策（使用 Drizzle）在新的 ADR 中被再次确认。

    # ADR-018：继续使用 Drizzle ORM（确认 ADR-002）

    Status: Accepted (2025-03-10)。确认 ADR-002。

    ## Context
    ADR-002 于 2023 年选择 Drizzle 作为 ORM。2025 年 Q1，三位工程师提议
    迁移到 Prisma（RFC-014）。支持 Prisma 的理由：
    - 更大的社区；更多 StackOverflow 答案。
    - 嵌套查询中更好的 TypeScript 推断。
    - 更成熟的迁移工具。

    反对迁移的理由：
    - 估计需要 200 小时迁移约 400 个查询点。
    - Drizzle 的包体积更小；对我们的 Cloudflare Workers 部署很重要。
    - Drizzle 的 SQL-like API 对团队一直工作良好。
    - Prisma 的运行时需要单独的 engine 二进制文件；会使构建管道复杂化。

    经过两周 RFC 讨论，团队共识是迁移成本超过收益。Drizzle 的痛点真实但
    可忍受；Prisma 的收益会受欢迎，但不是变革性的。

    ## Decision
    继续使用 Drizzle。原本用于迁移的 200 个工程小时将用于解决 Drizzle 的
    具体痛点（RFC-014 列出了 `src/db/` 中 Drizzle wrapper 的三个具体改进）。

    ## Consequences
    - 没有迁移工作；工程能力保留给产品工作。
    - Drizzle 痛点通过针对性 wrapper 改进解决（issue #1842）。
    - 如果 Drizzle 被其维护者放弃，或 Prisma 优势显著增长，重新评估
      （建议目标日期：2026 年 Q1）。

    ## Alternatives considered
    - 迁移到 Prisma（RFC-014）：因成本被拒绝。
    - 迁移到第三种选择（Kysely、TypeORM、原始 SQL）：未被认真考虑；
      当时的选择是 Drizzle vs Prisma。
    - 按 RFC-014 维护 Drizzle wrapper：作为本 ADR 的一部分被接受。

ADR 两页。它捕捉了问题、决策、后果和备选方案。2027 年的未来工程师读到时知道 2025 年发生了什么、为什么。如果 Drizzle 形势变化，重新评估有起点。

写这份 ADR 的投入约三小时，包括 RFC 讨论综合。收益是持久的：这个决策不需要从头再讨论。
