### 附录E — 模板

本书给了你纪律和背后的理由。本附录给的是*起始产物*——四个你今天就可以复制到仓库并按团队具体情况调整的模板。每个模板故意简短。最长的单个模板只占一屏。调整而不是放弃：没人填的长模板，比团队能下意识使用的短模板更糟糕。


#### 模板 1：`~/.gitmessage` — commit message 模板

    # Subject: 祈使语气，≤ 50 字符，句尾无句号
    #
    # 为什么需要这个改动（不是它做了什么——diff 会显示做了什么）。
    # 在 72 字符处换行。
    #
    # Refs: TICKET-123

用 `git config --global commit.template ~/.gitmessage` 启用。来自第 3 章 §3.8 Q7。


#### 模板 2：`.github/pull_request_template.md` — PR 描述模板

    ## What
    <一句话改动摘要。>
    
    ## Why
    <动机。解决什么问题？链到 ticket、ADR 或事故。>
    
    ## How
    <方法简要概述。实现中有什么非明显之处。>
    
    ## Testing
    <测了什么、没测什么。如果做了手工测试，场景是什么。>
    
    ## Risk
    <可能出什么错。回滚方案。是否在功能标志后？哪个？>
    
    ## Reviewer note
    <作者希望审查者关注的具体区域，如果有。>

"Why" 是杠杆最高也最常薄弱的章节；把它当作必填项。来自第 16 章 §16.2。
