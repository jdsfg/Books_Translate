#### Oracle 技术详解

Oracle 技术值得单独讨论，因为它异常有效。假设你在把一个慢函数 `slow_f` 优化成快函数 `fast_f`。属性是：

    @given(input_strategy)
    def test_fast_matches_slow(x):
        assert fast_f(x) == slow_f(x)

慢函数就是你的参考。框架生成输入并确认快版与之一致。当快版不一致时，你就发现了优化里的 bug。这几乎是一种完美的测试设置：你不需要知道正确答案是什么，只需要信任慢版。

Aki 在 Helix 用 oracle 技术验证一个 Rust 重写解析器与原始 Python 解析器：生成数千输入，每次不一致都是 bug，每次一致都是测试通过。Rust 版本经过一周的基于属性测试后发布，如果用示例测试要达到同等信心需要数月。


#### 常见误解

一个常见误解是“基于属性的测试取代基于示例的测试。” 错误在于，基于属性的测试虽然覆盖面广，但缺少示例测试的可读性和意图即文档的作用。测试读者应该能从示例中学到函数的预期行为；属性确认广度。

纪律是两者都保留：示例测试用于文档化行为和典型边界情况，基于属性测试用于覆盖广度。只有属性的测试文件难读；只有示例的测试文件遗漏边界情况。两者都才是答案。


### 6.3 实践中基于属性的测试：工具

2026 年三个主要工具：

* **Hypothesis (Python)**：成熟；丰富的 strategies 库；优秀的 shrinking；Python 代码库标准选择。
* **fast-check (JavaScript/TypeScript)**：TypeScript 优先；集成 Jest、Vitest 和多数 JS 测试运行器。
* **Proptest (Rust)**：地道 Rust；基于 macro 的属性声明。

其他值得注意：ScalaCheck（Scala）、QuickCheck（Haskell，鼻祖）、jqwik（Java/Kotlin）、Hedgehog（Haskell 和 Rust 的替代）。


#### Strategies 与 generators

每个工具都有 *strategy* 或 *generator* 抽象：生成给定类型值的配方。内置 strategies 覆盖原始类型（整数、浮点、字符串、布尔）、集合（列表、集合、字典）和递归结构。用户组合 strategies 构建领域相关 generator：

    # Helix pricing 引擎的一位客户
    customer_strategy = st.builds(
        Customer,
        id=st.uuids(),
        region=st.sampled_from(['US', 'EU', 'APAC']),
        tier=st.sampled_from(['free', 'pro', 'enterprise']),
        is_grandfathered=st.booleans(),
        seat_count=st.integers(min_value=1, max_value=10000),
    )

现在属性测试生成逼真的 Customer 值。customer strategy 投资在很多属性测试中获得回报；它本质上是一个领域专用输入生成器。
