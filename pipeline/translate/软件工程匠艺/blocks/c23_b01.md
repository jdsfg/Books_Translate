2026 年 4 月，Aki 一个下午发布了一个 1,200 行的功能。该功能是 Helix 客户的一种新定价规则类型：基于使用量的阶梯，带 rollover credits。Aki 没有自己写一行代码；她做了现在每次非平凡智能体会话开始都会做的事：先写 failing test，在它们变红之前拒绝打开 Claude Code。这个习惯是去年秋天惨痛形成的：当时一个智能体生成了 600 行看似可信的代码，通过了她浅层测试，却仍把 staging 里的 webhook 状态搞坏；恢复花了两天加一个周日。这次八个测试。然后她才打开 agent mode 让它工作。两小时后，实现通过了全部八个测试。Aki 审查了每个 commit（智能体产出十一个），用两个基于属性的变体加强了测试，让智能体重构了一处偏离代码库风格的部分，然后合并。

同样功能在 2022 年会花 Aki 一周来写、审、调试、迭代。压缩不是 5 倍因为 Aki 在键盘编码更快；实际上她在编码键盘步骤更慢。压缩 5 倍因为智能体做了编码键盘步骤，而 Aki 的时间集中在会复利的部分：写 spec、审查输出、加强测试。

本章讲这个工作流：agent mode、spec 驱动工作流、有效的提示模式、CLAUDE.md / AGENTS.md 约定、AI 代码审查工具，以及更广的人类作为审查者 / 智能体作为实现者模式。第 1–21 章覆盖匠艺纪律，本章把它们与已成为团队一部分的 AI 协作者整合。


### 22.1 Agent mode

2026 年标志性能力是*agent mode*：一种能读取代码库、运行命令、写代码、运行测试并迭代的 AI 工具，无需每一步人工批准。


#### 定义：Agent Mode

Agent mode 是 AI 工具配置，智能体可跨多步自主运行：它能读文件、改文件、执行 shell 命令、观察结果、决定下一步。人类设定目标；智能体执行；人类审查结果。

直白地说：智能体开一会儿车；人类看并掌舵。
