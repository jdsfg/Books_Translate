### 本章总结

Agent mode（§22.1）是 2026 年的标志性能力：AI 工具在人类指导下跨多步自主运行。Cursor agent、Claude Code、Devin、v0 是主要工具。

Spec 驱动工作流（§22.2）把测试即 spec 与 agent mode 结合：人类写 failing tests，智能体实现，人类审查。工作流让人类时间集中在写 spec 和审查；智能体处理机械部分。

有效提示模式（§22.3）：提供上下文、要求测试、显式迭代、约束范围、先问计划。无效模式：模糊提示、无上下文、无成功标准、多天项目单次完成。

CLAUDE.md（§22.4）是项目根约定：智能体会话开始时读取的文件。它捕获代码库导航、约定、反模式和 gotcha，把智能体默认转向团队特定规范。

AI 代码审查工具（§22.5）补充人类审查：大规模处理战术问题，让人类专注架构与上下文。

智能体提交 PR 工作流（§22.6）让智能体接 ticket 并产出 PR；人类审查。该工作流需要清晰 ticket 纪律、CLAUDE.md 和审查产能；并非所有团队或任务都适用。

反模式（§22.7）：盲目信任“测试通过”、把初稿当终稿、让智能体做设计、忽视 CLAUDE.md。每个都有对应的纪律。

Helix 完整示例（§22.8）：一个下午发布 1,200 行功能。人类时间集中在 spec 和审查；智能体时间处理机械部分。这个工作流是此前每一章纪律的整合。

第 23 章以工作工程师的匠艺心智模型收尾：全书 22 章的综合、三位主角的汇合，以及 2026 年之后匠艺的轨迹。


#### 三条要点

  1. **本周为你的代码库写一份 CLAUDE.md。** 七部分：导航、命名约定、测试约定、模式偏好、反模式、架构形状、Git 约定。目标 300 行以内。之后每次 AI 会话都拿到你的默认，而不是训练数据默认。
  2. **下一次非平凡功能采用 spec 驱动工作流。** 先写 failing tests，再调用智能体，再审查。即使你通常 test-after。这个循环比 prose 描述更快；产出的测试是真实测试，不是填充覆盖。
  3. **正确排序：纪律第一，工作流第二，吞吐量第三。** Veridian 的失败案例在本章出现是有原因的。在采用第 15 章审查纪律前就采用智能体提交 PR 的团队会加速债务累积；按顺序采用的团队会复利优势。
