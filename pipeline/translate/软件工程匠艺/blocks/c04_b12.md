**Q7.** 配置你的编辑器和 shell，让本章和第 2 章的原子提交与笔记纪律成为习惯而非费力之举。描述 (a) 你会加的快捷键或别名，让 `git add -p` 一键可用；(b) 你会放在 `~/.gitmessage` 的提交信息模板；(c) 你会加的 shell 别名，用于 `git log --oneline --graph --decorate`。

提示

别名减少摩擦；摩擦会杀死纪律。

**答：** 三处具体配置：

(a) 一个用于分块 staging 的 Git 别名：

    git config --global alias.ap "add --patch"
    # 现在 `git ap file.ts` 进入 patch 模式

或 shell 别名：

    alias ga="git add --patch"

(b) `~/.gitmessage` 中的提交信息模板：

    # Subject: 祈使语气，<= 50 字符，不要末尾句号
    #
    # 为什么需要这个改动（不是做了什么；diff 会说明做了什么）。
    # 72 字符换行。
    #
    # Refs: TICKET-123

并启用它：

    git config --global commit.template ~/.gitmessage

(c) 一个美观日志别名：

    git config --global alias.lg "log --oneline --graph --decorate --all"
    # 现在 `git lg` 显示图

重点不是具体命令，而是原则：降低你想养成习惯的那些纪律的摩擦。一个要打 30 个字符才能做分块 staging 的工程师不会去分块 staging；一个只需打 `git ap` 的工程师会。
