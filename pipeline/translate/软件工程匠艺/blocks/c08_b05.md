#### CLAUDE.md 指令

2026 年的修复办法是在 `CLAUDE.md` 里明确规定偏好（第 22 章）：

    ## 测试替身
    - 对有状态依赖优先用 fake 而非 mock。使用 `tests/fakes/` 里的内存 Repository 实现。
    - 对简单返回值用 stub。
    - 对验证副作用（邮件发送、事件发布）用 spy。
    - 只在以下情况用 mock：无法 fake 的外部 SDK、专门验证交互协议的测试（例如重试逻辑）。
    - 如果在测试里写了 `Mock()`，必须在注释中说明理由。

有了这个指令，LLM 的默认倾向会转变。剩余失效模式是 LLM 在长会话或 PR 模式下忘记该指令；周期性通过引用 `CLAUDE.md` 重新锚定。


#### 重构 mock 重的测试

当你继承一个充满 mock 的测试套件时，不要一次性全部重写。模式：

  1. 识别测试中 mock 使用最多的前三个 Repository 或服务。
  2. 为每个构建内存 fake。
  3. 测试因其他原因失败或被改动时，把它们迁移到 fake。
  4. 一个季度到两个季度内，mock 使用自然下降。

开篇小插曲里的 Trellis 工程师正处于这次迁移中；重构后崩溃的测试用了 mock，把它迁到 fake 就是修复的一部分。
