#### 定义：并行路径

并行路径策略同时运行同一功能的两种实现：旧（生产）路径和新（重构）路径。请求可根据功能开关路由到任一路径；两种路径的输出可比较验证；随着信心增长逐步迁移流量。

直白地说：不是一次性替换一条路径，而是两条路径共存直到迁移完成。旧路径是安全网；新路径成长为主路径；旧路径在新路径被证明后删除。


#### 操作步骤

团队在子系统之上构建抽象层。请求进入抽象；抽象根据功能开关（第 4 章）把请求分派给旧实现或新实现。结果返回给调用者；在双运行模式下，两种实现都会执行并比较输出（*shadow read* 模式）。

    class BillingService:
        def __init__(self, old_impl, new_impl, flag_provider):
            self._old = old_impl
            self._new = new_impl
            self._flags = flag_provider

        def charge_customer(self, customer, amount):
            if self._flags.is_on('billing_new_impl', customer_id=customer.id):
                # 新路径为主；如 dual_run 启用，旧路径作为 shadow 运行
                new_result = self._new.charge_customer(customer, amount)
                if self._flags.is_on('billing_shadow_read', customer_id=customer.id):
                    try:
                        old_result = self._old.charge_customer(customer, amount)
                        self._compare_results(new_result, old_result)
                    except Exception:
                        pass  # shadow 失败不影响主路径
                return new_result
            return self._old.charge_customer(customer, amount)

功能开关 `billing_new_impl` 控制哪条路径为主。第二个开关 `billing_shadow_read` 控制是否同时运行另一条路径做比较。通过调整开关，团队可以：

* 第 1 阶段：100% 旧，无 shadow。基线。
* 第 2 阶段：100% 旧，1% 流量 shadow。新路径不影响生产；比较输出。
* 第 3 阶段：100% 旧，100% 流量 shadow。全面比较。
* 第 4 阶段：1% 新（金丝雀），99% 旧。新路径服务真实流量的一个小切片。
* 第 5 阶段：10% 新，90% 旧。更大金丝雀。
* 第 6 阶段：50/50。一半流量各走一条。
* 第 7 阶段：100% 新。旧路径仍存在但不用。
* 第 8 阶段：删除旧路径。

每个阶段都有指标：错误率、延迟、shadow 模式下的输出不匹配。某个阶段引入问题会触发回滚到上一阶段；团队调查后再推进。
