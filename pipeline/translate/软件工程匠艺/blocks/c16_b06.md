### 15.6 AI 代码审查工具

2026 年，AI 代码审查工具为每个 PR 自动提供第二双眼睛。三个主流工具：

* **Greptile**：深度代码库索引；理解跨仓库上下文；适合架构和一致性反馈。
* **CodeRabbit**：逐行反馈；周转更快；适合战术 bug 捕获。
* **GitHub Copilot Review**：与 GitHub 工作流集成；与平台紧耦合；适合已深度使用 GitHub 的团队。

每个工具都有优劣。Carmen 的 Currents 在 2025 年采用 Greptile；该工具的上下文审查能捕获逐行工具遗漏的一致性和架构问题。其他团队更喜欢 CodeRabbit 对快速 PR 的更快反馈。选择取决于团队 PR 形状和复发问题类型。


#### AI 审查工具如何补充人类审查

工具擅长：规模化扫描常见 bug 模式、捕获一致性问题、浮现潜在边界情况、应用超出静态工具的 linting。

工具不擅长：理解团队架构决策、权衡问题重要性、区分真实关切与误报、以恰当语气与作者沟通。

组合：AI 工具先运行，列出一系列潜在问题；人类审查者阅读 AI 发现，排除误报，补充 AI 遗漏的架构和上下文反馈。总审查时间有时比纯人类短（因为 AI 快速浮现战术问题），有时更长（因为人类要 triage 更多问题）。bug 捕获率稳定更高。


#### AI 审查工具的失效模式

* **告警疲劳**：一个 PR 浮现 30 个问题、多数低价值的工具会让团队忽视它。解法是调整工具严格度；有些工具允许配置。
* **只反馈风格**：只捕获 lint 级问题的工具重复 linter 而无额外价值。解法是选择更深度的工具。
* **架构盲**：不理解团队架构约定的工具会标记团队接受的违规（或漏掉团队会阻塞的违规）。解法是向工具配置中添加团队约定（相当于 AI 审查工具的 CLAUDE.md）。
