#### 定义：Decorator

Decorator 模式把对象包装在另一个实现相同接口的对象里；外层对象在委托给内层对象之前或之后增加行为。Decorator 可堆叠：你可以把 decorator 再包进 decorator，每层加自己的行为。

直白地说：当你有一个做 X 的东西，想在外面加 Y（日志、缓存、重试、验证），就包一层做 Y 再转发给它。


#### 2026 年示例

你有一个 HTTP client。想加日志、重试和缓存。每项都是横切关注点；每项都应独立应用：

    class HttpClient(Protocol):
        def get(self, url: str) -> Response: ...

    class CoreHttpClient:
        def get(self, url):
            return requests.get(url)

    class LoggingHttpClient:
        def __init__(self, inner): self._inner = inner
        def get(self, url):
            log.info(f'HTTP GET {url}')
            return self._inner.get(url)

    class RetryingHttpClient:
        def __init__(self, inner, max_attempts=3): self._inner = inner; self._max = max_attempts
        def get(self, url):
            for attempt in range(self._max):
                try:
                    return self._inner.get(url)
                except TransientError:
                    if attempt == self._max - 1:
                        raise

    class CachingHttpClient:
        def __init__(self, inner, cache): self._inner = inner; self._cache = cache
        def get(self, url):
            if url in self._cache:
                return self._cache[url]
            response = self._inner.get(url)
            self._cache[url] = response
            return response

    # 组合：最外层缓存（命中缓存避免重试），然后重试，然后日志，最内层核心
    client = CachingHttpClient(RetryingHttpClient(LoggingHttpClient(CoreHttpClient()), max_attempts=3), cache)

收益：每个行为在自己的类里；可以任意组合；测试核心 client 不需要日志或重试 mock；包装顺序就是行为应用顺序。


#### 何时 Decorator 是正确模式

* **你想给现有行为加横切关注点**（日志、重试、缓存、验证、认证）。
* **各关注点独立**，你可能只想用其中一部分。
* **你希望核心对象保持聚焦**于其主责。


#### 何时 Decorator 是错误模式

如果行为增加是一次性的且不太可能重新组合，内联修改或子类可能更简单。Decorator 在存在*一族*可组合关注点时才闪耀；对单一、无组合的横切关注点，抽象可能比内联替代更重。


### 12.4 Observer（观察者）

Observer 模式让一个对象发布事件，其他对象订阅事件，而发布者不知道订阅者。


#### 定义：Observer

Observer 模式定义*主题*与其*观察者*之间的一对多关系。当主题状态变化，它通知所有观察者；观察者作出反应。主题不知道观察者的类型；观察者自行注册。

直白地说：当你有某个东西发出事件，而其他东西应该对这些事件作出反应时，Observer 就是解耦形状。
