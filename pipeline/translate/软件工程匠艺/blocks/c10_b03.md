### 9.2 重构 2：内联函数（Inline Function）

**信号**：函数除了函数体本身外没有语义价值。函数名和函数体基本相同，或函数只被调用一次，且调用点没有比直接内联更清晰。

**之前**：

    def is_premium_customer(customer):
        return customer.tier == 'enterprise'

    def get_pricing(customer, product):
        if is_premium_customer(customer):
            return product.enterprise_price
        return product.standard_price

如果 `is_premium_customer` 只在 `get_pricing` 里调用，且函数名没有让调用点更清晰：

**之后**：

    def get_pricing(customer, product):
        if customer.tier == 'enterprise':
            return product.enterprise_price
        return product.standard_price

收益：少一个要读的函数；条件现在内联可见。

这个重构是抽取函数的逆操作。关键是*方向*：抽取函数把重复逻辑 Consolidate 成命名单元；内联函数解开一个没赚到名字的单元。

**AI 层**：当函数只有一个调用者时，AI 智能体能安全执行内联函数。函数有多个调用者时就没那么可靠；内联会以智能体未必充分考虑的方式改变代码库形状。


### 9.3 重构 3：重命名（Rename）

**信号**：名字具有误导性、过于泛化或已过时。常见罪犯：`data`、`info`、`process`、`handle`、`manager`、`helper`。不那么常见但更危险：写时准确、但随着周围代码演化而变错的名字。

**之前**：

    def process(data):
        """Apply tax to the order total."""
        return data * 0.08

**之后**：

    def apply_tax(amount):
        return amount * 0.08

收益：函数目的现在在调用点可见；参数名与实参匹配。

重命名是最被低估的重构。第 18 章（命名即设计）专门讨论它。在本章，重点是机械的：2026 年每个 IDE 和多数智能体都有重命名工具，操作便宜、价值高。

**AI 层**：当重命名纯粹是机械的（单一语言内的函数或变量）时，AI 智能体能安全执行。当名字也编码在代码库之外时（序列化格式、外部配置、数据库 schema），它们会失败。人类的工作是划定范围：只在代码内安全；跨系统需要更谨慎。
