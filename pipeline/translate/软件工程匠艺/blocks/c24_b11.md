#### 应用问题

**Q5.** 取你最近一个季度的工作，用七项纪律审计。每项按 1–5 分给自己打分。最低分是哪项？你能养成什么习惯来提高它？

提示

最低分就是最高杠杆。

**答：** 这是开放练习。常见发现：

* 编码机械（重构、版本控制）得分高；战略性纪律（ADR、命名即设计、AI 指导）得分低。
* 最低项通常是工程师还没刻意练习过的。
* 一个具体习惯：对最低分的纪律，承诺在接下来的一个月每个 PR 都应用一次。几周刻意练习后，习惯会变成反射。

更深教训：在最低分纪律上改进产生最大杠杆，因为其他纪律已经大体就位；抬高地板比抬高天花板更有价值。

**Q6.** 从 §23.1 选一条纪律，计划下季度深度投资。具体计划：你会养成哪些习惯、如何衡量进度、谁会给你反馈？

提示

具体计划比模糊意图更持久。

**答：** 这是开放练习。一个合理的计划结构：

* **选择纪律**：例如命名即设计。
* **要养成的习惯**：每个我开的 PR 至少识别并改一个可改进的名字；每个我审查的 PR 至少评论一个命名决策；每月与一位队友做一次小型重命名 workshop。
* **进度衡量**：追踪每个 PR 的重命名数；每月调查团队对代码清晰度的感受。
* **反馈来源**：审查我 PR 的资深工程师，对命名质量给出反馈。

计划足够具体可执行；衡量足够具体可评估。季度末根据实际效果调整。

**Q7.** 与团队做一次综合讨论。识别团队做得好和忽视的纪律。对忽视的纪律，团队计划是什么？

提示

团队层面讨论产生团队层面承诺。

**答：** 这是开放练习。常见发现：

* 团队通常 3–5 项做得好，2–4 项做得差。
* 被忽视的纪律往往相关（不做 ADR 的团队通常也不做强审查，因为两者都需要刻意流程）。
* 团队计划应解决阻塞其他改进的纪律：不做 ADR 的团队会反复辩论已经做过的决策；解决 ADR 能解锁更好的债务管理、更好的 onboarding、更好的审查。

团队讨论产生个人承诺无法产生的承诺。纪律在团队层面复利；练习是集体行为。
