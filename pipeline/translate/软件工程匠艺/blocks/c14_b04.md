#### 2026 年的现实

Python 3.10 的 `match` 语句、TypeScript 的 discriminated unions、Rust 的 `enum`、Scala 的 `sealed` traits、Kotlin 的 `sealed` classes：对 sum type 做模式匹配已是标准。新代码里出现 Visitor 通常是工程师或 AI 智能体在套用训练数据中的模式，而没有意识到语言已有更简单工具。


### 13.3 Abstract Factory Factory：从未有效的模式

本章开头的 `CustomerRepositoryFactoryProvider` 是更广泛反模式的一个实例：只为把构造决策推迟到“某种未来灵活性”而存在的间接层，而这种灵活性从未兑现。


#### 反模式的形状

GoF 目录里包含 Abstract Factory：一个构造相关对象族的类。在少数特定场景（跨平台 UI 工具包、插件架构）中，Abstract Factory 有用。反模式是它的过度应用：

* **Abstract Factory**：`WidgetFactory` 创建 `Button`、`Window`、`Menu`。
* **Factory Factory**：`WidgetFactoryFactory` 基于平台创建 `WidgetFactory`。
* **Factory Factory Factory**：`WidgetFactoryFactoryProvider` 基于配置选择正确的 `WidgetFactoryFactory`。

每层都加一层间接。每层当时都被辩解为“未来灵活性”。每层都会复利：读代码需要先理解三层构造，才能到达真正的 `Button`。


#### 反模式为何在遗留代码中延续

* **每层都是善意加入的**，通常工程师真心预期需要灵活性。灵活性很少兑现；层留了下来。
* **移除一层需要理解其所有调用方**。层在两端复利；把它们重构掉是真实工作。
* **原加层的团队已经离开**。新团队继承层时没有原始理由。
