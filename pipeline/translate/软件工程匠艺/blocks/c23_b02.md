#### 2026 年主要 agent-mode 工具

* **Cursor agent**：集成在 Cursor 编辑器中；专长重构、功能工作、代码库导航。
* **Claude Code**：Anthropic 基于 CLI 的智能体；适合终端驱动工作流、复杂多步任务、与现有工具链集成。
* **Devin**：更沙箱化环境中的 agentic 工具；专长 ticket 到 PR 的完整周期。
* **v0**：Vercel 面向 UI 的智能体；专长前端工作。

每种工具各有所长。团队可能用 Cursor agent 做 IDE 内工作，Claude Code 做终端工作，Devin 做自主 ticket 执行。选择取决于工作形状。

> **工具名说明**：本书点出具体工具（此处及别处：Cursor、Claude Code、Devin、v0、Greptile、CodeRabbit、GitHub Copilot Review、LaunchDarkly、Statsig、Unleash、Flipt），因为它们是 2026 年实际工程师在用的。到 2027–2028 年，这份名单会显得过时：工具会更名、被收购、退役；新工具会出现。agent mode 的*形态*（人类指导下自主多步执行）和 AI 审查工具的*形态*（深度代码库索引、逐行反馈、平台集成审查）是持久的。具体名字不是。2028 年读本书时，在脑中替换为团队正在用的工具；纪律可以迁移。


#### Agent mode 擅长什么

* **机械多步工作**：跨多文件重构、一致重命名、根据规范生成测试。
* **自我验证**：运行测试、观察失败、修复失败、迭代直到通过。
* **代码库导航**：读取多文件、理解模式、应用团队约定（当约定被明确时）。
* **基于模式的实现**：实现遵循智能体已见过已知模板的功能。


#### Agent mode 不擅长什么

* **新颖架构决策**：智能体不知道你的领域、团队历史、战略约束。它选默认；人类选战略。
* **调查非确定性 bug**：给智能体“这个 flaky”，它会试明显方法；真正难的 bug 需要人类调查。
* **权衡谈判**：智能体按 spec 做；人类决定 spec 该是什么。
* **维护制度记忆**：智能体会话间遗忘；ADR 和 CLAUDE.md 是持久记录。


### 22.2 Spec 驱动工作流

2026 年的主导工作流把测试即 spec（第 8 章）与 agent mode 结合：

  1. **人类写 spec**：描述期望行为的 failing tests。
  2. **人类调用智能体**：带上 spec、代码库和相关上下文。
  3. **智能体实现**：写代码、运行测试、迭代。
  4. **人类审查**：智能体报告完成后，人类逐行审查 diff。
  5. **人类迭代**：要求改动（重命名这个、加强这个测试、重构那段）。
  6. **人类合并**：满意时。

工作流的关键属性是：人类角色是*写 spec 和审查*，不是*编码*。智能体打字；人类思考。
