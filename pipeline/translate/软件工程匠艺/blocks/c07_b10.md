#### 应用问题

**Q5.** 从代码库选一个小纯函数，为它写三个基于属性的测试，并为每个标明属性家族。跑一遍确认通过。

提示

规范化器、格式化器、解析器、算术辅助函数都是好起点。

**答：** 这是开放练习。示例：函数 `normalize_email(s: str) -> str` 小写并去除首尾空格：

    @given(st.text())
    def test_normalize_email_idempotent(s):
        assert normalize_email(normalize_email(s)) == normalize_email(s)

    @given(st.text())
    def test_normalize_email_lowercase(s):
        assert normalize_email(s) == normalize_email(s).lower()

    @given(st.text())
    def test_normalize_email_no_whitespace(s):
        result = normalize_email(s)
        assert result == result.strip()

属性家族：幂等（测试 1）、不变量（测试 2 和 3）。三者一起规定了函数输出属性；实现必须同时满足才算正确。

**Q6.** 在代码库最小模块上跑变异测试。报告覆盖率和变异分数。挑三个 survive 变异体；分别判断它表示缺测试、等价变异体还是死代码。分别处理。

提示

小模块变异测试跑得快；挑一个 supposedly 已充分覆盖的模块。

**答：** 这是开放练习。100 行模块常见发现：

* 覆盖率 92%。变异分数 60%。
* Survive 变异体 1：`if x > 0` → `if x >= 0`。表示缺 `x = 0` 边界测试。加测试。
* Survive 变异体 2：`return None` → `return False`。函数只在把返回值当 truthy/falsy 的地方调用。该变异体等价；标记为等价。
* Survive 变异体 3：防御性 `assert isinstance(x, int)` 没有测试触发，因为所有调用者都传 int。该行是死代码；要么删除，要么加非 int 输入确认断言行为的测试。

修复后：覆盖率 92%（不变或略升），变异分数 75%。75% 到 100% 的差距主要是等价变异体和取舍；75–85% 是多数模块的健康运行区间。

**Q7.** 取一个 AI 助手生成的函数，为它加基于属性的测试。前后跑变异测试。报告变异分数差值。差值告诉你 AI 生成测试的什么信息？

提示

应用 §6.7 组合工作流。

**答：** 这是开放练习。常见发现：AI 生成测试产生中等变异分数（40–60%），加两三个基于属性测试后分数提高 15–25 分。差值说明：AI 测试覆盖了幸福路径；基于属性测试抓住了 AI 没考虑到的边界情况。组合套件明显比仅 AI 套件更强。

如果差值很小（变异分数几乎不动），函数要么太简单（没有真正的测试缺口可填），要么属性陈述太弱。加强属性再试；通常问题在于属性说得不够强。
