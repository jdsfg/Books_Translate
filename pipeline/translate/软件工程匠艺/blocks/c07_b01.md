Helix 的一个 ISO 8601 日期字符串解析器有 94% 行覆盖率。团队信任它。124 个单元测试覆盖了每种已记录的格式。然后客户的数据流水线在生产环境对 `2024-02-29T23:59:60Z`（闰秒、闰年）这类日期开始失败。这个 bug 在解析器里已潜伏 7 个月。124 个测试覆盖了作者当时想到的所有格式；闰秒情况不在其中。

次周 Aki 在解析器上跑了一个变异测试工具。变异分数：41%。覆盖率 94%，变异杀灭率 41%。差距在于 bug 类别空间：测试覆盖了行，但没抓住许多会改变语义的小改动。Aki 用 Hypothesis 加了基于属性的测试：对任意有效 datetime，先序列化再解析的字符串可 round-trip；对任意非 datetime 字符串，解析应抛出特定异常。一天内，测试套件生成并测试了数千个输入；它发现了闰秒情况、一个 Aki 没考虑到的闰年情况、以及一个在半小时时区偏移（印度、伊朗）上失败的情况。

加入后的变异分数：87%。接下来季度解析器缺陷率：零。

本章讲把通过测试套件变成*锋利*测试套件的两项纪律：基于属性的测试，它生成你的团队没想到过的输入；变异测试，它衡量套件是真的在测试，还是仅仅覆盖。


### 6.1 基于属性的测试：思想

传统单元测试是示例驱动。你挑具体输入，预测输出，断言。测试覆盖范围就是你想象力的覆盖范围：你想到的情况被测到；你没想到的就没有。闰秒在你的解析器坏掉之前很难想到。

基于属性的测试反转结构。你陈述函数对某类输入应满足的*属性*，框架生成许多输入来尝试证伪。如果框架找到让属性失败的输入，你就发现了一个 bug（并且得到了一个自动化回归测试）。


#### 定义：属性

属性是一条关于函数行为的逻辑陈述，对某类输入必须成立。典型属性形式包括：round-trip 恒等式（`parse(serialize(x)) == x`）、幂等（`f(f(x)) == f(x)`）、交换律（`f(a, b) == f(b, a)`）、不变量（`for all x, |f(x)| ≤ |x|`）。

直白地说：属性是你可以对函数行为*形态*做出的声明，独立于任何具体输入。它们通常比完整规约弱，但比示例测试在输入域覆盖上更强。
