#### 三条要点

  1. **下一个冲刺把 `git add -p` 当作默认。** 逐块 staging，而不是 `git add .`；每个概念改动单独提交。一个 PR 很痛苦，三个后成为反射。如果一个冲刺后它省的不多，就放弃——但多数试过的人发现它留下了。
  2. **为你想养成习惯的纪律配置 shell 别名。** `git ap` 用于分块 staging，`git lg` 用于美观图，`~/.gitmessage` 用于提交信息模板。摩擦会杀死习惯；别名消除摩擦。
  3. **下次遇到来源不明的回归时，先拿起 `git bisect run`，再拿起调试器。** 写一个失败测试，命名最后一个已知好标签，然后走开让 Git 二分查找。答案在几分钟内到达；替代方案是数小时。
