### 14.2 五张地图，做着各自的五件事

**它的四肢是 API 调用（本卷，第五卷）。** 这条管道真正对外部世界_做_的每一件事，都是通过柜台窗口完成的。读取订单，是向店铺的订单柜台发出读取请求。读取库存表并写回库存表，是向表格柜台发出的请求。起草感谢信，意味着请邮件服务的柜台准备消息。门铃，则是店铺的柜台窗口反过来伸手，来给 Mara 响铃。把其他一切剥掉，这条管道就是一组对柜台窗口的造访：按约定格式询问，读取返回来的带标签盒子，也尊重诚实的“不”。这些是管道的四肢，是伸出去触碰各项服务的部分。而它的**日记**，也就是它每个星期一做了什么的流水记录，仍然属于本卷：那份日志，是 Mara 扫一眼就能确认“起草了十二封，跳过了两封”的东西。

**它的配方住在带历史的 repo 里（第一卷）。** 管道不只是它的运行；它还有自己的_定义_：WHEN-THEN 计划、精确指令、告诉助手如何写出 Mara 声音的提示词。这个定义值得像任何你花了几个月打磨过的东西一样保存：放在一个带版本控制的项目里，每一次改动都被记录，任何过去版本都能找回。当 Mara 改进感谢信措辞时，repo 也记得旧版本，所以她可以比较，也可以回滚。而 repo 恰恰是她的密钥_绝不能_进去的地方，因为 repo 会记住历史；所以密钥住在外面，住在管道会读取的私密位置。repo 是管道对自身的记忆。

**私有模型可以成为它的一名工人（第二卷）。** 其中一名工人，也就是根据 Mara 买家的私密细节来起草内容的那一名，可以是一个_本地模型_：她自己的 AI，运行在她自己的常开机器上，让敏感处理永远不离开房间。不是每条管道都需要这一点；这一条有我们在第 11 章见过的、由隐私塑造出来的理由，而地图会告诉她，这样一名工人该准确插进哪里。

**它运行在终端的世界里（第三卷）。** 管道并不漂浮在抽象里；它作为真实机器上一项真实任务，在真实的文件与进程之间运行，也就是第三卷的世界。它的星期一定时运行，由那位不知疲倦的日历办事员设置，也就是按时钟触发它的调度器。当 Mara 或她的助手需要看着它工作、一步步看它运行、读过流过屏幕的内容时，这种观看发生在终端的世界里，像站在正在运行的任务肩后。这就是管道行走的地面，是四肢之下的操作楼层。

**它永远在线的部分住在服务器上（第四卷）。** 每周组装可以住在 Mara 自己的机器上，星期一她打开盖子时触发。但急单委托的_门铃_不能这样；它必须每一个小时都醒着，在一个固定地址监听，因为委托可能在凌晨 3 点落地。所以这一块住在一台小服务器上，成为互联网上一个从不睡去的存在，随时准备接住店铺的响铃，并把它传给 Mara。服务器是这条管道永远敞开的耳朵。
