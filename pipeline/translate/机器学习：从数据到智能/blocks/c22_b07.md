#### 应用问题

**Q1.** 你的创业公司想为一家软件公司构建客户支持机器人。你有 500 条标注（用户问题，正确答案）对。可在以下方案中选择：(A) 从头训练 Transformer；(B) 用 SFT 微调 BERT；(C) 用 LoRA 微调 GPT-3.5；(D) 少样本提示 GPT-3.5。从成本、性能、延迟、隐私比较这些方案。

*提示*

考虑你拥有的标注数据量（500 对），以及问题是事实性还是推理性。

**答案：**

| 方案 | 性能 | 成本 | 延迟 | 隐私 |
|---|---|---|---|---|
| A：从头训练 | 低（500 样本太少） | 高（GPU） | 低 | 高（本地部署） |
| B：BERT 微调 | 中等 | 低（BERT 小） | 很低 | 高（本地部署） |
| C：GPT-3.5 LoRA | 高 | 中等（LoRA 训练） | 中等 | 取决于托管方 |
| D：少样本 GPT-3.5 | 高 | 低（API 调用） | 高（API 延迟） | 低（数据发给 OpenAI） |

**建议：** 对多数初创公司，先用 **(D) 少样本提示**——零训练成本、性能不错、迭代快。若性能不够或隐私要求禁止将数据发到外部 API，再转向 **(C) 在自托管模型（如 Llama-3-8B）上用 LoRA 微调**。500 条样本足以显著提升 7–13B 模型在特定产品域上的准确率。**(A) 从头训练** 在 500 条样本下绝不合理；**(B) BERT** 适合分类式路由，但难以处理开放式回复。


#### 深入思考

**Q1.** 大语言模型有时会自信地陈述错误信息（"幻觉"）。鉴于你已知 LLM 的训练方式（在互联网文本上做下一个 token 预测，RLHF 优化 helpfulness），解释为什么幻觉是训练目标的可预见后果，而非意外或 bug。

**讨论：** 幻觉是训练目标的直接后果：

**来自下一个 token 预测：** 模型因预测流畅、合理的续写而获得奖励，而非因准确。像 "Marie Curie 在 1904 年获得诺贝尔物理学奖" 这样合理但错误的陈述可能有高预测概率（Marie Curie、Nobel Prize、Physics 经常共现），尽管年份是错的（应为 1903）。流畅度与准确率不是同一目标。

**来自 RLHF：** 人类评分者通常无法核实冷门话题的事实声明。他们更偏好自信、结构良好的回复，而非不确定的回复（"I'm not sure" 常比自信但错误的答案得分低）。RLHF 可能无意中奖励自信的幻觉。

**来自数据分布：** 训练数据包含事实错误、过时信息和虚构内容。模型无法可靠区分事实（Wikipedia）与虚构（小说）——两者都是"要续写的文本"。

**结构性原因：** Transformer 有固定上下文窗口，训练后无法访问外部事实。当被问到知识截止日期之后的事件时，它必须基于训练数据中的模式生成，而非实际知识。它没有"知道自己不知道"的机制。

正在探索的解决方案：检索增强生成（RAG）、带引用的思维链提示、不确定性量化、宪法 AI（RLAIF）。目前还没有一个能完全解决幻觉——它仍是 LLM 部署中最核心开放问题之一。
