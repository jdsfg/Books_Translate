#### 应用题

**Q1.** 你正在调试一个 bug：Web 应用的深色模式开关在设置页可用，但用户导航到另一个页面后不会保持。请写出一段关于这个 bug 的小黄鸭解释，逐步走过预期的数据流。至少指出两个你会说“等等，让我检查这个假设”的位置。

提示

追踪深色模式偏好，从：用户点击开关 → 状态变化 → 状态被保存 → 用户导航 → 新页面加载 → 状态被读取 → 主题被应用。

**答案：** 小黄鸭解释：

“好，用户在设置页点击深色模式开关。点击后，React 状态更新——`setDarkMode(true)`。设置页用深色模式样式重新渲染。这部分是有效的。

现在，这个偏好被_保存_到哪里了？**[等等——让我检查这个假设。]** 我假设它被保存到了某个持久位置——localStorage、数据库、cookie。让我检查一下……_查看代码_……啊，开关处理器调用了 `setDarkMode(true)`，但它是否也调用了保存函数？让我确认。

假设它确实被保存了——比如保存到 localStorage。用户导航到另一个页面时，新页面加载后需要读取深色模式偏好。layout 组件很可能在 mount 时从 localStorage 读取……**[等等——让我检查这个假设。]** layout 组件真的读取了这个偏好吗，还是依赖刚才设置页上的 React 状态？如果它是局部组件状态（设置页中的 `useState`），用户导航离开后这个状态就会被_销毁_。新页面必须从持久存储读取。

所以最可能的两个原因是：(1) 偏好根本没有保存到持久存储——只保存到了局部组件状态。(2) 偏好保存了，但其他页面没有在 mount 时读取它。”

**识别出的两个假设检查点：**

  1. “我假设它被保存到了某个持久位置”——检查保存是否真的发生。
  2. “layout 组件真的读取了这个偏好吗”——检查其他页面上的初始化逻辑。

**Q2.** 你团队里的一名初级开发者被一个 bug 卡住了。他来找你说：“API 坏了。它返回了错误的数据。” 运用本章原则，你会如何引导他进行一次小黄鸭式的调试会话，而不是直接告诉他答案？写出你会问的苏格拉底式问题。

**答案：** 引导调试的苏格拉底式问题：

  1. **“你能把 API 实际返回的数据，以及你预期的数据，准确展示给我看吗？”**——迫使他们进行精确观察，而不是含糊地说“错误数据”。让他们比较预期与实际。

  2. **“带我走一遍这个请求——你发送的是什么 URL、什么方法、什么参数？”**——迫使他们表达输入侧。他们可能会发现自己调用了错误 endpoint 或发送了错误参数。

  3. **“数据的旅程中，在哪个点开始变错？它在数据库里就错了吗，还是在某个环节被错误转换了？”**——把他们引向二分查找思维（第 5 章），但不直接告诉他们这项技术。

  4. **“你对这个 API 做了哪些假设？API 文档怎么说？”**——暴露假设。他们可能假设 API 的行为和实际不同。
