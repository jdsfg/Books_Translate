#### 定义：调试中的假设

调试假设是关于已观察症状原因的、具体且可测试的主张。它必须精确到你可以设计一个测试来支持或反驳它。

用普通话说：假设是你最有根据的猜测——但它必须是你愿意承认可能错、并且能够检查的猜测。


#### 步骤 3：预测

如果你的假设是正确的，那么_还应该_有哪些事情为真？这是大多数人会跳过的一步，也是最重要的一步。

如果元素不存在是因为 ID 拼错了：

* 预测 1：查看第 42 行会看到一个带有特定 ID 的 `document.getElementById()` 调用
* 预测 2：在 HTML 中搜索那个精确的 ID 不会找到匹配项
* 预测 3：HTML 中会有一个相似但不完全相同的 ID（正确的那个）

如果元素不存在是因为它尚未渲染：

* 预测 1：如果你加一个延迟，同一段代码可能会工作
* 预测 2：脚本可能是在 `<head>` 中加载的，并且没有 `defer` 或 `DOMContentLoaded`

预测会把假设变成你可以用一个动作来测试的东西。没有预测，测试就会变得漫无目的。


#### 步骤 4：测试

执行能够区分你的假设是对还是错的_最简单测试_。

打开 `form.js`，跳到第 42 行。你看到：`document.getElementById('user-emial').value`。现在搜索 HTML：元素的 ID 是 `user-email`。问题就在这里——`emial` 和 `email`。一个拼写错误。

这个测试花了 30 秒。如果你直接跳到“让我重写整个表单处理器”，你会花一个小时去修并没有坏掉的东西。


#### 步骤 5：缩小范围

你的测试结果会缩小搜索空间。要么：

* 假设得到了**支持**：你已经找到了原因（或者至少大幅接近了原因）。在我们的例子中，这个拼写错误完美解释了 `null` 错误。
* 假设被**反驳**：ID 完全匹配，所以问题在别处。现在你根据学到的东西形成一个_新_假设，然后再来一轮。

即使被反驳的假设也是有价值的——它排除了一种可能性，并教会你关于系统的一些东西。唯一浪费的循环，是你什么也没学到的循环；这通常发生在测试不够具体的时候。


#### 常见误解

**“如果我的第一个假设错了，我就浪费了时间。”** 这是调试中最适得其反的信念之一。被反驳的假设不是浪费时间——它是_信息_。你现在知道了一件之前不知道的事：缺陷不在你刚刚检查的区域。如果你在每个循环中都在缩小搜索空间，那么即使猜错了，你也在取得进展。浪费时间的唯一方式是不缩小范围：反复测试同一个区域，运行无法区分可能性的含糊测试，或者在没有实际测试的情况下放弃一个假设。
