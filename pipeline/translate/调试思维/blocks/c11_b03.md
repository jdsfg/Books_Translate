### 11.4 变量作用域缺陷

变量有作用域——它们存在于代码的某些部分，而不存在于其他部分。当变量在错误的作用域中被访问，或不同作用域中两个同名变量被混淆时，就会发生作用域缺陷。
    
    
    // Bug: inner 'result' shadows outer 'result'
    let result = "success";
    if (condition) {
        let result = computeValue();  // New 'result', shadows outer
        console.log(result);          // Shows computed value — correct
    }
    console.log(result);  // Still "success" — the inner assignment didn't affect this
    
    
    
    # Bug: loop variable leaks into outer scope (Python-specific)
    for item in items:
        if item.price > 100:
            expensive = item
    
    # After the loop, 'expensive' holds the LAST expensive item found,
    # or causes NameError if NO items were expensive
    print(expensive.name)  # Bug if items list had no expensive items
    

**诊断模式** ：如果某个变量的值不对，而你确信自己正确地给它赋过值，检查是否存在遮蔽（另一个不同作用域中的同名变量）。如果某个变量在本应有值时却是 `undefined`，检查它是否定义在一个已经无法访问的作用域中（在已经结束的块、函数或循环内部）。


### 11.5 状态变更缺陷

状态变更——在原地修改数据，而不是创建新的副本——是最容易滋生缺陷的土壤之一。
    
    
    // Bug: the function modifies the input array
    function getTopScores(scores) {
        scores.sort((a, b) => b - a);  // sort() modifies the array IN PLACE
        return scores.slice(0, 3);
    }
    
    const allScores = [45, 92, 78, 61, 88, 73];
    const top = getTopScores(allScores);
    // Now allScores is [92, 88, 78, 73, 61, 45] — permanently reordered!
    // Any code that expected allScores to be in its original order is now broken.
    

变更缺陷的阴险之处在于：造成问题的代码（排序）通常离表现出症状的代码（稍后读取被重新排序数组的某段代码）很远。反向追溯（第 8 章）至关重要——从错误的数据一路追踪回变更发生的位置。

**常见变更陷阱：**

* `Array.sort()` 会原地变更（JavaScript、Python、Java）
* 对象赋值复制的是引用，而不是值：`b = a; b.x = 5;` 也会改变 `a.x`
* 将对象传给函数——函数可以修改调用者的数据
* 组件或线程之间共享的可变状态

**诊断模式** ：如果数据是错的，而你找不到它是在哪里被设置成错误值的，就怀疑变更。别的东西正在修改同一份数据。添加一个观察点（第 10 章）来捕捉变更发生的瞬间，或者把数据设为不可变，看看代码在哪里断裂（那些地方就是变更点）。


### 11.6 竞态：最困难的缺陷

竞态是代码逻辑缺陷中最困难的一类，因为它们是非确定性的——它们取决于时序，而时序会在不同运行、不同机器、不同环境之间变化。
