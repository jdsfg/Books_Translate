### 11.4 变量作用域缺陷

变量有作用域——它们存在于代码的某些部分，而不存在于另一些部分。作用域缺陷发生在变量被错误地在某个作用域中访问，或者不同作用域里同名的两个变量被混淆的时候。
    
    
    // 缺陷：内部的 'result' 遮蔽了外部的 'result'
    let result = "success";
    if (condition) {
        let result = computeValue();  // 新的 'result'，遮蔽外部变量
        console.log(result);          // 显示计算得到的值——正确
    }
    console.log(result);  // 仍然是 "success"——内部赋值没有影响这里
    
    
    
    # 缺陷：循环变量泄漏到外部作用域（Python 特有）
    for item in items:
        if item.price > 100:
            expensive = item
    
    # 循环结束后，'expensive' 保存找到的最后一个昂贵商品，
    # 或者如果没有任何商品昂贵，则导致 NameError
    print(expensive.name)  # 如果 items 列表中没有昂贵商品，这里就是缺陷
    

**诊断模式**：如果某个变量的值不对，而你确信自己已经正确赋值，就检查是否发生了遮蔽（不同作用域中存在另一个同名变量）。如果某个变量本该有值却是 `undefined`，就检查它是否定义在一个已经无法访问的作用域中（例如已经结束的块、函数或循环内部）。


### 11.5 状态变异缺陷

状态变异——原地修改数据，而不是创建新的副本——是最容易滋生缺陷的领域之一。
    
    
    // 缺陷：该函数会修改输入数组
    function getTopScores(scores) {
        scores.sort((a, b) => b - a);  // sort() 会原地修改数组
        return scores.slice(0, 3);
    }
    
    const allScores = [45, 92, 78, 61, 88, 73];
    const top = getTopScores(allScores);
    // 现在 allScores 是 [92, 88, 78, 73, 61, 45]——顺序被永久改变了！
    // 任何期望 allScores 保持原始顺序的代码现在都会出问题。
    

变异缺陷阴险之处在于：造成问题的代码（排序）往往离表现出症状的代码（稍后读取已重排数组的代码）很远。向后追踪（第 8 章）至关重要——从错误的数据一路追溯到变异发生的地方。

**常见变异陷阱：**

* `Array.sort()` 会原地变异（JavaScript、Python、Java）
* 对象赋值复制的是引用，而不是值：`b = a; b.x = 5;` 也会改变 `a.x`
* 把对象传给函数——函数可以修改调用者的数据
* 组件或线程之间共享可变状态

**诊断模式**：如果数据错了，而你找不到它在哪里被设置成了错误的值，就要怀疑变异。其他东西正在修改同一份数据。添加观察点（第 10 章）来捕捉变异发生的瞬间，或者把数据改为不可变，看看代码在哪里崩掉（那些位置就是变异点）。


### 11.6 竞态：最难处理的缺陷

竞态是代码逻辑缺陷中最困难的一类，因为它们是非确定性的——它们依赖时序，而时序会在不同运行、不同机器和不同环境之间变化。
