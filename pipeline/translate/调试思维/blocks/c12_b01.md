在软件开发中引发过无数争论的五个词："It works on my machine."

开发者说的是实话。代码在他们的笔记本上运行得完美无缺。而在预发布服务器、CI 流水线、生产集群或同事的机器上，它会崩溃、挂起、产生错误结果，或静默失败。代码是相同的。行为却不同。为什么？

因为代码并不是在真空中运行的。它运行在一个_环境_中——操作系统、一组已安装包、文件系统、环境变量、网络配置、可用内存、CPU 架构，以及十几个会因机器而异的其他因素。当环境变化时，行为就会变化——即使代码完全相同。

环境缺陷是最令人沮丧的一类调试对象，因为代码看起来是正确的（在你的环境中，它确实正确），而标准调试技巧（阅读代码、用调试器逐步执行）不会揭示问题，因为问题不在代码里。


### 12.1 "Works on My Machine" 分类法

环境缺陷分为几类，每一类都有不同的诊断方法：


#### 配置差异

同一段代码在不同环境中读取不同的配置值。

**示例** ：你的应用在开发环境中连接 `localhost:5432`，在生产环境中应连接 `db.production.internal:5432`。但生产环境变量 `DATABASE_URL` 被拼错成了 `DATABSE_URL`。应用找不到预期变量，回退到 `localhost:5432`，然后无法连接，因为生产服务器上没有本地数据库。

**诊断** ：比较不同环境中的环境变量、配置文件和功能开关。在两台机器上都使用 `env | sort`，并 diff 输出。


#### 依赖版本差异

同一个库的不同版本会表现不同。

**示例** ：你使用 Node.js 20.11.0 开发。CI 服务器运行 Node.js 18.17.0。你使用的某个特性（`Array.prototype.findLast()`）是在 Node 18.4.0 中加入的——所以两边都能工作。但 Node 20.0.0 引入了 `JSON.parse()` 处理某些 Unicode 字符方式的细微行为变化。你的代码在不知情的情况下依赖了这个新行为。

**诊断** ：比较运行时版本（`node --version`、`python --version`、`java -version`）和包版本（`npm ls`、`pip freeze`、`mvn dependency:tree`）。不要只检查主版本——补丁版本也重要。


#### 操作系统差异

macOS、Linux 和 Windows 对某些事情的处理方式不同。

**关键差异：**

* **文件系统大小写敏感性** ：macOS 和 Windows 默认不区分大小写；Linux 区分大小写（第 9 章讨论过）
* **换行符** ：Windows 使用 `\r\n`，Unix 使用 `\n`。解析文本文件的代码可能会因错误换行符而坏掉。
* **路径分隔符** ：Windows 使用 `\`，Unix 使用 `/`。硬编码路径会跨 OS 失效。
* **默认 locale 和编码** ：不同系统可能使用不同文本编码，导致字符显示问题。
* **文件权限** ：Unix 有 owner/group/other 权限；Windows 有 ACL。在一个系统上可读的文件，在另一个系统上可能不可读。
