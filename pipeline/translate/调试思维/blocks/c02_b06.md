#### 常见误解

**“调试循环太慢了——我应该直接动手开始修。”** 这个循环感觉慢，是因为每一步都显得很小。但总耗时几乎总是少于另一种做法。跨 4 个循环，每一步花 2 分钟 = 8 分钟。随机戳代码 45 分钟，最后偶然撞上答案 = 45 分钟。调试循环胜出，不是因为每一步都快，而是因为每一步都_有产出_——你每次都会学到东西。


### 2.7 练习


#### 概念检查

**Q1.** 按顺序列出调试循环的五个步骤，并用一句话解释每个步骤完成什么。

**Answer:** (1) **观察**——收集关于症状的、具体且可验证的事实。(2) **假设**——形成一个关于原因的、具体且可测试的主张。(3) **预测**——确定如果假设正确，还应该有哪些事情为真。(4) **测试**——执行最简单的检查，以区分对错。(5) **缩小范围**——使用测试结果为下一轮循环缩小搜索空间。

**Q2.** 收敛和打转有什么区别？举出一个你可能正在打转的迹象。

**Answer:** 收敛意味着每个调试循环都会缩小问题空间——你正在更接近根本原因。打转意味着你在原地绕圈，没有取得进展。打转的一个迹象是：你已经调试了 30 分钟，却说不清自己已经排除了哪些可能性。其他迹象包括：反复检查同一区域，假设随着时间推移变得越来越含糊，或者在没有预测的情况下改东西“看看会发生什么”。

**Q3.** 为什么预测步骤很重要？跳过它会出什么问题？

提示

想一想，当你在不知道自己要找什么结果的情况下运行测试时会发生什么。

**Answer:** 预测步骤迫使你把假设变得具体且可测试。没有它，你运行的测试会含糊不清——你不知道什么结果会确认假设、什么结果会反驳假设，因此无法清楚解释结果。例如，如果你的假设是“数据库很慢”，然后你在没有预测的情况下查看数据库仪表盘，你可能看到响应时间为 200ms，却不知道这算“慢”还是“正常”。有了预测——“如果数据库是瓶颈，那么当我绕过数据库时，API 响应时间应该降到 100ms 以下”——测试结果就很清楚：要么会，要么不会。预测把含糊的测试变成决定性的测试。

**Q4.** 在资料页演练（2.6 节）中，如果调试者跳过循环 2 的测试（通过 curl 调用 API），会发生什么？

**Answer:** 没有 curl 测试，调试者会假定 API 处理器有缺陷，然后花时间阅读服务器代码、检查数据库查询，并可能对 API 逻辑做出不必要的修改。curl 测试揭示了 API 在直接调用时工作正常——这是一个关键信息，它把调查从“服务器缺陷”转向“浏览器请求的某些因素”。跳过这个测试可能会导致花数小时调查错误的层。这说明为什么测试每一个假设如此重要：它能防止你深入错误的兔子洞。
