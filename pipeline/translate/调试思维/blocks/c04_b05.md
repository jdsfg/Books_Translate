### 4.6 搜索错误消息的艺术

有时错误消息本身还不够——你需要搜索帮助。但搜索有正确方式，也有错误方式。

**错误方式：** 把整个错误消息，包括你的具体文件路径、行号和变量名，复制到 Google 里。这通常不会产生结果，因为你的具体上下文是独一无二的。

**正确方式：** 提取错误消息中_通用_的部分——错误类型和一般描述——然后搜索它：

* 不要搜索：`TypeError: unsupported operand type(s) for +: 'float' and 'str' at app.py line 45 in process_order`
* 要搜索：`Python TypeError unsupported operand type(s) for + float and str`

通用版本能匹配到成千上万遇到同类错误的其他人。你的文件名和行号只属于你，不会出现在别人的问题里。

**更好的方式：** 添加描述你情境的_上下文_关键词：

* `Python TypeError float str when reading from CSV` —— 如果你正在从 CSV 读取数据（CSV 会返回字符串）
* `JavaScript ReferenceError not defined after import` —— 如果该变量本应已经被导入

**阅读 StackOverflow 答案时：** 寻找解释错误_为什么_发生的答案，而不只是给出修复的答案。一个说“在变量外面加上 `float()`”的答案能修复你的眼前问题。一个说“CSV readers return all values as strings; you need to convert numeric columns”的答案会给你理解，避免未来再次遇到同一类错误。


#### 常见误解

**“如果我看不懂错误消息，那它一定没用。”** 有时错误消息确实晦涩难懂——但很多时候，它们只是陌生。你第一次看到 `ECONNREFUSED` 时，它看起来像乱码。一旦你知道它的意思是“connection refused”（E = error prefix，CONN = connection，REFUSED = refused），它就完全清楚了。随着时间建立你的错误消息词汇表。考虑把陌生的错误消息加入你的**调试日志**——写下消息、它是什么意思，以及在你的具体案例中是什么导致了它。你会惊讶于它们很快就会变成第二天性。
