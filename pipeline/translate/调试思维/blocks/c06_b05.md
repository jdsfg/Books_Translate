### 6.8 调试谜题：排序惊喜

**调试谜题：为什么排序会破坏搜索？**

一个 Web 应用有一个产品列表，包含搜索和排序功能。用户报告，在按价格对产品列表排序后，搜索功能停止工作——即使搜索列表中清楚可见的产品，也返回无结果。

**线索逐步揭示：**

**线索 1：** 构建一个 MRE——一个简单 HTML 页面，包含一个有 5 个 products 的 JavaScript array、一个 sort function 和一个 search function——复现了 bug。排序前搜索正常，排序后搜索失效。

**线索 2：** 排序后添加 `console.log(products)` 显示 products array 看起来正确——所有 products 都存在，并按价格排序。

**线索 3：** search function 搜索的是一个名为 `searchIndex` 的_单独_ array，它是在页面加载时构建的。排序会 mutate main array，但 `searchIndex` 仍然引用原始顺序。search function 按 array index 进行比较。

**你的任务：** 根因是什么？MRE 如何帮助你比调试完整应用更快地找到它？

**解答：** search function 使用 array indices 来匹配 products。页面加载时，`searchIndex[0]` 映射到原始顺序中的第一个 product。排序后，`products[0]` 是另一个 product（最便宜的那个），但 `searchIndex[0]` 仍然指向原始的第一个 product。index mismatch 意味着搜索会查找错误的 products。修复方法是：排序后重建 search index，或者使用 product IDs 而不是 array indices 来匹配。

MRE 有帮助，是因为：在完整应用中，search 和 sort 系统位于不同文件中，中间有多层抽象。基于 index 的映射隐藏在 function calls 背后。在 30-line MRE 中，两个系统都能在一个屏幕上看到，使 shared-index dependency 变得明显。
