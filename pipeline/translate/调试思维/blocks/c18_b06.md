#### 应用题

**Q1.** 一名初级开发者向你求助：“我的 React 组件渲染了，但没有显示任何数据。控制台没有错误。” 写出你会按顺序提出的苏格拉底式问题，引导他们找到缺陷。对每个问题，注明它教授的调试原则。

提示

带他们走过：观察（他们实际看到了什么？）、假设（数据可能在哪里丢失？）、测试（如何检查每个假设），以及缩小范围（每个测试结果告诉了我们什么？）。

**答案：**

  1. **“这个组件现在在浏览器里看起来是什么样？”**（教授精确观察——第 2 章。“什么都不显示”可能意味着“组件渲染了但数据为空”，也可能意味着“组件根本没有渲染”。这种区别很重要。）

  2. **“数据来自哪里？你能追踪它从源头到屏幕的旅程吗？”**（教授小黄鸭调试法——第 7 章。把数据流说出来会暴露假设。）

  3. **“在这段旅程的哪个点，数据是正确的？你检查过 API 返回了什么吗？”**（教授二分查找——第 5 章。拆分系统：数据在 API 层是正确的吗？如果是，缺陷就在前端。如果不是，它就在后端。）

  4. **“在你把它传给组件之前，`console.log(data)` 显示了什么？”**（教授可观测性——第 10 章。检查真实数据，不要假设。）

  5. **“有没有可能数据是在组件渲染之后才到达的？”**（教授假设生成。这会把他们轻轻推向异步/时序问题，而不直接给出答案。）

  6. **“如果你不获取数据，而是硬编码一些测试数据，会发生什么？组件会显示硬编码数据吗？”**（教授最小可复现示例思维——第 6 章。如果硬编码数据能显示，组件本身是工作的；缺陷在数据获取中。）

  7. **“根据我们学到的内容，最可能的原因是什么？”**（教授学习者综合发现并形成结论——缩小范围步骤。）

**Q2.** 设计一个“调试道场”——一种团队学习练习，让开发者练习调试技能。你会使用什么形式，准备哪些缺陷，又会如何促进学习？

**答案：**

**形式：** 每月 1 小时会话。每组 3-4 名开发者。1 名引导者。

**准备：**

* 创建 3 个带缺陷的代码示例，难度逐渐增加。每个缺陷说明一种具体技术。
    * 缺陷 1（15 min）：一条清晰的错误消息和栈跟踪。测试：团队能否读取错误并追踪到根本原因？（第 4 章）
    * 缺陷 2（20 min）：一个没有错误的逻辑缺陷——代码能运行，但产生错误输出。测试：二分查找、反向追溯。（第 5、8 章）
    * 缺陷 3（25 min）：一个间歇性缺陷（竞态或环境相关）。测试：假设生成、偏差意识。（第 3、11 章）

**引导：**

* 团队协作调试，把他们的过程大声说出来
* 引导者观察并记录团队什么时候跳过步骤（没有读取错误消息）、陷入偏差（过早结论），或者使用了好技术（二分查找、构建最小可复现示例）
* 每个缺陷后进行 5 分钟复盘：哪种技术有效？出现了什么偏差？你下次会做什么不同的事？
* 保持有趣：庆祝有创意的调试方法，而不只是快速解法

**学习成果：**

* 在安全环境中练习应用技术
* 从同伴的方法中学习
* 建立共享的调试词汇
* 让关于偏差和错误的讨论正常化
