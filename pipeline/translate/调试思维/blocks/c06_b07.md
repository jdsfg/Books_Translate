#### 应用题

**Q1.** 一个 React 应用有一个 bug：表单验证消息在页面加载时立即出现，而不是等到用户提交表单后才出现。该应用有 40 个 components、Redux state management、custom hooks 和一个 CSS-in-JS library。描述你会如何使用减法方法为这个 bug 构建 MRE，逐步说明。

提示

从识别明确无关的东西开始。bug 与表单验证时机有关——你可以立即排除什么？

**答案：** Step-by-step MRE construction：

  1. **移除所有非表单 pages/routes。** bug 在表单中——其他 35 个页面无关。测试：只保留表单页面时 bug 仍然存在吗？几乎肯定是。

  2. **移除无关 services。** Authentication、analytics、notifications——这些都不会影响 form validation rendering。全部移除。

  3. **简化表单。** 如果表单有 15 个 fields，减少到 2 个——一个有 validation，一个没有。测试：validation message 是否仍在加载时出现？

  4. **移除 CSS-in-JS。** 用 plain HTML 替换 styled components。如果 bug 仍然存在，CSS 没有参与。

  5. **简化状态管理。** 用 local component state（`useState`）替换 Redux。如果 bug 仍然存在，Redux 不是原因。如果它消失，Redux state initialization 参与其中。

  6. **移除 custom hooks。** 如果表单使用 `useFormValidation()`，就把它的逻辑直接 inline。这会暴露 validation trigger logic。

  7. **检查剩下的内容。** 到这里你很可能拥有：one component、one form field、one validation rule 和 local state。bug 现在位于约 30 行代码中。最可能的原因是：validation 在 render 时触发（在一个没有 proper dependency array 的 `useEffect` 中，或 initial state 已经包含 validation errors），而不是在 submit 时触发。

**Q2.** 你想在 StackOverflow 上就一个 bug 寻求帮助：你的 Python script 在读取某个特定 CSV 文件时崩溃。该 CSV 是一个来自生产数据库的 50MB 文件，有 200,000 行和 45 列。你会如何创建一个适合公开发布的 MRE？除了最小性之外，你还需要处理哪些顾虑？

**答案：** 从生产数据创建公开 MRE 需要几个步骤：

**Step 1 — 最小化数据：**

* 从完整 CSV 开始。只用前 100 行 bug 会发生吗？10 行呢？1 行呢？
* 一旦找到最小行数，检查：只保留相关列 bug 会发生吗？移除列，直到只剩下必要列。
* 目标：一个也许只有 3 行、3 列但仍然显示 bug 的 CSV。

**Step 2 — 匿名化/合成数据：**

* 永远不要公开发布生产数据。用具有相同特征的合成值替换真实值。如果 bug 是由 name field 中的特殊字符导致的，就创建一个带有该字符的假名字。
* 确保合成数据仍能复现 bug。

**Step 3 — 最小化代码：**

* 把 script 剥离到只剩 CSV reading 和 failing operation。移除所有与 crash 无关的 business logic、error handling 和 output formatting。

**Step 4 — 保证完整：**

* 内联包含 CSV data（把它嵌入为 string 或 multiline variable），使 MRE 自包含——读者不应需要下载文件。
* 包含确切 Python version 和 library versions。
* 包含确切 error message 和 stack trace。
