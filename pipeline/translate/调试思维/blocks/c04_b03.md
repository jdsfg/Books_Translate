#### 定义：堆栈跟踪

堆栈跟踪（或 traceback）是在错误发生时对活动函数调用的报告。它显示导致错误的函数调用链，让你能够从崩溃点向后追踪执行路径，直到其起源。

用通俗语言说：堆栈跟踪回答的是“我们是怎么到这里的？”它就像穿过你代码的一串面包屑——从错误被_检测到_的位置，回溯经过导致该点的每一次函数调用。

下面这个关键洞见能把堆栈跟踪从噪声变成信号：

**抛出错误的那一行，并不总是导致错误的那一行。**

考虑：
    
    
    function getUser(id) {
        return database.query(`SELECT * FROM users WHERE id = ${id}`);  // Line 5
    }
    
    function showProfile(userId) {
        const user = getUser(userId);
        console.log(user.name);  // Line 10 — crash: user is undefined
    }
    
    function handleClick() {
        showProfile(null);  // Line 14 — the ACTUAL bug
    }
    

堆栈跟踪会指向第 10 行——那里 `user.name` 崩溃了，因为 `user` 是 `undefined`。但_原因_在第 14 行：`null` 被作为用户 ID 传入。而_传播_发生在第 5 行：用 `null` 查询数据库没有返回结果。

阅读堆栈跟踪意味着_反向_追踪因果链：

  1. 第 10 行崩溃，因为 `user` 是 undefined
  2. `user` 是 undefined，因为 `getUser` 什么也没返回
  3. `getUser` 什么也没返回，因为 `id` 是 null
  4. `id` 是 null，因为 `handleClick` 传入了 `null`

根因在第 14 行。堆栈跟踪让你从第 10 行开始，但你必须沿着链条继续跟下去。

**实用提示** ：在大多数堆栈跟踪中，你会看到你的代码和框架代码混在一起。略过框架行——它们几乎从来不是缺陷所在。寻找你的文件中的行。缺陷通常在堆栈跟踪中最靠上的那一行你的代码（抛出错误的行），或者在堆栈更下方第一个传入坏数据的你的代码调用中。


### 4.4 错误消息是线索，不是解决方案

错误消息告诉你程序在哪里_失败_，但那里并不总是程序_出错_的地方。

把它想象成一座桥梁倒塌。桥梁检查员可以准确告诉你哪根梁断了（错误）。但_原因_可能是：

* 这根梁制造时有缺陷（抛出错误的函数中有缺陷）
* 这根梁安装不正确（调用者中有缺陷）
* 设计让这根梁承受了过多载荷（架构问题）
* 指定了错误类型的梁（上游类型不匹配）

类似地，`TypeError: Cannot read property 'name' of undefined` 告诉你，在这条具体语句中某个东西是 `undefined`。_原因_可能在任何上游位置：不正确的函数参数、未处理的失败 API 调用、数据结构中缺失的属性，或者数据尚未加载完成的竞态。

错误消息为你的调查提供_起点_。应用第 2 章中的调试循环：

  1. **观察** ：完整阅读错误消息。哪个变量不对？它是什么类型？
  2. **假设** ：那个变量从哪里取得它的值？什么会让它变错？
  3. **预测** ：如果我的假设正确，当我检查上游代码时应该看到什么？
  4. **测试** ：检查。
  5. **缩小范围** ：沿着链条追踪，直到找到根因。
