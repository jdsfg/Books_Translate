* **删除，如果：** 代码不可达（没有调用路径）、被永久关闭的 flag 保护，或已被活跃代码复制替代。版本控制会在日后需要时保留历史。
* **保留，如果：** 代码是已知 fallback path、实现了必要但罕见的错误处理，或属于已发布 API 的一部分（即使当前没有调用者使用它——外部调用者可能在用）。
* **调查，如果：** 代码看起来是死的，但你不是 100% 确定——它可能通过 reflection、dynamic dispatch 或 external triggers 被调用。

**流程：** 安排季度“死代码清扫”。指派工程师审查被标记的候选项，并删除已确认的死代码。把死代码删除视为安全措施，而不是 housekeeping。
