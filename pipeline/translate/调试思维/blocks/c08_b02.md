### 8.2 反向追溯的实践

让我们把反向追溯应用到一个具体例子上。

**症状：** 一个电商应用把某位客户的总额显示为 0.00 USD，尽管购物车里有三件商品。

**步骤 1 —— 0.00 USD 显示在哪里？** 在 cart 组件中，有一行：`<span>{order.total}</span>`。所以 `order.total` 是 0。

**步骤 2 —— `order.total` 从哪里取得值？** 它由 `calculateTotal(order.items)` 计算。所以 `calculateTotal` 返回了 0。

**步骤 3 —— `calculateTotal` 做什么？**
    
    
    function calculateTotal(items) {
      let total = 0;
      for (const item of items) {
        total += item.price * item.quantity;
      }
      return total;
    }
    

在有三件商品的情况下返回 0，说明要么 `items` 为空，要么每个 `item.price * item.quantity` 都是 0。

**步骤 4 —— items 是空的吗？** 记录 `items`：它有 3 件商品。记录每个 `item.price`：它们全都是 0。所以价格是问题。

**步骤 5 —— item prices 来自哪里？** 它们来自 `cart.addItem(product)`，该方法复制 `product.price`。检查 product 对象——它们的价格是正确的（19.99、24.99、9.99）。

**步骤 6 —— `addItem` 如何复制 price？**
    
    
    addItem(product) {
      this.items.push({
        name: product.name,
        price: product.Price,  // Bug: capital P!
        quantity: 1
      });
    }
    

找到了。`product.Price`（大写 P）而不是 `product.price`（小写 p）。JavaScript 在访问不存在的属性时不会抛出错误——它会静默返回 `undefined`。而 `undefined * 1 = NaN`，但是……等等，总额显示的是 0.00 USD，不是 NaN。

**步骤 7 —— 为什么是 0.00 USD 而不是 NaN？** 检查显示代码：`order.total.toFixed(2)`。`NaN.toFixed(2)` 是什么？它是 `"NaN"`。但显示的是 0.00 USD……

回到 `calculateTotal`：`total += item.price * item.quantity`。如果 `item.price` 是 `undefined`，那么 `undefined * 1` 是 `NaN`，而 `0 + NaN` 是 `NaN`。但显示值是 0，不是 NaN。

更仔细检查实际数据：`console.log(item.price)` 显示 `0`，不是 `undefined`。所以这个属性确实被设置了，但被设置成了 0。

重新检查：`product.Price`。如果 product 对象有 `Price` 属性（大写 P），那么 `product.Price` 会有值。检查产品数据源……API 返回 `{"Price": 19.99}`（来自后端的大写 P）。前端代码期望 `product.price`（小写）。但 `addItem` 使用 `product.Price`（大写 P），这反而是有效的！那它是在哪里变成 0 的？

检查 cart 显示代码：它读取 `item.price`（小写 p）。`addItem` 把它存成了 `price: product.Price`，所以存储的属性确实是 `price`（小写）。但这个值……等等。

让我重新读一遍 `addItem`：
    
    
    price: product.Price,  // product.Price = 19.99 ✓
    

实际上，这应该有效。让我再检查一次。product 数据是来自 API，还是来自前端某个已经转换过它的地方？
