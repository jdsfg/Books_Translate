#### 定义：接口契约

接口契约是一份明确的规格说明，描述一个组件发送什么、另一个组件期望接收什么，包括数据类型、单位、格式、有效范围和错误条件。定义良好的接口契约会把隐含假设变成明确且可测试的内容。

用直白的话说：当两个系统彼此交谈时，双方需要就语言达成一致。火星气候轨道器灾难发生，是因为一方说英制，另一方说公制，而没有人检查。

**如何防止接口假设类 bug：**

  1. **明确记录所有接口。** 包括单位、数据类型、有效范围和预期格式。
  2. **使用类型系统。** 如果有一种类型能区分 `PoundForceSeconds` 和 `NewtonSeconds`，就会在编译时捕获这种不匹配。
  3. **专门测试接口。** 不要只孤立地测试每个组件，还要测试组件之间的 _连接_。把数据从系统 A 发送到系统 B，并验证 B 正确解释了它。
  4. **在边界处验证。** 从另一个系统接收数据时，要验证它：是否在预期范围内？是否匹配预期格式？对这些值做合理性检查。

第 8 章的 Ampersand Bug 是同一类错误的小规模版本。浏览器以 URL 编码格式发送密码；服务器却以不同方式解释它，因为 `&` 在那种格式中有特殊含义。双方都是“正确”的——bug 在它们之间的接口里。


### 13.2 Cloudbleed（2017）：当解析器 bug 泄露内存

2017 年 2 月 17 日，Google 的安全研究员 Tavis Ormandy 注意到一件奇怪的事：他在 Google 搜索爬虫结果中看到了随机网页的片段。来自约会应用的聊天消息片段、带有个人信息的酒店预订确认、密码管理器内容——这些全都泄露进了无关网站的 HTML 中。

原因被追溯到 Cloudflare，这是一家为数以百万计的网站处理 Web 流量的内容分发网络。Cloudflare 的 HTML 解析器中有一个 bug，导致它读过了内存缓冲区的末尾，并把相邻内存中碰巧存在的任何内容都包含进来——也就是其他客户 Web 请求中的私有数据。
