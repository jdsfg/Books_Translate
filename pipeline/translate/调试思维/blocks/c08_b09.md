#### 应用题

**Q1.** 一份财务报告显示 Q3 收入为 1.2M USD，但从原始交易手工计算得到 1.5M USD。数据流为：raw transactions → currency conversion → regional aggregation → quarterly roll-up → report。应用反向追溯技术：描述你会检查的每一步、会寻找什么，以及如何判断哪一次转换引入了 300K USD 的差异。

提示

300K USD 的差异约为正确总额的 20%。这个百分比是否暗示了某种错误类型？

**答案：**

**反向追溯：**

**步骤 1 —— 报告。** 报告显示 1.2M USD。检查：报告是否准确显示了它的输入？如果 quarterly roll-up 给出 1.2M USD，报告只是显示它收到的内容。不是报告的错。

**步骤 2 —— quarterly roll-up。** 对月度值求和。Q3 = July + August + September。检查：三个月是否加总为 1.2M USD？如果是，一个或多个月份的值不正确。如果不是，roll-up 公式有错。

**步骤 3 —— regional aggregation。** 检查：所有地区总额是否加总为月度总额？也许某个地区缺失或重复。缺失地区可以解释 300K USD 缺口——该地区的贡献丢失了。

**步骤 4 —— currency conversion。** 检查：汇率是否正确？300K USD 缺口约为正确总额的 20%。如果某些交易使用的货币汇率偏差 20%，或者未转换的交易（某种每单位约值 0.80 USD 的货币）被当作 USD 处理，就会产生约 20% 的低估。

**步骤 5 —— raw transactions。** 检查：所有 Q3 交易是否都存在？也许有些交易被日期范围过滤掉（时区问题——见第 8 章的时区谜题），或被过于激进的数据质量过滤器过滤掉。

**调查策略：** 从报告开始反向检查每个边界处的数据。第一个数据正确的步骤说明紧随其后的转换就是罪魁祸首。20% 的提示指向 currency conversion 或缺失某个地区子集——同时测试这两个假设。

**Q2.** 你正在调试一个 Web 表单：即使用户勾选了 “Subscribe to newsletter” 复选框，表单提交时它也总是未勾选。请同时应用反向追溯和变量隔离来诊断这个 bug。展示每种技术下的推理过程。

**答案：**

**反向追溯：**

  1. **服务器收到 unchecked：** 服务器日志显示 POST data 中复选框值为 `false`（或不存在）。所以要么浏览器发送了错误值，要么服务器解释错了。

  2. **浏览器发送了什么？** 检查 Network tab 的 form data。如果复选框值在 POST data 中不存在，说明浏览器发送的是“未勾选”。如果它存在但服务器读错了，bug 在服务器端。

  3. **提交时复选框是否处于勾选状态？** 在 submit handler 中、构造 form data 之前添加 `console.log(checkbox.checked)`。它是 `true` 吗？

  4. **如果提交时它是 `false`：** 有东西在用户点击和提交之间取消了勾选。很可能是某个 `useEffect` 或 event handler 重置了表单状态，或者表单组件在提交时用初始状态（未勾选）重新渲染。
