#### 概念检查

**Q1.** 定义确认偏差，并给出一个它在调试期间如何表现的具体例子。

**答案：** 确认偏差是指倾向于寻找、解释和记住那些证实你既有信念的信息，同时忽略矛盾证据。例如：你怀疑 bug 在支付处理模块中。你给支付模块添加日志，并发现一条警告消息。你宣布“找到了！”——但你从未给订单处理模块打日志，而根本原因实际上在订单处理模块里。你只选择性地调查了自己怀疑的区域，并把一条切线相关的警告解释为确认。

**Q2.** 锚定和可得性启发有什么区别？它们似乎都会让你固定在某个特定嫌疑对象上。

提示

想想固定的来源。每种情况下，最初的嫌疑对象来自哪里？

**答案：** 区别在于固定的_来源_。**锚定**发生在你遇到的第一条信息上——有人提到 DNS，你读到一个关于连接的错误，或者你的第一个随机想法是“是缓存”。你最先听到/想到的东西会变成锚，不管你以前是否经历过它。**可得性启发**发生在你的个人经验和记忆上——你最近处理过认证，或者你以前见过这个症状，当时原因是 X，所以 X 很容易浮现在脑海中。锚定关乎什么是_第一个_；可得性关乎什么在记忆中_生动且新近_。它们经常重叠（你的第一个想法通常就是最可得的记忆），但它们也可能分离：一位同事随口评论 DNS（锚定，不是你的经验）与上个月调试类似问题的记忆（可得性，不一定是第一个）。

**Q3.** 与其他偏差相比，为什么过早闭合尤其危险？

**答案：** 过早闭合尤其危险，因为它会_完全停止调试过程_，而其他偏差只是_误导_它。带着确认偏差、锚定或可得性时，你仍然在调查——只是方向错了。最终，缺乏证据可能会迫使你重新考虑。但过早闭合时，你会因为相信自己已经找到了答案而彻底停止调查。你可能应用一个并未解决根本原因的“修复”，宣布 bug 已解决，然后继续前进——留下真正的原因未被修复，并可能造成未来事故。它是唯一一种能让调试循环过早结束的偏差。
