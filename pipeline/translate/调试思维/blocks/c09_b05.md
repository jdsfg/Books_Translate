### 9.8 调试谜题：依赖幽灵

**调试谜题：自己把自己弄坏的包**

一个已经连续数月保持绿色的 CI 流水线突然开始失败。没有提交任何代码。错误是：`TypeError: flatMap is not a function`。代码使用 `Array.prototype.flatMap`，它从 Node.js 11 版本开始就可用了。

**线索 1：** CI 流水线使用 Docker，并以 `node:lts` 作为基础镜像。

**线索 2：** 上周 `node:lts` 指向 Node 20。昨天，Node 团队发布 Node 22 作为新的 LTS 版本。现在 `node:lts` 指向 Node 22。
**线索 3：** 但 `flatMap` 从 Node 11 开始就可用了。Node 22 肯定支持它。那么为什么会报错？

**线索 4：** 失败的测试文件导入了一个工具库。该库的 `package.json` 指定了 `"engines": {"node": ">=14 <22"}`。这个库的 postinstall 脚本会检查引擎约束，并在约束被违反时安装一个 polyfill bundle，而这个 bundle 意外地用一个损坏的实现遮蔽了 `Array.prototype.flatMap`。

**你的任务：** 有多少个"版本对比"变化共同导致了这次失败？

**解答：** 两个变化叠加在一起：(1) Node.js 的 LTS 标识从 20 移动到了 22——这是自动且不可见的变化，因为 CI 使用 `node:lts`，而不是像 `node:20` 这样固定版本。(2) 工具库的 postinstall 脚本在 Node 22 上的行为不同于 Node 20——这不是你项目中的代码变化，而是由环境变化触发的依赖行为变化。

经验教训：(a) 固定 Docker 基础镜像版本（`node:20.11.1`，而不是 `node:lts`）。(b) 理解 `latest` 和 `lts` 标签是移动目标——它们指向什么随时可能改变。(c) "什么都没变"的说法是错的——有两件事变了，而且都在项目代码库之外。
