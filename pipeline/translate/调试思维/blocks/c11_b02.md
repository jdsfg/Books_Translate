### 11.2 空值和未定义：价值十亿美元的错误

Tony Hoare 在 1965 年发明了空引用，他称之为自己的“价值十亿美元的错误”。空值和未定义引用导致的运行时崩溃，比任何其他单一类别的缺陷都更多。

根本问题是：某个变量本应包含一个值，却包含了 null（或 undefined、nil、None，取决于语言）。任何把它当作有值来使用的尝试都会崩溃。
    
    
    // user 对象可能不存在
    const user = getUser(id);  // 如果找不到 user，则返回 null
    console.log(user.name);    // TypeError：无法读取 null 的属性 'name'
    

**空值的常见来源：**

  1. **没有找到任何结果的数据库查询。** 如果用户 99 不存在，`SELECT * FROM users WHERE id = 99` 会返回 null。
  2. **静默失败的 API 调用。** API 返回 null 或空响应，而不是抛出错误。
  3. **可选字段。** user 对象的 `middleName` 可能为 null，因为不是每个人都有中间名。
  4. **竞态。** 当你尝试使用数据时，数据还没有加载完成。
  5. **数组访问越界。** 当数组只有 5 个元素时访问 `array[10]`，在 JavaScript 中会返回 `undefined`（而在大多数其他语言中会崩溃）。

**诊断模式**：`NullPointerException`，表示无法读取 null/undefined 的属性 `X` 的 `TypeError`，或表示 `NoneType` 对象没有属性 `X` 的 `AttributeError`。看到这些时，问题是：这个变量为什么是 null？向后追踪（第 8 章），找出它本该在哪里被赋值，以及为什么没有被赋值。

**预防模式**：

* **使用前检查 null**：`if (user != null) { ... }`
* **默认值**：`const name = user?.name || "Anonymous"`
* **可选链**：`user?.address?.city`（如果任何部分为 null，就返回 undefined 而不是崩溃）
* **类型系统**：TypeScript、Kotlin、Rust 和其他语言可以在编译时标记潜在的 null 访问


### 11.3 错误条件：逻辑出错时

布尔逻辑是精确的。人类思维不是。两者之间的差距会持续产生缺陷。

**反向条件：**
    
    
    # 缺陷：条件写反了
    if user.is_active:
        return "Account suspended"  # 应该用于非活跃用户
    

**错误运算符：**
    
    
    # 缺陷：AND 应该是 OR
    if age < 13 and age > 65:  # 不可能——没有人既小于 13 岁又大于 65 岁
        apply_discount()
    
    # 修复：
    if age < 13 or age > 65:
        apply_discount()
    

**缺少否定：**
    
    
    # 缺陷：缺少 'not'
    if user.has_permission("admin"):
        return "Access denied"  # 管理员被拒绝？这就反了。
    

**条件中的差一错误**（第 11.1 节的一个特例）：
    
    
    # 缺陷：> 应该是 >=
    if balance > 0:
        allow_withdrawal()
    # 恰好为 0 的余额不被允许——这是有意的吗？
    

**诊断模式**：如果代码做了和你预期_相反_的事情，就检查条件。如果它在大多数情况下做对了，但在特定边界情况中出错，就检查边界条件和运算符。把条件大声读出来：“如果用户是活跃的，那么显示账户暂停消息”——听到这种矛盾，往往就能发现缺陷。
