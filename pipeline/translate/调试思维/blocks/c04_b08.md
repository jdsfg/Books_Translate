#### 概念检查

**Q1.** 列出错误消息中常见的五个组成部分，并解释每个部分提供什么信息。

**答案：** (1) **错误类型/类别** —— 对错误类型进行分类（TypeError、NullPointerException、ECONNREFUSED），帮助你快速理解问题的一般性质。(2) **错误消息** —— 对具体问题的人类可读描述（"unsupported operand type(s) for +: 'float' and 'str'"）。(3) **位置** —— 错误被检测到的文件、行号和函数。(4) **堆栈跟踪** —— 导致错误的一连串函数调用，让你能够追踪执行路径。(5) **上下文/建议** —— 额外信息或建议修复方法（并不总是存在；例如 Python 的 "Did you mean 'print'?"）。

**Q2.** 用你自己的话解释为什么“抛出错误的那一行并不总是导致错误的那一行”。给出一个具体示例。

**答案：** 错误在某一具体行被_检测到_——那里是程序崩溃或抛出的地方。但_原因_常常在上游——是某一行产生了坏数据，最终导致崩溃。示例：函数 A 把 `null` 作为用户 ID 传给函数 B，函数 B 又把它传给函数 C，函数 C 试图在它上面调用 `.toString()` 并崩溃。堆栈跟踪指向函数 C（在那里对 null 调用了 `.toString()`），但根因在函数 A（它一开始传入了 `null`）。函数 B 和 C 只是无辜的中间人，把坏数据继续向前传递。要找到根因，你要从崩溃点沿链条向后追踪。

**Q3.** 在线搜索错误消息时，为什么应该从搜索查询中移除文件路径、行号和变量名？

提示

想一想错误中哪些部分只属于你的代码，哪些部分对遇到此类错误的任何人都是通用的。

**答案：** 文件路径、行号和变量名对你的项目来说是唯一的——世界上没有其他人有一个名为 `app.py` 的文件，其中一个名为 `tax_rate` 的变量在第 45 行崩溃。包含它们会让你的搜索查询过于具体，无法匹配任何现有答案。错误的_通用_部分（错误类型和描述，比如 "TypeError: unsupported operand type(s) for +: 'float' and 'str'"）才是其他开发者也遇到并提问过的内容。剥离具体细节后，留下的就是能够匹配现有解决方案的通用模式。

**Q4.** `404 Not Found` HTTP 错误告诉你什么信息，又没有告诉你什么？

**答案：** 404 告诉你服务器收到了你的请求，但在你指定的 URL 上没有资源——URL 与服务器上的任何路由或文件都不匹配。它没有告诉你：(a) 服务器是否是正确的服务器（你可能访问了错误的 host/port），(b) 资源是否存在于一个略有不同的 URL（路径里有拼写错误），(c) 资源过去是否存在（它可能已被移动或删除），或者 (d) 你的路由配置是否正确（路由可能没有在应用程序的 router 中注册）。404 是 URL 错误的线索，但“错误”可能意味着很多事。
