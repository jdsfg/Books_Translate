### 7.6 调试谜题：过于好用的功能

**调试谜题：为什么过滤器显示了太多结果？**

一个 Web 应用有一个产品过滤器：用户可以选择“类别：电子产品”，只查看电子产品。一次近期更新后，选择“电子产品”显示的是所有产品，而不是只过滤出电子产品。

一名开发者开始使用小黄鸭调试法：

“好，用户点击电子产品过滤器。这会把 `category` 状态设置为 `'Electronics'`。产品列表组件接收这个状态，并把它传给过滤函数。过滤函数接收产品数组和 `category` 字符串，并返回满足 `product.category === category` 的产品。”

停顿。开发者打开过滤函数：
    
    
    function filterProducts(products, category) {
      if (category === '') {
        return products;  // 不过滤——显示全部
      }
      return products.filter(p => p.category === category);
    }
    

“所以如果 `category` 是 `'Electronics'`，它应该会过滤。但现在显示了所有产品，这意味着……它命中了 `category === ''` 分支？可 `category` 是 `'Electronics'`，不是空字符串……”

开发者检查点击过滤器后的 `category` 状态：
    
    
    console.log(category);        // "Electronics"
    console.log(typeof category); // "string"
    console.log(category === ''); // false
    

“嗯，`category` 确实是 `'Electronics'`，而且不是空字符串。所以过滤应该生效……让我用测试数据实际跑一下过滤函数……”
    
    
    const result = filterProducts(testProducts, 'Electronics');
    console.log(result.length); // 3——正确！
    

“等等，我直接测试过滤函数时，它工作正常。所以缺陷不在过滤函数里。一定是在组件调用它的方式上……”

开发者查看组件：
    
    
    const filtered = filterProducts(products, selectedCategory);
    setDisplayedProducts(filtered);
    // ... 稍后，还有一个也会更新显示产品的 useEffect：
    useEffect(() => {
      setDisplayedProducts(products); // 它在之后运行并覆盖结果！
    }, [products]);
    

“哦。`useEffect` 在过滤更新之后运行。它把展示产品重置为未过滤的列表。过滤器本身工作正确，但它的结果立刻被覆盖了。”

**教训：** 小黄鸭流程带开发者走过了三个阶段：(1) 怀疑过滤函数——但测试证明它是正确的。(2) 质疑数据——但 `category` 值是正确的。(3) 质疑_流程_——组件如何编排过滤器——这揭示了覆盖结果的 `useEffect`。如果没有把每一步说清楚，开发者可能会在过滤函数内部耗费数小时，而它其实没有问题。
