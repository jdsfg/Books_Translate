#### 概念检测

**Q1.** 用自己的话陈述康威定律，并举例说明来自 SocialSnap 历史或你了解的系统。

**答案：** 康威定律：组织的沟通结构倾向于反映在其构建的软件设计中。系统有接口的地方就是团队有接口的地方。SocialSnap 的具体例子：工程团队是 8 个人同一房间时，系统是单体——大家自由沟通，代码深度集成。团队增长到 50 人、跨越多个办公室时，系统分解为服务——因为跨团队沟通的高成本迫使团队在职责边界定义明确接口。服务接口（服务间 REST API）映射了团队接口（团队拥有的系统间的 API 契约）。另一个具体例子：如果一家公司的计费团队和产品团队很少沟通，计费系统和产品系统通常会有 poorly designed 集成——每方对另一方的约束和需求只有模糊理解，集成 bug 出现在与沟通缺口匹配的接口上。

**Q2.** Serverless（FaaS）与传统基于服务器的部署有何关键区别？以下用例你会选择 serverless，为什么？(a) S3 上传触发图片缩略图生成，(b) SocialSnap feed API 端点，(c) 夜间报表作业。

**答案：** 关键区别：基于服务器：持久基础设施，为空闲时间付费，完全控制运行时，无冷启动，执行时长无限制，可维护有状态会话。Serverless：每次调用短暂，按执行付费，托管运行时，冷启动惩罚，最大执行 15 分钟（15 minutes），无状态。(a) 图片缩略图生成：**serverless 理想。** 事件驱动（S3 上传触发函数），执行时间短（每张图几秒），负载可变且突发（内容发布后上传聚集），无状态（每张图独立处理）。没有冷启动问题，因为精确延迟不重要——用户不是同步等待。(b) Feed API 端点：**适合基于服务器。** 冷启动延迟（100ms–2s）对必须 < 200ms 响应的端点是灾难性的。高且持续的请求量使按调用付费比预留容量更贵。Feed 服务还受益于 serverless 跨冷启动无法维护的进程内缓存。(c) 夜间报表作业：**serverless 理想。** 每天只运行一次，因此运行之间无空闲成本。执行时间可预测且短（假设报表生成快）。无延迟要求。事件驱动（定时触发）。低运营开销——无需维护服务器。
