### 11.1 会话问题——隐藏的状态

要理解这个 bug，需要先理解登录会话如何工作。

当用户登录（提交用户名和密码）时，服务器验证凭据并创建一个**会话（session）**：一条“用户 42 当前已认证”的记录。服务器需要把该用户后续请求与认证会话关联起来。

传统方案：**cookie**。登录后，服务器用 `Set-Cookie` 头响应，其中包含一个**会话 ID**——类似 `sess_a7b3c9d2e4f1...` 的随机字符串。浏览器存储这个 cookie，并在之后对同一域名的每个请求中附带发送。服务器在**会话存储（session store）**（存放会话数据的位置）中查找该会话 ID，并取回相关用户信息。

在 SocialSnap v3（仍是单台服务器）中，会话存储就是应用服务器自己的内存——一个 Python 字典：


    sessions = {
        "sess_a7b3c9d2e4f1": {"user_id": 42, "username": "alice", "created_at": ...},
        "sess_b8c4d0e5f2a3": {"user_id": 7, "username": "bob", "created_at": ...},
        ...
    }


当带 cookie `sess_a7b3c9d2e4f1` 的请求到达时，服务器在本地 `sessions` 字典中查找，找到用户 42，就知道请求来自 Alice。

一台服务器时没问题。三台服务器就坏了。
