#### 提示移交（Hinted Handoff）

Node B 不可达期间，Node A 或 C 会接收原本给 Node B 的写，并带一个“提示”——一条说明“这条写是给 Node B 的”。Node B 重新上线后，提示节点把队列中的写投递过去。Node B 重放这些写并追上来。

提示移交在节点临时不可用（网络抖动、短暂重启）时有效。对长期不可用无效——提示只保留有限时间。


#### 定义：反熵（Anti-Entropy）

**反熵（anti-entropy）** 是定期比较副本间数据并传播缺失或分歧更新的后台修复过程。在 Cassandra 中，这通过 **repair** 进程完成，使用一种叫 **Merkle tree（默克尔树）** 的数据结构来高效识别副本之间哪些数据不同。

通俗语言：反熵就是系统定期检查副本是否有分歧并修复它们。它是“最终一致性”里的“最终”——即使提示移交失败，反熵最终也会把所有副本拉到一致。


### 14.7 向量时钟——追踪因果关系

最后写入获胜（LWW）冲突解决很简单但危险：它会静默丢弃几乎同时发生的并发写。对很多应用不可接受。Amazon 的购物车 famously 用了更复杂的方法：不是丢弃冲突写，而是保留两者，让应用（或用户）解决冲突。

要知道两次写是真正并发（因而冲突）还是顺序排列（因而后一次是正确值），分布式系统使用**向量时钟（vector clocks）**。


#### 定义：向量时钟

**向量时钟（vector clock）** 是一种追踪分布式系统中事件因果历史的数据结构。它是每个节点一个计数器的列表：`[Node_A: 3, Node_B: 2, Node_C: 1]`。节点发送消息或执行写时，递增自己的计数器。节点收到消息时，通过取每个位置的最大值更新自己的向量时钟。

通过比较向量时钟，可以确定：

* **因果有序：** 如果 X 的向量时钟每个分量都小于等于 Y，且至少有一个严格小于，则写 X 发生在写 Y 之前。Y“知道”X。
* **并发：** 如果 X 和 Y 互不因果前于对方，它们就是并发的。没有因果关系。这表明冲突。

通俗语言：向量时钟让你检测两个事件是否可能知道对方。如果它们不可能知道对方，那它们就是并发的，可能冲突。

向量时钟概念优雅，但运维复杂。实践中，许多系统接受同步时钟 LWW 的不精确（Amazon DynamoDB），或使用应用级冲突解决，或设计数据模型使冲突不可能发生（通过追加只写设计，只创建新记录，不更新）。


### 14.8 CRDT——无冲突数据结构

冲突问题更优雅的解决方案：使用**设计上无论顺序或并发如何都能正确合并**的数据结构。这就是**无冲突复制数据类型（Conflict-free Replicated Data Types，CRDT）**。
