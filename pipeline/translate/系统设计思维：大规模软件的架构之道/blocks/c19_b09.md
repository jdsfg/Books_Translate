#### 密钥管理

服务运行需要密钥：数据库密码、第三方服务 API key、TLS 私钥、JWT 签名密钥。安全地管理这些密钥是关键运营挑战。

幼稚做法——把密钥存在配置文件或环境变量中——带来多种风险：

1. **版本控制泄露：** 如果带数据库密码的配置文件被提交到 git，密码就永远留在仓库历史中。即使后来删除文件，任何克隆仓库的人仍能在历史中看到它。
2. **日志泄露：** 如果应用在启动时记录配置，数据库密码会出现在日志中，而日志通常被发送到访问范围更广的集中式日志系统。
3. **扩散：** 存在环境变量中的密钥往往被复制到部署脚本、CI 配置和文档中——扩散到许多难以审计的地方。

正确做法是使用**密钥管理服务**（HashiCorp Vault、AWS Secrets Manager、GCP Secret Manager）：

1. 密钥存在密钥管理器中，静态加密，每次访问都有审计日志。
2. 服务向密钥管理器认证（使用云身份——例如 AWS IAM 角色）并在启动时获取密钥。
3. 密钥可在密钥管理器中轮换，服务自动更新。
4. 对特定密钥的访问由策略控制：Feed Service 只能访问 feed 数据库的凭证——不能访问 auth 数据库凭证或支付服务凭证。这就是最小权限原则在密钥上的应用。

**密钥管理最重要规则：** 永远不要向版本控制提交密钥。永远不要把密钥包含在日志输出中。永远不要把密钥硬编码在应用代码中。如果做了其中任何一件事，假设该密钥已泄露并立即轮换。
