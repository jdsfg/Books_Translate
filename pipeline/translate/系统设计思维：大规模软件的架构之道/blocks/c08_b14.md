**密码重置邮件：** 如果用户在中断期间请求密码重置，重置链接通常只有 30–60 分钟有效。15 分钟处理延迟可能只剩 15–45 分钟有效期——给急需重置的用户造成压力，他们可能已放弃并请求了第二个重置链接（造成重复）。对这些事件：以最高优先级立即处理，并在发送前验证重置 token 仍有效。如果已过期，生成新 token 或发送“你的重置链接已过期，请重新请求”消息。

**双因素认证码：** 6 位 OTP 通常有效期为 30 秒到 5 分钟。15 分钟队列积压使积压中的任何 OTP 通知完全无用。这类事件绝不应放入带延迟重试的队列——它们应该同步处理（为时间关键动作绕过队列）或在过期后丢弃。

**“你的订单可取了”或“你的车快到了”：** 一条 15 分钟前的“你的车 2 分钟后到”通知不仅无用，还会 actively 误导。这些事件应在事件 payload 中包含过期时间戳；消费者处理前检查时间戳，并丢弃超过动作相关窗口的事件。

**架构修复——事件过期元数据：**


    {
      "event_type": "post.liked",
      "event_id": "evt_abc123",
      "timestamp": "2024-03-15T14:23:01Z",
      "expires_at": null,
      "priority": "normal"
    }



    {
      "event_type": "password_reset_email",
      "event_id": "evt_def456",
      "timestamp": "2024-03-15T14:23:01Z",
      "expires_at": "2024-03-15T14:53:01Z",
      "priority": "high"
    }


消费者在处理前检查 `expires_at`。高优先级事件跳到积压队列前面（通过 8.8 节讨论的优先级队列机制）。这种设计承认了并非所有事件都同样时间敏感——而队列积压会尖锐地暴露这些差异。
