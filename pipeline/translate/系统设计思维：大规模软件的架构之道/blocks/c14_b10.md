#### 概念检测

**Q1.** 用你自己的话描述强一致性（strong consistency）和最终一致性（eventual consistency）的区别。各举一个强一致性必须、最终一致性可接受的场景。

**答案：** 强一致性保证每次读都返回最近写入的值。从读者视角，系统仿佛只有一份始终最新的数据副本。每个已完成写对所有后续读立即可见。

最终一致性只保证：如果写停止，所有副本最终会收敛到同一个值。正在写时，不同读者可能因访问的副本及该副本落后程度不同而看到不同值。

强一致性必要场景：用户银行余额。如果 Alice 给 Bob 转 100 USD，Alice 账户扣减和 Bob 账户贷记必须强一致。如果任一节点的后续读仍能返回转账前 Alice 的余额，她可能再次转出同样 100 USD，导致双重支付。

最终一致性可接受场景：SocialSnap 帖子的显示点赞数。如果一条帖子有 10,247 个赞，而某个用户的点赞还没传播到所有节点，一些读者暂时看到 10,246，另一些看到 10,247。这种不一致只持续毫秒到秒，没有业务后果——短暂看到略旧的计数不会伤害任何用户。

**Q2.** 解释 quorum 条件 `W + R > N`。为什么满足该条件就能保证读返回最近写入的值？

**答案：** N 个副本中，W 是必须确认写的副本数，R 是必须响应读的副本数。如果 `W + R > N`，那么参与写的节点集合与参与读的节点集合必须重叠——不可能选出 W 个写节点和 R 个读节点而至少一个节点不在两个集合里。（最小重叠节点数为 `W + R - N`。）

这保证强一致性，因为重叠节点参与了最近写，因此拥有最新值。当 R 个读 quorum 响应时，读者可取版本号最高的响应——它来自重叠节点。因此读总是返回最近写。

如果 `W + R <= N`，就可能写到一组节点，而读只联系没见到最新写的节点，从而返回陈旧数据。

**Q3.** 什么是 CAP 定理？AP 系统在网络分区期间做何选择？

**答案：** CAP 定理指出，分布式数据存储最多只能同时保证一致性（每次读返回最近写）、可用性（每个请求都收到响应）、分区容错性（网络分区时继续运行）中的两项。由于分区在真实分布式系统中不可避免，有意义的选择是分区期间要一致性还是可用性。

AP 系统在网络分区期间选择可用性：当某些节点无法与其他节点通信时，系统继续为每个孤立分组服务请求。这意味着请求可能从潜在陈旧副本中服务——读可能不反映最近写。系统始终可用，但可能返回不一致数据。
