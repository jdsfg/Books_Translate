1. **静态加密（而非哈希）：** 用由密钥管理器管理的应用级密钥存储加密手机号。数据库中是密文；应用需要时解密。数据库管理员没有应用密钥就无法读取手机号。

2. **哈希索引（index）用于查找：** 同时存储 `SHA-256(phone_number)`（归一化为 E.164 格式后）用于查找。这允许在不解密所有号码的情况下查询“这个手机号是否已注册？”。哈希是单向的——适合等值查找，不适合显示号码。

3. **访问控制：** 只有 Auth Service 能解密手机号。Feed Service、Post Service 和其他服务没有手机号解密密钥。需要显示后 4 位的支持工具通过 Auth Service API 访问——并受审计。

4. **审计日志：** 每次访问用户手机号——无论是系统（发送 SMS）还是支持人员——都记录谁访问、何时、为何。

**支持账户恢复：** 支持人员可以调用返回手机号后 4 位的端点（Auth Service 解密并截断）。除非有明确的升级访问权限和额外授权及增强日志，否则他们看不到完整号码。

这种方法满足：用户隐私（加密，数据库无明文）、运营需求（SMS 发送和支持时可解密）和审计要求（所有访问都被记录）。
