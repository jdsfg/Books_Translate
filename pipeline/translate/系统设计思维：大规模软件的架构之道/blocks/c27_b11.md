**答案：** 迁移计划：阶段 1（Shadow 模式，2 周）：部署 Go 服务与 Python 服务并行。通过镜像代理把所有通知事件同时路由到两个服务。Python 服务继续实际投递通知；Go 服务处理事件但抑制实际投递（只记录它会发送什么）。比较两个服务打算执行的动作：它们计算的通知内容是否相同？这能在不影响用户的情况下验证正确性。阶段 2（金丝雀，2 周）：把 5% 通知事件专门路由到 Go 服务（实际投递）。密切监控投递率、错误率和延迟。若错误率或投递失败上升，立即通过把 100% 流量切回 Python 服务来回滚（功能开关变更）。阶段 3（渐进推出，2 周）：把 Go 服务流量从 5% → 25% → 50% → 100%，每个阶段停留 3–5 天。每个阶段比较两个服务的投递率和错误率。阶段 4（下线 Python 服务，1 周）：Go 服务无事件地处理 100% 流量一周后，下线 Python 服务。保留其代码分支 30 天以备紧急回滚。回滚机制：配置服务中的单个功能开关控制流量路由。把开关从 “go” 改为 “python” 立即重定向所有流量。开关变更通过 gossip（第 26 章）在 10 秒内传播到所有路由节点。
