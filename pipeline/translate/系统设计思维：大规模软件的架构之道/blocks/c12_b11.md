用户名存在两个地方：users 表和每条 post 行。

**答案：** 伪代码：


    1. UPDATE users SET username = 'new_name' WHERE user_id = 42;  // 在用户所在 shard
    2. 对每个 shard (0..7):
         UPDATE posts SET author_username = 'new_name' WHERE user_id = 42;
    3. 使 Redis 中用户 42 的缓存条目失效（见第 7 章）。


失败场景：

**失败 1：** 应用在完成第 1 步后、但在完成第 2 步所有 shard 前崩溃。`users` 表显示新用户名，但某些 shard 的 `posts` 表仍显示旧用户名。用户现在看到旧帖子上是旧用户名，新帖子上是新用户名——不一致。这是部分更新失败。

**失败 2：** 第 2 步很慢（用户 42 有数百万帖子）。第 2 步运行期间，有些 shard 已更新，有些还没有。跨 shard 的查询返回混合用户名值的帖子。读者看到系统不一致的快照。

两个失败都说明为什么反规范化是维护负担：规范化 schema 下单一原子操作，变成多步骤、跨 shard 并带有一致性窗口的过程。
