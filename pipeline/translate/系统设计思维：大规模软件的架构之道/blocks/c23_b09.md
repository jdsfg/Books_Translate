#### 概念检测

**Q1.** 什么是 URL frontier，为什么它比简单 FIFO 队列更复杂？

**答案：** URL frontier 是爬虫的调度数据结构——决定接下来获取哪些 URL、以什么顺序、以什么速率。简单 FIFO 队列不足，原因有三：(1) 它会让爬虫向单个域名发送大量并行请求，压垮该域服务器。URL frontier 用 per-domain 队列执行礼貌策略（每个域名一次一个请求，可配置延迟）。(2) 有些页面更重要，应优先爬取（高 PageRank 域名、频繁更新站点）。FIFO 队列平等对待所有 URL；URL frontier 使用优先级机制。(3) frontier 必须集成重复检测，避免把已见 URL 重新入队。

**Q2.** 用自己的话解释 TF-IDF 直觉。为什么 IDF 用对数？

**答案：** TF（词频）捕捉一个词对特定文档的重要性：一个词在文档中出现很多次，很可能是文档焦点。IDF（逆文档频率）捕捉一个词在整个文档集中的罕见程度：几乎每份文档都出现的词区分力很小。两者相乘，TF-IDF 高当且仅当一个词在文档中出现频繁且在整个文档集中罕见——两个条件都信号真实相关性。IDF 中的对数防止极罕见词主导。否则，100 亿份文档中只有 1 份出现的词原始 IDF 是 100 亿，完全压倒其他词的 TF 贡献。对数压缩范围，使罕见词信号与常见词信号成比例。

**Q3.** 什么是倒排索引，它如何实现快速搜索？

**答案：** 倒排索引是一种数据结构，将每个词（term）映射到包含它的文档列表。它反转了自然的“文档 → 词”关系。它使搜索快，因为查询通过：(1) 在索引中查找每个查询词——每词 O(1) hash 查找；(2) 交集结果倒排记录表。两个有序列表交集是 O(n + m)，n 和 m 是倒排记录表大小。这比扫描所有文档快得多，因为即使对常见词，倒排记录表也只是所有文档的极小一部分。

**Q4.** 为什么爬虫的 seen-set 需要 Bloom filter 而不是标准 hash set？

**答案：** 标准 hash set 把每个 URL 存为完整字符串。100 亿（10 billion）URL 平均 100 字节，精确 seen-set 约需 1 TB 内存——昂贵，可能超过单机可用 RAM。Bloom filter 用多个哈希函数每个条目只存几位；1% 误报率下可在大约 10 GB 内表示 100 亿 URL。误报代价微不足道——爬虫可能偶尔跳过未见 URL，但它会从其他链接路径再次遇到。误报率（把未见 URL 判为已见）按构造为零——Bloom filter 永远不会把未见条目误判为已见。
