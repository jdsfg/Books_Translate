对“把帖子分享到 DM”：DM 系统收到一条包含帖子引用（`{type: "shared_post", post_id: 12345}`）的消息。渲染该消息时，DM 客户端从帖子服务 API 拉取帖子以显示。DM 数据库只存帖子 ID 引用——不存帖子内容。这维护了单一所有权原则：帖子内容由帖子服务拥有，DM 服务只持有其引用。

集成约束：事件必须设计为向后兼容（第 18 章的 expand-contract 也适用于事件 schema）。如果 DM 系统发布 `dm_received` 事件而通知服务依赖该 schema，schema 变更必须向后兼容——添加字段，没有弃用窗口绝不删除字段。


### 本章总结

聊天设计颠覆了 URL 短链的假设。URL 短链无状态的（stateless）、读多、优化快速查找；聊天有状态的（stateful）、写多、优化低延迟双向通信。

WebSocket 是实时消息的首选传输：持久、双向、支持服务器主动推送。连接服务器管理 WebSocket 连接并维护连接注册表（在 Redis 中），用于在不同服务器上的用户之间路由消息。

消息总是先持久化再投递——持久化层提供持久性，实时投递只是其上的尽力优化。已读回执是最终一致的分布式状态：“真实”状态在数秒内收敛到用户可见状态。

在线状态使用 Redis 中基于心跳的 TTL 过期，接受最多 60 秒陈旧作为可用性和简单性的权衡。60 秒陈旧是对完美在线状态在移动网络上不可能实现这一事实的诚实承认。

群聊扇出——把一条消息投递给 N 个成员——在小 N（100–500）时通过批量投递可管理，但在大 N 时成为架构挑战。这个扇出问题在群聊设计中初现端倪，是第 22 章的中心话题。

SocialSnap v7 代表完整的当前架构：核心产品用无状态的（stateless）HTTP 服务，实时消息用有状态的（stateful）WebSocket 服务，每个都有各自的扩展模型、一致性要求和运营特征。
