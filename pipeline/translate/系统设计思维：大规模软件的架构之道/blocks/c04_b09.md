#### 应用问题

**Q1.** 考虑一个多人在线游戏，它有一个全球排行榜，按分数显示前 100 名玩家。玩家每秒更新分数数千次。你会为排行榜选择什么一致性模型，为什么？你的选择带来怎样的用户体验？

提示

想想用户实际看到什么，以及陈旧是否有害。比较写密集型工作负载每秒数千次更新的强一致性成本（延迟、吞吐）。

**答案：** 为排行榜选择**最终一致性**。

**理由：** 排行榜可能被全球数百万玩家每秒更新数千次。强一致性要求所有更新在被确认前先串行化并跨全球副本确认。跨洲往返 150ms+，这意味着全球每秒最多约 7 次排行榜更新——完全不可行。

更重要的是，最终一致性对用户影响很小：玩家更新分数后，2–3 秒才出现在全球排行榜上是可以接受的。排行榜用户知道他们看到的是快照，不是实时 Feed。“你排第 42 名”和“接下来 3 秒你排第 43 名”之间的差异没有实际意义。

**最终一致性的用户体验：** 玩家有时会看到略旧的排名。一个玩家的分数更新可能不会立即出现在另一个玩家的排行榜视图中。两个玩家同时看排行榜可能看到略有不同的排名。这些都不会造成伤害或困惑——对任何全球排行榜来说都是预期行为。

**与支付或库存系统的对比：** 如果排行榜追踪的是库存（“只剩 10 件！”），最终一致性会导致超卖。用户体验伤害是具体且财务性的。这就是为什么选择一致性模型需要理解用户可见后果，而不仅是抽象一致性理论。

**Q2.**（联系第 3 章估算概念）你正在构建一个社交平台，必须跨两个数据中心同步复制写入到 3 个节点（为了持久性和灾备）。一个数据中心在 Virginia，一个在 Oregon。只有当 3 个副本都确认时，写入才算完成。估算最低写入延迟，并解释这如何约束你的架构。

提示

用第 3 章的延迟数字。Virginia 到 Oregon 的距离约 2500 英里。一个数据包跑这段距离要花多久？记住写入必须等待最慢的副本。

**答案：**

**网络延迟估算：** 真空中光速为 186,000 英里/秒；在光纤中约 124,000 英里/秒（由于玻璃折射率，refractive index；光学中的 index，不是数据库索引）。Virginia 到 Oregon 距离：约 2500 英里。

单向传播时间：2500 / 124,000 ≈ 0.02 秒 = **20 ms 单向**

往返时间（写入 + 确认）：**约 40 ms**，仅跨洲这段。

**完整写入延迟拆解：**

* 数据中心内本地网络：约 0.5 ms
* 每个副本处理：约 2 ms
* Virginia → Oregon → Virginia 往返：约 40 ms
* 最低写入延迟总计：约 42 ms

采用同步复制时，每次写入都要等待最慢的副本。如果 Oregon 副本需要 42 ms，每次写入至少 42 ms。
