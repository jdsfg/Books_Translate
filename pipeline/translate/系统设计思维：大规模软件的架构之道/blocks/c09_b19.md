### 本章总结

本章追踪了从用户浏览器到分布式应用的请求，检查了每一步的基础设施。

**DNS** 把域名翻译成 IP 地址，TTL 带来新鲜度与传播速度之间的缓存式 tradeoff（权衡）。DNS 可用于粗粒度地理负载分发。

**负载均衡器** 把请求分发给服务器池。第 4 层负载均衡器基于网络层信息路由（快、与协议无关）。第 7 层负载均衡器基于应用层内容路由（灵活、SSL 终止、稍慢）。健康检查实现自动故障检测。

**一致性哈希** 解决缓存 key 分布问题——集群扩缩容时，只需重新分配相应比例的 key。

**TCP 与 UDP** 代表传输层的基本选择：TCP 的可靠与有序 vs UDP 的速度与可容忍丢失。大多数 Web 应用流量用 TCP；实时媒体常用 UDP。

**WebSocket** 为实时应用实现全双工服务器推送，代价是有状态的连接，使水平扩展复杂化（第 11 章直接处理这个问题）。

**REST、GraphQL 和 gRPC** 是三种各有 tradeoff（权衡）的 API 风格。REST 通用、可缓存。GraphQL 消除过度取回和取回不足。gRPC 是服务间通信的最高性能选择。访问模式线索指导选择。

**API 网关** 在系统边界集中处理横切关注点（认证、限流、路由）。**限流**（令牌桶、滑动窗口）保护后端免受滥用和过载。

本章的权衡矩阵项显示，请求路径上的每个组件都会增加延迟开销，但作为回报提供可用性、可扩展性或运维收益。模式始终如一：你总是在用付出的延迟购买某些东西。

在第 10 章，我们从网络层转向存储层——不是数据库（第 5–6 章已覆盖），而是数据库所依赖的底层存储系统：块存储、对象存储、文件存储，以及决定每一层成本和延迟的存储层级。
