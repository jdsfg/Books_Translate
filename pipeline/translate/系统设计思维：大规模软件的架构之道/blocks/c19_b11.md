### 19.7 攻击者作为对抗性侦探

本章早些时候我们观察到，攻击者以反向方式应用侦探纪律：收集线索并推理如何利用。这种框法有助于设计安全系统——问问自己系统泄露了什么线索。

**通过错误消息泄露信息：** 一个登录表单返回“未找到该邮箱对应的用户”会泄露信息——攻击者现在知道某个邮箱是否已注册。一个对两种情况都返回“邮箱或密码不正确”的表单则不泄露任何信息。原则：错误消息应足够让合法用户纠正错误，但不要足够让攻击者枚举有效输入。

**时序攻击：** 如果你的密码比较函数在第一个字符不匹配时立即返回，攻击者可以通过测量响应时间来逐个确定正确字符。密码比较必须使用**常量时间比较**——无论匹配多少字符都耗时相同——以防止时序信号泄露信息。

**API 枚举：** 如果你的用户资料端点是 `/users/12345`，且对不存在 ID 返回“User not found”，攻击者可以枚举所有用户 ID 来找到有效用户。使用不透明、非顺序的用户 ID（UUID 而非递增整数）让这更难。此外，对端点限流可防止自动枚举。

**堆栈跟踪与内部错误细节：** 生产 API 在错误响应中返回堆栈跟踪会暴露内部架构——语言、框架、库版本、内部服务名。每条都是线索。在 API 边界捕获所有异常并返回通用错误消息；把完整堆栈跟踪记录到内部日志。

**版本披露：** 透露服务器软件和版本的 HTTP header（`Server: nginx/1.14.0`）让攻击者搜索这些版本的已知漏洞。移除或混淆版本 header。

安全根本上是信息不对称：让对手难以学到足以利用系统的信息，同时让合法用户轻松完成工作。系统泄露的每一条信息都是攻击者手中的工具。
