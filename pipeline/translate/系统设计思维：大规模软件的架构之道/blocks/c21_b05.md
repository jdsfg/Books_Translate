#### 消息表

    messages:
      message_id    (BIGINT, globally unique)
      conversation_id (BIGINT, FK → conversations)
      sender_id     (BIGINT, FK → users)
      content       (TEXT, up to 10KB)
      sent_at       (TIMESTAMP WITH TIME ZONE)
      deleted_at    (TIMESTAMP, NULLABLE — soft delete)
    
    
    conversations:
      conversation_id (BIGINT, PRIMARY KEY)
      created_at      (TIMESTAMP)
    
    conversation_participants:
      conversation_id (BIGINT, FK → conversations)
      user_id         (BIGINT, FK → users)
      joined_at       (TIMESTAMP)
      last_read_at    (TIMESTAMP) — 用于已读回执与未读计数
    

**索引策略：**

查询 1（对话历史）：查询是 `SELECT * FROM messages WHERE conversation_id = ? ORDER BY sent_at DESC LIMIT 50`。索引：`(conversation_id, sent_at DESC)` —— 复合索引，让数据库可用单次索引扫描获取对话中最近 50 条消息。没有该索引，数据库要扫描对话所有消息并排序——O(N) 而非 O(log N + 50)。

查询 2（收件箱）：找到用户 A 参与的所有对话及最新消息。这需要 join `conversation_participants` 和 `messages`。为避免全表扫描 `messages`，维护 `conversations.last_message_at` 列，每次发消息都更新。收件箱查询变成：`SELECT c.* FROM conversations c JOIN conversation_participants cp ON c.id = cp.conversation_id WHERE cp.user_id = A ORDER BY c.last_message_at DESC LIMIT 20`。索引 `(cp.user_id, c.last_message_at)`。

查询 4（未读计数）：`SELECT COUNT(*) FROM messages WHERE conversation_id = ? AND sent_at > (SELECT last_read_at FROM conversation_participants WHERE conversation_id = ? AND user_id = ?)`。`conversation_participants` 的 `last_read_at` 字段高效驱动该查询。
