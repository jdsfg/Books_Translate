### 28.6 基础设施即代码——自我描述的系统

全书焦点都在应用架构上。但基础设施——服务器、负载均衡器、数据库、网络——从哪里来？

**基础设施即代码（Infrastructure as Code, IaC）** 是通过机器可读配置文件定义和管理基础设施的实践，对待这些配置像对待应用代码一样：版本控制、代码审查、测试、自动应用。

**Terraform**（来自 HashiCorp）是最广泛使用的 IaC 工具。Terraform 文件描述基础设施的期望状态：


    resource "aws_db_instance" "socialsnap_postgres" {
      engine         = "postgres"
      engine_version = "14.0"
      instance_class = "db.r5.xlarge"
      allocated_storage = 500
      multi_az      = true
      backup_retention_period = 7
    }


应用此配置会在 AWS 上创建指定参数的 PostgreSQL 数据库。修改 `instance_class` 并重新应用即可升级实例。配置文件是基础设施状态的权威描述。

**IaC 的好处：**

* **可复现性：** 任何基础设施都可以通过运行相同配置在新环境中完全重建（例如镜像生产的 staging 环境）。
* **可审计性：** 所有基础设施变更都是代码变更——它们经过代码审查并留下版本历史。“谁改了数据库大小、何时改的？”由 `git log` 回答。
* **灾难恢复：** 若数据中心故障，IaC 允许在数小时（而非数天）内在不同区域重建整个基础设施。
* **漂移检测：** IaC 工具可以比较基础设施实际状态与声明配置，并在两者偏离时告警（工程师绕过 IaC 流水线手动修改了什么）。

SocialSnap 的完整基础设施——200 台应用服务器、40 个数据库实例、15 个 Redis 集群、8 个 Kafka 集群、负载均衡器、VPC、DNS 配置——用约 1.5 万行（15,000）Terraform 配置文件描述。任何工程师运行 `terraform apply` 并等待 20 分钟（20 minutes）即可创建隔离的 SocialSnap 测试环境。
