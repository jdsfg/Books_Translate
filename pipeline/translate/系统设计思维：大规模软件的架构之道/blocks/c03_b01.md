侦探不会等待供词。她会利用可用证据——靴子上的泥、手指上的墨迹、不在场证明的时间——构建最可能的故事。她会得出一个能解释事实的结论，并知道新证据出现时可能需要修正。

系统设计就是侦探工作。在画任何架构图之前，你需要知道自己要构建的东西规模多大。每秒多少请求？多少存储？多少网络带宽？这些数字决定一切——是一个数据库还是五十个，缓存是否有用，单台服务器够用还是荒谬。

你几乎永远不会拥有回答这些问题的完美数据。但你几乎总能估算得足以排除整类糟糕决策。这种从粗略数字推理到自信结论的技能，就是信封背面估算（back-of-the-envelope estimation）。

它是工程中最被低估的技能之一。


### 3.1 你必须知道的延迟数字

在做任何估算之前，你需要了解你所用硬件的速度极限。这些数字不是要背了就忘的——它们是你这个世界的物理规律。掌握它们的工程师能在房间这头就闻出设计里的麻烦。

下面是现代数据中心（2020 年代）延迟数字表，大致正确：

| 操作 | 近似延迟 | 直观感受 |
|---|---|---|
| L1 缓存引用 | 1 ns | CPU 能做的最快的事 |
| L2 缓存引用 | 4 ns | 比 L1 慢约 4 倍 |
| RAM 访问 | 100 ns | 比 L1 慢约 100 倍 |
| 用 Snappy 压缩 1KB | 3 μs | 快，但不是免费 |
| 从 RAM 顺序读 1MB | 10 μs | RAM 顺序读取很快 |
| SSD 随机读 | 150 μs | SSD 快，但不如 RAM |
| 从 SSD 顺序读 1MB | 1 ms | 顺序读取远快于随机读 |
| HDD 寻道 + 读取 | 10 ms | HDD 寻道主导其延迟 |
| 同一数据中心内数据包往返 | 0.5 ms | 数据中心内网络很快 |
| 跨洲数据包往返 | 150 ms | 物理限制了跨洲速度 |
| 从 HDD 顺序读 1MB | 20 ms | HDD 顺序读比 SSD 慢约 20 倍 |

花点时间感受这些数字的量级。RAM 比 SSD 快 100 倍。SSD 随机读比 HDD 快 100 倍。跨洲网络往返比同一数据中心往返慢 300 倍。

这些比例在硬件代际间保持稳定（绝对值会改进，但相互比例保持类似）。掌握它们能让你快速做合理性检查：

* “这个设计每次请求需要 10 次磁盘寻道。每次 10ms，最低延迟就是 100ms——还没加网络时间就已经接近我们的 SLO 上限。这不行。”
* “我们每次 API 调用都做一次跨洲数据库读。每次 150ms。我们的 SLO 是 100ms。没有缓存或把数据搬到离用户更近的地方，这不可能。”
