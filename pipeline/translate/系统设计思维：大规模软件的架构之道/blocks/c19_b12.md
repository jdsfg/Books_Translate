#### 概念检测

**Q1.** 用户加载 SocialSnap 帖子，浏览器将部分帖子内容渲染为 HTML，导致脚本执行。该脚本把用户会话 cookie 发到外部服务器。这是什么类型的攻击，根因是什么？

**答案：** 这是**存储型跨站脚本（stored XSS）**攻击。根因是应用把用户生成内容未经转义就渲染为 HTML。帖子作者在他们的帖子内容中提交了 script 标签。当应用直接把这些内容插入 HTML 响应而不转义时，浏览器把它解释为可执行 JavaScript 而非显示文本。修复方法是在渲染到 HTML 前转义所有用户生成内容——把 `<` 转为 `&lt;`、`>` 转为 `&gt;` 等——让浏览器将其视为文本而非 markup。

**Q2.** 对密码做哈希与加密的区别是什么，为什么哈希是存储密码的正确选择？

**答案：** 加密是可逆的——给定密钥，你可以解密密文恢复原始密码。哈希是单向的——给定哈希，你无法恢复原始密码，除非暴力破解。存储密码应哈希，因为：(1) 应用永远不需要知道原始密码——只需验证提交的密码是否与存储的匹配。它通过对提交的密码做哈希并比较结果与存储的哈希来实现。(2) 如果数据库被入侵，攻击者只有密码哈希——但他们无法在没有暴力破解的情况下恢复原始密码。(3) 使用专用慢哈希算法（bcrypt、Argon2）意味着即使暴力破解也极慢——比使用 SHA-256 等快速哈希慢数千倍，使攻击者对强密码的计算不可行。加密是错误的，因为如果解密密钥也泄露，所有密码都暴露；而且密钥必须存放在某处，成为另一个需要保护的密钥。

**Q3.** 用一个 SocialSnap 架构的具体例子解释最小权限原则。

**答案：** 最小权限原则：每个实体只访问它需要的资源，不多不少。具体例子：SocialSnap 的 Feed Service 需要读取帖子和用户资料来生成 feed。它不需要写帖子、删除用户或访问支付记录。Feed Service 使用的数据库账户应拥有：`posts` 表的 `SELECT`、`users` 表（仅限公开字段）的 `SELECT`，仅此而已。

如果 Feed Service 被攻击者入侵——可能通过远程代码执行漏洞——攻击者只能使用被入侵账户读取帖子和用户资料。他们无法修改数据、删除记录或访问支付信息。相比之下，一个对所有表都有完整 `CRUD` 权限的数据库账户：同样的入侵会让攻击者删除所有用户数据、修改支付记录、提升他们在其他系统的权限。最小权限限制爆炸半径。
