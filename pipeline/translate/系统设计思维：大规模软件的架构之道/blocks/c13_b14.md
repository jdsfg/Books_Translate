Protocol Buffers（protocol buffer 协议）真正的优势主要不是性能，而是**契约强制（contract enforcement）**：`.proto` 文件是客户端和服务器共享的机器可读契约。两边生成的代码确保它们在字段名、类型和结构上一致。用 JSON REST API 时，客户端和服务器很容易悄悄分叉（服务器重命名字段，客户端仍发旧名，被静默忽略）。Protocol Buffers 让这种不匹配变成编译时或 schema 校验错误。


### 本章总结

微服务把单体拆分成独立部署的服务，每个服务拥有自己的数据，通过显式 API 通信。好处真实存在：独立扩展、独立部署节奏、独立故障隔离，以及与团队结构的组织对齐。

成本同样真实：运维复杂度、网络开销、分布式计算谬论（可靠性、延迟、带宽），以及服务边界错误时构建分布式单体的风险。找到正确边界需要侦探的纪律——从组织结构、扩展需求、故障容忍和数据所有权中读取线索。

单体与微服务的抉择不是二元的，而是连续的。结构良好的模块化单体常常是正确起点。当耦合成本超过分布成本时，再抽取服务。

第 14 章，我们将看到服务拆分数据库后数据一致性会发生什么。“每个服务一个数据库”规则通过完全消除共享数据库来解决第 12 章的跨分片查询问题——但它制造了一个新问题：当用户数据在用户服务、支付数据在支付服务，而业务操作必须跨两者一致时，如何在没有分布式事务的情况下保持一致？
