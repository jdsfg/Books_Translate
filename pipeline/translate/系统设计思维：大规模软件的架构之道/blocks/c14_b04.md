#### 定义：网络分区

**网络分区（network partition）** 是分布式系统中某些节点因网络故障无法与其他节点通信的情况。节点被分成若干组，组内可通信，但跨组不能。

plain 语言：CAP 说你不能拥有一切。在网络分区——任何真实分布式系统中都会发生——你必须在**一致性**（返回错误或阻塞直到通信恢复）和**可用性**（返回可能陈旧的数据，继续服务）之间做选择。

既然网络分区是分布式系统的事实，每个分布式系统必须选择做 **CP**（分区时一致，但可能拒绝服务）还是 **AP**（分区时可用，但可能返回陈旧数据）。

传统关系型数据库（PostgreSQL、MySQL）是 CP：它们宁愿拒绝读也不返回陈旧数据。Amazon DynamoDB 和 Apache Cassandra 是 AP：即使在分区期间也继续提供读，代价是可能返回陈旧数据。

CAP 定理常被误解为“三选二”。但分区容错性在真实分布式系统中不是可选的——分区会发生。真正的选择是在分区期间选 C 还是选 A。正常操作（无分区）时，大多数系统同时提供一致性和可用性。


### 14.5 复制因子与 Quorum——可调一致性

在“始终强一致”和“始终最终一致”之间有一系列可配置选项。Cassandra、DynamoDB、Riak 等分布式数据库允许你通过 **quorum** 机制按操作配置一致性级别。


#### 定义：复制因子

**复制因子（replication factor）**（或 **N**）是存储每份数据副本的节点数量。复制因子为 3 时，每次写同时存储在 3 个不同节点上。

plain 语言：复制因子就是你的数据有多少个备份副本。复制因子 3 意味着数据同时存在三台独立机器上——任意两台故障都不会丢数据。
