#### 深入思考

**Q1.** SocialSnap 4 年内从 0 增长到 80 名工程师。架构在此期间发生巨大变化。如果创始人试图从第一天就设计 v7 架构，会发生什么？

**讨论：** 从第一天设计 v7 会出于几个原因而灾难性。首先，创始人第一天不知道用户会关心哪些功能、哪些数据访问模式会占主导、负载曲线如何。社交平台的架构由用户实际使用方式塑造——而只有观察真实用户才能发现。为有 0 个用户的系统用 Kafka 和 Kubernetes 做微服务网格，意味着在产品上花几个月而不是在基础设施上。其次，即使创始人正确预测了规模架构，他们也无法运维它。Kubernetes 集群需要 DevOps 专长；Kafka 部署需要分布式日志运营知识。2 人创始团队没有这种专长，在公司有收入前招聘这些人员也贵得不可能。第三，每个阶段添加的组件都是因为它解决了具体的、观察到的问题。Redis 缓存是因为个人资料读取慢才加的；消息队列是因为邮件投递阻塞 API 响应才加的。每个组件都是先有问题再 earned。这不是“一开始就把它建好”的次优方法——它本身就是正确方法。系统是通过为具体观察到的问题累积具体解决方案而构建的，而不是抽象设计出来的。
