假设你刚写出第一个真正的程序。不是作业——是一个真正的程序。你写了一个小博客：用户可以注册、写文章、互相阅读。你在笔记本电脑上运行它。三个朋友在用。一切正常。

现在假设某天早上醒来，一百万陌生人也想用它。

什么会先崩溃？

这是系统设计的核心问题，而答案几乎从来不是“代码”。代码可能没问题。出问题的全是代码周围的东西——它如何存储数据、如何处理同时到达的请求、出错时如何表现、又如何恢复。系统设计就是思考这一切的学科。它是一个能运行的程序与一个能持续运行的服务之间的鸿沟。

本章从最基本的问题开始我们的旅程：系统到底是什么？为什么规模改变一切？

### 1.1 什么让某个东西成为系统？

从一个小例子开始。这是一个 Python 函数：

```python
def get_post(post_id):
    return database.query("SELECT * FROM posts WHERE id = ?", post_id)
```

这算一个系统吗？从狭窄的技术意义上说，是的——它有输入、处理、输出。但当工程师谈论“系统”时，他们的意思远不止于此：一组组件（component）为了某个目标协同工作，并有明确的边界定义什么可以进来、什么必须出去。

上面的函数本身不是系统。但把它和数据库、一个负责路由 HTTP 请求的 Web 服务器、一台把流量分发到多台机器的负载均衡器、一个让重复读取更快的缓存，以及一个出故障时报警的监控服务组合起来——现在你就有了一个系统。

#### 定义：系统（软件工程）

**系统**是一组软硬件组件，它们相互作用以完成既定目标，具有明确的接口（interface，即输入与输出），以及明确的边界将其与外部世界分开。

用大白话说：系统就是多个东西协同工作，去完成单一个体无法完成的事情。

这个定义里包含的关键思想值得逐一拆解：

**组件。** 系统由部分组成。这些部分可以是进程、服务器、数据库、缓存、队列、服务，甚至是人工操作员。每个组件都有特定的职责。

**交互。** 组件不是相互独立的。它们通过网络调用、共享内存、消息队列、文件或其他任何渠道进行通信。交互本身与组件同等重要。

**目标。** 系统存在是为了给某些人做某些事。博客系统存在是为了让作者分享想法、读者找到它们。系统中的所有东西都应该能追溯到这个目标。如果不能，你就有了没有价值的复杂性。

**边界。** 系统有边缘。边缘以内，你说了算；边缘以外，不是。边界就是你的责任终止、别人责任开始的地方——浏览器、第三方支付处理商、操作系统。
