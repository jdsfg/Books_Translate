#### 服务发现（Service Discovery）

单体中，一个组件通过函数调用另一个。微服务架构中，“调用”服务 B 意味着向服务 B 的地址发送 HTTP 请求。但这个地址是什么？

在云环境中，服务 B 可能在多台机器上运行多个实例，实例动态增减。服务 B 今天的地址明天可能就不是了。

**服务发现（service discovery）** 是服务互相找到对方的机制。有两种模型：

**客户端服务发现：** 每个服务知道一个**服务注册表**（服务名到网络地址的数据库）。服务 A 想调用服务 B 时，先查询注册表：“服务 B 当前的地址有哪些？”注册表返回可用实例列表。服务 A 选一个（用负载均衡算法）并直接发送请求。

**服务器端服务发现（server-side）：** 服务 A 把请求发给负载均衡器或 API 网关。负载均衡器在注册表中查找服务 B 并转发给合适的实例。服务 A 无需知道注册表。

流行的服务注册表包括 Consul、Etcd 和 Zookeeper。Kubernetes（主导的容器编排平台）内置服务发现——每个服务获得一个 DNS 名，Kubernetes 自动把请求路由到健康实例。
