#### URL 模式与签名 URL

对公开照片（任何人都能看的头像），对象存储 URL 可以公开访问。但对私有内容（用户私有帖子、私信照片），你不希望 URL 公开访问。

**签名 URL（signed URLs）** 解决这个问题。应用不存储普通 URL，而是在提供内容时生成临时签名 URL：


    def serve_private_photo(user_id, photo_key, requesting_user_id):
        # 检查授权
        if not user_can_access(requesting_user_id, photo_key):
            raise Unauthorized()

        # 生成有效期 1 小时的签名 URL
        signed_url = object_store.generate_signed_url(
            key=photo_key,
            expiry_seconds=3600
        )
        return signed_url


签名 URL 包含用对象存储密钥生成的加密签名，在设定时间后过期。浏览器可以用这个 URL 直接从对象存储获取照片——但只在过期前。这保留了“直接从对象存储服务”的性能收益，同时执行访问控制。


### 10.6 HDFS——大数据的分布式文件存储

为完整起见，存储全景还包括为特定问题设计的另一种类型：**HDFS（Hadoop Distributed File System）**。


#### 定义：HDFS

**HDFS** 是一种分布式文件系统，设计用来在许多普通服务器上存储非常大的文件（每个 GB 到 TB 级），并支持高吞吐顺序读。

HDFS 围绕一个特定假设设计：工作负载涉及顺序读取整个大文件（例如处理 100 GB 日志文件以提取统计信息），而不是对许多文件的小部分随机访问。对这种工作负载模式——在数据分析中常见——HDFS 的设计高度优化。

**HDFS 设计原则：**

**大文件块大小：** HDFS 使用 128 MB 或 256 MB 的块大小（传统文件系统通常是 4 KB）。1 GB 文件只存为 4–8 个块。这减少元数据开销并优化顺序读。

**复制以实现持久性：** 每个块默认复制到三个节点。如果一个节点故障，数据仍可在另外两个节点上获取。

**一次写入、多次读取：** HDFS 不支持原地更新。文件写入一次，然后只读。这种简化实现高吞吐。

**数据本地性：** 计算（MapReduce 或 Spark 作业）在与数据相同的节点上运行。不是把数据移到计算，而是把计算移到数据，消除大数据集的网络瓶颈。

**HDFS 适用场景：** 大数据分析管道。一家公司把 10 TB 每日用户事件日志存在 HDFS 中。 nightly Spark 作业读取整个数据集以生成推荐。一次读取、高吞吐模式正是 HDFS 所优化的。

**HDFS 不适用场景：** 随机访问工作负载（按 ID 查找一条记录）、小文件工作负载（HDFS 的大块大小对 1 KB 文件浪费），或对延迟敏感的应用。

对 SocialSnap，HDFS 不是头像照片的正确选择（随机访问、小文件）。但如果 SocialSnap 后来在其用户事件流（点击、浏览、点赞）上构建 PB 级分析管道，HDFS 或云等价物（Amazon S3 用作 Spark 作业的类 HDFS 对象存储）就会变得相关。
