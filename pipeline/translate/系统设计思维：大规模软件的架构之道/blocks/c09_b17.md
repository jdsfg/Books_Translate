#### 深入思考

**Q1.** 把 9.1 节的 CDN、9.5 节的 DNS 和 9.8 节的 API 网关一起考虑。这三个组件位于用户与应用服务器之间。对请求 `www.socialsnap.com/users/alice`（一个公开资料页），如果 CDN 已缓存该页，追踪哪个组件处理请求、哪些被绕过。这告诉你正在发挥什么设计原则？

**讨论：**

如果 CDN 缓存了 Alice 的资料页：

1. **DNS 解析：** 域名解析为 CDN 边缘节点 IP（DNS 记录指向 CDN，而非直接指向 SocialSnap 服务器）。DNS 解析仍然发生——浏览器仍需查找 IP 地址。

2. **CDN 边缘节点完全处理请求。** CDN 有 `/users/alice` 的缓存 HTML 响应。它立即返回。没有请求到达 API 网关，没有请求到达应用服务器，也没有数据库查询。

3. **API 网关被绕过。** 无限流检查、无认证、无路由。

4. **应用服务器被绕过。** SocialSnap 源基础设施对该请求零负载。

发挥中的设计原则：**在协议栈尽可能早的位置服务请求**。请求经过的每个组件都会增加延迟和负载。通过在 CDN 边缘缓存——地理位置靠近用户——请求从离用户可能 20km 的地方毫秒级返回，而不是离源服务器 10,000km。源基础设施对缓存响应零负载。

这是第 7 章缓存命中率洞察的架构体现：CDN 边缘的一次缓存命中不只是减少数据库负载——它消除了用户与数据库之间每个组件的负载。CDN 是杠杆最高的缓存放置点，因为每次命中的请求都免除了下游每个组件的工作。

但如第 7 章所述：CDN 缓存只适用于所有用户都相同的内容（公开、非个性化）。Alice 登录后的 home feed——个性化、动态——不能在页面级缓存到 CDN。
