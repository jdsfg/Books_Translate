#### 概念检测

**Q1.** L4 和 L7 负载均衡器有什么区别？给一条只能用 L7 实现的具体路由规则。

**答案：** **第 4 层（L4）负载均衡器** 工作在传输层。它只能看到源 IP、目的 IP、源端口、目的端口。它不能读取数据流内容。路由决策完全基于网络层信息。

**第 7 层（L7）负载均衡器** 工作在应用层。它读取完整 HTTP 请求——URL 路径、头、cookie，以及可选的请求体。路由决策可以基于任何 HTTP 层属性。

**只能用 L7 实现的路由规则：**

“把所有 URL 路径以 `/api/video/`（API 视频端点）开头的请求路由到视频处理服务器集群，其他请求路由到通用应用服务器集群。”

这需要读取 URL 路径，属于 HTTP 请求内容——应用层信息。L4 负载均衡器只看到 TCP 连接到达 443 端口，无法区分 `/api/video/upload` 和 `/api/users/42`。L7 负载均衡器解析 HTTP 请求后可以应用基于 URL 的路由规则。

**Q2.** 什么是一致性哈希？解释为什么它在缓存集群加入或移除节点时优于简单取模哈希。

**答案：** **一致性哈希** 把缓存节点和缓存 key 都放到一个概念环形哈希空间（“环”）上。每个 key 被分配给环上从它位置顺时针最近的节点。

**为什么取模哈希在大规模下失败：** 有 `N` 个节点时，每个 key 映射到 `hash(key) mod N`。当加入节点（N 变 N+1），几乎每个 key 的分配都变了——因为几乎所有 key 在 `mod(N+1)` 和 `mod N` 下哈希到不同位置。向 10 节点集群加 1 节点会改变约 91% 的 key。整个缓存实际上失效。

**为什么一致性哈希更好：** 向环中加入节点时，只有新节点“接管”的环段中的 key 会被重新分配。其余 key 都留在现有节点上。对 N 节点集群新增节点，大约 1/N 的 key 被重新分配——正好是现在属于新节点区段的那些。

数值上：向 3 节点一致性哈希集群加入第 4 节点，重新分配约 25% 的 key（环的 1/4 属于新节点）。向 3 节点取模集群加入第 4 节点，重新分配约 75% 的 key。对大型缓存，这种差异巨大，因为大规模缓存未命中会冲垮数据库。

**Q3.** 什么是 WebSocket？它与标准 HTTP 在实时应用中有何不同？举出一个适合 WebSocket 的应用，以及一个 HTTP 轮询就够用的应用。

**答案：** **WebSocket** 是一种通信协议，在单个持久 TCP 连接上提供客户端与服务器之间的全双工、双向通信。经过升级的初始 HTTP 握手后，任何一方都可以随时发送消息，无需等待对方请求。

**与标准 HTTP 的不同：** 标准 HTTP 是请求-响应：客户端发起每次交换。服务器不能主动发送数据——只能响应请求。对实时应用（通知、实时数据），客户端必须反复轮询检查更新，效率低且延迟高。
