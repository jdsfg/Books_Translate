**答案：** 康威定律指出，组织设计的系统反映其沟通结构。80 名工程师跨 8 个团队：团队主要在内部每天沟通，与相邻团队偶尔沟通。若这 8 个团队共享单体，代码库变成协调问题——任何需要破坏性变更的团队都会阻塞所有 8 个团队，部署计划必须同步，一个团队代码中的 bug 可能影响所有团队的服务。系统结构必须与组织沟通结构匹配。8 个团队时，自然架构是 8 个服务——每个团队一个——之间有明确接口。每个团队拥有、独立部署、可在不与所有其他团队协调的情况下演进实现。架构使组织自治，而非限制它。单体在 8 个团队中造成瓶颈：单体的协调要求超过组织的沟通能力。

**Q4.** 什么是架构债务，为什么它比代码级技术债务更昂贵？

**答案：** 架构债务是在系统结构层面的设计决策，对当前规模和上下文合适，但限制未来演进。例子：SocialSnap 的模运算分片键、后来需要多区域部署的单体数据库、后来需要解耦的服务间同步 API 调用。架构债务比代码债务更昂贵，因为：(1) 它同时影响多个组件——改变分片键需要迁移所有使用该数据库的组件数据。(2) 通常不能小步变更——你无法缓慢从 `mod 8` 变到一致性哈希；某个时刻必须完全切换到新方案。(3) 需要跨团队协调——架构变更影响许多团队的服务，需要同步迁移计划。(4) 风险更高——代码重构中的错误影响一个组件；架构迁移中的错误可同时影响所有服务。代码债务通常一天可还；架构债务可能需要数月或数年工程努力。
