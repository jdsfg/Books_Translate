大多数系统设计书籍要么给你一堆菜谱（“如何设计一个 URL 短链接服务”），要么把你淹没在学院派的分布式系统理论里。本书做的是更罕见的事：它教你如何思考系统——在动手设计之前该问什么问题，哪些 tradeoff（权衡）始终在场，以及为什么看似随意的选择一旦理解了约束，就会发现其实经过深思熟虑。

主线是 SocialSnap，一个虚构的社交平台。它从笔记本电脑上的一个 Python 函数开始，逐章演进为全球分布式服务：sharded databases（分片数据库）、circuit breakers（熔断器）、CDN-backed video delivery（由 CDN 支持的视频分发），以及 200 台由 Terraform 管理的服务器。你会看到它在负载下以真实系统崩溃的方式崩溃，看到修复方案被引入，然后看到下一个扩展天花板出现。到第 27 章回顾 SocialSnap 做过的每一个架构决策时，你已经和这些决策共处了数百页——它们会显得来之不易，而非抽象空洞。

另外两条线索贯穿全书。Tradeoff Matrix（权衡矩阵）在第 2 章以一个简单的三列表格引入，每做一个重大架构决策就增加一行。到第 28 章，它已成为每位资深工程师脑中携带的完整权衡速查卡。Detective's Discipline（侦探式纪律）这条线索把系统设计框定为基于证据的推理：像收集线索一样收集需求，形成假设，排除不可能，然后选择“最不错误”的答案。案例研究章节（第五部分）以一份“Detective's Brief（侦探简报）”开篇，把需求呈现为一个谜题——而这正是真实工程团队设计讨论的实际方式。

最后一章跳出架构，审视人的层面：Conway's Law（康威定律）如何意味着组织架构无论你是否愿意都会塑造系统，blameless post-mortems（无追责事后复盘）为何是可靠性机制而非管理仪式，以及 Inverse Conway Maneuver（逆康威策略）有时为何是最有效的架构干预手段。本书认真对待一个理念：系统由人建造，而不只是由遵循最佳实践的工程师建造。

**目标读者**：CS（计算机科学）本科生（大三/大四）、准备系统设计面试的软件工程师、希望更具架构思维的后端工程师，以及需要评估系统方案的技术经理。

**先修要求**：具备基本编程概念（写过函数、循环、条件语句）；大致了解 database（数据库）和 API 是什么。不需要分布式系统背景——本书从零讲起。

**学习时长**：28 章共 120–160 小时（每章约 4–6 小时，含练习）
