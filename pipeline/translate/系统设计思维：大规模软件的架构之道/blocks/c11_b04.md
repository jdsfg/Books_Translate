#### 方案 3：外部会话存储（Redis）——正确答案

正确方案：把会话存储从应用服务器内存移到共享外部存储。所有应用服务器从同一个 Redis 实例读写会话。


    # 之前：会话在本地内存中（水平扩展错误）
    sessions = {}  # 服务器本地字典

    # 之后：会话在 Redis 中（水平扩展正确）
    def create_session(user_id, username):
        session_id = generate_random_id()
        session_data = {"user_id": user_id, "username": username, "created_at": now()}

        redis.setex(
            f"session:{session_id}",   # key
            3600 * 24,                  # TTL: 24 小时
            json.dumps(session_data)    # value
        )

        return session_id

    def get_session(session_id):
        data = redis.get(f"session:{session_id}")
        if data is None:
            return None  # Session expired or invalid
        return json.loads(data)


现在 Alice 在 Server A 登录时，会话存在 Redis 中——Server B 和 C 都能访问。Alice 的下一个请求到 Server B 时，Server B 在 Redis 中找到会话。Alice 保持登录。应用服务器现在是无状态的——它自己内存里不保存任何每个会话的数据。

**额外收益：**

**会话 TTL：** Redis 原生支持 key 的 TTL（`SETEX`）。会话在 24 小时无活动后自动过期，无需清理作业。本地内存方案则需要后台线程驱逐过期会话。

**会话检查：** 存在 Redis 中后，会话可以被查看和管理。“登出用户 42 的所有会话”变成：按 user_id 过滤 `DEL session:*`（或维护反向索引 `user:42:sessions = [sess_id1, sess_id2, ...]`）。本地内存则需要向所有服务器广播登出命令。

**可用性：** 配合 Redis 复制（一个主节点和一个或多个副本），会话数据能经受任何单个 Redis 实例故障。本地内存中，服务器重启会丢失所有会话。

注意 Redis 在 SocialSnap 架构中已经是第三次出现：

1. 第 7 章：作为资料和帖子数据的缓存
2. 第 9 章：作为限流令牌桶的存储
3. 第 11 章：作为外部会话存储

这不是巧合。Redis 的优势——亚毫秒延迟、TTL 支持、原子操作、持久化选项——使它成为需要快速、共享、临时存储的多个组件的正确工具。
