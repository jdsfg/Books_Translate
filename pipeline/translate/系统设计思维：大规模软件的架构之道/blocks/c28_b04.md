#### 五个为什么——根本原因侦探工具

“五个为什么”技术反复问“为什么？”，从症状钻取到潜在原因：

**事件：** 支付服务不可用 8 分钟（8 minutes）。

* 为什么？数据库连接池耗尽。
* 为什么？一个慢查询每个连接持有 60 秒（60 seconds）。
* 为什么？数据库索引被迁移脚本删除。
* 为什么？迁移脚本在 staging 测试过，但 staging 数据集更小，所以查询跑得很快。
* 为什么？Staging 和生产数据量不同；查询计划行为不同。

**根本原因：** Staging 环境不能反映生产数据量，导致性能差异未被发现。

**行动项：** 用生产代表性数据量加载 staging；添加查询性能回归测试。

五个为什么是侦探纪律（Thread C）应用于系统失败：沿着连续原因追踪证据，直到找到真正起源。

### 28.3 Serverless 计算——抽象的未来

全书基础设施讨论都围绕服务器：我们把服务部署在服务器（物理或虚拟）上，管理它们，水平扩展，监控健康。Serverless 计算代表一种不同模型：如果你可以只写一个函数而完全不用考虑服务器，会怎样？


#### 定义：Serverless（Function-as-a-Service）

**Serverless**（也称 Function-as-a-Service 或 FaaS）是一种云执行模型，开发者部署单个函数（而非整个服务），云 provider 处理所有基础设施：服务器分配、扩展、负载均衡和维护。开发者只为代码实际执行时间付费，而不为空闲服务器时间付费。

plain 语言：你写一个函数，上传到 AWS Lambda 或 Google Cloud Functions。请求来时，云 provider 在需要的基础设施上运行你的函数，自动扩展以处理更多请求，并按毫秒执行时间收费。你从未配置过服务器或负载均衡器。
