### 本章总结

新闻 feed 是扇出问题的最复杂形式。单次帖子创建可能需分发给数百万关注者，约束是读取必须快（200ms p99）且写入不能压垮系统。

两种基本策略存在——写时扇出和读时扇出——每种在社交平台上纯形式都不切实际。写时扇出对高关注者用户造成压垮性写入负载。读时扇出对 feed 组装查询造成压垮性读取负载。

混合策略——普通用户写时扇出、名人读时扇出——利用关注者数量的幂律分布。因为 99.99% 用户关注者数在写时扇出可行范围内，而名人帖子可在读取时从缓存中廉价获取，混合方法高效处理整个分布。

Timeline 存储（Redis sorted set 中的预计算帖子 ID 列表）让普通用户部分 feed 组装达到亚毫秒级。名人帖子在读取时合并，开销可忽略。读时用用户专属信号重新排序给出个性化 feed，而无陈旧预计算分数。

Fanout Service（异步 Kafka 消费者）把帖子创建与扇出解耦，让帖子创建立即返回，而扇出在后台在新鲜度 SLO 内完成。

关注者分布——在侦探简报中被识别为“关键线索”——是整个设计的关键。不理解幂律，设计者可能统一应用单一策略，直到生产环境才发现名人问题。先收集所有证据再设计的侦探纪律防止了这一失败。

第 23 章设计搜索引擎——一个完全反转 feed push 模型的系统：不是预计算向用户展示什么内容，而是用户表达想要什么内容，系统必须在数十亿文档中毫秒级找到它。倒排索引与预计算 timeline 一样，用写入成本换读取速度——这一主线回连到本章核心权衡。
