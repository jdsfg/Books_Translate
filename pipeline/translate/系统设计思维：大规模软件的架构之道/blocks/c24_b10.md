#### 应用问题

**Q1.** 某视频平台新加坡边缘 CDN 峰值服务 1000 万（10 million）观众。平均片段 5MB（1080p 10 秒）。观众平均每 8 秒请求一个新片段（考虑 ABR 缓冲区管理）。估算新加坡边缘集群所需出站带宽，并估算该边缘集群占平台总流量的比例（平台全球峰值 1 亿（100 million）同时观众，新加坡服务其中 5%）。

提示

带宽 = 观众数 × 每秒每观众字节数。然后思考“1 亿观众中的 5%”在片段请求层意味着什么。

**答案：** 新加坡服务 1000 万（10 million）观众。每个观众每 8 秒请求一个 5MB 片段 = 625 KB/s。新加坡边缘总带宽：10 million × 625 KB/s = 6.25 TB/s = 50 Tbps。全球层面：1 亿（100 million）观众 × 625 KB/s = 62.5 TB/s = 500 Tbps 总计。新加坡服务 1000 万 / 1 亿 = 10% 全球流量 = 50 Tbps。这说明了 CDN 容量规划是巨大的基础设施投资：单个区域集群必须配备 50 Tbps，需要数千台带 100Gbps 网卡的服务器及多条冗余 100Gbps 上行光纤。

**Q2.** 回忆第 7 章，缓存带来陈旧。CDN 缓存视频片段 TTL 为 24 小时。创作者发现视频有事实错误并上传修正版。遍历在全球 CDN 用正确版本替换已缓存错误版本所需的完整事件序列。

提示

考虑转码流水线、存储层和 CDN 缓存层各需发生什么。思考 URL 版本化策略及播放器如何知道使用新 URL。

**答案：** 步骤 1：创作者上传修正视频。上传流水线摄取并触发转码。步骤 2：转码产生新编码片段。采用 URL 版本化，它们存在新 URL：`.../movie123/v2/1080p/seg001.ts` 而非 `.../movie123/v1/1080p/seg001.ts`。步骤 3：生成新清单，指向 v2 片段 URL。清单本身获得新 URL，或清单 URL 不变但指向 v2 内容。步骤 4：平台元数据服务更新引用新清单 URL。步骤 5：新播放会话的观众从 API 收到新清单 URL，指向 v2 片段，永远看不到旧内容。步骤 6：旧清单正在观看的观众继续用 v1 片段直到会话结束，体验不中断。v1 片段在 CDN 缓存中保留到 TTL 过期（最多 24 小时），但由于所有新会话都使用 v2 URL，v1 缓存条目自然老化。若需立即移除（如法律下架），平台调用显式 CDN purge API，在数分钟内把删除命令传播到所有边缘服务器。

**Q3.** 你在为视频平台设计存储层级策略。某视频在上传后前 7 天（短视频）或前 14 天（电影）获得其终身播放量的 90%。设计一个平衡成本和访问延迟的存储生命周期策略，已知热存储 0.05 USD/GB/月、温存储 0.01 USD/GB/月、冷存储 0.001 USD/GB/月。
