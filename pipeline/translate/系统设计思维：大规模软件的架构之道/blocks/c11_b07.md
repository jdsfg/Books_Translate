#### 何时用哪一种

**何时使用 Redis 会话：**

* 需要立即撤销能力（账户冻结、安全事件）
* 用户登录时间久且执行敏感操作
* 会话数据量大或变化频繁
* 需要服务器端会话管理（例如，追踪每个用户的活跃会话）

**何时使用 JWT：**

* 短生命周期令牌可接受（15-60 分钟过期 + 刷新令牌）
* 服务间认证（微服务互相验证身份）
* 无需撤销的无状态 API 场景
* 大规模系统，即使每次请求 1ms 的 Redis 查找也成本显著

SocialSnap v4 使用 Redis 会话。撤销能力（账户安全）比 JWT 验证带来的边际延迟改善更重要。


### 11.6 垂直扩展 vs 水平扩展——何时用哪种

在继续之前，先为扩展决策建立一个清晰框架，因为这些术语会不断出现。


#### 定义：垂直扩展（Scale Up）

**垂直扩展**指增加单台机器资源：更多 CPU 核心、更大 RAM、更快存储。目标是让现有服务器更有能力。

通俗语言：垂直扩展就是升级机器。

**优点：**

* 简单：无需改代码。配置更大的实例并重启。
* 无协调开销：一台机器，一个进程。
* 对任何瓶颈（CPU、内存、磁盘 I/O）都立即有效。

**局限：**

* 存在物理上限。截至 2024 年，AWS 最大实例有 448 个 vCPU 和 24 TB RAM。你无法给单台机器加第 2,000 个 CPU。
* 成本非线性：一台 10 倍 RAM 的机器通常比基础（BASE）实例贵 10 倍以上。
* 单台机器再强也是单点故障。
* 升级需要停机（不过云厂商通常可热迁移实例）。


#### 定义：水平扩展（Scale Out）

**水平扩展**指增加更多机器，并行运行相同软件。不是一台强服务器，而是多台普通服务器。

通俗语言：水平扩展就是加机器。

**优点：**

* 理论上无上限：可以一直加服务器。
* 普通硬件：便宜、可互换的实例。
* 内置冗余：单个服务器故障被其他服务器吸收。
* 可独立扩展特定层（加应用服务器而不加数据库）。

**局限：**

* 需要无状态应用设计（本章教训）。
* 协调开销：分布式系统需要负载均衡器、服务发现、共享状态管理。
* 调试更难：问题可能是间歇性且与特定服务器相关。
* 不适用于所有组件：你不能轻易水平扩展单节点数据库。
