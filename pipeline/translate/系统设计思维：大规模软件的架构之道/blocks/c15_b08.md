#### 定义：Outbox 模式

**Outbox 模式**是一种可靠发布事件的技术。服务不直接把事件发布到消息队列，而是把事件与业务数据更新写在同一数据库事务中，写入自己的“outbox”表。一个独立进程（**消息中继，message relay**）从 outbox 表读取并向消息队列发布事件。

plain 语言：不是两个独立写入（数据库 + 消息队列），而是在一个事务里做两个数据库写入（业务数据 + 事件记录）。事务保证这两次写入原子。然后消息中继处理第二步（数据库 → 消息队列），用重试逻辑确保事件最终被发布。

带 Outbox 模式的支付操作：


    BEGIN;
        INSERT INTO payments (user_id, amount, ...) VALUES (42, 9.99, ...);
        INSERT INTO outbox (event_type, payload, status)
            VALUES ('payment.charge.succeeded', '{"user_id": 42, "amount": 9.99}', 'pending');
    COMMIT;


事务保证：要么支付记录和 outbox 记录都保存，要么都不保存。消息中继（后台进程）查询 outbox 中 pending 事件并发布到消息队列，然后标记为已发送。如果中继在标记已发送前崩溃，它重试——并且由于消息队列支持幂等消费（消息按消息 ID 去重），重试是安全的。

Outbox 模式把双写问题转换为单数据库写入（通过数据库事务原子）加一个可靠中继进程。中继可能多次发布事件（至少一次投递），但消费者反正必须处理幂等性。
