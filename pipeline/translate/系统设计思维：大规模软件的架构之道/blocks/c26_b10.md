#### 应用问题

**Q1.** SocialSnap 键值集群 N=3 副本，配置 W=1、R=1。网络分区期间，节点 A 和 B 可相互通信，但节点 C 被隔离。一个写到达：`PUT("user:101:timeline", new_value)`。写协调器是节点 A，preference list 是 [A, B, C]。追踪 sloppy quorum 加 hinted handoff 下该写的去向。然后追踪后续读 `GET("user:101:timeline")` 在 R=1 下的去向。读有哪些可能结果，什么决定哪种结果？

提示

记住 sloppy quorum 允许写到任意 W 个可用节点。从 A 的视角看哪些节点可达。然后想 R=1 的读可能联系哪个节点。

**答案：** 写追踪：节点 A（协调器）尝试写入 preference list [A, B, C]。节点 C 被隔离——不可达。在 sloppy quorum 下，A 用可用节点继续。W=1，所以只写到 A 就满足写 quorum。A 也复制给 B（都在 preference list 且可达）。C 不可达；A（或 B）存储 hint：“节点 C 恢复时应接收该值。” 写成功并返回客户端。分区愈合后：B 或 A 通过 gossip 检测到 C 恢复，把 hinted 值发给 C，C 更新。读追踪：R=1 的读联系一个节点。可能结果：(1) 读路由到节点 A 或 B：返回 `new_value`——最新写。(2) 读在 hinted handoff 完成前路由到节点 C：C 仍有旧值。返回 `old_value`——陈旧，但系统不知道是陈旧的。(3) 读在 hinted handoff 后路由到节点 C：返回 `new_value`。决定结果的因素：负载均衡器的节点选择、分区恢复时机、hinted handoff 传播速度。这就是最终一致性的本质：系统会收敛，但在收敛窗口期间读可能返回陈旧值。

**Q2.** 为 SocialSnap 200 节点键值集群设计 gossip 协议参数，使集群状态在 10 秒内全集群传播。每次 gossip 轮耗时 1 秒并到达一个随机 peer。需要多少轮？若把协议改为每轮每个节点向 K 个 peer gossip，fanout 如何变化？

提示

把 gossip 传播建模为指数增长。fanout 为 1 时，k 轮后约 2^k 个节点知道信息（k 相对集群较小时的粗略近似）。
