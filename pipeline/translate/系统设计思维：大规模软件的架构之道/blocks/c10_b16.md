**5. 浏览器对旧图片 URL 的缓存：** 与 CDN 同理。如果用户浏览器缓存了旧照片 URL，该 URL 在资料更新后不再被任何页面引用。浏览器缓存的旧图片副本（`profile_photo_v3.jpg`）不会再被应用请求——它会在浏览器缓存自己的驱逐策略下失效前一直闲置。

**为什么 URL 版本化是不可变媒体的正确模式：**

对对象存储响应设置 `Cache-Control: max-age=31536000, immutable`（整整一年）是安全的，正因为每次上传 URL 都改变。给定 URL 处的媒体文件永远不会变化——因此无限 TTL 是正确的。缓存失效通过改变 URL 实现，而不是过期或 purge 现有缓存条目。这是 CDN 和 Web 框架对静态资源做指纹化（fingerprinting）的相同原则（例如 `app.a3f2b9.js`）。

照片更新时唯一需要主动失效的缓存是 Redis 资料缓存——因为它包含 URL 指针，而不是图像数据本身，且它的 key 不会随照片版本改变。
