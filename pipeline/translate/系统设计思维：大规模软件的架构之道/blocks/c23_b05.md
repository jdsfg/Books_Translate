#### 索引流水线

构建倒排索引不是单步过程。爬取页面到达后，索引流水线执行多次转换：

1. **解析：** 从原始 HTML 提取干净文本。移除 HTML 标签、JavaScript、CSS。
2. **分词：** 把文本切分成单个 token（词）。
3. **归一化：** 转小写；去除标点。"Distributed," "distributed," 和 "DISTRIBUTED" 变成同一 token。
4. **停用词移除：** 移除几乎每份文档都出现的极常见词，这些词对相关性贡献很小："the"、"is"、"and"、"a"。这些词会创建巨大 posting list 却只有微不足道的排序收益。
5. **词干提取或词形还原：** 把词还原为词根。"Running"、"ran"、"runs" 都可能变成 "run"。这让查询 "running distributed systems（分布式系统）" 能匹配包含 "run distributed system" 的文档。
6. **倒排索引更新：** 对每个剩余 token，把该文档的 ID、TF 和位置追加到 token 的 posting list。

该流水线对每个爬取页面运行。100 亿（10 billion）页面，且为保持索引新鲜每天可能重新爬取 10% 网页，流水线每天必须处理数亿页面。


#### 索引分片

没有单机能容纳 100 亿（10 billion）页面的完整倒排索引。常用词如 "systems" 的 posting list 可能包含数亿文档 ID——仅这一个词就几十 GB。整个网页倒排索引是数百 TB。

如第 12 章所学，解决方案是分片。对搜索索引，有两个自然分片维度：

**按词分片：** 每个分片按字母顺序拥有一段词。分片 1 拥有 A–G 的词；分片 2 拥有 H–P 的词；依此类推。查询 "distributed systems（分布式系统）" 必须命中两个分片（每个词一个），然后求交集。这叫 **term-based sharding**。

**按文档分片：** 每个分片拥有所有文档的一个子集，并为其文档子集维护完整的小型倒排索引。查询 "distributed systems" 并行命中所有分片；每个分片返回本地结果；结果合并。这叫 **document-based sharding**。

实践中，大型搜索引擎使用 document-based sharding，因为它允许最自然的并行：查询同时发往所有分片，每个分片并行产生结果，再合并。Term-based sharding 会产生倾斜问题（有些词远比其他词常见，造成热分片）且多词查询需要跨多个分片协调。
