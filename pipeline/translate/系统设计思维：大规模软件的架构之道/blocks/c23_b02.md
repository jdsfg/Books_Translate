### 23.1 网络爬虫——追踪线索的侦探

网络不是一个有已知所有文档列表的数据库。它是一个图。网页包含指向其他网页的链接。那些页面又包含更多链接。要发现网络，你必须跟随这些链接。

这是最简单的爬虫，已包含所有正确思想：

    seed_urls = ["https://en.wikipedia.org", "https://nytimes.com", ...]
    queue = Queue(seed_urls)
    
    while queue is not empty:
        url = queue.dequeue()
        page = fetch(url)
        links = extract_links(page)
        for link in links:
            queue.enqueue(link)
        store(url, page)

这是对网页图做广度优先搜索，从一组种子 URL 开始。爬虫获取一个页面，发现新链接，并将它们加入队列供后续处理。

但考虑这个最简单爬虫立即遇到的问题。

**重复问题。** 许多页面互相链接。如果 Wikipedia 链接到纽约时报，纽约时报又链回 Wikipedia，我们的爬虫会再次把 Wikipedia 加入队列并爬第二次——然后无限循环。队列变成无限。

解决方案是 **seen set** —— 所有已访问 URL 的集合。入队前检查 URL 是否在 seen set 中。如果是，跳过。

    if url not in seen_set:
        queue.enqueue(url)
        seen_set.add(url)

100 亿（10 billion）URL 时，seen set 是 100 亿 URL 字符串。精确存入内存不可行（每个 URL 约 100 字节；100 亿 × 100 字节 = seen set 单独 1 TB 内存）。实用方案是 **Bloom filter** —— 一种概率数据结构，以极高确定性回答“我见过这个 URL 吗？”，但每个条目只用几位。1% 误报率下，100 亿 URL 的 Bloom filter 约需 9.6 GB——更易管理。误报代价只是偶尔跳过其实未爬过的 URL。由于大多数这类误报针对非常次要的页面，这是可接受的权衡。

**礼貌问题。** 如果爬虫在 1000 台服务器（server）上并行运行，每台每秒 10 个请求，则每秒产生 1 万（10000）个请求。单个新闻网站总容量可能只有 1000 请求/秒——我们的爬虫会耗尽它全部容量。这称为 **爬取速率限制** 或 **礼貌** 问题。

解决方案是按域名限速爬取请求。每个域名有 **per-domain 队列**：每个域名一次只取一个 URL，请求之间设可配置延迟（例如 1 秒）。机器人遵守 `robots.txt`——Web 服务器（web servers）发布该文件说明哪些页面可以爬、哪些不可以以及速率。

    User-agent: *
    Disallow: /private/
    Crawl-delay: 2

设计良好的爬虫在爬某域名任何页面前先读取 `robots.txt`，并遵守 disallow 指令和 crawl 延迟。这不仅是礼貌，还有法律意义：忽略 `robots.txt` 可能让公司承担法律责任。

**URL frontier 设计。** per-domain 队列、礼貌控制和优先级（某些页面更重要，应优先爬取）的组合称为 **URL frontier**。URL frontier 是大型爬虫的核心调度数据结构。
