#### 定义：CRDT

**CRDT（Conflict-free Replicated Data Type）** 是一种可以跨多个节点复制、在任意节点上并发独立更新、并且总能合并成一致结果而无需协调的数据结构。其数学性质保证所有并发更新的顺序都会产生相同最终状态。

通俗语言：CRDT 是一种精心设计的数据结构，你可以以任意顺序应用更新，总能得到相同答案。没有冲突需要解决。

例子：

**G-Counter（只增计数器）：** 每个节点维护自己本地计数器。G-Counter 的值是所有本地计数器之和。任意节点都可以无需协调递增自己的本地计数器。合并两个 G-Counter 时，取每个本地计数器的最大值。这总能得到正确的总和。SocialSnap 帖子的点赞数可以是 G-Counter——任何服务器都可以本地记录一次点赞递增，最终通过合并计算总数。

**OR-Set（Observed-Remove Set）：** 一种同时支持 add 和 remove 的集合，设计上让并发 add 和 remove 操作能确定性地解决。两个节点可以同时 add 和 remove 同一个元素；CRDT 的合并操作会产生定义好的、一致的结果。

CRDT 用灵活性换取一致性保证。不是每种数据类型都能表达为 CRDT——它们最适合天然具有可加或结合结构的数据（计数器、集合、追加操作序列）。对需要复杂语义的数据（例如“余额绝不能为负”），CRDT 可能不适用。


### 14.9 跨区域复制

随着 SocialSnap 国际化增长，欧洲用户距离美国数据中心 150 毫秒。欧洲用户的每次数据库读仅网络往返就要 150 毫秒。对交互式应用不可接受。

解决方案：在多个地理区域运行数据库。欧洲节点服务欧洲用户；美国节点服务美国用户。欧洲用户的写进入欧洲节点；美国用户的写进入美国节点。节点之间后台互相复制。

这就是**跨区域复制（multi-region replication）**，它以最尖锐的形式引入一致性挑战。
