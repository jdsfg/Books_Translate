#### 概念检测

**Q1.** 说出三种存储系统，并描述每种最适合的一种工作负载。从访问模式、延迟要求和成本角度解释你的理由。

**答案：**

**基于 DRAM 的缓存（Redis）：**

最佳工作负载：Web 应用会话数据。每次认证请求都访问会话（高读取频率），数据小（每个会话约 1 KB），必须在 1 毫秒内取回，才不会给页面加载增加可感知延迟。成本可接受：100,000 并发会话 × 1 KB = 约 100 MB 内存，在 Redis 定价下可忽略。

访问模式：按 session ID 随机访问（key 查找）。延迟要求：亚毫秒。成本：对小数据可行；对大数据昂贵。

**对象存储（类 S3）：**

最佳工作负载：视频分享平台的用户上传视频。视频大小从 50 MB 到 2 GB。一次上传、多次读取。读取可容忍 50-200ms 延迟（视频播放器会提前缓冲）。平台可能存储 PB 级视频。按 0.023 USD/GB/月计，存 1 PB 每月 23,000 USD——只有 SSD 成本的零头（100,000+ USD/月）。

访问模式：按 URL key 顺序读取大二进制对象。延迟要求：几十到几百毫秒可接受。成本：PB 级唯一经济可承受的分层。

**NVMe SSD 关系型数据库：**

最佳工作负载：电商订单管理。订单包含结构化数据（客户 ID、商品、价格、送货地址、状态）。需要复杂查询：“显示过去 24 小时内所有状态为 pending、总额超过 500 USD 的订单，并与客户送货偏好 join。”这些查询跨多张表，需要索引和 join。延迟要求是个位数毫秒（订单状态页必须快速加载）。

访问模式：多张表的结构化关系查询。延迟要求：1-10ms。成本：对几十 TB 数据量合适；再往上变贵。

**Q2.** 对象存储和文件存储有什么区别？为什么不能在对象存储上直接运行数据库（如 PostgreSQL）？

**答案：** **文件存储**（如 NFS）提供分层目录结构，客户端挂载后像本地磁盘一样使用。多个客户端可同时读写文件。文件操作——打开、读取、写入、定位、追加——在字节级别工作，文件系统维护元数据（权限、修改时间、目录结构）。

**对象存储**提供扁平的 key-value 命名空间，每个对象都是不透明的 blob，通过 HTTP 访问（`PUT`/`GET`/`DELETE` by key）。没有目录层次（只有用 key 前缀模拟），没有字节级别的部分读或部分写（你要读或写整个对象），也不能挂载成本地磁盘。

**为什么 PostgreSQL 不能直接在对象存储上运行：**

PostgreSQL（像所有数据库）需要块级随机读写——能够读写文件中特定块而不读整个文件。PostgreSQL WAL 写入会更新 WAL 文件的特定字节。B-tree 插入会修改索引文件中特定页面。这些都是小而随机的原地修改。
