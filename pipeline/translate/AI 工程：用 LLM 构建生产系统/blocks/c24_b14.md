3. **替代路径可触发**。当模型说"我不知道"时，系统可路由到人工、标记供审查或提供替代资源。当系统自信地错了，替代路径不触发；错误答案传播。
4. **它是可测量的质量信号**。eval 可评分：模型是否在应该拒绝时拒绝？它是否在不该自信回答时自信回答？自信错误率是需追踪和改进的关键指标。

纪律：训练系统（通过 prompt、微调如适用、和 eval）在正确上下文中偏好拒绝而非虚构。在 eval 中奖励拒绝；惩罚自信错误；将 _我不知道_ 输出视为特性，非缺陷。

平衡：不要过度拒绝。拒绝一切的系统无用。校准是在置信度证明时拒绝；在不需要时回答。eval 信号双向：应在有充分理由时拒绝却回答了，以及应在有充分理由时回答却拒绝了。

**Q5.** 为什么成本断路器设计在 agent 合理需要花费超过静态上限允许时失败？识别在不禁用保护的情况下处理此情况的设计模式。

**答案：** 静态成本断路器设为每轨迹单一预算（如每次 agent 运行 1.50 美元）。它保护团队免受失控循环（第 14 章的 52K 美元隔夜故障模式）。但一些合理轨迹 _应该_ 花费超过静态上限：复杂多文档研究；涉及多次工具调用的长时间客户支持会话；递归分解问题的分析。如断路器设太低，合理工作被杀；如设太高，对失控循环的保护被削弱。

这是纯静态断路器无法解决的 _保护与能力之间的张力_。处理两者的设计模式：

1. _两级断路器_。_软上限_ 和 _硬上限_。软上限触发 _预算耗尽信号_ 给 agent，agent 必须在继续前确认。agent 然后可在意识到已用大部分预算的情况下规划剩余工作；它可优先最有价值的剩余步骤或升级到人工。硬上限是绝对终止开关；agent 在任何情况下不能超过它。
2. _合理例外日志_。当 agent 合理花费超过软上限时，记录轨迹元数据：哪个用户、哪个任务、哪些工具调用消耗了预算、交付了什么价值。日志馈入 _昂贵轨迹_ 的季度审查：它们是否交付了成比例价值？如是，该轨迹类别的软上限应提高。如否，保护是正确的。
3. _按轨迹类别断路器_。而非全局上限，按轨迹类型设置按类别上限。简单客户 FAQ：0.25 美元上限。复杂研究：5.00 美元上限。关键法律审查：20.00 美元上限。分类在前端发生（用户请求在 agent 运行前被分类到层级）；上限按层级设置。
4. _人工批准预算续期_。当 agent 达到硬上限时，它不静默终止；它产生 _预算耗尽结果_ 并请求人工批准以额外预算继续。人工（高级 agent 或指定审查者）批准或拒绝。agent 的昂贵路径由人工判断门控，非任意数字。
