#### Qdrant — OSS、Rust、payload 丰富

开源向量数据库用 Rust 编写；在 payload 过滤（向量搜索前/后按元数据过滤）上强；中等规模高效。

**适配**：需要丰富元数据过滤的团队（例如按租户过滤、时间范围过滤）；OSS + 自托管团队；基准测试发现 Qdrant 性能对其工作负载有说服力的团队。

**限制**：比 pgvector 更小生态；比 Pinecone 更不成熟的托管服务。

### 10.5 混合搜索：向量 + BM25 + 元数据

纯向量搜索不完整。差距：

* **精确关键词查询**。"7-CFR-1.4(a) 节说了什么？"用户想要按精确引用的节；向量嵌入不很好地保留精确 token 匹配。
* **罕见术语**。关于特定产品名、错误码或人名的查询；向量相似性可能将语义相邻内容排名高于精确匹配。
* **元数据约束查询**。"我们 2025 年策略关于 X 说了什么？"这需要日期过滤，不仅是语义相似性。

**混合搜索**将向量相似性与经典文本匹配（BM25）和元数据过滤结合。结果融合来自多信号的分数。

    def hybrid_search(query: str, top_k: int = 20) -> list[Chunk]:
        query_vec = embed(query)
        # 扩展因子：每个信号获取约 1.5×–2× top_k 候选使
        # 排序融合有足够材料。Strata 在 §10.6 中调到 30/30 → 20；
        # 这里的 2× 默认是合理的起点。
        vector_results = vector_db.search(query_vec, top_k=top_k * 2)
        keyword_results = bm25_index.search(query, top_k=top_k * 2)
        fused = reciprocal_rank_fusion(vector_results, keyword_results)
        return fused[:top_k]


**倒数排名融合（RRF）**是标准融合算法：每个块获得一个分数，是每种检索方法的 `1 / (rank + k)` 之和（k 通常 60）。被任一方法排名高的块冒泡到融合列表顶部。

元数据过滤在向量/BM25 检索 _之前_（将语料库过滤到相关子集）或 _之后_（过滤检索结果）。预过滤在规模上更高效但需要元数据被索引。

对于 Strata：混合在精确引用查询（常见查询类型）上比纯向量高 +4 分。成本：除向量索引外的 BM25 索引；检索时一些额外代码。提升值得。

2026 年生产 RAG 默认：**带元数据过滤的混合搜索**，除非你有明确理由跳过。纯向量是生产质量系统通常超越的基线。
