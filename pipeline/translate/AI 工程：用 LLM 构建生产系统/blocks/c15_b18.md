**答案：** 有用的 prompt：_一个 agent 在生产中运行了 8 分钟。正常轨迹 30 秒。设计值班响应：数据、决策树、行动、事后。_ 你验证 (a) 提议的行动包含立即停止机制（LLM 可能默认 _先调查_；生产中先停止后调查），以及 (b) 事后流程包含 eval 级缓解（回归测试防止复发）。

**Q3.** _设计轨迹内摘要步骤_。指定：(a) 摘要何时触发；(b) 什么被压缩 vs 保留；(c) 摘要 prompt；(d) 对轨迹连续性的影响。

**答案：**

(a) **触发**：工作记忆超过 30K token（通过 tokenizer 估算）。阈值低于上下文窗口（Claude Sonnet 4 为 200K）以给下一次迭代的工具输出留余量。

(b) **压缩 vs 保留**：

* _逐字保留_：原始用户目标（第 1 轮）；最后 5 轮（最近的思考和工具结果）；agent 做出的任何显式约束或承诺（例如"agent 在第 7 轮发出 50 美元退款——逐字保留此事实"）。
* _压缩_：第 2 到 N-5 轮。替换为结构化摘要，涵盖：调用的工具及其返回；做出的决策；未解决的问题或后续。

(c) **摘要 prompt**：


    摘要以下 agent 轨迹的轮次。保留：
    - 调用的工具及其输出的关键事实（agent 拥有的数据）。
    - 做出的决策（例如"发出退款"；"升级到人工"）。
    - 识别的开放问题或后续行动。
    - 与早期事实矛盾或限定的新信息。

    丢弃：
    - 填充推理（"让我想想这个..."）。
    - 重复工具描述的精确措辞。
    - 已摘要的冗长工具输出。

    输出结构化摘要，约 300-500 token。格式：
    - 使用的工具及其返回
    - 做出的决策
    - 待办事项


摘要本身是 LLM 调用（便宜模型即可；约 0.001 美元每次摘要）。

(d) **对轨迹连续性的影响**：如做好则最小。压缩后 agent 的工作记忆包含：
* 用户目标（逐字）。
* 轨迹中段的结构化摘要。
* 最后 5 轮逐字。

agent 有继续所需的一切：目标、关键事实、近期状态。压缩风险是丢失中间推理的细微差别，但对于已产生具体工具调用和决策的轨迹，结构化摘要保留了重要的。

经验上：设计良好的轨迹内摘要在长轨迹（>15 次迭代）上导致约 2-3% 轨迹质量下降，权衡是能够 _完成_ 否则会溢出的轨迹。净赢。

**AI 协作子问题**：你会如何请 LLM 帮助完成这个练习，你会在它的回答中验证什么？

**答案：** 有用的 prompt：_为 agent 设计轨迹内摘要：何时触发、压缩什么 vs 保留什么、摘要 prompt、对连续性的影响。_ 你验证 (a) 逐字保留列表捕获 agent 实际需要的数据（用真实长轨迹测试），以及 (b) 摘要 prompt 足够结构化以产生一致输出（LLM 可能给模糊摘要 prompt；坚持结构化格式）。
