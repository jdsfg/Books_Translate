* `order_worker`：处理订单查找、配送状态、交付问题。工具：lookup_order、check_shipping_status、get_inventory。
* `refund_worker`：处理退款请求和资格。工具：check_refund_eligibility、process_refund（门控）。专业 prompt 强调退款政策。
* `address_worker`：处理配送地址更新。工具：update_customer_address（门控）、verify_address。
* `billing_worker`：处理发票查询、支付方式问题。工具：get_invoice、lookup_payment_method、schedule_payment_retry。
* `technical_support_worker`：处理产品使用问题、故障排除。工具：search_knowledge_base、run_diagnostic。

每个工作器有专业 prompt 将工作器定位为其领域专家。

(c) **通信协议**：

* 编排器通过 "spawn_worker" RPC 生成工作器：发送子问题文本 + 客户上下文。
* 工作器返回结构化 `WorkerResult` 对象：状态（success/error/needs_escalation）、发现、采取的行动、给客户的建议。
* 编排器聚合结果；如任何工作器返回 `needs_escalation`，整个工单升级到人工（按 Helios 安全策略）。

(d) **系统级界**（按第 14 章 §14.7）：

* 每编排器轨迹最大工作器数：4。
* 跨系统所有 agent 的总成本上限：1.00 美元。
* 不允许递归工作器生成（工作器不能生成子工作器）。
* 总墙上时钟上限：15 秒后强制优雅退出。
* 编排器个体预算：0.30 美元；工作器个体预算：每个 0.20 美元。

组合系统适合 Helios 流量的 5% 多 agent 份额；质量提升经 eval 验证；成本纪律由系统级界强制。

**答案：** 有用的 prompt：_为多问题支持工单设计编排器-工作器系统：编排器、工作器类型、通信、系统级界。_ 你验证 (a) 工作器的工具目录没有有问题的重叠（每个工作器有其专长），以及 (b) 系统级界正确跨规划器+工作器聚合（无个体界分别强制导致的隐式爆炸）。

**Q3.** _试点计算机使用部署_。你的团队正在考虑为内部任务使用计算机使用 agent。设计试点。指定：(a) 任务；(b) 成功标准；(c) 安全考量；(d) 界；(e) 上线计划。

**答案：**

(a) **任务**：从供应商客户门户提取结构化发票数据（供应商不暴露发票下载 API）。试点覆盖运营团队每天约 50 张发票。

(b) **成功标准**：

* 任务完成率：≥80% 的尝试产生正确发票数据。
* 每成功任务成本：≤1.00 美元。
* 无安全事件（无凭证泄露、无未授权行动）。
* 延迟：每任务 60 秒以内（异步批处理工作流可接受）。

(c) **安全考量**：

* 沙箱 VM：agent 在专用 VM 中操作，仅供应商门户可访问；无其他应用、无其他凭证。
* 每任务凭证：VM 有特定供应商账户的凭证，无其他。
* 行动日志：每张截图和每个行动记录；可回放轨迹。
* 不允许高风险行动：agent 可读发票，不能修改或删除；不能花钱；不能发送通信。
