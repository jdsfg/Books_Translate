### 章节小结

工具将 LLM 从说话者转变为做事者。工具是 LLM 通过发出结构化工具使用块调用的函数；应用执行；结果反馈到 LLM 的下一次推理。执行决策留在你的代码中，而非模型中。

工具 schema 是给模型的文档：清晰名称、动作和目的描述、约束参数。差的 schema 产生混乱行为；纪律是写工具描述如同向不熟悉的工程师简报。

标准多轮模式是 ReAct（推理 → 行动 → 观察 → 推理），现代 API 支持并行工具调用。先规划后执行和反思变体存在于复杂任务但通常是过早优化。

工具目录设计纪律：工具应正交（每个做一件事）；优雅失败（结构化错误，非崩溃）；破坏性工具需要显式门控（LLM 决策和执行之间的策略层）。

绑定工作流 #6（§13.5）是沙箱代码执行模式：E2B（或 Modal，或自托管）为 LLM 生成代码提供隔离运行时；资源限制、网络隔离、沙箱内无凭证、有界输出、每次执行记录。2025–2026 主导的代码解释器模式。

Helios 的 40 工具生产规模目录（§13.7）是工作案例：工具按类别组织（信息/计算/操作/升级/诊断）；带版本化的中央注册表；每工具成本和延迟跟踪；操作工具的策略门控。纪律从 5 工具原型扩展到服务每月 1000 万工单的 40 工具生产 agent。工具调用直接构建于第 7 章的结构化输出机制；第 14 章将工具层包装进 agent 循环；第 15 章将相同原语提升到多 agent 协调；第 17 章在工具层接续成本纪律；第 23 章回到 prompt 注入作为工具执行层威胁。

要带向前的：工具是 LLM 做事的方式，工程纪律在工具层——schema、目录组织、确定性策略门控、危险工具的沙箱——而非仅在 prompt 层。
