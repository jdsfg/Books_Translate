### 章节小结

超越现成 AI 涉及三个决策：是否微调；是否自托管；是否设备端。每个是真实杠杆；每个有真实维护成本。

微调，以 LoRA 为 2026 年主导方法，适用于特定领域/格式需求、延迟敏感的更小模型和风格/人设一致性。不适用于基础 + prompt 足够时、任务需要最新信息时（用 RAG）、或团队缺乏半衰期问题的维护能力时。

半衰期问题（线索 B 失败 4）是核心警示：微调随基础模型改进而过时。缓解：维护数据流水线；监控微调 vs 基础；计划每 6-12 个月重新调优。

2026 年的开放权重格局——Llama 4+、Qwen、DeepSeek、Mistral、Gemma——对特定用例是真实且生产相关的。托管 API 上的开放权重（Together AI、Replicate）是最简单路径；自托管是更重投资。

自托管经济学在低到中等量（<10M token/天）偏向托管 API；在中等高量（10-100M）变得有竞争力；在很高量（>100M token/天）配合运维能力时明显胜出。大多数团队不应自托管。

边缘/设备端推理（Apple Intelligence；Phi-4；Gemma 3；Llama 3.2 1B/3B；MLX；llama.cpp；Ollama）对隐私敏感、离线、延迟关键或消费者规模成本案例是真实的。目前是专门选择；增长快速。

Triangle 侧栏（§22.7）展示中等量下的成本权衡：托管工作模型 API 通常是成本赢家；自托管在大多数生产规模下是错误答案；托管开放权重是特定需求的中间地带。

超越现成方案的决策回溯到第 17 章（路由作为微调的更便宜替代）、第 18 章（规模下的成本纪律）、第 19 章（随时间观察微调 vs 基础）和第 21 章（当微调在画面中时变得特别关键的模型升级工作流）。展望未来，第 23 章覆盖自托管模型特有的安全考虑，第 24 章处理团队能力和自建 vs 购买，第 25 章勾勒开放权重和边缘的发展方向。

要点：现成托管 API 是生产 AI 的正确默认。微调、自托管和边缘是特定案例的真实选项，但每个都携带重大维护负担，对微调，**半衰期问题是核心警示**。
