#### 概念检查

**Q1.** 什么是 _OCR 替代故事_（§12.1），它对 2026 年新文档 RAG 项目意味着什么？

**答案：** OCR 替代故事是文档理解的架构转变：而非 OCR-然后-解析（Tesseract → 文本 → 自定义布局恢复），2026 年文档 RAG 使用视觉语言模型直接取页面图像并一步产生结构化输出（文本、布局、表格、图表、签名）。

对于 2026 年新文档 RAG 项目，这意味着：

* **摄取管道跳过 OCR。** 将页面图像传给 VLM；使用 VLM 的结构化输出作为索引基础。
* **不构建自定义布局解析器。** VLM 原生处理布局；工程精力投入提取的 prompt 设计和结构化输出验证（第 7 章）。
* **规划视觉 token 成本。** 每页处理约 0.01 美元–0.03 美元（当前 2026 年定价）。10 万页约 1K–3K 美元。真实，但通常比维护 OCR 管道 + 解析器便宜得多。

例外：非常高量、稳定格式文档（已知模板打印表格；收据；特定发票格式），经典 OCR 在成本和准确率上仍有竞争力。对于这些，经典 OCR + 专用解析器可能仍是正确选择。通用默认翻转到视觉优先；专用案例保留。

**Q2.** 什么是 _ColPali_，为什么 _后交互_ 架构与标准向量搜索有意义不同？

**答案：** ColPali 是 2024 年文档图像检索模型，使用后交互架构。而非每文档图像产生一个密集向量（CLIP 和标准文本嵌入使用的双编码器方法），ColPali 将图像分为块；每块有自己的嵌入。查询时，查询嵌入（一个或多个向量）与每块嵌入交互；文档分数是块级相似度的聚合（通常 max-pooling）。

与标准向量搜索的区别：

* **标准向量搜索**：双编码器。每查询一个向量，每文档一个。检索时余弦相似度。快（预计算文档向量；常数时间评分）。粗糙（文档向量概括整个文档；位置细节丢失）。
* **后交互（ColPali）**：每文档多向量（每块一个）。检索时查询与每块交互，文档分数聚合。慢（交互必须在查询时运行，不能预计算为余弦）。更准确（位置细节保留；查询可在文档内找到特定区域）。

对于相关内容局部于页面特定区域的文档 RAG（50 页合同中的特定条款；报告中的特定表格），ColPali 显著优于标准双编码器检索。成本是更重存储和更慢检索，但对于正确用例，质量提升证明其合理。
