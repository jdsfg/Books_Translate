(b) **提升到下一流量步骤的阈值**：

金丝雀分阶段递增：1% → 5% → 20% → 50% → 100%。每步有门控。

* _从 1% 提升到 5%_：至少观察 200 条轨迹；生产 eval 通过率在离线 eval 预测的 0.1 以内；无安全事件；审查者接受率达到或超过 0.7（agent 离线验证的最低值）；每轨迹成本在成本包络的 1.5 倍以内。
* _从 5% 提升到 20%_：至少观察 1,000 条轨迹；与上述相同标准；此外，按维度分数全部达到或超过其离线验证阈值。
* _从 20% 提升到 50%_：观察 5,000 条轨迹；标准持续满足；延迟 p99 在 SLA 内；过去 5 天成本轨迹稳定。
* _从 50% 提升到 100%_：观察 15,000 条轨迹；所有标准持续满足；审查者接受-修改分析显示无新的系统性 agent 错误模式。

(c) **立即回滚的阈值**：

* 任何安全事件（跨租户访问尝试；PII 泄漏；客户依赖的条款上自信但错误的风险标记）。
* 生产 eval 通过率在 6 小时窗口内低于离线预测超过 0.2。
* 超过 5% 轨迹的每轨迹成本超过包络的 3 倍（agent 循环或失控检索信号）。
* 延迟 p99 超出 SLA 50% 以上持续 2 小时。
* 审查者接受率降至 0.5 以下（agent 误服务工作流而非帮助它）。

回滚不是单一命令；它是团队已测试的预建路径。在金丝雀前练习它。

(d) **金丝雀期间的人在回路组件**：

没有先前生产历史的新 agent 需要比模型升级更密集的人工监督。推荐密度：

* _1% 金丝雀期间_：100% 的 agent 输出在到达客户前由合同审查者审查。审查者接受或修改；他们的决策馈入生产 eval。
* _5% 金丝雀期间_：人工审查密度降至 30%，采样以确保覆盖完整风险条款空间。
* _20% 金丝雀期间_：审查密度 10%；聚焦高风险条款（赔偿、责任、知识产权转让）。
* _50% 金丝雀期间_：审查密度 5%，最高风险合同（如超过阈值金额的合同）继续 100% 审查。
* _100% 推出时_：审查密度 3% 作为持续 eval 基线，加最高风险层级 100%。

人工密度计划是新 agent 金丝雀的显著特征。没有它，团队无法判断 agent 是否在最重要的案例中有效。有了它，团队同时构建生产 eval 数据和客户信任。纪律与第 14 章有界 agent 设计平行：团队承诺随信心增长而递减的监督密度，而非以完全自治启动。

这与第 23 章 §23.3 的四层 prompt 注入防御交叉引用：新 agent 的工具目录应从第一天起就策略门控，而非部署后添加。金丝雀标准验证安全架构在真实流量下运作，然后 agent 才达到规模。
