1. **几何 agent 生成爆炸**。规划器 agent 在自身迭代上限（比如 15）内可在每次迭代生成 10 个工作器 agent。每个工作器在自身界内。但 15 次迭代 × 10 个工作器 = 每系统轨迹 150 个工作器 agent，每个消耗其完整每 agent 预算。系统总成本是任何单独 agent 显示的 150 倍。

递归使它更糟：工作器生成子工作器，每个在自身界内，树爆炸。每 agent 界看不到树；树主导系统成本。

2. **协调死锁和停止条件失败**。辩论模式系统有两个 agent，每个在自身迭代上限内。它们在第 1 次迭代不同意；重新考虑后第 2 次仍不同意；持续到第 15 次（每个在自身界内）。系统未产生答案；每个 agent 消耗了预算；系统卡住。每 agent 界不包含协作工作的停止条件；系统需要单独的"已结论？"检查，没有单独 agent 强制。

其他需要系统级界的多 agent 故障模式：

* 编排器丢失工作器：工作器成功完成但编排器未聚合其结果；每 agent 界不检测缺失的协调。
* 工作器矛盾工作流：一个工作器撤销另一个工作器的行动；每 agent 界单独允许每个行动。
* 通过 API 速率限制的系统级成本放大：许多 agent 同时命中 LLM API 可触发速率限制导致重试，使实际成本倍增超出任何每 agent 预算所计。

教训：**多 agent 安全是系统属性，非每 agent 属性**。纪律涌现：每 agent 界（第 14 章）加系统级界（总 agent 数、总成本、递归深度、停止条件、协调完整性）。两层互补；都必需。

交叉引用：这与分布式系统设计中更广需要的组合推理相同。每节点界（CPU、内存）不约束集群；需集群级限制。多 agent 系统从分布式系统继承此纪律，应用于 agent 轨迹而非计算节点。
