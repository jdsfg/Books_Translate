2026 年交叉启发式（按 §22.4）：低于 10M token/天，托管 API 几乎总是胜出；10M 到 100M 之间，答案取决于服务引擎、利用率和运维成熟度（以及 _托管开放权重_ 提供商如 Together 是否定价过于激进以致无法击败）；100M+ token/天持续配合良好利用率，自托管明显胜出。

具体因素：

* _硬件成本_：典型 GPU 实例（约 30 美元/小时）服务中等 token 吞吐；每 token 成本取决于利用率。
* _工程成本_：严肃的自托管运营需约 1-2 FTE 做设置、持续维护、值班。年全面成本 200K-400K 美元。
* _利用率_：大多数工作负载无法达到 100% 利用率；有效利用率 50-80%。更低利用率将盈亏平衡推高。

超越纯成本：自托管也因数据敏感性（HIPAA、机密、气隙）、特定定制需求或战略供应商独立（独立于仅成本经济学）而合理。

对大多数低于盈亏平衡量的团队，**自托管的工程成本超过推理成本节约**。团队的工程师在产品工作上比在基础设施运维上更有价值。

**Q4.** 什么是设备端/边缘推理（§22.6），何时适用？识别两个场景。

**答案：** 边缘推理在用户设备（手机、笔记本、边缘服务器、车辆）上运行 LLM 推理而非在云数据中心。2026 年栈：小模型（Phi-4、Gemma 3、Llama 3.2 1B/3B）；推理引擎（MLX for Apple、llama.cpp 跨平台、Ollama for 开发者）。

两个适用场景：

1. **隐私敏感的个人数据任务**。Apple Intelligence 是消费者示例：转录个人语音备忘、摘要你的消息、帮助你的照片：都受益于留在设备端，不传输到云。一些用户偏好设备端以保护隐私；一些法规要求它（特别是儿童或医疗数据在个人设备上）。
2. **离线/不可靠连接操作**。野外工作者（林业、采矿、建筑）；车辆（飞机、船只、越野）；远程位置（石油平台、极地研究站）。当连接不可靠时，依赖云的 AI 不工作；边缘 AI 可以。

其他值得提及的场景：

* _延迟关键_：到云的往返增加 50-200ms；对实时交互应用（游戏、AR），边缘显著更快。
* _消费者规模成本经济_：当应用有数百万用户每用户多次调用，累积云成本大；边缘将成本移到用户硬件。

边缘有权衡：更小模型质量更低；用户硬件各异（一些根本无法运行模型）；电池和热限制约束重推理。对正确用例，权衡可接受；对一般用途，云端仍是默认。
