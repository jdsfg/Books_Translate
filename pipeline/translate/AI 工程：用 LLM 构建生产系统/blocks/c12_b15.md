* _待生效立法_：如果法规已通过但尚未生效，它有未来 effective_date；当前查询不检索它；effective_as_of >= 未来日期的查询会。
* _追溯适用_：一些法规追溯适用；prompt 指示 LLM 在标明处考虑追溯性。
* _日期模糊查询_：如果用户问"当前规则是什么？"无日期，默认今天。如果用户问特定事件（"我们 2022 年的合同"），LLM 提取相关日期。

时间有效性层的成本在于元数据维护（法律研究团队或监控服务必须为每个块记录 effective_date 和 deprecation_date）。收益是答案不引用已取代的法律，这对法律技术是关键正确性维度。

**AI 协作子问题**：你会如何请 LLM 帮助完成这个练习，你会在它的回答中验证什么？

**答案：** 有用的 prompt：_为法律 RAG 设计时间有效性层：元数据存储、查询时过滤、答案时暴露、漂移处理、边界情况。_ 你验证 (a) 元数据 schema 捕获实际法律文档更新模式（一些法规有部分修订；设计必须处理此），以及 (b) 漂移处理与你的法律监控服务集成（LLM 可能假设不存在的服务；检查你的团队有此类服务访问）。

**Q4.** _诊断 RAG 质量问题_。你的团队 RAG 系统显示：检索 recall@10 = 0.85（好），答案忠实性 = 0.62（差）。客户报告答案包含检索块中没有的声明。诊断问题并在正确层级提出修复（prompt？检索？LLM 选择？其他？）。

提示

检索工作良好。问题在下游。

**答案：** 诊断：检索在做其工作（recall 0.85 意味相关块被检索到）。忠实性差距（0.62）在 _生成_ 层：LLM 产生检索块不支持的声明。这是经典 _尽管有 RAG 仍幻觉_ 故障。

根因，按优先级排序：

1. **prompt 未严格强制接地。** LLM 被允许（甚至被鼓励）将训练知识与检索块一起使用；它最终混合两者。修复：prompt 级约束说"仅使用检索块中的信息回答。如果检索块未涉及问题，明确说明而非用先验知识回答。"
2. **引用强制未要求。** 模型产生声明而不引用来源块；这使模型可以无追溯性地编造声明。修复：要求每个声明有 chunk-id 引用；后处理验证引用指向真实块；拒绝未引用声明的答案。
3. **检索块未被很好利用。** 也许 LLM 被给 10 个块的扁平列表无结构；模型注意力可能被稀释。修复：在 prompt 中结构化检索块（例如带 chunk-id 标签的编号列表）；将最相关块放在块的开头和结尾（按第 8 章的 lost-in-the-middle）。
4. **模型可能不足。** 工作马层级模型（mini、Haiku、Flash）有时在 RAG 上下文中更多幻觉。如果你在工作马上，尝试前沿；提升可能证明成本合理。
