#### 模式 3：带重排序的生产 RAG

**解决什么问题。** LLM 需要回答关于它未被训练的语料的问题——客户文档、内部 wiki、判例法、医学文献。原始向量搜索产生基于错误文档的流畅答案；生产 RAG 添加重写、混合检索和重排序以将 precision-at-k 推到 LLM 停止幻觉引用的阈值之上。

**拓扑。** 查询进入重写阶段——一个小而便宜的 LLM 调用（或微调模型）扩展为一到三个搜索友好变体，处理同义词、缩写和针对最近轮次的代词消解。每个变体通过两个并行检索器：对向量存储（Pinecone、Weaviate、pgvector 或 2026 年的 Turbopuffer）的稠密嵌入搜索，和对倒排索引（Elasticsearch、OpenSearch 或 Tantivy）的 BM25 词法搜索。候选集——通常每检索器每变体 50 个——去重并合并为 100 到 200 的池。交叉编码器重排序器（Cohere Rerank、BGE-reranker 或微调的内部模型）对每个候选针对原始查询评分并保留前 8-20。选定的块进入 prompt 带显式文档 ID。LLM 生成带引用这些 ID 的结构化引用；后处理阶段验证每个引用对应 prompt 中的真实块且被引文本确实出现在源中——否则引用被剥离或答案用更严格 prompt 重新生成。

**何时用。** 语料太大无法放入上下文窗口（超过几十万 token）。引用因信任、监管或产品原因需要。原始向量搜索已产生足够幻觉引用事件以证明重排序基础设施合理。

**何时不用。** 语料足够小可塞入上下文（20 万 token 以下）——2026 年长上下文模型常优于半构建的 RAG。或查询不需要接地（创意写作、头脑风暴、针对训练数据的代码生成）。

**交叉引用。** 第 9 章（向量检索），第 10 章（重排序和混合），第 11 章（引用和后处理）。
