**Q4.** _诊断多 agent 失败_。你的编排器-工作器系统在 8% 轨迹上产生不完整响应：工作器完成但编排器的响应遗漏一些工作器的发现。诊断并提出修复。

**答案：** 诊断：故障模式是 _丢失工作器跟踪的编排器_（§15.9）。工作器在做其工作；问题在协调。

可能原因：

1. **状态存储竞态条件**：工作器将发现写入共享存储；编排器在所有写入完成前读取。症状：缺失发现与时间模式相关。
2. **编排器等待超时太短**：编排器放弃等待慢工作器。症状：缺失发现与接近超时阈值的工作器完成时间相关。
3. **聚合逻辑 bug**：编排器的聚合步骤有边缘情况（例如特定工作器输出格式未处理）。症状：缺失发现与特定工作器类型相关。
4. **工作器输出在状态存储写入时丢失**：工作器偶尔未能写入发现（瞬时错误）。症状：缺失发现是随机的。

**诊断步骤**：

* 检查失败轨迹的追踪：工作器是否完成？其发现是否到达状态存储？编排器的等待是否足够长？
* 将失败与工作器类型、时间和负载关联。模式提示具体原因。
