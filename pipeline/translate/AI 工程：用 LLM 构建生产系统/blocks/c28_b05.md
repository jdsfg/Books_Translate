#### 模式 5：带工具目录的有界 agent

**解决什么问题。** 单次 LLM 调用无法完成工作——任务需要读数据库、调 API、写文件并迭代中间结果。朴素 agent 循环（"LLM，这是工具，去吧"）失控：无限迭代、成本爆炸、模型卡住时重复相同工具调用。有界 agent 是生产安全变体。

**拓扑。** 用户目标进入维护按会话状态的 agent 服务：迭代计数、累计 token 成本、工具调用历史（参数哈希用于去重）、预算信封。循环是显式的：(1) 组合 prompt——系统指令、目标、运行草稿本、工具目录；(2) 调用 LLM；(3) 如 LLM 发出工具调用，对照历史去重（最近 N 次迭代内相同名称加参数被拒绝并告知模型它已试过），然后在沙箱中执行——gVisor、Firecracker 或带严格系统调用允许列表的进程隔离子进程——带每次调用超时（5-30 秒）和结果大小上限（4-16 KB）；(4) 将结果追加到草稿本；(5) 检查断路器——迭代上限（10-30）、成本上限（累计 token × 单价）、墙上时钟上限（60-300 秒）——并在任一触发时优雅中止。完整轨迹（每个 prompt、响应、工具调用、结果）带单一轨迹 ID 记录使事后复盘可处理。

**何时用。** 任务确实需要工具使用和迭代。工具有有意义的副作用（写入、支付、不可逆操作）需要沙箱。你已发布一两个非 agent AI 功能且有可观测性故事。

**何时不用。** 任务可用一次 LLM 调用加结构化输出解决。或团队从未发布过生产 AI 功能且因炒作伸手 agent——多数 2025 年"agent"用例最终是一调用加 RAG 的伪装。
