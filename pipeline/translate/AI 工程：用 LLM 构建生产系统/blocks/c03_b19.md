你不能通过 prompt 修复这个。任何"prompt engineering"防御（在 system prompt 中告诉模型忽略注入尝试）本身只是模型在注入内容之间平衡的又一个条件。一些防御平均上有帮助；没有一个是万无一失的。正确的缓解措施是架构性的（§2.11 的 _将模型与产品分离_；第 23 章的四层防御）：将模型输出视为不可信；在对其采取行动之前验证它；将工具调用隔离在确定性策略检查之后；在输入中标记不可信内容使模型将其视为数据而非指令。这些是围绕模型的工程层，不是给模型的 prompt。

本章对 prompt 敏感性（§2.7）和对没有内部 _不要 hallucinate_ 开关（§2.6）的强调可以泛化：也没有内部 _不要被欺骗_ 开关。模型是一个概率性条件器；唯一可靠的防御是围绕它分层。

**Q5.** prompt 缓存（Sonnet 4 上 0.30 美元/百万缓存读取 vs 3.00 美元/百万新输入）是 KV cache 的工程可见产物，KV cache 是模型服务栈内部的一个机制。在工程师层面解释 KV cache 实际是什么，以及为什么缓存输入 10 倍的降价对 provider 来说在经济上可辩护而非营销促销。然后指出一个这个事实应该改变的 prompt 设计决策。

提示

K 和 V 代表 _key_ 和 _value_，是 transformer attention 步骤中每个 token 在每层计算的三个矩阵中的两个。这些矩阵中哪些只依赖于之前看到的 token，哪些依赖于新 token？

**答案：** 在工程师层面：当模型处理一个 prompt 时，每个 token 在每个 transformer 层产生三个投影向量，叫做 query、key 和 value。attention 机制使用 query 对 key 来决定 _attend 到哪些更早的 token_，结果 attention 分数应用于 value。token 1 到 N 的 key 和 value 矩阵只依赖于这些 token；一旦计算完毕，如果相同前缀再次发送，它们可以被缓存和重用。只有新的 query 需要在扩展 prompt 时对现有 key 计算。这就是 KV cache：它是模型服务栈对之前见过的 prompt 前缀的（key, value）张量的记忆化。

10 倍降价是可辩护的因为 provider 在缓存命中时的实际边际成本由对缓存 key 的 value 应用和 softmax 步骤主导，而非从头计算那些 key 的更昂贵的前向传递。节省的计算工作是 prompt 编码成本的一大部分。provider 保守定价折扣（原则上他们可以把缓存读取定价得更便宜）因为缓存命中跨请求不保证，前缀匹配的基础设施有自己的开销。关键是：这是真实计算被节省，不是销售噱头。
