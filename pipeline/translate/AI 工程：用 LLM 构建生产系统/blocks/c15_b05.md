#### 层 2：情景记忆（会话内跨轮次）

agent 记住此 _会话_（用户交互）中发生的事，即使跨多个子轨迹。客户支持会话可能涉及多次 agent 调用；情景记忆在它们之间携带学习。

实现模式：

* _对话摘要_：会话关键事实和决策的运行摘要。重新注入每次新 agent 调用的上下文。
* _决策日志_：会话期间所做决策的结构化记录（"agent 在第 7 轮发出 50 美元退款"）。可作为工具供后续调用查询。
* _用户状态_：agent 对用户目标、偏好、阻碍的理解。跨会话更新。

#### 层 3：长期记忆（跨会话）

agent 记住跨多个会话与同一用户或关于同一主题发生的事。识别回头客户的客户支持 agent；记住你项目约定的编码助手。

实现模式：

* _向量记忆_：先前交互被嵌入和存储；需要时检索相关过去交互。通常是每用户索引。
* _结构化事实_：关于用户的显式事实存储在数据库中（偏好、常见工作流、过去问题）。通过工具查询。
* _档案摘要_：用户历史的运行摘要，定期更新，会话开始时检索。

#### 长时间运行中的工作记忆问题

对于长 agent 轨迹，工作记忆累积。30 轮后，工作记忆可能 30K token。agent 的有效焦点变窄；中间丢失效应（第 8 章）出现；成本上升。

工程模式：**周期性轨迹内摘要**。每 K 轮，将旧轮次压缩为结构化摘要；用摘要加最后几轮替换逐字历史。agent 的工作记忆保持有界；轨迹可无限继续（在 §14.4 的界内）。

    def maybe_compress(messages: list, threshold: int = 30_000) -> list:
        tokens = estimate_tokens(messages)
        if tokens < threshold:
            return messages
        # 保留首条消息（用户目标）+ 最后 5 轮逐字；摘要中间部分
        middle = messages[1:-5]
        summary = summarize_via_small_llm(middle)
        return [messages[0],
                {"role": "assistant", "content": f"[先前摘要: {summary}]"},
                *messages[-5:]]
