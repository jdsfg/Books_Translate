### 章节小结

2026 年的 prompt 工程已从 2022–2023 年的广泛学科收窄为四个特定用例：通过 prompt 设计优化成本和延迟；约束输出结构（第 7 章）；引出工具使用（第 13 章）；安全加固（第 23 章）。文献中的命名模式（思维链提示，Wei 等 2022；ReAct，Yao 等 2022；Self-Refine，Madaan 等 2023）已被部分吸收进前沿模型的训练；它们在特定场景中仍有帮助，尤其在工作马梯队模型上，但不再是三年前的差异化技能。

DSPy 和 MIPRO 代表 _prompt 即代码_ 纪律：签名替代字符串；优化替代手动调优。框架在你有清晰 eval 集、良好边界任务且愿意放弃直接 prompt 控制时是正确的。对于简单案例或严格利益相关者可见性约束它是过度的。

Prompt 注册表模式（§6.4）是将 prompt 视为版本化制品的纪律。每个 prompt 有版本、基线 eval 分数和部署清单。绑定工作流 #2（§6.5）是具体制品：三个候选 prompt 版本，每个对相同 golden set 评估，delta 并排可见。团队基于数据选择版本，通过清单更新部署，通过清单恢复回滚。

Strata Research 的 V1→V4 迭代弧（§6.6）在实践中展示纪律：每个版本针对特定 eval 维度；累积提升是工程化的，非幸运的。Prompt 从约 150 增长到约 450 token；成本可接受；准确率在完整 eval 支持下从 64% 移动到 81%。

Prompt 即代码建立在第 4 章的 eval 纪律和第 5 章的工具之上。下游用例——结构化输出（第 7 章）、工具使用（第 13 章）、prompt 缓存作为成本杠杆（第 18 章）、安全加固（第 23 章）——各自将本章的注册表模式视为给定并在其上工程化。

在任何特定 2026 年策略过时后存活的是 _纪律_：prompt 作为版本化代码、对照 golden set 评估、通过清单部署。策略会轮换；工作流形态是传承的东西。
