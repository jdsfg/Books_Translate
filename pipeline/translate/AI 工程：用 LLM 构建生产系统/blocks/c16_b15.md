#### 应用题

**Q1.** _决定单 agent vs 多 agent_。对每个任务，推荐单 agent 或多 agent 并附理由：(a) LLM 驱动的代码审查 bot 审查单个 PR (b) 企业研究助手跨多个网络来源和内部文档收集竞争对手信息 (c) 接受客户请求并安排会议的自动化（日历查找、冲突解决、预订） (d) 通过检查日志、指标和追踪诊断生产问题的事故响应 agent

**答案：**

(a) **单 agent**。审查一个 PR 是单线程任务：读 diff、分析代码、发评论。无自然并行分解；多 agent 会增加协调开销。单 agent + 好工具目录（read_file、search_codebase、post_comment）是正确架构。

(b) **多 agent（编排器-工作器）**。跨多来源研究天然并行：每种来源类型一个工作器（网络搜索、内部文档、数据库）。编排器将发现聚合为综合。单 agent 会串行检索并浪费并行机会。

(c) **单 agent**。会议安排是串行的：查用户日历、提议时间、获取与会者日历、找重叠、预订。每步依赖前一步。无并行机会。工具增强单 agent 即可。

(d) **多 agent 或复杂单 agent**。事故响应涉及多个独立来源（日志、指标、追踪）；每个可能受益于专业分析。多 agent 配专业工作器（日志分析器、指标异常检测器、追踪调试器）可并行运行。单 agent 可串行做但更慢。推荐：时间关键事故用多 agent；非紧急调查用单 agent。

**AI 协作子问题**：你会如何请 LLM 帮助完成这个练习，你会在它的回答中验证什么？

**答案：** 有用的 prompt：_对每个任务，推荐单 agent 或多 agent 并附理由。_ 你验证 (a) 推荐考虑并行机会（LLM 可能默认 _全部用多 agent_；坚持 _这是天然并行的吗？_ 标准），以及 (b) 理由命名具体架构关注（延迟、并行性、工具目录大小）而非通用"看起来复杂"。

(a) **编排器**：

* 角色：将工单分类为子问题；生成适当工作器；聚合发现；组合客户面向响应。
* Prompt：

        你是客户支持 agent 系统的编排器。你的工作是：
        1. 阅读客户工单。
        2. 识别工单中的不同子问题（通常 1-3 个）。
        3. 对每个子问题，决定哪种工作器类型处理它。
        4. 工作器完成后，将其发现聚合为连贯的
           客户面向响应。
        可用工作器类型：order_worker、refund_worker、address_worker、
        billing_worker、technical_support_worker。
