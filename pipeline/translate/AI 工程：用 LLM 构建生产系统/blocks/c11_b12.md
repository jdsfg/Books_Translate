#### 应用题

**Q1.** _为新 RAG 项目选择嵌入 + 向量数据库_。你的团队在公司 monorepo（约 1200 万行代码、约 80M token、多语言：Python、Go、TypeScript）上构建代码搜索和问答工具。工程团队规模：8 人。现有基础设施：Postgres 存业务数据、Kubernetes 存服务。推荐嵌入模型和向量数据库。各用两句话论证。

提示

代码是受益于专用嵌入的领域。将向量数据库匹配你现有基础设施。

**答案：**

**嵌入模型：Voyage `voyage-code-3`**（或微调 BGE-Code-v1.5 作为开放权重替代）。代码嵌入从专用训练中大幅受益；通用嵌入在代码相似性任务上低 5–10 分。Voyage 的代码专用模型是 2026 年的强默认；成本溢价小。

**向量数据库：pgvector**。你已使用 Postgres；80M token 语料库转化为约 1–3M 块典型代码块大小，在 pgvector 舒适范围内。_无新基础设施_ 的运维简单性对 8 人团队胜出；专用数据库在此规模增加运维负担而无比例收益。

替代答案是 Pinecone 如果团队预期扩展到更多仓库（10+ 公司代码库合并）索引增长超过 pgvector 甜点。对于一个 monorepo 在所述规模，pgvector 是正确选择。

**AI 协作子问题**：你会如何请 LLM 帮助完成这个练习，你会在它的回答中验证什么？

**答案：** 有用的 prompt：_为 80M token monorepo 上的代码搜索工具选择嵌入模型和向量数据库，8 人团队，Postgres + K8s 基础设施。_ 你验证 (a) LLM 提到专用代码嵌入（不仅是通用嵌入，常见 LLM 疏忽），以及 (b) 向量数据库推荐考虑团队规模 + 现有基础设施（LLM 有时对一切都推荐 Pinecone；检查推理匹配你的规模）。

**Q2.** _设计混合搜索系统_。Strata 的 RAG 必须处理三种查询类型：(1) 改述法律问题（"责任是否延伸到..."），(2) 精确引用（"26 USC § 162(a)"），(3) 日期限定查询（"截至 2024 年的加州消费者保护法"）。设计混合搜索架构。指定使用的信号、融合逻辑和元数据过滤层。

**答案：**

信号：

1. **向量搜索**：查询嵌入（Voyage voyage-law-2）→ 从 Pinecone 向量索引 top-30。最适合改述查询。
2. **BM25 搜索**：查询词 → 从块文本上的 BM25 索引 top-30。最适合精确引用和精确法规编号查询。
3. **元数据预过滤**：解析查询的管辖权和日期约束；在检索前作为过滤应用。最适合日期限定查询。

融合：**倒数排名融合（RRF）k=60** 结合向量和 BM25 排名。融合分数为 `1/(rank_vector + 60) + 1/(rank_bm25 + 60)`。按融合分数 top-20 进入重排序器。
