每层捕获不同流量模式。一起它们复合：团队应用全部三层对可缓存流量获得合计约 40-60% 降低。Helios 的栈有全部三层加 OpenAI 隐式缓存用于 OpenAI 路由部分。

投资顺序：提供商侧 prompt 缓存优先（免费 + 低投入）；应用层精确缓存其次（低投入）；语义缓存最后（更高投入 + 风险管理）。

**Q4.** 批量推理何时适用，何时不适用？各识别三个工作负载。

**答案：**

**批量适用**：

1. **文档摄取**。索引语料库；用户不等待索引完成。Strata 的合同摄取（第 12 章）是示例：50 万页通过批量索引，节省 50%。
2. **回填和迁移**。当 prompt 或 schema 变更时重新处理历史数据。天然异步。
3. **定期 eval 运行**。在夜间计划上对完整 golden 集运行 eval。延迟不重要；成本重要。

**批量不适用**：

1. **交互式客户聊天**。用户实时等待；亚秒延迟期望。
2. **语音助手**。亚 500ms TTFT 预算对批量不可能。
3. **实时告警和事故响应**。如 LLM 是告警分析流水线的一部分，你需要秒级响应，非小时级。

一个细微处：一些工作负载 _部分_ 批量合格。OCR 和增强流水线可能在交互路径处理实时上传并在夜间用批量重新处理长尾积压。纪律：审计工作负载；将合格的路由到批量；将需实时的保持在实时。

批量的节省是纯利润：50% 折扣无质量损失。不审计工作负载批量合格性的团队在把钱留在桌上。

**Q5.** 第 19 章将引入可观测性追踪作为生产 AI 工程的基础。解释成本追踪（本章纪律）如何依赖可观测性（第 19 章纪律）。识别两个没有追踪数据不可能的成本追踪实践。

**答案：** 本章要求的级别的成本追踪不能仅从提供商侧仪表板实现。提供商仪表板在账户级聚合：总支出、也许按模型分解。它们无法回答生产团队必须回答的问题：

* 每租户成本归因。
* 每功能成本归因。
* 每任务类成本（哪些工作类型最贵）。
* 每业务结果成本（每解决支持工单的成本、每成功检索的成本）。

这些问题每个都需要 _带维度标记的每调用数据_。标记在应用层完成；存储在可观测性层（Langfuse、Phoenix、自定义 OTel 流水线）完成。没有可观测性层捕获每调用及其标记，成本问题根本无法回答。

两个没有追踪数据不可能的具体成本追踪实践：

1. **每租户成本仪表板**（§18.8）。仪表板需要带 tenant_id、cost 和 tier 标记的每调用记录。提供商仪表板没有 tenant_id（提供商不知道你的租户）；只有你的可观测性层有。没有追踪，每租户归因最多是基于调用计数的电子表格练习，丢失了来自缓存、输出长度和层级的每调用成本差异。
