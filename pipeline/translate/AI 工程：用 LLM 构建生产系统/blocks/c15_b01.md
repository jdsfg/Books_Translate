在 2024 年 10 月一个成为警示锚点的事件中（本书框架中的线程 B 失败 5），一个早期初创公司部署了一个内部 AI agent 旨在帮助工程师调试生产问题。agent 有权访问包括代码执行、文件读取和出站 API 调用的工具目录。一个周五傍晚，工程师让 agent"调查暂存服务器的延迟问题"。agent 开始调查。它运行诊断。诊断产生模糊结果。agent 运行更多诊断。每次新工具调用的输出为 agent 产生更多不确定性；每次新不确定性产生更多工具调用。到周一早上，agent 调用工具 380 次，运行 14 小时，累计 52,000 美元 API 成本账单。它没有解决延迟问题。它没有停止。

这是本章围绕的故障模式。**失控螺旋的 agent 不是假设性关注。** 它们是 2025–2026 生产 AI 的主导故障模式，而 _有界性_ 的工程纪律——防止螺旋的设计选择——是区分生产级 agent 和昂贵灾难的关键。

本章做两件事。首先，定义 agent 是什么及 agent 故障模式目录长什么样。其次，构建工程纪律：有界设计、记忆架构、agent 设计文档的绑定工作流（#7）。Helios Customer AI 的有界 agent 是工作案例；团队通过线程 B 失败 5 的复合及其 2026 年继任者（教学大纲的失败 6：多 agent 递归）学到教训。

### 14.1 Agent 实际是什么

agent 是 **LLM + 工具 + 循环 + 记忆**。展开：

* **LLM** 是推理引擎。它决定下一步做什么。
* **工具** 是操作面。它们让 agent 影响世界。
* **循环** 是迭代。agent 行动、观察结果、再行动，直到完成。
* **记忆** 是跨迭代和跨会话持久化的东西。它是 agent 如何在即时推理调用之外维护上下文。

去掉任一个你就有更简单的东西。LLM + 工具（无循环、无记忆）只是工具调用函数。LLM + 循环 + 记忆（无工具）是带对话历史的聊天机器人。LLM + 工具 + 循环（无持久记忆）是会话间遗忘的会话内 agent。

四者合一是 agent。到 2026 年，agent 是大多数 AI 工程师花最多时间的架构模式。它们也是最可能灾难性失败的架构。

#### 定义：Agent

基于 LLM 的系统，跨多个推理轮次运行，使用工具采取行动和观察来告知后续决策，记忆跨轮次（有时跨会话）持久化，追求在轨迹开始时声明的目标。

用通俗语言：agent 是在循环中运行的 LLM，调用工具和读取结果，试图完成用户要求的事。agent 的行为是工具调用和推理步骤的轨迹；agent 的成功是轨迹是否以期望结果结束。
