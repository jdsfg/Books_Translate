### 2.9 model card 作为规格表

2026 年的每个前沿模型发布都附带一份 _model card_：由实验室发布的文档，描述模型的能力、局限性、预期用途、在标准基准上的评估结果、安全测试结果和运营特征（上下文窗口、支持的功能、定价）。model card 是模型的规格表，工程师应该像芯片工程师读数据手册一样读它。

作为 AI 工程师，在 2026 年的 model card 中要关注什么：

1. **上下文窗口**（以 token 为单位，输入和可能的输出分别列出）
2. **知识截止日期**（模型在此日期之后没有可靠训练数据的日期）
3. **支持的功能**：streaming、工具调用、JSON-schema 输出、vision、音频输入/输出、长上下文计费率
4. **定价**：每百万 token 输入成本、每百万 token 输出成本、任何按功能的附加费（vision 通常比文本高，batch 通常打五折）
5. **基准结果**：MMLU、HumanEval、AIME 等（用作模型间的相对比较，而非绝对能力声明）
6. **安全评估**：拒绝率、prompt 注入易感性、red-team 结果
7. **延迟特征**：首 token 时间、每秒输出 token 数，通常按区域和流量水平分别列出
8. **速率限制**：默认每分钟请求数和每分钟 token 数；什么层级解锁更高限制
9. **弃用时间线**（如果披露）：模型预计何时下线，以及其继任者是什么

关于 model card 局限性的两点说明。第一，实验室报告的基准数字是营销相关的：它们往往是模型在所选基准上的最佳表现，不能泛化到你的任务。始终运行你自己的 eval。第二，model card 是关于能力的文档，不是关于行为的合同：模型在你特定 prompt 上的行为是经验性的，不能从 card 中推导。card 缩小搜索空间；它不替代 eval。
