### 5.3 Beacon Health AI：HIPAA 安全 eval 集构建

Beacon 的 eval 集构建是 eval 基础设施遇到监管现实的案例。临床笔记摘要器的 golden set 由真实患者就诊的口述笔记组成。口述包含 PHI：姓名、日期、状况、药物，有时有健康的社会决定因素，有时有心理健康背景。PHI 受 HIPAA 监管并受公司与每家医院的业务伙伴协议（BAA）约束。eval 不能使用原始 PHI；eval 也不能丢失 _真实 PHI_ 提供的关于模型在生产中会做什么的信号。

团队的解决方案是 **合成 PHI eval 构建**：一个管道接受真实口述，用保留原始结构性和统计性属性的合成替代物替换每个 PHI 元素，并产生一个 HIPAA 安全的 eval 集，可在 CI、SaaS 可观测性和跨团队审查中使用。

管道：

1. **命名实体检测** 识别 PHI 元素：姓名、出生日期、病历号、年龄、地点、服务日期等。
2. **替换** 用合成等价物替换每个 PHI 元素。姓名 → 从姓名语料库中随机抽取，保持与原始相同的性别和种族分布。日期 → 按每患者随机偏移移动（保留事件间持续时间）。年龄 → 分桶（保留年龄范围信号）。病历号 → 随机生成的有效格式标识符。
3. **临床内容精确保留**。状况、药物、剂量、检查发现、化验值：这些不是 PHI，精确保留。模型在实际临床内容上的行为是 eval 测量的东西。
4. **样本人工审查**。临床医生审查 10% 的合成 PHI 案例以确认它们临床现实且没有 PHI 通过替换步骤泄漏。
5. **合成 PHI eval 集然后是 HIPAA 安全的**：它可以检入版本控制、在 CI 中运行、由非临床利益相关者审查，并在团队中共享。

成本是真实的：构建替换管道花了两个工程师月加隐私/合规团队的咨询时间。收益也是真实的：有了 HIPAA 安全的 eval 集，团队可以在标准 CI 中使用 `pytest-evals`，在非 PHI eval（CodeReview Bot）上使用 `braintrust` 进行跨团队可见性，并避免在 PHI 感知沙箱内运行每个 eval 的运营复杂性。合成 PHI 模式可在 Beacon 的其他 AI 功能中复用。

#### 常见误解

去标识化——剥离姓名和明显标识符——对合成 PHI eval 构建 _不够充分_，尽管很多团队将其视为默认。去标识化的 PHI 通常可以通过组合临床细节（罕见诊断、不寻常的人口统计组合、独特日期）重新识别。HIPAA 的 Safe Harbor 去标识化要求移除 18 个特定标识符类别，即使 Safe Harbor 对不寻常案例也有已知重新识别风险。_替换_ 方法更进一步：用保留统计属性但打破逆向识别链的合成等价物替换标识符。两种方法不等价；替换方法对于数据可能由直接临床团队外人员审查的 eval 用例更可辩护。
