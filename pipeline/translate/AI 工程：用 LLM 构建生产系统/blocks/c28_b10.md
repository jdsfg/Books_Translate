#### 模式 10：成本优化的多层缓存栈

**解决什么问题。** LLM 账单是最大工程条目。每 token 成本逐年下降但量增长更快。缓存栈通过不命中模型服务重复和相似请求、以及将非紧急工作移到更便宜的异步通道来挤压账单。

**拓扑。** 层在 LLM 调用前运行，每层比下一层更便宜更快。层 1，精确匹配应用缓存：Redis 或 Memcached 查找，键为 `(规范化 prompt, 模型, 温度, 工具, 系统 prompt 版本)` 的哈希；TTL 分钟到小时；用户界面命中率 5-20%，自动化工作负载更高。层 2，语义缓存：计算 prompt 的嵌入（复用 RAG 嵌入器），在小型专用索引中向量查找先前 prompt 高于余弦阈值（0.95-0.98）；如阈值和新鲜度检查通过返回缓存响应。阈值设错的语义缓存返回错误答案——0.92 会愉快地误路由——所以对照 eval 集校准并仪表板显示命中率。层 3，提供商 prompt 缓存：Anthropic 的功能（2026 年 OpenAI 和 Gemini 也有类似）折扣重复前缀 token；将 prompt 结构化为长的稳定部分（系统 prompt、工具目录、会话稳定的 RAG 上下文）在前。层 4，批量端点：对非同步工作负载（隔夜分析、文档处理、eval 运行），提交到提供商的批量 API 约 50% 折扣带 24 小时 SLA。仅在四层全部未命中后请求才命中同步端点。每层可观测：命中率、按租户命中率、仪表板上"本月节省成本"。

**何时用。** LLM 支出年度六位数或更高。工程带宽运营缓存（它们会过期、会返回错误答案、需要运行手册）。流量模式有结构性重复（同一用户问相似问题、系统 prompt 加上下文跨请求大部分稳定）。

**何时不用。** 流量多数唯一且缓存不会命中。或你未测量命中率上限且在先发制人地过度工程。从层 1 和层 3 开始；数据说明回本时添加 2 和 4。

**交叉引用。** 第 18 章（成本优化），第 17 章（提供商策略和 prompt 缓存）。
