### R

**RAG**：检索增强生成。获取相关内容并在生成前将其包含在 prompt 中的模式。接地回答的主导模式（第 9 章）。

**速率限制**：提供商对请求频率的上限。按每分钟请求数（RPM）和每分钟 token 数（TPM）强制执行；相应规划容量（第 3 章，§3.5）。

**ReAct**：推理与行动循环：模型思考、选择工具、观察结果并重复。经典 agent 模式（第 13 章，§13.3）。

**ReAct 循环**：见 _ReAct_（第 13 章，§13.3）。

**Recall@k**：在 top-k 检索结果中找到的相关项比例。主要检索阶段质量指标（第 9 章，§9.5）。

**倒数排名融合**：见 _RRF_（第 10 章，§10.5）。

**参考标准**：黄金集中每个示例附带的"正确答案"。可以是特定字符串、评分标准或检查器函数（第 4 章，§4.3）。

**反思**：agent 模式，模型批评自己的输出并决定是否重试或修改。对困难推理有用；成本翻倍（第 14 章，§14.2）。

**拒绝**：模型输出拒绝遵从请求，通常因安全、能力或知识原因。需调优而非消除的行为（第 2 章，§2.3）。

**拒绝模式**：系统如何拒绝或升级的可复用结构：说明限制、建议替代、如有则升级到人工（第 23 章，§23.5）。

**回归检测**：当新模型、prompt 或管道变更的 eval 分数低于阈值时自动告警。"我们刚弄坏了什么"的信号（第 5 章，§5.7）。

**Replicate**：在 API 后运行开放权重和自定义模型的云平台。比自托管更低摩擦；比 Modal/Anyscale 更少控制（第 22 章，§22.4）。

**重排序器**：对 top-N 检索项重新评分以最终排序的交叉编码器或 LLM。混合搜索后单一最大检索质量增益（第 11 章，§11.1）。

**请求 ID**：提供商为每次调用返回的唯一标识符，用于支持、去重和追踪（第 3 章，§3.5）。

**响应格式**：声明预期输出形状（文本、JSON、结构化）的 API 字段。常与 schema 配对用于约束解码（第 7 章，§7.2）。

**重试预算**：单个逻辑请求的最大累积重试（次数或时间）。防止提供商停机期间的重试风暴（第 3 章，§3.5）。

**RLHF**：人类反馈强化学习。通过学习的奖励模型将基础模型与人类偏好对齐。2026 年在很大程度上被 DPO 及变体取代（第 2 章，§2.3）。

**角色**：消息轮次上的说话者标签：`system`、`user`、`assistant` 或 `tool`。不同提供商强制不同角色规则（第 3 章，§3.1）。

**路由层**：网关组件，基于成本、延迟、能力或回退规则为给定请求选择模型/提供商（第 17 章，§17.4）。

**RPM**：每分钟请求数。标准速率限制单位（第 3 章，§3.5）。

**RRF**：倒数排名融合。组合多个检索器（如 BM25 + 向量）排名列表的简单鲁棒算法。默认融合选择（第 10 章，§10.5）。

**评分标准**：将质量分解为带锚点的命名标准的结构化评分指南。从"我看到就知道了"到可用 eval 的桥梁（第 4 章，§4.4）。

**推理模型**：内置扩展思考模式的 LLM（如带思考的 Claude、GPT o 系列、DeepSeek R1）。更高成本和延迟，在困难分析任务上更好（第 2 章，§2.3）。
