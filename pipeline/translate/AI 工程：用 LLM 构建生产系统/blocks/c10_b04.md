#### 杠杆 4：排序（重排序）

Top-K 向量搜索快但粗糙。_重排序器_ 是更强的相关性模型，对 top-K 候选重新评分并返回 top-N（通常 N << K）。

重排序器通常是交叉编码器：它们将查询和候选一起取并产生相关性分数。交叉编码器比用于嵌入的双编码器准确得多（因为它们可以联合关注查询和候选），但也慢得多（你不能预计算候选分数）。所以它们只在向量搜索的小 top-K 上运行。

2026 年，Cohere Rerank 和 BGE-Reranker 是主导重排序器选择。添加重排序器通常在生产 RAG 上将相关性指标提升 10–20 分。Strata 的 V1→V2 跳跃（0.43 → 0.62 总体通过率，+19 分；完整表格在第 11 章 §11.5）主要是重排序器。第 6 章 §6.6 引用了相同弧线，用更简单的"准确率"指标表示，运行略高因为它不是多维通过率。

### 9.4 朴素 RAG 基线及其为何在生产中从不奏效

朴素 RAG 是大多数团队首先构建的：

* 任意大小的固定大小块
* 现成嵌入模型带默认维度
* Top-5 向量搜索，无重排序器
* 将检索到的块拼接进 prompt
* 希望 LLM 正确接地

朴素 RAG 足以演示。不足以生产。典型朴素 RAG eval 得分在相关性 和回答质量上 50–65% 范围；生产需要大多数用例 80%+。

差距：

* **分块对文档结构错误** → 检索在块边界丢失上下文
* **嵌入模型通用** → 在领域特定术语（医学、法律、代码）上表现差
* **无混合搜索** → 精确匹配查询表现不佳
* **无重排序器** → top-5 底部的块污染上下文
* **无查询重写** → 不与文档语言词汇匹配的用户查询遗漏
* **无接地强制** → 检索差时模型仍从训练知识回答

每个生产 RAG 系统解决这些差距。纪律是认识它们并工程化每一层。Strata 的 V1→V4 弧线（第 6 章）是典型进展。
