#### 应用题

**Q1.** _勾画你的 AI 系统架构_。选一个你团队正在上线或已上线的真实 AI 功能。将其映射到 9 层架构。对每层，识别什么存在、什么缺失、谁拥有它。

提示

此练习是诊断性的。不要填充答案；识别实际缺失的。

**答案：** 一个假设的中期创业公司 RAG 支持客户支持助手的工作示例（你的实际答案应来自你自己的系统）：

层 | 什么存在 | 缺口 | 所有者
---|---|---|---
模型提供商 | Anthropic Sonnet 4 + GPT-4o-mini | 两个提供商都宕机时无回退到 Gemini | 平台团队
路由器 / 网关 | 直接 API 调用；无路由器 | 需要 LiteLLM；成本感知路由缺失 | 平台团队（未分配）
编排 | Python 自定义 agent 循环 | OK；按第 14 章有界 | 功能团队
Eval 平台 | 150 golden 案例的 pytest-evals | 未接入 CI；手动运行 | 功能团队
可观测性 | Langfuse SaaS | 一些工作流未插桩（管理工具） | DevOps
成本追踪 | 月末手动审查 | 无实时仪表板；无告警 | 工程经理
特性开关 | LaunchDarkly（通用） | 未用于 AI 特定版本管理 | 平台团队
安全 / 护栏 | Prompt 级约束 | 无输出验证；无 prompt 注入 eval | 功能团队
应用层 | Web UI + 聊天嵌入 | OK | 功能团队

需解决的缺口（按优先级排序）：

1. 添加 LiteLLM 路由器并插桩回退（1-2 工程师周）。最高 ROI：捕获提供商宕机，启用成本纪律。
2. 将 eval 接入 CI（1 工程师周）。阻止未检测回归的质量衰退。
3. 添加成本追踪仪表板带实时告警（2 工程师周）。防止账单意外。
4. 在 Langfuse 中插桩未插桩工作流（1-2 工程师周）。关闭可观测性缺口。
5. 添加输出验证和 prompt 注入对抗 eval（2 工程师周）。关闭安全缺口。

总计：约 7-9 工程师周平台工作，按最高 ROI 优先排序。每个解决的缺口是参考架构中填入的一层。
