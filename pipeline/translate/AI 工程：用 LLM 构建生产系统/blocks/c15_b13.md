具体地：螺旋 14 小时做无用之事的无界 agent 不比在 15 次迭代以优雅错误停止的有界 agent 更有能力。有界 agent 快速失败并报告；无界 agent 慢速失败并累积成本。

能力问题是关于 _agent 能完成什么任务_，而非 _agent 能消耗多少资源_。对于任何有合理解空间的明确定义任务，本章的界（最多 15 次迭代、0.50 美元预算）足够；agent 在这些界内完全运行。对于确实需要更多的任务（罕见；通常是任务范围错误或需要不同架构的信号），显式操作员批准可提高界。

心智转变：界是定义 agent 可尝试什么的工程包络。agent 在包络内完全运行。无界替代有相同的包络内能力 _加上_ 灾难尾部——而灾难尾部不是能力，是灾难。

**Q4.** 什么是 _轨迹内摘要_ 及何时启动？为什么与会话间摘要不同？

**答案：** 轨迹内摘要在工作记忆超过阈值（例如 30K token）时压缩当前轨迹的旧轮次。旧工具调用、观察和推理被结构化摘要替换；agent 的工作记忆保持有界而轨迹可继续。

启动条件：

* 轨迹累积了大量工作记忆（通常 15+ 次迭代后或几次大工具输出后）。
* 达到阈值；进一步累积将冒上下文溢出风险（故障模式 4）。

与会话间摘要不同因为：

* 轨迹内摘要发生在轨迹 _期间_；agent 在压缩状态上继续运行。
* 会话间摘要发生在轨迹或会话 _之间_；结果馈入下一会话的设置。
* 轨迹内必须快（轨迹在等待）；会话间可批量处理。
* 轨迹内保留 agent 当前目标和近期决策（即将使用）；会话间保留长期模式。

两者用类似工具（LLM 调用摘要）但服务不同目的。生产 agent 两者都做：轨迹内保持工作记忆有界；会话间维护情景和长期记忆。

**Q5.** 第 13 章引入工具使用作为 agent 的构建块；本章引入使工具成为 agent 的有界循环。识别两个从循环（和界）中涌现但在一次性工具调用时不存在的具体属性。为什么这些涌现属性证明 _agent_ 这一术语区别于 _工具增强 LLM_ 是合理的？

**答案：** 两个涌现属性：

1. **多步规划能力。** 一次性工具调用用单一工具回答单一问题。有界循环让 LLM 顺序调用多个工具，观察每个结果，并基于所学调整后续调用。LLM 可将任务（"查客户订单；查配送状态；如延迟，查承运商追踪；如无信号，升级"）分解为单一调用无法表达的工具调用轨迹。有界循环是使此组合成为可能的关键。
