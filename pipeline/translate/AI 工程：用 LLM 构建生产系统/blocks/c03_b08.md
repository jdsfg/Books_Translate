### 2.6 为什么 LLM 会 hallucinate：架构层面的回答

hallucination——模型自信地产生事实上错误的信息——是 LLM 最被讨论的故障模式。工程师层面的解释很简单。

回忆生成循环：在每一步，模型通过从概率分布中采样来选择下一个 token。模型 _总是_ 在选择 _某个东西_。它没有单独的 _我不知道_ 机制。当下一个 token 的分布尖锐地峰化在单个 token 上时，模型发射一个感觉自信的补全。当下一个 token 的分布更均匀时，因为模型确实没有清晰的预测，模型 _仍然发射某个东西_，从（现在不那么峰化的）分布中抽取。对外部读者来说，结果文本看起来和峰化分布的补全一样自信。模型的词语不携带概率信息。

所以：hallucination 是模型不得不在不确定性高时仍要承诺一个下一个 token 选择的可见产物。模型不知道自己不知道。模型只是发射其分布中最可能的 token，如果高不确定性分布中最可能的 token 是一个听起来合理但错误的信息片段，你就得到了一个 hallucination。

几个推论随之而来。

**hallucination 不是随机的。** 它们倾向于在"事实性"输出区域（姓名、日期、引用、数字）比在风格性输出中更常出现。如果模型在生成关于抽象主题的散文，它在生成风格性续写，不强烈需要事实基础；不确定性被很好地处理。如果模型在生成对特定论文的引用，它在承诺一个 token 序列（作者姓名、年份、标题），其中任何错误的 token 都会产生错误的引用，而模型的训练有许多合理的模式可以插值。这就是为什么"hallucinated 引用"是经典的 hallucination 例子。

**hallucination 不等于说谎。** 模型不是在欺骗你；它在根据训练产生最可能的 token，没有内省能力来意识到自己在产生不可靠的东西。_说谎_ 暗示对正在被违反的真相有意识；模型没有这种意识。这是一个有用的框架，因为它去除了道德语言并澄清了工程问题：我们在处理一个以校准概率水平发射输出的系统，而校准是不完美的。

**hallucination 被后训练缓解而非消除。** RLHF/DPO 可以教会模型在检测到某些类型的分布外查询时产生"我没有关于那个的信息"的模式。但模型无法可靠地内省自己的不确定性。它不能说 _我对此有 60% 的把握_；它只能说 _我确定_ 或 _我不确定_，而这两者之间的选择本身是一种训练行为，不是真正的不确定性估计。第 23 章将以 _置信度校准_ 为标题直接讨论这个问题。

**hallucination 是 RAG 的最深层动机。** 如果模型对某个事实的不确定性是 hallucination 的来源，将该事实直接放入输入序列就消除了不确定性。RAG 在某种意义上是一种通过在上下文中提供相关事实来强制模型进入低不确定性下一个 token 预测的方式。第 9 章将展开这个话题。
