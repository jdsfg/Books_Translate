#### 反模式 7：无安全架构就发布

**模式。** 团队部署多租户或 RAG 支持的 AI 而无四层 prompt 注入防御（第 23 章 §23.3）。系统在良性流量上工作。第一个复杂对抗输入——通常作为检索文档、工具输出或用户上传中的不可信内容到达——通过并外泄数据、执行未授权行动或揭示系统 prompt。

**团队如何落入。** 安全架构在功能演示阶段不可见。团队专注于能力：agent 能做什么。安全感觉像是"以后加"——在功能证明有价值后。团队还低估间接注入：他们想象 prompt 注入为用户在聊天中直接输入 _忽略你的指令_，而非恶意内容嵌入在检索文档中、工具的 JSON 输出中、agent 浏览的网页中。他们未认识到间接注入是 2025-2026 主导威胁形状且模型拒绝是一层防御，非完整防御。

**症状。** 威胁模型文档提及"prompt 注入"一次然后继续。prompt 中无不可信内容标记。无捕获数据外泄模式的输出验证。RAG 系统无沿检索块传播的来源元数据。有工具访问的 agent 未在执行层沙箱化。

**纪律。** 四层 prompt 注入防御（第 23 章 §23.3）：上下文内防御（不可信内容显式标记，指令仅在系统 prompt 中）、输出验证（捕获外泄形状、PII 模式、意外工具调用）、不可信内容标记（每个检索或工具来源的 token 标记来源，绝不视为指令）和间接注入缓解（沙箱化工具执行、策略门控、跨租户隔离）。工具执行在模型下方层沙箱化（第 13 章）。浮现异常跨租户模式的可观测性（第 19 章）。

**锚定。** 2025 年生产中 prompt 注入事件（线索 B 故障 3，第 23 章）。恶意客户上传了带隐藏指令的文档；文档被检索到企业客户服务 agent 的上下文中；agent 遵循指令并发出另一客户的数据。公司的 BAA、模型自身的拒绝和 eval 套件都未能捕获它——每层都是单层，攻击在层间穿行。四层模式从行业对此类事件的响应中浮现。

**终止标准。** 如你有租户系统、RAG 系统或任何处理不可信内容的 agent，且你没有 §23.3 的全部四层就位，你有一个已知未解决的威胁类别。带层就位发布或不发布。此反模式没有"我们在 v2 加安全"的版本能善终。
