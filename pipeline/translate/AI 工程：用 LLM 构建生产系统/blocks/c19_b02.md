### 18.2 Anthropic Prompt 缓存：稳定内容 90% 折扣

Anthropic 的 prompt 缓存（2024 年引入；2026 年成熟）是 2026 年的主导缓存机制。定价：

* **缓存写入**：标准输入费率的 1.25 倍。包含缓存块的第一次调用支付略多（以填充缓存）。
* **缓存读取**：标准输入费率的 0.1 倍。包含相同缓存块的后续调用支付少 90%。
* **TTL**：默认 5 分钟；1 小时缓存以基础输入费率的 2 倍可用（vs 5 分钟 TTL 的 1.25 倍）。当缓存前缀在长窗口间稳定时使用 1 小时 TTL（例如多轮 agent 会话、批量作业热缓存）。

盈亏平衡计算：

对 1500 token 缓存前缀按 Sonnet 4 定价（3 美元/100 万输入）：

* 未缓存：1500 × 3 美元/100 万 = 0.0045 美元/调用
* 缓存写入：1500 × 3.75 美元/100 万 = 0.0056 美元（首次调用）
* 缓存读取：1500 × 0.30 美元/100 万 = 0.00045 美元（后续调用）

盈亏平衡：多少次调用后节省超过写入溢价？

* 写入溢价：0.0056 美元 - 0.0045 美元 = 0.0011 美元
* 每次缓存读取节省：0.0045 美元 - 0.00045 美元 = 0.00405 美元
* 盈亏平衡：0.0011 美元 / 0.00405 美元 ≈ 0.28 — 写入溢价在大约一次后续读取的 28% 后回收（即一次写入 + 约 0.28 次读取 = 净零；一次写入 + 一次或多次读取已净正）。

写入溢价在不到一次后续调用中回本。实践中：任何在 5 分钟 TTL 内至少读取一次的缓存前缀都是净正。阈值如此低以至于应对任何稳定内容启用缓存。

应缓存什么：

* **系统 prompt**。始终稳定；始终缓存。
* **工具定义**。每个 agent 版本稳定；始终缓存。
* **频繁访问的检索 RAG 上下文**。如热门查询的 top-K 片段在 TTL 窗口内跨多次用户调用相同，缓存它们。
* **Few-shot 示例**。稳定；缓存。

不应缓存什么：

* **用户当前消息**。每调用动态；缓存增加写入溢价无收益。
* **每轮增长的对话历史**。大部分动态；特定旧轮可缓存但工程复杂度常超过节省。
