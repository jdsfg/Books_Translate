1. _企业折扣_：大客户谈判获得标价 20-50% 折扣。盈亏平衡量上升（托管比你以为的更便宜；自托管需更大量才能胜出）。
2. _预留吞吐定价_：一些提供商以固定月费提供专用容量；有效每 token 成本取决于利用率。高利用率下，预留层可比标价低 30-60%。盈亏平衡交叉点进一步上升。
3. _促销价格层_：新的托管开放权重提供商可能低于成本定价以获取客户。这是现在真实的现金节约但短暂的；当促销结束，成本回归。基于促销价格构建经济论证的团队六个月后面临意外账单增加。
4. _Token 定价套利_：输入 vs 输出 token 价格因提供商而异；团队的工作负载混合改变哪个提供商最便宜。以长上下文输入和短输出为主的工作负载看到的盈亏平衡与以输出生成为主的工作负载不同。

如何避免被暂时价格误导：

1. _同时用标价对标价和折扣对折扣场景构建盈亏平衡模型_。交叉点在场景间可能移动 2-3 倍。
2. _验证你今天支付的价格在合同上对接下来 12-24 个月持久_。如合同是按月或促销绑定，将价格视为可能上升；用促销后预期价格而非当前价格构建盈亏平衡。
3. _在架构中构建可选择性_。使用路由器（第 17 章）使价格变化不需要重新架构。提供商可移植性的成本主要是抽象掉提供商特定行为的工程工作；一旦完成，团队可随价格变化移动工作负载。
4. _将自托管保留为战略选项，非常规成本策略_。自托管在特定条件下决定性胜出（非常高持续量；特定监管要求；特定定制需求）。对其他一切，竞争价格下的托管在工程成本基础上胜出。

这连接到第 17 章的路由纪律：支持提供商可移植性的架构是在价格层变化中无需重新平台化就能存活的架构。没有基于路由器的抽象，团队受制于其现有提供商选择的定价模型。
