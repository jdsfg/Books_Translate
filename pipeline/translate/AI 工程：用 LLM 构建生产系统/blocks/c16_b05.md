### 15.4 2026 年现实：生产 agent 比演示更简单

多 agent 演示在 2025–2026 年很丰富。"看六个 agent 协作构建创业公司！""agent 团队规划、编码、测试、部署、监控！"演示很吸引人。

2026 年生产现实更清醒。三个观察：

**观察 1：复杂多 agent 演示很少成为可靠生产**。演示运行有效；生产运行累积演示光鲜掩盖的失败（第 14 章的目录）。采用演示式多 agent 架构的团队常发现其生产系统比替换的更简单单 agent 替代方案更不可靠。

**观察 2：编排器-工作器是生产甜区**。大多数成功的生产多 agent 系统是扁平编排器-工作器，2-5 个工作器，有良好边界，有清晰交接。层次和辩论模式出现在生产中但频率低得多。

**观察 3：单 agent + 好工具目录对许多任务与多 agent 竞争力相当**。单 agent 配工程良好的工具目录（第 13 章 §13.7）可处理在演示式框架中看似需要多个 agent 的复杂任务。决策应基于 eval，非架构优雅。

对 Helios 具体：75% 工单由单 agent 循环处理；20% 由编排器-工作器（当编排器分类识别分解价值时）；5% 升级到人工。单 agent 份额有意更大。团队测量：单 agent 处理受益于多 agent 的工单显示边际更低质量但显著更低成本和延迟；多 agent 处理不受益的工单显示更差质量（过度分解引入错误）。分配是 eval 驱动的，非架构信念驱动的。

多 agent 和计算机使用共享一个工程压力，证明在同一章覆盖合理。两者都扩展 agent 可尝试什么（多 agent 通过组合专业能力，计算机使用通过让 agent 接触无 API 的系统），且都添加新失败面（协调失败、UI 误点击失败）而不移除旧的。第 14 章的有界设计纪律以更强形式适用。下一节转向计算机使用作为 2025–2026 最有后果的能力扩展，然后 §15.6–15.7 走过 Helios 跨两轴的生产姿态。

### 15.5 计算机使用前沿

2024 年末，Anthropic 发布 **Computer Use**，允许 Claude 看屏幕、点击、输入并像人类一样操作计算机的能力。OpenAI 在 2025 年初跟随发布 **Operator**。浏览器使用 agent 激增。

前沿扩展了 agent 能做什么：不再需要 agent 交互的每个系统都有 API，agent 可操作任何有 UI 的系统。承诺：在用户真实桌面环境中工作的 agent，完成跨多应用的任务，处理"你在电脑上做的事"的长尾。

现实：它有效，有时，带显著失败率和显著安全考量。
