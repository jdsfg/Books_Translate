### 20.4 轮次结束检测：关键问题

轮次结束（EOT）检测是系统识别用户已说完且 agent 应响应的时刻。弄错了：

* **太激进**（小 EOT 超时）：agent 在用户句子中间打断。用户正在思考中；agent 插入；用户重复自己；对话崩溃。
* **太慢**（大 EOT 超时）：agent 等太久才响应。对话感觉生硬；用户怀疑 agent 是否听到了；一些用户挂断。

技巧：

* 语音模型通常通过静音持续时间阈值、韵律线索（用户声音渐弱、音高下降）和语义线索（句子似乎完整）的组合检测 EOT。
* 端到端语音模型原生做此；STT+LLM+TTS 流水线需要显式 EOT 逻辑。
* 正确阈值因领域而异：技术支持（用户停顿思考）容忍更长 EOT；随意对话容忍更短。

Helios 2026 年 EOT 工程：按客户调优（一些企业客户有特定偏好）；典型设置 350ms 静音阈值；通过语音模型做韵律线索调整。

### 20.5 打断处理

语音对话包含打断：用户在 agent 还在说话时开始说话。agent 必须：

1. **检测打断**：用户的声音现在在 agent 输出之上活跃。
2. **停止说话**：agent 当前语音生成立即停止。
3. **处理用户打断**：用户说了什么？对 agent 行为意味着什么？

处理：

* _停止合成_：简单。需要时在词中间切断 TTS 输出。
* _重新规划_：更难。agent 之前在回答一个问题；用户的打断可能是澄清、重定向或新问题。agent 的下一个响应应反映打断，而非继续之前的思路。
* _确认_：可选。一些 agent 设计包含对打断的显式确认（"抱歉，我明白了——你想了解……"）；其他则自然地响应新输入。

端到端语音模型原生处理打断（音频输入/输出统一；模型可关注打断事件）。STT-LLM-TTS 流水线需要显式打断事件处理：通常通过流式音频接口，应用可中断 TTS 流。
