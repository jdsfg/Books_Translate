### 12.1 OCR 替代故事

二十年来，文档理解意味着 Tesseract、ABBYY、AWS Textract、Google Cloud Vision：一个光学字符识别（OCR）管道将扫描或拍照文档转为文本字符串，加一个下游层在文本上重新施加结构。

管道有结构性问题：

* **OCR 错误传播**。误读字符变成错误单词；错误单词改变语义内容；下游层无法恢复。
* **布局丢失**。表格变成扁平文本；多栏文档混在一起；图注与图分离。
* **非文本内容不可见**。图表、签名、图表、照片——静默丢弃。
* **文档结构恢复是独立的工程项目**。从 OCR 文本重新推断节、标题、表格需要每种文档类型的自定义解析器。

2024–2025 年，主导模式转变。VLM（前沿多模态模型）可以取页面图像作为输入并产生捕获文本、布局、表格和图表的结构化输出。转变最好这样框架：**模型现在就是 OCR**。

典型 2026 年摄取管道：


    def process_pdf_page(page_image: bytes) -> ProcessedPage:
        response = vision_model.complete(
            model="claude-sonnet-4-20260315",  # Sonnet 4 在同一模型中处理视觉；
            # 不存在单独的视觉变体
            max_tokens=4000,
            messages=[{
                "role": "user",
                "content": [
                    {"type": "image", "source": {"type": "base64", "data": page_image}},
                    {"type": "text", "text": "提取此页的结构化内容。"
                    "包括：节标题、段落、表格（markdown）、图（描述）、"
                    "签名（描述）以及任何其他可见内容。"},
                ],
            }],
            response_model=ProcessedPage,
        )
        return response


模型返回结构化表示：标题标签段落、保留表格结构的 markdown 表格、图表和签名的散文描述、布局感知分组。下游 RAG 索引此结构化输出而非原始 OCR 文本。

2026 年质量对大多数文档类型比经典 OCR 显著更好：

* **表格**提取为可往返回可识别结构的 markdown。
* **布局**保留（多栏文档保持连贯）。
* **图**用散文描述（"液压系统示意图，两个气缸通过控制阀连接"）。
* **签名**被标记（"页面右下方手写签名"）。
* **混合内容**（打字文本旁手写边注）被恢复。

2026 年成本：每页约 0.005 美元–0.02 美元（因 provider 而异；视觉 token 通常定价比文本 token 高）。索引 1000 页语料库是 5 美元–20 美元，实践中微不足道。传统 OCR 管道的每页原始 API 成本更低但工程运维通常更高（运行 Tesseract 服务器、维护解析器、处理故障模式）。

2026 年新文档 RAG 项目的默认：**视觉优先摄取**。跳过 OCR；将页面图像传给 VLM；使用 VLM 的结构化输出作为索引基础。
