#### 本书不是什么

本书不是对 LLM 能力的综述；那类内容存在于别处。它不是 AI 研究专著；研究者会觉得深度不够。它不是 prompt engineering 技巧清单；这门纪律已经超越了那个框架。它不是 LangChain 教程——LangChain 只是众多工具之一；本书是框架多元主义的。

它也不是一份静态参考。特定的工具、特定的价格、特定的命名模型会过时。本书在最容易过时的章节中带有明确的"截至 2026 年"侧栏。2027 年第二版将刷新这些部分；而持久性的纪律（eval 驱动开发、bounded 设计、安全架构）需要的修订会更少。

#### 本书的核心承诺

如果你只能从本书中带走一件事，那就是：**eval 就是规范；成本/延迟/质量是一个没有免费午餐的三角；每种模式都有故障模式；AI 工程是工程，不是炼金术。**

每一章在某种意义上都是对这四个论断的展开。读完本书的读者应该能够在职业生涯中为每一个架构选择回答四个正交问题：

1. 模式是什么？
2. eval 是什么样的？
3. 它在生产环境中如何失败？
4. 成本是多少？

每次都问这四个问题的纪律，正是本书存在并要植入的东西。如果你读完本书后这些问题感觉是自然的——如果你发现自己对团队提出的新功能自动提出这些问题——这本书就成功了。

现在去构建点什么。纪律是有效的；领域是开放的；实践属于你。

#### 本书使用的约定

**模型标识符。** 全书的代码示例固定到带日期的模型版本，如 `claude-sonnet-4-20260315`、`claude-haiku-4-20250630` 和 `gpt-4o-realtime-preview-2025`。这些是_说明性占位符_，代表生产代码应使用的那种带日期版本固定方式。这些确切的日期字符串并非真实的 Anthropic / OpenAI 公开快照 ID；在运行代码之前，请从你的 provider 的 API 文档中替换为当前带日期的版本。固定纪律是真实且推荐的；具体的日期字符串则不是。

**定价。** 书中引用的 2026 年价格（Sonnet 4 为 3 美元/百万输入 token，15 美元/百万输出等）截至 2026 年年中是准确的，但 provider 每季度调整定价。在做盈亏平衡计算前请核实。

**贯穿角色。** Aiyana Carter（Beacon Health AI）、Strata Research 团队和 Helios Customer AI 的工程师是基于真实情况构建的复合角色，用于教学。公司、姓名和事件是虚构的；工程决策和 trade-off 不是。
