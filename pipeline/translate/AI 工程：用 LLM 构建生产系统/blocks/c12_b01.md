### 11.1 重排序器，深入

第 9 章将重排序器作为第四个杠杆介绍。本章看重排序器实际如何工作以及如何工程化好它们。

重排序器是 **交叉编码器**：它将查询和候选块一起取，通过模型的注意力机制联合关注两者，输出相关性分数。这比双编码器嵌入架构（查询和块分别嵌入并通过余弦比较）更准确，因为交叉编码器可以直接建模查询-块交互。

权衡：交叉编码器每查询-块对慢得多（通常 50–200ms vs 余弦比较 <1ms）。你无法在整个语料库上运行它；你只在向量搜索的 top-K 上运行。

2026 年重排序器格局：

* **Cohere Rerank 3**：成熟的商业选项。跨领域强性能；API 定价。偏好 SaaS 团队的默认。
* **BGE-Reranker-v2**：强开放权重重排序器。自托管；在通用基准上与 Cohere Rerank 质量竞争；美元免费但计算成本是你的。
* **Voyage rerank-2**：Voyage 的重排序器；与其嵌入模型自然配对。
* **领域特定重排序器**：专用重排序器（医学、法律）涌现；用于相关性信号不同于通用语义相似性的领域。

重排序器调优：

* **向量搜索的 top-K**：通常 20–50。更大 K 给重排序器更多选择；更小 K 限制重排序器从差向量检索中恢复。
* **重排序后的 top-N**：通常 3–10。更小 N 更锐利但风险丢失相关块；更大 N 更安全但膨胀 LLM 上下文。
* **分数阈值**：低于相关性分数（Cohere 的 0–1 标度上通常 0.5）的块被丢弃。空结果集处理是单独关注。

实用工程注意：重排序器倾向 **可批处理**。如果你有 20 个候选，你可以在一次 API 调用（或一次 GPU 批处理）中评分而非 20 次顺序调用。Cohere 和 Voyage API 都暴露批处理重排序端点；使用它们。
