**Q5.** _为单提供商锁定场景设计回退_。你的公司全 Anthropic 已 18 个月。产品依赖 Claude Sonnet 4。董事会指令（在最近一次提供商侧宕机导致业务 4 小时停机后）是"添加回退提供商；我们不能有另一次单提供商宕机。"约束：应用的 prompt 专门为 Sonnet 调优；你有 200 案例 eval；团队有 3 工程师周上线。设计回退。指定：(a) 提供商选择；(b) prompt 可移植策略；(c) 质量门控策略；(d) 验证前流量拆分计划；(e) 你向董事会承诺什么。

提示

现实的答案 _不是_ "上线与 Sonnet 质量等价的跨提供商回退"。而是诚实接受故障转移窗口期间降级但可用的服务，加上确切了解降级程度的工程工作。

**答案：**

(a) **提供商选择**：GPT-4o 或 Gemini 2.5 Pro。基于哪个对你的任务类与 Sonnet 行为特征最接近选择（这需要小型前置 eval；选质量差距较小的）。现实地，GPT-4o 对大多数知识工作任务是最接近的类似物；Gemini 2.5 Pro 在长上下文上有竞争力。

(b) **prompt 可移植策略**：

* 用现有 prompt 不变对回退运行。记录每任务类的 eval delta（Sonnet vs 回退）。
* 对 delta 大的任务类，编写回退特定 prompt 变体。变体更短、对输出格式更明确、已测试。作为 `fallback_prompt.md` 与主 prompt 并存。
* 今后每任务类维护两个 prompt。主 prompt 更新包含回退 prompt 更新；这是 prompt 变更纪律的一部分。

(c) **质量门控策略**：

* 回退必须在每任务类的 eval 上达到 Sonnet 的 10% 以内。如某任务类不满足此门控，不路由到回退；而是返回优雅错误（"服务暂时不可用，请几分钟后重试"）。一些类不会有可行回退；这是诚实的。
* 每月重新运行门控 eval。模型变化；门控可能偏移。

(d) **流量拆分计划**：

* 阶段 1（第 1 周）：影子流量。5% 生产调用同时发到两个提供商；结果离线比较；eval 评分。无客户影响；仅数据。
* 阶段 2（第 2 周）：金丝雀回退。1% 生产调用实际路由到回退。对这些 eval 评分。客户体验监控。
* 阶段 3（第 3 周）：激活回退路径。回退配置为仅在主模型失败时触发；正常流量仍在 Sonnet。合成宕机测试验证回退实际触发且 eval 成立。向董事会汇报。

(e) **对董事会的承诺**：
