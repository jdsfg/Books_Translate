#### 应用题

**Q1.** _为新功能设计 golden set_。Beacon Health AI 正在添加新功能：一个内部分诊助手，根据简短临床摘要为传入的患者转诊建议紧急程度（立即/紧急/常规）。为 eval 设计 golden set。指定：(a) 目标规模；(b) 分层轴；(c) 标注协议；(d) 标注者间一致性目标；(e) golden set 应何时对照生产进行代表性审查。

提示

按临床上有意义的维度分层：输入临床状况、紧急程度梯队、边缘案例。标注协议应指定谁标注以及如何解决不一致。

**答案：**

(a) **目标规模：300 个案例**，规模设定为在合理标注成本下给出有意义的每层信号。小于 200 使每层切片不可靠；大于 500 使标注成本对起始迭代过高。300 是最佳点。

(b) **分层轴**：

* _紧急程度梯队_：100 个立即、120 个紧急、80 个常规（对更高风险梯队过采样，因为那里的错误后果更大）。
* _临床状况类别_：粗略覆盖心脏、神经、呼吸、心理健康、肿瘤、创伤和 _其他_ 的桶，每个类别以大致与预期生产流量成比例的量出现。
* _输入质量_：70% 格式良好的临床摘要，30% 嘈杂或部分摘要（现实转诊通常不完整；eval 必须覆盖这个）。
* _对抗性案例_：30 个手工设计的测试边缘条件的案例（例如，一个同时提及常规慢性病和急性新症状的摘要：紧急程度应反映急性症状，而非慢性基线）。

(c) **标注协议**：

* 每个案例由两位独立临床医生标注（一位 MD，一位经验丰富的护士执业者）。
* 标签是分类的（立即/紧急/常规）加上可选的 _不确定_ 标记。
* 不一致通过校准会议解决：两位标注者和一位高级临床医生讨论案例，就标签达成一致，并为任何他们没见过的模式更新标注说明。
* 标注说明版本化；v1 是起始说明；后续版本跟踪细化。

(d) **标注者间一致性目标：κ ≥ 0.7**（三向紧急程度标签的加权 kappa，因为立即 vs 紧急比立即 vs 常规更近）。可接受下限 0.6，要求不一致案例被显式审查并要么调和要么标记为固有模糊（可能从 eval 中排除）。

(e) **代表性审查节奏：每季度**，AI 运维工程师将 golden set 案例分布与生产分布比较。如果生产分布漂移（新临床状况类别变得突出；新转诊来源改变输入质量），golden set 更新以跟踪。不跟踪生产漂移是 eval 无法预测生产失败的最常见原因。
