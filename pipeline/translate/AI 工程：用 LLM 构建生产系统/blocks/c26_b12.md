5. **事件累积**。eval 中的漂移；对演进攻击的老化防御；错过的优化机会：这些缓慢累积。到团队注意时，恢复需大投资。

缓解是文化的：持续学习实践融入团队运营。会议、内部技术讨论组、显式探索时间、为成长招聘。纪律不仅是 _团队今天做什么_ 而是 _团队承诺学习什么_。后者决定长期竞争位置。

**Q5.** 论证 §25.1 的七个反模式并非等可能困扰任何给定团队。识别团队阶段、市场背景和工程文化如何偏移哪个反模式对特定团队是最高风险。

**答案：** 反模式共享不良工程的结构，但根据团队条件不同地表现。团队的 _最可能_ 反模式很少是他们最担心的；相反，倾向于其文化奖励的那个。

阶段驱动风险：

1. _最早阶段（产品前）_：无 eval 的直觉编码是主导风险。速度重要；eval 感觉像开销；团队快速发布并累积质量债务。当创始人是非工程师且奖励可见功能发布而非不可见 eval 工作时风险放大。
2. _成长阶段（产品后，扩展用户）_：忽视成本维度是主导风险。账单上升快于团队成本纪律；意外账单触发打断功能工作的反应性优化。当财务不在工程审查循环中时放大。
3. _成熟阶段（稳定运营，客户扩展）_：无安全架构就发布是主导风险。团队现有架构对原始用例工作；新用例（受监管行业；企业客户；多租户）暴露原始架构未预期的安全缺口。当团队将 _我们未出过事件_ 解释为架构安全的证据时放大。

市场驱动风险：

4. _受监管市场（医疗、金融、法律）_：信任未验证的 LLM-as-judge 危险因为团队的 eval 成为合规声明的基础。未校准的 judge 产生无法在审计中存活的合规证据。
5. _快速迭代的消费市场_：用框架过度工程是主导风险。团队伸手重量级框架以感觉专业；框架减慢迭代；更轻工具的竞争对手发布更快。
6. _企业 B2B_：工作流足够时构建 agent。企业客户点名要 _agent_；团队构建多 agent 系统以满足请求；系统脆弱而工作流本会更好服务。客户满意度短暂；维护成本长久。

文化驱动风险：

7. _奖励发布的文化_：直觉编码（反模式 1）被强化。晋升给发布最多的工程师；质量工作不可见；团队的已发布 vs 已 eval 功能比不利偏移。
8. _奖励新颖的文化_：工作流足够时构建 agent（反模式 6）被强化。工程师想工作于令人印象深刻的多 agent 系统；无聊的工作流无人配备。
