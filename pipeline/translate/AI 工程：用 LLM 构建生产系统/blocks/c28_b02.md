#### 模式 2：带回退的多模型路由

**解决什么问题。** 单提供商的停机使 AI 功能宕机；或 60% 流量可在更便宜模型上运行无质量损失而 40% 确实需要前沿模型。路由器分类请求并在 5xx、429 或过度延迟时回退。

**拓扑。** 在 LLM 调用前，路由阶段在 AI 服务内运行。第一版本基于规则（用户层级的正则、请求类型、prompt 长度阈值）；需要更多的团队升级到小分类器——微调的 7B 甚至 prompt 特征上的逻辑回归——发出 tier-1、tier-2、tier-3 之一。Tier-1 路由到前沿模型（Claude Opus、GPT-5 或等价物）；tier-2 到中层模型（Sonnet、GPT-4-class）；tier-3 到便宜模型或团队 GPU 池上的自托管开放权重模型。每层有主提供商和指定回退提供商；断路器（60 秒滑动窗口上的失败率阈值）自动切换流量。LiteLLM 是 2026 年默认提供提供商抽象和回退接线的工具；有强偏好的团队在原始 HTTP API 上写自己的薄 SDK。

**何时用。** 成本压力真实（月度 LLM 支出达薪资规模，财务在问）。或单提供商停机会是客户可见事件。或你在运行 A/B 模型实验且想要一个地方编码路由。

**何时不用。** 一个 AI 功能，单提供商停机可接受，发布更快胜过构建路由器。路由器是非平凡的运维面——每次模型升级现在意味着重新调阈值。
