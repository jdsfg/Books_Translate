1. **情景记忆可更新**：它反映世界的 _当前_ 状态，非不可变历史。旧声明保留（带时间戳）用于审计；agent 的工作模型使用最新的。
2. **长期记忆保守**：单次矛盾不更新长期信念；矛盾的模式才更新。agent 有稳定的先验；异常值不立即覆盖它们。
3. **重新调用纪律**：每次多日工作流调用开始时，显式加载相关情景记忆；不假设 agent 先前轮次的上下文仍在工作记忆中（不在；已过数天）。

教训泛化：生产多日工作流 agent 需要单轨迹 agent 不需要的深思熟虑的记忆架构。框架（LangGraph、AutoGen）提供原语；应用团队设计 schema。跳过此设计的团队发布的 agent 在会话间"遗忘"、与自己先前的建议矛盾或无法随时间学习。

交叉引用：

* 第 11 章 RAG：情景和长期记忆可实现为对话历史的 RAG；分块和检索纪律适用。
* 第 13 章工具使用：记忆更新是工具调用（`record_lead_response`、`update_student_mastery`）；工具目录包含记忆管理工具与任务工具并列。
* 第 19 章可观测性：多日工作流 agent 需要跨会话的追踪，而非仅单轨迹；追踪关联键是工作流标识符（lead_id、project_id、student_id）。

2026 年教训：多日工作流仍是新兴用例；模式正在结晶。现在构建这些 agent 的团队正在做将成为 2028 年教科书模式的工程工作。这里的结构（三层、保守长期、可更新情景、显式重新调用加载）是合理的起始框架。
