* **调试保真度损失在此比医疗更昂贵**。移民法调试常需要理解特定国家、状态和案件时间线；激进脱敏使追踪对工程调查几乎无用。权衡：在静态追踪存储中脱敏，但提供审计的"为调查取消脱敏"路径，有文档化理由的工程师可访问特定轨迹的未脱敏追踪。取消脱敏操作本身被记录。
* **假阴性在此是灾难性的**。泄露的客户姓名 + 国家 + 状态组合在某些情况下可能危及客户（来自敌对政府国家的庇护寻求者）。脱敏模式应偏向过度脱敏；假阳性成本（更少有用的追踪）可接受；假阴性成本（真实 PII 泄漏）不可接受。
* **"PHI"术语不适用**。使用 _PII 和案件敏感数据_；记录领域特定类别。§19.7 的框架迁移（类别 + 模式 + 脱敏标签 + 审计），但法律上下文是律师-客户特权而非 HIPAA，有自己的保留和披露规则。让事务所的合规团队参与定义类别和模式。

(d) **审计频率**：

* **每周**：自动化 PII 扫描器扫描近期追踪（搜索未脱敏模式的独立进程；任何匹配告警）。这是假阴性检测器。
* **每月**：合规意识工程师手动审查 20 条追踪的随机样本。检查未捕获的 PII；建议模式改进。
* **每季度**：与事务所合规团队全面重新评估类别和模式。添加新模式（如某国发布新模式首次编写时不存在的 ID 格式）。
* **事件触发**：任何报告的 PII 事件触发立即审查脱敏规则；记录根因；更新模式。

框架的迁移：§19.7 的 _结构_（类别 + 模式 + 标签 + 审计）直接迁移。_内容_ 是领域特定的。将 §19.7 读为"实现 PHI 脱敏"的团队错过了泛化；教训是"为你的特定数据类型实现敏感数据脱敏"。医疗示例是更广纪律的一个实例。

更深的观察：任何有敏感数据的领域（法律、金融、政府、医疗、教育）需要此纪律。模式和类别各异；框架不变。这些领域的生产 AI 系统要么有此纪律要么有等待被报告的未检测泄漏。

**AI 协作子问题**：你会如何请 LLM 帮助完成这个练习，你会在它的回答中验证什么？

**答案：** 有用的 prompt：_将 PHI 脱敏框架适配到移民法敏感数据：类别、模式、权衡、审计频率。_ 你验证 (a) LLM 正确识别领域特定类别（LLM 可能默认"姓名、地址、SSN"而遗漏移民特定的 A 号码/收据号码模式；对照你事务所处理的实际文档类型验证），以及 (b) 权衡讨论承认此领域的假阴性成本可以是生命安全，不仅是合规（LLM 可能将所有脱敏权衡视为类似；移民/庇护上下文更严重）。
