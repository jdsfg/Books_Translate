设计文档是一页。在发布前审查。它是团队对安全属性的显式承诺。文档在 agent 演化时更新；审计轨迹在版本控制中。此模式可移植到任何生产 agent。

### 14.7 线程 B 失败 5 和 6：52K 美元事件和 2026 多 agent 递归的教训

本章锚定的两个失败：

**失败 5（2024 年末复合）：52K 美元隔夜 agent**。从章节开头回顾。教训：

* 无迭代上限。agent 运行直到速率限制。
* 无成本断路器。团队对问题的第一个信号是账单。
* 无轨迹长度告警。agent 可运行 14 小时而无操作员知晓。
* 工具目录允许无界范围：agent 可调用任何工具，用任何参数，无每轨迹限制。

缓解措施（§14.4 的全部四界 + 第 19 章的可观测性）合计花费几个工程师日实现且将完全防止事件。事件后，公司采用它们作为所有 agent 部署的标准。纪律通过 2025 年在行业中传播。

**失败 6（2026 复合）：多 agent 递归成本超支**。团队构建了多 agent 系统：一个 _规划器_ agent 将任务分解为子任务；_工作器_ agent 执行子任务。规划器的界被强制；工作器的界被单独强制。未被强制的是：跨系统的 _组合_ 成本。每个工作器在其个体预算内，但规划器生成 8 个工作器，然后在第一批结果不满意时再 8 个，然后再 8 个。总成本在单一轨迹中超过 30K 美元。系统技术上在每个 agent 的界内运行；_系统级_ 界缺失。

教训：

* 多 agent 系统需要 _系统级_ 预算，附加于每 agent 预算。规划器的界必须包含生成工作器的成本，而非仅自身推理成本。
* 递归生成是乘法器。每代 agent 乘以成本；无代数上限或系统级界，成本几何增长。
* 可观测性需系统感知。追踪必须显示系统中所有 agent，而非一次一个。

第 15 章显式构建多 agent 协调；那里的成本纪律模式由失败 6 塑造。

#### 常见误解

反射性担忧——_界降低 agent 能力_——不经受生产数据的接触。设计良好的有界 agent 在界允许的任务上与无界 agent 同样能干：界允许有意义的轨迹并防止无意义的轨迹。心智模型：界是定义 agent 可尝试什么的工程包络；在包络内，agent 完全运行。无界 agent 尝试一切（包括不应尝试的事），带灾难性尾部。有界 agent 尝试适当的；失败是优雅的。
