#### 模式 2：辩论

两个或更多 agent 争论不同立场；它们的分歧暴露单 agent 可能遗漏的问题。适用于盲点重要的高风险决策。

    [问题]
         ↓
    [Agent A: 论证选项 X] ←→ [Agent B: 论证选项 Y]
         ↓                              ↓
    [裁判 agent 或人工决定]


适用情况：想要显式考虑替代方案的判断调用；承诺前的决策审查；eval 的 eval 场景。

不适用：答案明显的常规任务；辩论的 2 倍成本不证明罕见洞察增益合理的高量使用。

Helios 不在生产 agent 流中使用辩论；他们在内部评估新 prompt 时使用类辩论模式（"批评 agent"审查"候选 agent"的轨迹）。

#### 模式 3：层次分解

多级分解：编排器 → 中级协调器 → 工作器。适用于分解本身有结构的非常复杂任务。

层次分解比扁平编排器-工作器更重；额外层增加复杂性、可观测性负担和有界工程工作。2026 年教训：**扁平编排器-工作器处理大多数情况；仅当你能说清扁平为何不行时才用层次**。
