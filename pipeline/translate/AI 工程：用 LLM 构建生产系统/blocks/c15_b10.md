### 14.10 How This Breaks：_以为_自己有界的 agent

**命名的故障模式**：_以为_自己有界的 agent。团队给 agent 添加界。实现有一个微妙 bug：摘要发生时累积 token 计数器重置。触发摘要阈值的 agent 然后有 _无限_ 有效预算：计数器不再反映总支出。界在位但不再强制。

**真实或复合事件**：来自多个生产部署的复合。模式是：_界在设计中存在但在实现中损坏_。团队未注意到因为常规轨迹不触发损坏路径；只有边缘情况（触发摘要的长轨迹）揭示缺失的强制。

**工程缓解措施**：**测试界，而非仅快乐路径**。eval 套件必须包含 _试图逃逸界_ 的轨迹：长轨迹、重复工具调用、触发多次迭代的模糊推理。验证界正确触发：agent 在迭代上限停止；成本计数器在摘要中正确维护；断路器触发。

第二个缓解：**生产中周期性合成压力测试**。启动设计来压力测试界的 agent 轨迹；验证它们干净停止。捕获代码变更导致的界回归。

**本应捕获它的 eval**：agent 设计文档 eval 套件（§14.6）中的 _对抗性轨迹 eval 切片_。设计来测试界的轨迹（长会话、重复调用、模糊目标）；eval 验证界正确启动。如 eval 在 agent 代码库每次变更时运行，界回归在 PR 时捕获，而非在生产中。
