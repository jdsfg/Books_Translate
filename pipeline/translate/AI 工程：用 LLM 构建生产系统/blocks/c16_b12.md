#### 概念检查

**Q1.** 何时多 agent 有帮助何时有害？各给两个场景。

**答案：**

**有帮助**：

1. 多问题客户支持工单（退货 + 地址更新 + 计费问题）。专业工作器处理每个问题；编排器聚合。单 agent 要么过度泛化（失去质量）要么有不可管理的 prompt。
2. 研究综合任务：一个 agent 从网络检索；另一个从内部文档；另一个从数据库。并行检索节省墙上时钟时间；专业检索 prompt 提高召回率。

**有害**：

1. 单问题工单（仅查订单）。生成多 agent 系统增加协调开销无并行收益；延迟和成本上升无质量提升。
2. 迭代调试任务每步依赖前一步输出。天然串行；多 agent 不并行化；agent 间通信增加延迟。

通用模式：多 agent 在子任务独立且专业时出色；多 agent 在子任务依赖或简单时失败。承诺前先 eval。

**Q2.** 比较三种协调模式（编排器-工作器、辩论、层次）。对每种，识别一个适配的生产场景。

**答案：**

* **编排器-工作器**：Helios 的多问题客户支持工单。编排器分类；工作器并行执行专业子任务；编排器聚合。适配因为子任务（退款、地址、计费）天然独立。
* **辩论**：高风险判断任务——内容审核系统两个 agent 争论是否移除一条内容。分歧暴露边缘情况。适配因为答案不明显；多视角增值。生产部署比编排器-工作器窄（2 倍成本溢价；仅在判断边际重要时使用）。
* **层次分解**：复杂编码助手任务涉及多级规划（高层架构 → 文件级设计 → 函数级实现）。每级进一步分解。生产部署罕见；通常扁平编排器-工作器配聪明编排器做同样工作无额外层。

2026 年教训：编排器-工作器是日常工具；辩论和层次是特定价值主张的专用模式。

**Q3.** 比较四个命名框架（LangGraph、AutoGen、Pydantic AI、MCP）。对 2026 年新成立的 5 人公司，推荐起始选择。

**答案：**

**LangGraph**：基于图；成熟；LangChain 生态系统。适合已在 LangChain 中或想要可视化工作流工具的团队。

**AutoGen**：多 agent 对话框架。适合研究；生产成熟度在改善。

**Pydantic AI**：轻量、类型安全 Python。适合 Python 类型化代码库和想要最少魔法的团队。

**Anthropic MCP**：非框架；工具集成协议。补充任何框架。

**对 2026 年新 5 人公司的推荐**：**Pydantic AI + MCP 做工具集成**。
