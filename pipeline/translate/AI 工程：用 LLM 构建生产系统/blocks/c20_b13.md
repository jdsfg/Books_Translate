**答案：** 结构性主张：语音轨迹仍是轨迹（随时间的 LLM 调用和工具分发序列，带结果）。§19.2 引入的追踪 schema 正确捕获它；语音不需要根本不同的可观测性范式。它需要的是 _每个调用和轨迹级的额外维度_。

三个语音特定维度：

1. **每轮延迟分解**。语音轨迹比文本有更多延迟阶段：语音转文本、LLM 推理、文本转语音、音频播放。每个阶段贡献于用户感知的总量。追踪 schema 扩展每轮带 `stt_ms`、`llm_ms`、`tts_ms`、`playback_start_ms` 字段。§19.2 的每 LLM 调用 schema 变为带这些分解延迟字段的每轮 schema。
2. **轮次结束检测事件**。语音系统关于用户何时说完的决定本身是判断（由 VAD 或 LLM 驱动的检测器做出）；像任何判断，它应被记录带检测的结束时间、置信度、以及（发生打断时）覆盖原因。追踪 schema 扩展带 `eot_detected_ms`、`eot_confidence`、`interruption_occurred`。这些是轮次边界的事件，捕获在同一追踪中作为 LLM 调用。
3. **模态切换事件**。当语音回退到文本（按第 20 章的回退到文本纪律），追踪记录回退触发、切换点的状态、以及面向用户的消息。schema 扩展带 `modality`（语音/文本/混合）、`fallback_trigger`（如有）、`state_preserved`（布尔）。轨迹可跨两种模态；追踪记录转换。

这些扩展如何适配 §19.2 格式：每个是字段添加，非结构变更。追踪仍是 span 的轨迹；每个 span 仍带类型（LLM 调用、工具调用、或现在的轮次边界事件）；轨迹仍有结果和 eval 分数集成。语音可观测性栈是扩展了 schema 的 §19.2 栈；仪表板、告警和调试工具全部泛化。

章节级教训：可观测性是纪律先于工具栈。纪律（捕获每个相关事件；结构化以查询；与 eval 集成）跨模态不变。schema 扩展以捕获新维度；栈吸收扩展无需重新发明。为语音和文本构建独立可观测性栈的团队在重新发明轮子；扩展 schema 的团队以额外字段的成本获得语音可观测性。

一个 2026 年及以后的预测：随着模态增多（语音、视觉、计算机使用、多 agent），追踪 schema 继续扩展。追踪保持可观测性单元；捕获的维度增长。这与 §19.7 的 PHI 扩展和 §19.8 的告警纪律一致；每个是同一底层追踪结构上的额外维度。
