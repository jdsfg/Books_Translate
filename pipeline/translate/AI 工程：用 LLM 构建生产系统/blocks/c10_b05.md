### 9.5 RAG 检索评估如何不同于 LLM 评估

一个微妙但重要的点。标准 LLM 评估（第 4 章）测量回答质量。RAG 有两层，你需要评估两者。

**检索评估**测量：检索是否找到了相关内容？标准指标：

* **Recall@K**：对查询的真正相关块，多少在 top-K 检索中？
* **Precision@K**：在 top-K 检索块中，多少是真正相关的？
* **MRR（平均倒数排名）**：第一个相关块排名位置倒数的平均值。
* **NDCG（归一化折损累积增益）**：按排名位置加权，对将相关块排名更高给予信用。

这些是组件级 eval。它们需要 _标注相关性_——对 golden set 中的每个查询，语料库中哪些块相关？这生产成本高（人类或仔细的 LLM 作为评判者需要标注）。

**回答评估**测量：给定检索，答案是否正确？标准指标：

* **忠实度**：答案是否遵循检索到的块（无幻觉）？
* **回答相关性**：答案是否针对问题？
* **引用接地**：答案是否正确引用检索到的块？

这些是端到端 eval。它们需要回答质量量表或 LLM 作为评判者。

生产 RAG 系统需要两层。仅检索 eval 可以显示 90% recall@10 而端到端质量差（模型未能使用检索到的内容）。仅端到端 eval 不告诉你该修检索还是修 LLM。第 11 章构建多轴 RAG eval 量表（绑定工作流 #5）。
