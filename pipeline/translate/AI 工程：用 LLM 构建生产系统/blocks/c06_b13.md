### 章节小结

2026 年 eval 工具景观有五个主要参与者——`pytest-evals`（pytest 原生，OSS）、`inspect-ai`（安全 eval，OSS）、`ragas`（RAG 专家，OSS）、`braintrust`（SaaS）和 `langsmith`（SaaS，LangChain 绑定）——加上从零构建的选项。自建在数据敏感性排除 SaaS、技术栈不寻常或规模摊销时正确；否则购买或在 OSS 上构建。大多数团队安定于混合：CI 中用 OSS，跨团队可见性用 SaaS。

Beacon Health AI 的合成 PHI eval 构建管道是 eval 基础设施遇到监管现实的案例研究：真实 PHI 输入被转换为结构等价的合成 PHI 输出，在 CI 和 SaaS 可观测性中使用是 HIPAA 安全的。替换方法比朴素去标识化更可辩护。

SQLite 支持的 eval 存储是一个小而强大的组件：两张表、几个索引、每个 eval 结果永久保存、通过 SQL 进行回归分析。每 prompt 版本的 golden set 保持回归比较同类对同类。

本章的绑定工作流 #1 是一个真实的 GitHub Actions 配置，用每维度下限在 eval 回归时门禁 PR，发布比较评论，并上传结果作为制品。成本约每个 eval 相关 PR 3 美元；价值是 _无回归不经审查发布_ 的纪律。

eval 套件是活制品。它增长；案例被退休；套件每季度重新平衡。不健康的替代是持续膨胀的案例袋，变得太慢无法运行并被静默放弃。

这里的一切将第 4 章的纪律操作化。基础设施在第 6 章立即产生回报，prompt 迭代成为 eval 套件第一个指向的东西，并延续到第 19 章的生产可观测性和第 21 章的模型升级工作流。
