**Q3.** _审核任务的辩论模式设计_。§15.3 辩论模式被提及为高风险判断的专用工具。为内容审核设计具体辩论模式系统：一条用户生成内容被上游分类器标记为边界；两个 LLM agent 辩论是否移除；裁判 agent 决定。指定：(a) 两个辩论 agent 的 prompt 及什么使它们真正对抗（而非同一 agent 的两个副本）；(b) 结构化交换协议；(c) 裁判 agent 的角色；(d) 停止条件；(e) 两个辩论者同意错误答案的故障模式及系统如何捕获。

**讨论：**

辩论模式仅在辩论者 _真正_ 对抗时有效。两个相同 agent 会收敛；辩论的价值来自暴露边缘情况的结构化分歧。

(a) **辩论 agent 的 prompt（真正对抗）**：

**辩论者 A**（移除倡导者）：


    你是内容政策倡导者。你的工作是为移除
    被标记内容辩护。考虑：
    - 平台的内容政策（附在下面）。
    - 保留内容对用户的潜在伤害。
    - 先前移除的先例。
    你必须为移除做出最强论证。避免含糊。承认
    反论但解释为何移除仍胜。
    [政策文档附上]


**辩论者 B**（保留倡导者）：


    你是言论自由倡导者。你的工作是为保留
    被标记内容辩护。考虑：
    - 平台的内容政策及其界限。
    - 言论和表达原则。
    - 过度移除的风险（假阳性、用户信任伤害）。
    - 先前保留决定的先例。
    你必须为保留做出最强论证。避免含糊。
    承认反论但解释为何保留仍胜。
    [政策文档附上]


什么使它们真正对抗：每个 agent 被 _分配_ 一个立场；agent 被指示为该立场辩护。这是辩论和共识之间的结构差异。系统设计者确保两个 prompt 在能力上 _对称_（相同政策参考、相同先例可用）但在职责上 _相反_（一个论证移除、一个论证保留）。

常见失败：不对称地编写 prompt（例如移除倡导者比保留倡导者有更多信息）。不对称偏倚结果；裁判看似决定但实际偏倚预定了结果。对称性是承重的。

(b) **结构化交换协议**：

第 1 轮：每个辩论者独立产生开场陈述（3-5 段）。它们不看对方的陈述。
第 2 轮：每个辩论者看到对方的开场陈述并产生反驳（2-3 段）。反驳针对对方最强论证。
第 3 轮（可选，用于最高风险案例）：每个辩论者产生结案陈述（1-2 段）强调其最强论点。

协议是结构化的（非自由聊天）以防止失控轮次并使追踪可审查。
