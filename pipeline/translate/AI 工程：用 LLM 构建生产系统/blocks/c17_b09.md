#### 概念检查

**Q1.** 命名参考架构的 9 层并识别每层包装和暴露什么。

**答案：**

1. **模型提供商**：包装物理推理计算；暴露每调用 API 接口（聊天补全、嵌入等）。
2. **路由器 / 网关**：包装多个模型提供商；暴露带策略的统一接口（成本感知路由、回退、每租户预算）。
3. **编排**：包装模型接口；暴露 agent 循环、多步工作流、工具分发。
4. **Eval 平台**：包装被测系统；暴露对 golden 集的评分运行、回归检测、CI 集成。
5. **可观测性**：包装每层的运行时事件；暴露追踪、日志、指标用于调试和监控。
6. **成本追踪**：包装可观测性数据；暴露成本仪表板、预算告警、按维度成本归因。
7. **特性开关**：包装环境和版本路由；暴露按环境、按租户、按金丝雀的用哪个 prompt/model/agent 的配置。
8. **安全 / 护栏**：在应用边界包装输入和输出；暴露验证、PII 脱敏、prompt 注入防御、输出安全。
9. **应用层**：包装以上全部；暴露面向用户的功能。

层次是概念性的：每层构建在下面的层之上；每层添加上面层可以假设的纪律。

**Q2.** 为什么本章论证低层偏好购买而高层偏好构建？阐述成本经济和产品价值推理。

**答案：** 两个原因：

1. **成本经济**。低层（模型提供商、路由器）已商品化。内部构建竞争性路由器的工程成本是 4-8 工程师月；SaaS 或 OSS 替代以美元计成本几美元。比率不对；购买。
2. **产品价值**。低层是基础设施；不差异化产品。自定义路由器不让客户更满意（他们看不到）。高层（应用、安全）是产品价值所在；构建让你按产品需求专业化。在差异化的地方投资构建有回报；在基础设施投资构建没有。

补充原因：**维护成本**。构建的基础设施必须永远维护；购买的基础设施维护外包。低层有更通用的模式（每个团队需要路由）和高维护负担；高层有专业化模式（你产品的确切安全需求）且维护与产品演化绑定。

通用原则：**在差异化的地方构建；在不差异化的地方购买**。9 层架构将此原则映射到 AI 工程栈。

**Q3.** 为什么本章称 _AI 工程巨石_ 为反模式？识别巨石阻止的三个具体能力。

**答案：** 巨石混合层：prompt 管理、模型调用、eval、日志、成本追踪、业务逻辑全在一个模块。它阻止：

1. **多提供商路由**。没有分离的路由器层，从一个提供商切换到另一个或实现回退需编辑巨石。痛苦；很少做；团队因惯性留在单一提供商，非因为最优。
