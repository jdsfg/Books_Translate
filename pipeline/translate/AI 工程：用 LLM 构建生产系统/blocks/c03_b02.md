#### 定义：Token

token 是 LLM 的输入和输出单位。它和词不是同一个东西。它和字符不是同一个东西。它是 tokenizer 产生的单位，tokenizer 是一个与模型一起训练的独立软件，其工作是将文本切分为来自固定词表（通常 32K 到 256K 条目）的整数序列。

用大白话说，这意味着：当你向模型发送字符串 "Hello, world!" 时，tokenizer 首先将其变成类似 `[15496, 11, 1917, 0]` 的东西，四个整数分别代表 _Hello_、_,_、_world_ 和 _!_，尽管具体切分取决于 tokenizer。模型从不看到文本。它看到整数序列。每个计费表、每个上下文窗口限制、每个延迟测量都以 token 计量，而非字符或词。2026 年英文文本的一个有用经验法则是：一个 token 约等于 0.75 个词或四个字符；对于代码，更接近每 3 个字符一个 token；对于中文、日文和韩文，通常每 1-2 个字符一个 token。（tokenizer 因 provider 而异；我们将在 §2.6 中看到这很重要。）

这就是为什么 LLM 无法可靠地数 _strawberry_ 中字母 r 的数量：模型从未看到字母。它看到的是 _strawberry_ 的 token（通常是一个单一 token），本质上被要求对它以问题所暗示的形式无法访问的数据做计算。这不是 bug；这是位于文本和模型之间的 tokenization 层的后果。

### 2.2 工程师层面的预训练

函数 `model(token_sequence) -> next_token_distribution` 不是凭空来的。它是一个叫做 _预训练_ 的过程的结果，这是 LLM 创建中花费数千万美元、在数千个 GPU 上运行数月的部分。

以下是工程师层面的预训练做什么。取一个庞大的文本语料库：数万亿 token，从网络、书籍、代码仓库、科学论文、转录中抓取。对于语料库中的每个位置，遮住下一个 token 并要求模型从前面的上下文预测它。当模型错误时惩罚它；将模型的数十亿参数微调到本可以让它不那么错误的方向。重复数万亿次。

就是这样。模型被训练为人类书写文本的经验分布上的一个非常、非常好的下一个 token 预测器。模型似乎 _知道_ 的一切（语言结构、世界事实、编程语言、数学推理、haiku 是什么样子的）都编码在参数中，因为预测好下一个 token _需要_ 一个能捕获所有这些东西的表示。为了预测一个关于法国大革命的句子的下一个词，模型必须编码一些功能上像法国大革命的表示的东西。为了预测一个有语法错误的 Python 文件的下一个字符，模型必须编码一些功能上像对 Python 语法的理解的东西。这些表示不是标注的；它们从预测任务中涌现。这是 GPT 系列的深刻洞见，也是整个现代领域的基础。
