### 10.9 How This Breaks：在你脚下漂移的嵌入

**命名的故障模式**：在你脚下漂移的嵌入。团队使用基于 API 的嵌入模型（OpenAI、Cohere、Voyage）。Provider 发布嵌入模型的更新版本。Provider 的 API 静默将新请求路由到更新版本。团队现有索引（用旧版本构建）现在有与新版本查询向量不对齐的向量。检索质量静默退化。

**真实或复合事件**：来自行业的复合。多个团队经历了 OpenAI 的嵌入版本更新（text-embedding-ada-002 → text-embedding-3 是经典示例），教训是 _嵌入模型版本化是真实关注_。

**工程缓解措施**：

1. **在 API 调用中显式固定嵌入模型版本。** 大多数 provider 暴露带日期的版本；在生产代码中使用它们。
2. **迁移到新模型版本时重新嵌入语料库。** 在同一索引中混合不同模型版本的向量产生不可预测检索。重新嵌入完成时原子切换到新索引。
3. **每次模型版本变更时做嵌入版本 eval。** 对旧和新嵌入版本运行 eval；在切换前理解质量增量。
4. **监控生产检索质量**（第 19 章）：如果 recall@10 下降超过阈值，告警。

**本应捕获它的 eval**：_检索版本回归 eval_，按节奏（至少每周）对生产索引运行。漂移检测在客户注意到前捕获问题。完整缓解需要生产 eval 纪律（第 21 章）。
