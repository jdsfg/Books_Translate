#### 应用题

**Q1.** _为真实功能预算上下文窗口_。Helios 客服 agent 收到客户查询。团队当前加载：系统 prompt（1500 token）、工具定义（1200 token）、客户完整账户历史（15K token）、最近 3 个支持工单（4K token）、检索到的知识库块（5K token）、当前消息（200 token）、输出预算（1500 token）。Agent 的上下文预算是 64K token。剩余预算未使用。指出三个具体上下文工程手段将 token 使用减少 30%，并预测每个的节省。

提示

§8.4 有手段。具体应用。

**答案：** 当前总输入：1500+1200+15000+4000+5000+200 = 26,900 token。输出预算 1500 → 总预算消耗约 28.4K / 64K。30% 减少目标：削减约 8.5K token。

三个手段：

1. **用即时工具加载替换完整账户历史**：节省约 10K–13K token。Agent 不需要预加载 15K token 的账户历史；它可以在需要时通过 `get_customer_field(field)` 工具获取特定字段。大多数查询不需要完整历史；平均调用的账户历史足迹降到约 2K token（实际获取的字段）。这一手段单独实现 30% 目标的大部分。
2. **通过重排序 + top-5 压缩检索到的知识库块**：节省约 2K token。当前 5K token 的检索块可能包含一些边际内容。用重排序器（Cohere Rerank 或 BGE-Reranker）选 top 5 块而非 top 10；块更锐利且预算更小。质量通常提高（更少噪声）同时成本下降。
3. **摘要较早支持工单**：节省约 2K token。4K token 的"最近 3 个支持工单"可以摘要为 2K token，保留解决上下文而不需完整来回。每夜批量摘要保持摘要新鲜；主推理调用看到紧凑版本。

合计：12K + 2K + 2K = 16K token 节省，远超 30% 减少。每次调用成本节省：按 3 美元/1M 输入 × 16K 节省 token = 0.048 美元/调用。按每月 1000 万工单，那是 **每月 48 万美元成本节省**。实现工程工作（总共可能 2 工程师周）几天内回本。
