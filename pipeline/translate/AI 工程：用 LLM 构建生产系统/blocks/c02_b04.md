#### 技能层级

2026 年 AI 工程工作的形态大致如下：

1. **基础**：你能用高级语言编写生产软件。你能用 API 思维。你能调试分布式系统。你会使用数据库。你能读懂 stack trace。你能交付代码。这是底线；没有它其他一切都无法运作。
2. **LLM 素养**：你在工程师层面知道 LLM 是什么（第 2 章）。你能读懂 model card。你知道哪些 sampling 参数做什么。你知道 hallucination 在架构上为什么发生，而不只是道听途说。
3. **模式**：你知道生产模式。RAG、agent、结构化输出、工具调用、prompt 版本管理。你能命名它们，你能识别何时该用哪个，你知道每种模式如何失败。
4. **纪律**：你做 eval。你做成本预算。你做 instrumentation。你运行模型升级流程。你在思考能力之前先思考故障模式。
5. **判断力**：你能回答_我们到底该不该用 AI 来构建这个？_ 这个问题。你能诚实地回答。当答案是_不_的时候，你能说_不_。这是工作中最难的部分，也是第 24 章所构建的目标。

大多数进入 AI 工程的工程师已经具备了基础。其余四项就是本书的内容。

### 1.3 四种角色，以及你是哪一种

在 _AI 工程师_ 这个大类下，该领域已分化为四种角色。它们有重叠。一个人做多种角色。但区分很重要，因为日常工作是不同的。

**AI 工程师（产品侧）**：你在产品上下文中编写调用 LLM 的代码。你嵌入在产品团队中。你交付功能。你关心用户体验、关心每活跃用户成本、关心那个说_这个功能对这类用户有效_的 eval。你是阅读本书的大多数人。

**ML 平台工程师**：你构建其他 AI 工程师使用的平台。你运营 eval 基础设施。你运行 prompt 注册表。你搭建 router。你构建成本仪表盘。你管理与 LLM provider 的 BAA。你们比产品侧工程师少，但工作跨团队复合。

**AI 产品工程师**：一位对 AI 工程足够精通、能够实际可构建功能做规格说明的产品经理。这个头衔有时与 _AI PM_ 重叠。这个角色存在是因为概率系统打破了经典的 PM 到工程师的交接：一份说_模型应该正确地总结这个_的功能规格不是规格，而是愿望。所以需要有人把它翻译成 eval，而这个人越来越多地同时具备产品直觉和工程能力。

**AI 运维**：你在生产环境中运营 AI 系统。drift 检测。模型升级流程。事件响应。为那个一小时花了 4000 美元的 agent 值班轮换。你是凌晨 3 点读 trace 的那个人。大多数 AI 运维工程师来自 SRE 背景，在上面叠加了 LLM 专属层。

如果你在读这本书并且还不知道自己是哪一种，那很正常。大多数人在前两年会在角色之间滑动。这些角色还没有像 _后端工程师_ 和 _前端工程师_ 那样稳定，因为这个领域比 Web 年轻六到八年。它们会稳定下来的。现在，学习所有四种形态，选择你日常工作所要求的那一种。
