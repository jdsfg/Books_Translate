#### 故障模式 3：丢失目标

agent 忘记被要求做什么。对话漂移；agent 开始追求侧面话题；原始用户查询不再是活跃目标。常见于上下文增长且原始指令成为众多之一的多轮 agent。

原因：

* 上下文窗口压力；原始指令被推出注意力。
* agent 推理纠缠于从属问题。
* 记忆架构未在后续 prompt 中浮现原始目标。

缓解：记忆架构中的显式目标跟踪；每轮重新注入目标；在阈值间隔的"我们还在任务上吗？"反思 prompt。

#### 故障模式 4：上下文溢出

agent 累积状态（历史、工具输出、检索内容）超过上下文窗口。轨迹中途，API 调用失败或静默截断。agent 丢失上下文；行为退化；有时 agent 甚至不知道它丢失了上下文。

原因：

* agent 不摘要的长工具输出。
* 单一轨迹中多次工具调用累积。
* 随轨迹进展不修剪的检索内容。

缓解：轨迹内摘要（随轨迹继续压缩旧轮次和工具输出）；工具结果的激进输出截断（第 13 章）；上下文预算监控（第 8 章）。

#### 故障模式 5：成本超支

agent 烧穿预算而不产生价值。有时通过无限循环（上面）；有时通过 _确实_ 进展但成本巨大的慢轨迹。52,000 美元事件（失败 5）是此类别。

原因：

* 轨迹长度随任务复杂性缩放，而复杂任务未提前识别。
* 工具调用有可变成本（一些检索大内容；一些运行昂贵计算）；agent 不预算。
* 无成本感知决策；agent 视计算为免费。

缓解：成本断路器（每轨迹成本上限）；每工具成本感知；阈值告警；最终，轨迹中预算再平衡。

五个故障模式非独立。螺旋的 agent（无限循环）也是成本超支。上下文溢出的 agent 常丢失目标。缓解叠加：有界设计同时解决多个故障模式。
