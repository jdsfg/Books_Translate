> **截至 2026 年。** 本书所有内容中，agent 框架部分过时最快。正文中视为活跃的四个框架（LangGraph、AutoGen、Pydantic AI、Anthropic MCP）很可能在十八个月内变为不同的四个；CrewAI 和 OpenAI Swarm 出于同样原因放在附录 B 中。关注架构模式（编排器和工作器、辩论、层次分解）；这些比当前实现它们的任何框架都长寿。

第 14 章构建了单 agent 设计。本章扩展到多 agent：多个基于 LLM 的 agent 协调以完成任务的系统。它还涵盖 **计算机使用前沿**（agent 像人类一样操作计算机——点击、输入、浏览），这是 2025–2026 年最扩展 agent 能力的技术，伴随匹配的故障模式。

本章核心教训是双重的：

1. **大多数生产"代理式"系统比演示视频暗示的更简单。** 多 agent 架构是有真实复杂性成本的工程投资；它们对某些问题是正确答案，对许多其他问题是错误的。
2. **计算机使用真实且有用，但在重要方面不可靠。** 2026 年的现实是"用于正确的任务，带正确的保障，并接受失败率。"大多数生产部署在有真正 API 时仍偏好真正 API；计算机使用是最后手段工具。

Helios Customer AI 贯穿本章；其多 agent 分解对复杂工单使用编排器和工作器模式，对常规工单使用单 agent 循环。第 1 章的偏转率 KPI（自主解决的工单比例）处于权衡中心：更强能力的 agent → 更高偏转率，更强能力的 agent → 更高复杂性和更多失败面。
