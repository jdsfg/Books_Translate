### 2.10 Triangle Trade-off 侧栏：单次 API 调用的成本分解

§2.1–§2.9 的心智模型留下一个需要量化的问题：当你调用模型时，你实际在为什么付费？成本形态本身就是心智模型的一个属性——成本以 _token_ 计量，与模型推理的单位相同，定价中的输入/输出不对称有一个根植于模型生成方式的机制性原因（每个输出 token 需要一次完整的前向传递，每个输入 token 不需要）。本侧栏使这个联系具体化；第 3 章在 API 层将其操作化；第 18 章将其变成成本工程纪律。让我们从成本角度追踪一次 Sonnet 4 调用。

2026 年一次典型的 Sonnet 4 chat API 调用有以下成本组件，全部以 token 计量：

* **System prompt**：通常 300–1500 token。按每百万输入 token 3 美元计算，这是每次调用 0.0009 美元到 0.0045 美元。_在 5 分钟 TTL 窗口内首次调用后缓存（第 18 章）；缓存读取率为每百万 token 0.30 美元，即每次调用约 0.0001 美元到 0.0005 美元。_
* **用户消息和对话历史**：高度可变。新对话只有用户消息（可能 50–500 token，0.00015 美元到 0.0015 美元）。20 轮对话可能累积 5K–20K token（输入 0.015 美元到 0.06 美元）。
* **检索到的 RAG 上下文（如适用）**：每次检索增加 1K–10K token。按每百万输入 3 美元计算，这是每次调用 0.003 美元到 0.03 美元。
* **工具定义（如适用）**：200–1500 token。与 system prompt 相同的每 token 成本；以相同方式缓存。
* **模型响应（输出）**：聊天通常 100–2000 token；代码生成或文档合成可能更长。按每百万输出 token 15 美元计算，这是每次调用 0.0015 美元到 0.03 美元。_注意输出与输入成本 5 倍的比例：这在 2026 年大多数 provider 定价中都是成立的，这意味着每当你能在不损害质量的情况下结构化任务以减少输出长度时，你就省了真金白银。_

将这些汇总到一个代表性生产场景：Helios 的一个客户支持 agent 做一次带工具的增强响应，有 1500 token 的 system prompt（已缓存）、500 token 的近期对话历史、2K token 的检索知识库上下文、800 token 的工具定义（已缓存）和 600 token 的模型响应。成本分解：

* System prompt（缓存读取）：1500 × 0.30 美元 / 1M = **0.00045 美元**
* 对话历史（新输入）：500 × 3.00 美元 / 1M = **0.0015 美元**
* 检索上下文（新输入）：2000 × 3.00 美元 / 1M = **0.006 美元**
* 工具定义（缓存读取）：800 × 0.30 美元 / 1M = **0.00024 美元**
* 输出：600 × 15.00 美元 / 1M = **0.009 美元**
* **每次调用总计：约 0.017 美元（向上取整到 0.02 美元以留出方差和更长输出的余量）**
