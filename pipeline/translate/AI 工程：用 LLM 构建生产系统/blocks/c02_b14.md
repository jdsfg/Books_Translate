1. **参与度是一个嘈杂且多因的代理指标**。参与度可能因为功能好而上升，因为功能新颖而上升，因为用户没意识到答案是错的而上升，或者因为功能让用户困惑从而花更多时间搞清楚它说了什么而上升。没有一个衡量 _好的标准是什么_ 的 eval，你无法分辨是哪个因素在驱动参与度数字，你可能交付一个伤害用户的功能，同时在 A/B 测试中看起来像成功。
2. **灾难性故障检测在 A/B 测试节奏下太慢**。如果功能有一个单独罕见但全局严重的故障尾部（诽谤性输出、泄露 PII、错误的法律建议），A/B 测试无法及时检测到它们。你会在新闻文章中读到它们。Air Canada 案就是经典例子：故障足够罕见，流量级指标没有捕获到它；需要一个法庭来浮出水面。

PM 实际上正确的情况：当功能确实是新颖且定性的（例如一个创意写作助手，没有可辩护的 golden answer），且当坏输出的故障成本低且可逆（用户恼怒然后重试，没有金钱或安全风险）。第 4 章的边际递减小节明确划出了这个范围。PM 在受监管行业、金融流程、客户约束性声明以及任何单个坏输出有独立后果的地方是错的。他们并非在所有地方都错。

**Q5.** §1.7 将成本-延迟-质量三角称为"铁律"。为什么 _铁律_ 在这里是可辩护的词，而不是 _指南_ 或 _启发式_？指出三角要不再是铁律需要什么条件成立，以及为什么该条件在结构上不太可能对生产 LLM 系统成立。

提示

指南可以被聪明的工程师违反；铁律不行，因为违反会在别处付出代价。问问 _别处_ 在这里意味着什么。

**答案：** _铁律_ 是可辩护的，因为三角不是一种软偏好：它是当你追踪一次 LLM 调用的物理和经济基底时发生的事情。质量，在对生产有意义的区间内，来自每 token 运行更多计算（更大的模型、更长的推理、更多的 retrieval、更多的验证）。每 token 更多计算花费更多美元和更多毫秒。你可以移动一个旋钮，但另外两个吸收成本。声称违反了三角的工程师几乎总是在某个他们没有测量的地方付出代价：他们的更低成本模型在他们没有 eval 的切片上退化质量，或者他们的更低延迟设置在丢弃对长尾有影响的 retrieval 步骤。

要使三角不再是铁律，以下两件事之一必须成立。要么 (a) 前沿模型的边际计算变得实际上免费，使得质量不再花费美元和毫秒；硬件趋势不指向那条与需求相反的曲线。要么 (b) 你实际需要的质量在远低于前沿能力处达到平台期，使得更便宜的模型就够用且 trade-off 消失；这可能发生在狭窄的产品切片上，但不会泛化到真实应用的整个面。两个条件都是局部例外，不是一般性废除。所以 _铁律_ 是正确的词：trade-off 在你做出的每一个聪明工程动作下都存活，因为它所依赖的基底是物理和经济学，不是惯例。
