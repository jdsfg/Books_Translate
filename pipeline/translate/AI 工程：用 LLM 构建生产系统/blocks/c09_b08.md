### 8.9 How This Breaks：对话中途溢出的 prompt

**命名的故障模式**：对话中途溢出的 prompt。团队构建多轮 agent。对话历史增长。在长支持会话的第 23 轮，累计历史 + 检索上下文 + 工具定义达到 200K 上下文窗口。下一次 API 调用因上下文溢出错误失败。用户在对话中途看到 agent "崩溃"。团队的回退（开始新对话）丢失上下文；用户被要求重新解释问题。

**真实或复合事件**：来自 Helios 早期 agent 部署的复合。故障率低于 1% 但集中在最长会话中（最高价值会话：复杂客户问题、多轮来回）。最可能遇到此问题的客户是最可能因此体验流失的客户。

**工程缓解措施**：三层。

1. **阈值对话摘要**。当历史超过软阈值（比如 30K token）时，触发摘要压缩较早轮次。Agent 维护滚动摘要加最近轮次逐字。
2. **上下文预算监控**。Agent 的推理调用包装预算计算：估计即将调用的 token 使用；如果超过软阈值（例如上下文窗口的 80%），急切触发压缩。
3. **优雅溢出处理**。如果尽管有上述措施仍发生溢出，响应携带结构化 _context_overflow_ 错误变体（回忆第 7 章的判别联合）；应用程序通过触发摘要并重试来处理，而非崩溃对话。

**本应捕获它的 eval**：eval 套件中的 _长会话模拟_。合成 30 轮对话压力测试上下文工程；eval 报告上下文溢出错误率和延迟 p99（随上下文增长飙升）。没有长会话 eval，团队为典型会话优化并在生产中发现故障模式。修复是在 golden set 中包含长尾会话案例；纪律是在设计 eval 时想象生产流量的尾部。
