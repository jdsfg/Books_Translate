#### 深入思考

**Q1.** _有界工程作为存活演化的纪律_。本章论证有界工程是核心 agent 纪律。随着模型能力改善这是否仍成立？论证即使 2030 年模型远更可靠，界仍至关重要。识别两个具体原因。

**讨论：** 界仍至关重要的两个原因：

1. **成本不对称是持久的**。即使 99.99% 可靠的 agent 有 0.01% 灾难性尾部率。在规模上（数百万轨迹），那是每天数百个灾难性轨迹。界将每个灾难性轨迹的损害限制到已知上限；无界时，每个灾难性轨迹无界。成本不对称论证随部署规模缩放；随着 2030 年看到更大部署，界的理由加强而非减弱。
2. **有界系统更可调试**。即使有完美推理的 agent，调试生产问题需要理解 _此特定轨迹中发生了什么_。界强制轨迹有限、可观测和可审查。运行数小时的无界 agent 产生无界数据待调查；有界 agent 的轨迹适合可审查形式。有界系统的工程人体工程学是持久的。

净结论：界将继续在生产 AI 中必需；具体界参数可能放松（2030 agent 可能常规运行 30 次迭代而 2026 agent 用 15）但架构模式持续。本章教的纪律存活能力演化。

值得提及的第三个原因：**界是更危险能力安全部署的前提**。随着 2030 年 agent 采取更有后果的行动（直接数据库写入、金融交易、真实世界设备控制），有界工程纪律变得更重要而非更少。能力前沿和安全前沿一起前进；界的纪律是安全前沿的一部分。

**Q2.** _从单 agent 到多 agent 的演化_。失败 6（§14.7）是多 agent 故障模式。随着多 agent 系统成熟（第 15 章），涌现了哪些本章单 agent 框架未覆盖的额外纪律？

**讨论：** 多 agent 系统用几个新纪律扩展单 agent 框架：

1. **系统级界 vs 每 agent 界**。上面 Q4 中讨论。§14.4 的有界工程模式不朴素组合；需要系统级计数器。
2. **跨 agent 的信任和授权**。单 agent 系统中，agent 的工具目录是授权面；策略门控处理风险工具。多 agent 系统中，agent 互相通信；一个 agent 授予另一个什么权限？生成工作器的规划器必须指定工作器被授权做什么；无此，工作器可能超出规划器意图。
3. **协调模式**。单 agent：ReAct 循环，到此为止。多 agent：编排器和工作器；辩论；层次分解；发布订阅。每种模式有自己的故障模式、调试特性和成本特征。
4. **跨 agent 可观测性**。单 agent 轨迹的追踪是一条时间线。多 agent 追踪是多条并行时间线；将它们合并为连贯视图是自身的工程项目。
