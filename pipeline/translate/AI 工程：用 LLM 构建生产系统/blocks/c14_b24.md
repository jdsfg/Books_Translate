* 风险：agent 提交恶意变更；提交消息无意中包含敏感数据。
* 缓解：git 操作在沙箱工作目录中进行；提交到 agent 拥有的功能分支，从不直接到 main；提交在合并前经过 CI 和人工审查（按第 13 章"不可逆状态变更的人工在环"）。提交消息按长度和内容规则验证。

**git_push(branch)**：中风险（带凭证的网络操作）。

* 风险：agent 无意中推送凭证；推送到错误分支覆盖工作；使用 git 凭证推送到应用不拥有的仓库。
* 缓解：git 凭证范围化到特定仓库和特定分支命名空间（例如仅 agent 前缀分支）。推送 token 不能推到 main，不能推到其他仓库。预推送钩子扫描 diff 中的凭证模式（AWS 密钥、GitHub token）并拒绝匹配。

**search_web(query)**：如范围化则低风险。

* 风险：agent 使用网络搜索检索用户不应看到的敏感内容（例如违反内容过滤）；大输出溢出上下文。
* 缓解：搜索 API 密钥有租户级速率限制；结果为安全过滤（对返回片段的内容审核 API）；输出上限 N 结果 × M 字符。

**read_jira_ticket(ticket_id)**：如范围化则低风险。

* 风险：agent 读取不应读的工单（例如 HR 工单、安全事件）。
* 缓解：Jira API 凭证范围化到仅工程项目的工单；ticket_id 对照项目前缀允许列表验证。

**通用建议**：

1. **如可能去掉 `run_shell`**；用特定操作工具替换。Shell 访问是最常见的沙箱逃逸向量。
2. **所有代码执行工具在沙箱容器中运行**：临时、资源受限、网络限制、无主机凭证。
3. **所有写工具范围化其目标**：文件系统路径通过允许列表；git 操作到 agent 拥有的分支；Jira 到特定项目。
4. **每次工具调用记录日志**：工具名称、参数（净化；无凭证）、结果、agent request_id。日志馈送可观测性（第 19 章）。
5. **结构化输出纪律**（第 7 章）：工具输入按 schema 验证；工具输出结构化供 LLM 解析；失败返回结构化错误而非原始异常。

交叉引用：此审计是 §13.5"沙箱非可选"原则的生产工程版本。每个代码执行工具需要沙箱；每个写工具需要范围化；每次工具调用需要日志。纪律可扩展：8 个工具是小目录，但审计模式适用于任何大小的目录。
