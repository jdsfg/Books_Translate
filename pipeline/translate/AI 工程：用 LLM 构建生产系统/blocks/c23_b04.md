### 22.4 自托管经济学：何时 API 调用更便宜，何时自托管胜出

自托管经济学计算是高量团队最重要的决策之一。2026 年框架：

**API 成本** =（token × 每 token 费率）。随量线性；仅付所用；零固定成本。

**自托管成本** =（计算基础设施成本 + 工程运维成本 + 摊销的模型加载成本）/ 服务量。有大量固定成本；每 token 成本随量增长而缩小。

低量时，API 胜出。高量时，自托管可胜出。交叉点取决于：

* 模型尺寸的每 GPU 小时成本（因提供商和实例类型而异）。
* 每 GPU 吞吐量（每美元每秒 token）。
* 利用率（大多数团队无法达到 100% 利用率）。
* 运维工程成本（严肃的自托管运营约 1-2 FTE）。

**已加工的盈亏平衡示例（2026 年近似）**：

对 Llama 3.1 70B 推理：

* API 选项：Together AI、Anyscale、Replicate 以约 0.80 美元/百万输入 + 0.80 美元/百万输出提供 Llama 3.1 70B。（托管 API 上的开放权重模型通常定价与 Haiku 级闭源模型相似。）
* 自托管选项：AWS p4d.24xlarge 实例约 32 美元/小时；用 vLLM 服务约 3-5K token/秒。以 5K token/秒 × 3600秒 × 约 70% 利用率 = 约 12.6M token/小时。每百万 token 服务成本：32 美元 / 12.6 = 约 2.54 美元/M（对此特定配置远高于 API）。

但：正确配置自托管（合适 GPU 实例；合适服务引擎；高利用率），每 token 成本可下降。用不同实例选择和高利用率，0.40-0.60 美元/M token 可实现。此时，自托管在持续高量下胜过 API。

**交叉启发式**（对照 §22.7 的已加工示例细化）：低于 10M token/天，托管 API 几乎总是胜出。10M 到 100M token/天之间，答案高度取决于服务引擎选择、GPU 利用率和运维成熟度：在 50M token/天典型配置下，自托管仍输（见 §22.7 选项 D）。100M+ token/天持续基础上，配合良好利用率，自托管明显胜出。约束（数据驻留、延迟下限、供应商独立）可更早翻转答案。

这些数字随硬件成本、模型尺寸和提供商定价变化；启发式是持久要点。**大多数团队不应自托管**。自托管适用于极高量的专门案例或受监管用例。
