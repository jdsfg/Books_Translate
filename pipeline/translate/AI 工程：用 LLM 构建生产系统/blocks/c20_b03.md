### 19.3 2026 年 LLM 可观测性栈

三个命名入选者主导 2026 年的对话：

**Langfuse**：开源；SaaS 托管或自托管。专为 LLM 追踪构建。强大的 UI 用于浏览追踪、跨版本比较 prompt、识别异常。与大多数 LLM 提供商和 agent 框架集成。

_适用_：2026 年的大多数团队。OSS 选项（自托管）保留数据控制；SaaS 选项最快部署。默认推荐。

**Helicone**：SaaS；定位为"代理"：你的 LLM 调用通过 Helicone 代理且追踪自动流动。强于用户级分析、重试/错误追踪、缓存分析。

_适用_：偏好基于代理集成而非基于 SDK 的团队；重视 SaaS 速度的小团队。

_注意事项_：代理增加小延迟开销；数据驻留考虑（调用经过 Helicone）。

**Phoenix（Arize）**：开源；Arize ML 可观测性套件的一部分。强于多模态追踪、RAG 特定可观测性、eval 集成。

_适用_：已有成熟 ML 基础设施使用 Arize 的团队；需要跨模态可观测性（文本 + 视觉 + 音频）的团队。

其他工具存在（LangChain 团队的 LangSmith；一些带 LLM 扩展的通用 APM 如 Datadog AI）。以上三个代表专用 LLM 可观测性核心。

2026 年新生产部署的默认选择：**Langfuse，HIPAA/受监管环境自托管；通用场景用 SaaS**。如有特定功能需求则用专门选项（Helicone 的代理模型；Phoenix 的多模态深度）。

### 19.4 什么被插桩

生产 LLM 可观测性插桩多层：

**第 1 层：LLM API 调用**。对模型提供商的每次调用。大多数可观测性工具包装提供商的 SDK；插桩是自动的。捕获 §19.2 每 LLM 调用部分的数据。

**第 2 层：工具调用**。agent 在轨迹中调用的工具。需要在你的工具执行层显式插桩：记录工具名称、参数、结果、持续时间。大多数可观测性工具有此辅助工具。

**第 3 层：轨迹**。多步 agent 运行，分组为一个追踪。要求应用识别轨迹的起止并标记其中所有调用。现代可观测性工具原生支持轨迹分组。

**第 4 层：生产中的 eval 分数**。生产 eval 采样（第 21 章）将分数附加到追踪。追踪不仅显示发生了什么还显示评分如何。

**第 5 层：业务结果**。客户的问题是否被解决？用户是否点击通过？将业务结果关联回特定追踪让你测量系统有效性，不仅是系统行为。

插桩良好的生产系统有全部五层。插桩成本适中（完整设置几个工程师周）；价值大（每个生产问题可调查；每个质量回归可归因）。
