#### 模式 1：视觉 token 成本意识

VLM API 调用按 _视觉 token_ 计费，非按页。单个页面图像通常使用 1000–2000 视觉 token（因 provider 和图像分辨率而异）。按 provider 费率（Anthropic Vision 2026 年约 3 美元/1M 视觉 token；OpenAI 类似；Google Vision 类似），这仅视觉输入约 0.003 美元–0.006 美元/页，加文本输出成本。

对于高量摄取（数百万页），这累计到数千或数万美元。三个杠杆：

* **分辨率控制**：更高分辨率 = 更多视觉 token。大多数文档任务不需要最大分辨率；降采样到保持文本可读但使用更少 token 的级别。
* **批处理**：API provider 为非时间敏感工作提供约 50% 折扣的批端点（第 18 章）。文档摄取通常非时间敏感；使用批处理。
* **页面级缓存**：如页面在文档版本间未变，跳过重新处理。

#### 模式 2：手写和降质质量处理

扫描文档包含扫描质量差的页面、褪色墨水、手写内容、边注。VLM 在这些上质量下降。工程模式：

* **置信度标记**：VLM 被要求报告其提取置信度。低置信度页面路由到人工审查或更强模型。
* **多遍提取**：模糊内容可处理两次（不同 prompt、不同模型）并比较；不一致标记低置信度。
* **来源元数据**：每个提取块携带提取质量元数据（例如 `extraction_confidence: high|medium|low`）。需要高置信度的下游查询可在此过滤。

#### 模式 3：不可处理内容的优雅失败

某些页面将不可处理：损坏扫描、加密 PDF、不支持语言的页面。管道必须处理这些而不崩溃摄取。

* **故障隔离**：200 页合同第 47 页的失败不应阻止索引第 1-46 和 48-200 页。
* **故障跟踪**：失败页面被记录；操作员可见仪表板显示失败率；定期用更强模型批量重试捕获一些。
* **用户可见标记**：如查询结果依赖来自未处理页面的内容，结果包含标记（"此合同部分未完全处理；答案可能不完整"）。

#### 常见误解

将"VLM 替代 OCR"读为通用很诱人。它们并非在所有地方替代它。对于某些用例（非常高量、格式定义良好的文档如大规模打印收据；布局稳定的结构化表格），经典 OCR 仍更便宜且足够准确。2026 年教训是：**视觉优先是通用文档理解的正确默认；经典 OCR 是已知格式高量案例的专用**。正确选择是经验性的；在你的特定语料库上 eval。
