2. **减少访问面**：即使有 BAA，供应商人员可能有对托管 PHI 的供应商系统的工程访问。自托管完全消除此访问面。
3. **风险降低**：供应商违规暴露受监管团队。自托管移除供应商违规风险（替换为内部违规风险，团队可控）。
4. **特定合同义务**：客户合同可能包含特定数据处理要求（如"无第三方 SaaS 可见此数据"）而 BAA 保护的供应商不满足。

Beacon 的姿态在此类别中。BAA 保护的 SaaS 可用；团队选择自托管以获得更深的风险降低理由。权衡是运维负担（Beacon HIPAA 基础设施上自托管 Langfuse 耗费持续工程时间）；权衡由监管姿态证明合理。

对非受监管团队：SaaS 可观测性是默认，无需 BAA；更低运维负担胜出。

**Q4.** 什么是 _追踪中的 PHI 脱敏_（§19.7），权衡是什么？

**答案：** 追踪中的 PHI 脱敏是在存储前移除或替换追踪数据中 PHI 的工程模式。姓名、出生日期、病历号、社会安全号、地址、电话号码，全部替换为结构化占位符（`[NAME]`、`[DOB]`、`[MRN]`）。

两种实现方式：

1. **基于正则**：对已知 PHI 格式的模式匹配。快速、确定性、捕获明显案例。
2. **基于 NER**（命名实体识别）：训练模型在任意位置和上下文中识别 PHI。更全面；更慢；有自身假阴性率。

生产团队通常两者分层：正则捕获明显案例（90%+）；NER 捕获长尾（其余）；定期审计验证质量。

**权衡**：

1. **工程投入**：维护脱敏层（特别是 NER）是真实工作。正则模式漂移；NER 模型随内容变化需更新。
2. **调试保真度损失**：调查问题的工程师看到 `[NAME]` 而非"Mr. Smith"。对常规问题可接受；对深入调查，团队需通过审计协议获得未脱敏访问。
3. **性能开销**：脱敏增加追踪写入延迟（通常 10-30ms）。对大多数用途可接受；对极低延迟路径可能需优化。
4. **假阳性**：激进脱敏可能捕获非 PHI（如恰好匹配 DOB 模式但实际不是 DOB 的日期）。需调优。
5. **假阴性**：脱敏可能遗漏不寻常形式的 PHI。定期审计 + NER 回退有帮助。

本章的告诫：**脱敏减少暴露但不消除监管负担**。脱敏是纵深防御的一层；HIPAA 合规基础设施仍需要。
