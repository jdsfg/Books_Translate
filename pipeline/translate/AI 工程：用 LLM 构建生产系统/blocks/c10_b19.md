* _编造率_：任何非零率都是质量关注；如每周超过 1% 则告警。
* _低置信引用率_：高率可能指示 LLM 过度引用或语料库信息碎片化；定期审查。
* _陈旧来源率_：应低；飙升指示索引管道问题。

**成本。** NLI 评分步骤（步骤 4）是主导成本；像 Haiku 的小模型约 0.0005 美元/调用，每个 RAG 响应增加约 0.003 美元（假设每个响应约 6 个引用）。对用户体验提升可接受；对高量非法律查询可削减。

**与第 6 章的联系。** 引用格式规范（`[doc_id:para_id]`）由 prompt 设定（§6.1 的 _约束输出结构_）。后处理器依赖 prompt 的合规；如果 prompt 变更，后处理器的解析必须保持兼容。这就是 prompt 和后处理器共版本的原因（见第 7 章的共版本模式）。

**AI 协作子问题**：你会如何请 LLM 帮助完成这个练习，你会在它的回答中验证什么？

**答案：** 有用的 prompt：_设计引用后处理管道将 LLM 发出的 `[doc_id:para_id]` 引用转为面向用户的引用对象带稳定 URL、片段和置信度分数。指定每步的输入、输出和失败处理。_ 你验证 (a) LLM 包含 _编造检测_ 步骤（当 LLM 引用不在检索集中的 doc_id 时；这是最重要的防御而 LLM 有时跳过它），(b) LLM 提议 _置信度评分_ 步骤而非将所有验证引用视为等同（法律科技中用户需要此信号），以及 (c) LLM 正确识别稳定 URL 必须来自文档元数据存储而非 LLM 输出（LLM 无法可靠生成有效 URL；后处理器必须计算它们）。
