* _首先_，调查不一致模式。查看评判者和人工最不一致的案例；识别不一致是否在特定量表维度、特定输入类型上，还是全面的。
* _其次_，精炼量表 prompt。通常量表 prompt 相对于给人工的标注说明不够具体；关闭这个差距通常关闭一部分一致性差距。
* _第三_，更换评判者模型（尝试 Claude Sonnet 4 而非 GPT-4o；有时不同模型在特定任务上与人工更一致）。
* _第四_，如果以上都不能关闭差距，不要对此 eval 使用 LLM 作为评判者；要么在每次运行时投入人工评分，要么将 LLM 作为评判者限制在校准扎实的维度上。

失败校准的代价小（几个工程师日）；使用未校准评判者的代价大（数月静默误导的 eval 结果）。做校准。

**AI 协作子问题**：你会如何请 LLM 帮助完成这个练习，你会在它的回答中验证什么？

**答案：** 有用的 prompt：_我有一个由 GPT-4o 评分的四轴量表 eval。设计校准协议：样本量、评分流程、一致性指标、阈值和校准失败时怎么办。_ 你验证 (a) 提议的一致性指标对序数数据是否适当（二值的 Cohen's kappa、序数的加权 kappa、连续的 Spearman；LLM 有时在 Spearman 正确时推荐 Pearson），以及 (b) 提议的阈值对你的领域是否现实（κ ≥ 0.7 对清晰量表合理；对更难的量表，≥ 0.6 是工作下限）。如果 LLM 在不承认量表难度的情况下提出阈值，反驳。

**Q3.** _设计覆盖审查_。你即将将 eval 接入 Helios Customer AI agent 的 CI。eval 有 200 个案例覆盖主要客服流程。指出你会检查的五个具体覆盖维度，并提议如何处理你发现的差距。

提示

§4.11 _How This Breaks_ 节命名了常见遗漏。应用它们，加上思考 Helios 企业 agent 环境的特定之处。

**答案：** 五个覆盖维度：

1. **语气和情感敏感性**。eval 是否包含客户不满、愤怒或压力的案例？agent 在这些输入上的响应可能在技术上回答了问题但以进一步激化客户的语气。_差距处理_：如果缺失，添加 30 个情感负载客户输入案例，带语气的量表维度（温暖、共情、降级）。
2. **拒绝和安全**。eval 是否包含对抗性 prompt 注入尝试和应触发 agent 拒绝模式的输入（例如，受限信息请求、提取内部数据的尝试、通过嵌入指令的 prompt 注入）？_差距处理_：如果缺失，从已发布 prompt 注入语料库中添加 50 个对抗性案例加上 20 个 Helios 已知攻击面特定的案例。
3. **每租户变异性**。Helios 服务 200+ 企业客户，每个有自己的语气偏好、升级政策和产品目录。eval 是否覆盖至少最大 10 个租户的特定配置？_差距处理_：如果缺失，从前 10 列表中每个租户采样 5 个代表性输入，并确保在适当时用租户特定量表评分。
