* **整数长度问题**：码字长度是整数，但 -\log p(x) 不是。当某个符号概率接近 1 时，取整损失可能很大。
* **两遍需求**：Huffman 需要知道分布；实践中这意味着或者在代表数据上训练编码器，或者对信源做两遍（一遍估计 p(x)，一遍编码）。
* **自适应 Huffman**：一种在编码时更新树的变体，消除了两遍需求，用于某些经典压缩方案。
* **分组 Huffman**：编码 n 符号块。速率差距缩小到每符号 1/n，但字母表大小指数增长。

算术编码解决了 Huffman 的整数长度问题。它不将码字分配给符号，而是将整条消息表示为单位区间 [0, 1) 中的单个数。

#### 基本思想

从区间 [0, 1) 开始。对消息中的每个符号，将当前区间按符号概率比例划分为子区间，并选择对应于实际符号的子区间。编码整条消息后，最终区间是某个范围 [a, b)。编码输出是该区间中的任意一个数，以二进制小数传输，使用尽可能少的比特。

指定宽度为 w 的区间中的一个数所需的比特数为 \lceil -\log_2 w \rceil。编码 n 个 i.i.d. 符号后，区间宽度为 \prod_i p(x_i) = p(\text{message})，因此编码使用约 -\log p(\text{message}) = \sum_i -\log p(x_i) 比特——恰好是消息的自信息。

每符号期望编码长度为

\frac{1}{n} \mathbb{E}[-\log p(X^n)] + O(1/n) = H(X) + O(1/n),

因此算术编码以 O(1/n) 的差距达到熵速率，消息可以任意长。整数长度问题消失了：差距在整个消息上摊销，而非逐符号取整。

#### 示例：编码 "ba"

设 p(a) = 0.6, p(b) = 0.4。排序：a 得到 [0, 0.6)，b 得到 [0.6, 1)。

编码 "b"：当前区间为 [0.6, 1)，宽度 0.4。细分：a 得到 [0.6, 0.84)（宽度 0.24），b 得到 [0.84, 1)（宽度 0.16）。

编码 "a"：当前区间为 [0.6, 0.84)，宽度 0.24。细分：a 得到 [0.6, 0.744)，b 得到 [0.744, 0.84)。

"ba" 后的最终区间：[0.6, 0.744)，宽度 0.144。

指定该区间中的任意数，例如 0.7 = 0.10\overline{1100} 的二进制表示（截断到足够比特）。所需比特数为 \lceil -\log 0.144 \rceil = \lceil 2.80 \rceil = 3 比特。

对于消息 "ba"：X 的熵为 H_b(0.4) \approx 0.971 比特，因此两个符号期望花费 1.94 比特。3 比特与之接近。
