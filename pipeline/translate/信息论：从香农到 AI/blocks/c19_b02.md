    import torch
    import torch.nn as nn

    class SmallTransformer(nn.Module):
        def __init__(self, vocab_size=256, embed_dim=256, n_heads=8,
                     n_layers=6, context_len=256):
            super().__init__()
            self.token_emb = nn.Embedding(vocab_size, embed_dim)
            self.pos_emb = nn.Embedding(context_len, embed_dim)
            self.layers = nn.ModuleList([
                TransformerLayer(embed_dim, n_heads) for _ in range(n_layers)
            ])
            self.ln_final = nn.LayerNorm(embed_dim)
            self.head = nn.Linear(embed_dim, vocab_size)

        def forward(self, x):
            # x: (batch, seq_len) of token ids
            b, t = x.shape
            positions = torch.arange(t, device=x.device).unsqueeze(0).expand(b, -1)
            z = self.token_emb(x) + self.pos_emb(positions)
            for layer in self.layers:
                z = layer(z)
            z = self.ln_final(z)
            logits = self.head(z)
            return logits

### 18.2 交叉熵与困惑度

训练后，我们在留出文本（语料最后 100,000 字符，训练中未见）上评估。

典型结果：

* **交叉熵**：1.4 nats 每字符 ≈ 2.0 每字符比特数。
* **困惑度**：e^{1.4} \approx 4.06 每字符（模型平均每步在 4 个有效字符中选择）。

对比：

* 随机字节：8 每字符比特数。
* gzip 在同一语料上：约 4.5 每字符比特数。
* 前沿模型在多样化英文上：约 0.7 每字符比特数。

我们的小模型达到 2.0 每字符比特数，介于 gzip 和前沿模型之间。这合理：400 万参数远少于前沿模型，但架构仍然是 Transformer。

#### 验证

根据信源编码定理（第 4 章），我们的模型在留出文本上的交叉熵等于用作算术编码器时的压缩率。让我们验证。

实现：

1. 对测试集中每个字符，计算模型的预测分布。
2. 使用算术编码在此分布下编码实际字符。
3. 累加使用的比特数。

干净实现给出的压缩大小在 n \cdot \mathcal{L} 比特的 1% 以内，其中 n 是测试长度，\mathcal{L} 是以每字符比特数为单位的交叉熵。

对于我们的模型：100,000 字符 × 2.0 比特/字符 = 200 千比特 = 25 KB。

同一测试集的实际 gzip 压缩大小：56 KB。模型达到约 2.2 倍优于 gzip 的压缩。

这是第 15 章核心恒等式的经验验证：交叉熵就是压缩率。
