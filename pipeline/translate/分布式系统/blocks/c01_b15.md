### 本章总结

分布式系统在三件事上自欺欺人。它们在时间上说谎：时钟并没有同步到代码所假设的分辨率。它们在身份上说谎：每个节点把自己看作独一无二地扮演角色，而系统其余部分可能不同意。它们在失败上说谎：部分失败是默认模式，不是例外，bug 就住在“这个节点上发生了什么”与“系统整体经历了什么”之间的缺口里。

Crescent 事件在单一重试中同时利用了三个谎言。修复涉及 fencing token（第18章）、混合逻辑时钟（第3章）和 Raft 支持的提交日志（第9章）。单一修复无法弥合这个缺口。

这本书训练的心智动作很简单：当你遇到任何分布式系统时，问三个问题。它在时间上说了什么谎？在身份上？在失败上？如果你能回答，你就能推理失败模式。如果你不能，无论你对它的 API 多么熟悉，这个系统对你都是黑箱。

接下来的第2章把这些谎言量化。你将遇到 Deutsch 的八大谬误（它们以工程假设命名这些谎言）、CAP（它量化分区下一致性与可用性之间的权衡），以及 PACELC（它把 CAP 扩展到无分区情况）。然后第3章抓住第一个谎言——时间——展开让你能够不撒谎地推理顺序的协议（Lamport 时钟、向量时钟、HLC、TrueTime）。

本书会不断回到 Adaeze。本章倒数第二段让她被重复扣款的系统，就是四位主角在第28章一起交付的系统。中间的一切是路径；第29章收尾，区分什么会继续演进，什么会持久不变。
