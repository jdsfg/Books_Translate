#### 概念检测

**Q1.** 什么是混沌工程？说出五条原则。

提示

故意注入故障。五条原则：稳态假设、真实事件、生产规模、变化、最小化爆炸半径。

**答案：** 混沌工程是故意向系统注入故障以验证系统在故障下行为正确的实践。目标是把信念转化为证据：不假设防御有效，而是证明它们有效。

五条原则（来自 “Principles of Chaos Engineering” 网站，源自 Netflix 团队）：

(a) **围绕稳态行为建立假设**。用可测量输出（SLI）定义 “系统健康”。实验若维持稳态则成功。

(b) **变化真实事件**。注入生产中真实发生的故障：节点故障、网络分区、下游变慢、区域中断、时钟偏移、磁盘满。

(c) **在生产中运行实验**。生产具有测试环境无法复制的属性（规模、流量模式、完整依赖图）。实验室测试必要但不充分。

(d) **自动化实验以持续运行**。手动 game day 有价值；Chaos Monkey 风格的持续自动混沌让系统永久被测试。

(e) **最小化爆炸半径**。从小处开始（一个节点、一个 shard）；建立信心后再扩大。初期实验不能造成客户可见损害；后期防御确认后可扩大。

这些原则是基础。具体工具（Chaos Mesh、Litmus、Gremlin）实现它们；组织实践（game day、无责复盘、记录学习）让它们落地。

**Q2.** 什么是 game day？描述其结构。

提示

赛前、当天、执行、复盘、赛后。每个阶段有具体活动。

**答案：** Game day 是一次 scheduled、故意的混沌练习。团队聚集；注入故障；观察系统反应；记录学习。

结构：

(a) **赛前（1-4 周前）**：

* 设计实验：注入什么故障；爆炸半径多大；稳态假设是什么。
* 计划回滚：如何提前结束实验。
* 确认参与者和角色。

(b) **当天准备**：

* 向参与者简报角色和回滚计划。
* 通知其他团队（客服、on-call）有练习正在进行。
* 验证监控就位。

(c) **执行实验**：

* 注入故障。
* 实时观察系统反应。
* 记录发生时观察。

(d) **恢复与复盘**：

* 结束实验（计划超时，或需要时提前回滚）。
* 团队回顾：发生了什么、学到什么、有什么意外。

(e) **赛后**：

* 提交改进行动项（修复 bug、更新 runbook、增加监控）。
* 安排下一次 game day 验证修复。
* 向更广泛工程组织传播学习。

Game day 是周期性实践，不是一次性事件。每月或每季度节奏保持团队的故障响应肌肉锻炼。

**Q3.** 为什么心理安全在混沌工程实践中很重要？

提示

没有安全，团队会隐藏问题。Game day 暴露问题；安全让团队诚实讨论。
