### 28.1 架构

平台：Crescent 面向 enterprise 客户的多 region 支付处理器。全球接受支付，端到端 p99 延迟低于 750 ms（按产品团队协商的 SLO；§28.2 会拆解完整 p50 ~360 ms / p99 ~580 ms），结算到 50+ 国家银行，并提供实时欺诈检测。

组件：

(a) **API 网关**：Cloudflare Workers 在边缘。处理 TLS、认证、速率限制。路由到最近的健康的 regional 集群。

(b) **Regional 集群**：3 个 region（US-East、EU-West、US-West）。每个 region 有完整技术栈。

(c) **Operational 存储**：CockroachDB（每 region 12 节点，共 36）。存储账户、交易、商户数据。可串行化事务。

(d) **账本**：TigerBeetle（5 副本，多 region）。记录每笔资金流动。

(e) **协调器**：Stratus DB（现为 Crescent 组件）。管理分布式事务状态；经 Raft 复制；对安全关键操作使用 fencing token。

(f) **缓存**：每 region 一个 Redis Cluster。热路径：账户余额、幂等性 key。

(g) **队列**：每 region 一个 Kafka。异步工作流（通知、下游管道）。

(h) **商户协作**：基于 Yjs 的协作文档编辑器（Yuki 的组件），用于商户入驻合同。

(i) **欺诈检测**：Continuum 风格的 LLM 推理（Tobias 的组件）。每次交易欺诈检查 sub-100-ms p99。

(j) **可观测性**：OpenTelemetry traces、Prometheus metrics、Grafana dashboards、PagerDuty alerts。

(k) **Service mesh**：Consul 跨 region 服务发现；Envoy 用于 cluster 内。

(l) **锁服务**：etcd cluster 提供分布式锁（安全关键操作使用 fencing token）。

架构分层：边缘（Cloudflare）、regional 无状态（API 服务）、regional 有状态（CockroachDB、TigerBeetle）、跨 region 异步（Kafka）、边缘缓存（Redis）。
