#### 概念检测

**Q1.** 解释预填充/解码不对称性。为什么它证明分离两个阶段合理？

提示

预填充：compute-bound，矩阵-矩阵乘法。解码：memory-bound，矩阵-向量乘法。不同最优硬件。

**答案：** 预填充处理输入提示。GPU 并行计算所有提示 token 的注意力：矩阵-矩阵乘法。瓶颈是计算（TFLOPs）。内存带宽很少是限制。

解码逐 token 生成输出。对每个 token，GPU 读取整个上下文的 KV 缓存，计算注意力（仅新 token），并采样。这是矩阵-向量乘法。瓶颈是内存带宽（加载 KV 缓存）。

不对称意味着一张 GPU 同时运行两个阶段时，对哪个阶段都没优化：

* 对预填充，GPU 内存带宽过度配置（不是限制；浪费）。
* 对解码，GPU 计算过度配置（不是限制；浪费）。

综合利用率差（典型 40-60%）。

分离：

* **预填充节点**：使用最高计算 GPU（H100、H200）。饱和计算。
* **解码节点**：使用高内存带宽和大内存 GPU（H200、B100、B200）。饱和内存带宽。

每个阶段 GPU 利用率接近 100%；集群整体利用率大幅提升。

成本是两阶段间 KV 缓存传输（通常 50-100 ms）加架构复杂度。对大集群（50+ 节点），收益超过成本；对小集群不是。2026 年采用阈值大致是集群规模 50+。

**Q2.** 什么是 KV 缓存 sharding，它解决什么问题？

提示

长上下文产生巨大 KV 缓存；跨多节点分布；缓存层抽象。

**答案：** KV 缓存 sharding 把单个请求的 KV 缓存分布到多张 GPU（可能跨多个节点）。KV 缓存被分成块（PagedAttention 风格），存储在集群级缓存层；解码节点按需读取块。

它解决的问题：超长上下文（2026 年 1M+ token）每个请求产生数十 GB KV 缓存。没有单张 GPU 内存能放下一个。不分片，最大上下文长度受限于每个GPU 内存。

实现：

(a) **Mooncake**（Moonshot AI，2024 论文）：商业实现。KV 缓存作为独立层级；解码节点通过 RDMA 读取。用于 Moonshot 的 Kimi 产品，服务 1M+ token 上下文。

(b) **LMCache**（UC Berkeley，2024）：开源等价物。为 vLLM 集成设计。提供集群级 KV 缓存，任何解码节点可读。

收益：

(a) **超长上下文可行**：每个请求 KV 缓存不受单 GPU 内存限制。

(b) **跨请求复用 KV 缓存**：共享前缀的提示（系统提示、代理 scaffold）共享缓存块。节省在多请求间摊销。

(c) **解码节点可无状态**：按需读取缓存；KV 缓存不由它们负责。这简化故障处理（解码节点故障不丢失 KV 缓存）。

成本：

(a) **网络带宽**：每 token 的 KV 缓存读取必须非常快（>100 tokens/秒需亚毫秒）。需要 RDMA + 精心预取。

(b) **缓存层作为新故障模式**：缓存必须高可用；缓存故障影响所有读取解码节点。
