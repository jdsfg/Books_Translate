#### 概念检测

**Q1.** 解释 prefill/decode 不对称性。为什么它证明分离两个阶段合理？

提示

Prefill：compute-bound，矩阵-矩阵乘法。Decode：memory-bound，矩阵-向量乘法。不同最优硬件。

**答案：** Prefill 处理输入 prompt。GPU 并行计算所有 prompt token 的 attention：矩阵-矩阵乘法。瓶颈是计算（TFLOPs）。内存带宽很少是限制。

Decode 逐 token 生成输出。对每个 token，GPU 读取整个上下文的 KV cache，计算 attention（仅新 token），并采样。这是矩阵-向量乘法。瓶颈是内存带宽（加载 KV cache）。

不对称意味着一张 GPU 同时运行两个阶段时，对哪个阶段都没优化：

* 对 prefill，GPU 内存带宽过度配置（不是限制；浪费）。
* 对 decode，GPU 计算过度配置（不是限制；浪费）。

综合利用率差（典型 40-60%）。

分离：

* **Prefill 节点**：使用最高计算 GPU（H100、H200）。饱和计算。
* **Decode 节点**：使用高内存带宽和大内存 GPU（H200、B100、B200）。饱和内存带宽。

每个阶段 GPU 利用率接近 100%；集群整体利用率大幅提升。

成本是两阶段间 KV cache 传输（通常 50-100 ms）加架构复杂度。对大集群（50+ 节点），收益超过成本；对小集群不是。2026 年采用阈值大致是集群规模 50+。

**Q2.** 什么是 KV cache sharding，它解决什么问题？

提示

长上下文产生巨大 KV cache；跨多节点分布；缓存层抽象。

**答案：** KV cache sharding 把单个请求的 KV cache 分布到多张 GPU（可能跨多个节点）。KV cache 被分成块（PagedAttention 风格），存储在集群级缓存层；decode 节点按需读取块。

它解决的问题：超长上下文（2026 年 1M+ token）每个请求产生数十 GB KV cache。没有单张 GPU 内存能放下一个。不分片，最大上下文长度受限于 per-GPU 内存。

实现：

(a) **Mooncake**（Moonshot AI，2024 论文）：商业实现。KV cache 作为独立 tier；decode 节点通过 RDMA 读取。用于 Moonshot 的 Kimi 产品，服务 1M+ token 上下文。

(b) **LMCache**（UC Berkeley，2024）：开源等价物。为 vLLM 集成设计。提供集群级 KV cache，任何 decode 节点可读。

收益：

(a) **超长上下文可行**：per-request KV cache 不受单 GPU 内存限制。

(b) **跨请求复用 KV cache**：共享前缀的 prompt（system prompt、agent scaffold）共享缓存块。节省在多请求间摊销。

(c) **Decode 节点可无状态**：按需读取 cache；KV cache 不由它们负责。这简化故障处理（decode 节点故障不丢失 KV cache）。

成本：

(a) **网络带宽**：每 token 的 KV cache 读取必须非常快（>100 tokens/sec 需亚毫秒）。需要 RDMA + 精心预取。

(b) **缓存层作为新故障模式**：缓存必须高可用；缓存故障影响所有读取 decode 节点。
