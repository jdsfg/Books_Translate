更深主张：分布式代码是 LLM 生成最糟糕的类别。不是因为 LLM 不能产出看起来像分布式代码的代码；它们能。问题是 LLM 生成分布式代码默认嵌入了第1章的谎言，而谎言对没有内化它们的人来说是不可见的。


### 27.1 六个谎言，整合版

第1章，每个分布式系统都会说的谎言：

(a) **时间**：机器时钟为事件排序。用 `time.Now()` 做排序的代码在推理一个虚构。

(b) **身份**：每个节点唯一地扮演其角色。假设 “领导者” 而不经协议强制唯一性的代码是脆弱的。

(c) **故障**：部分故障是例外。只有 happy path 和 error path 的代码把故障当作罕见；现实是部分故障是默认。

Thread C 的六个谎言，作为贯穿第1-2章的前瞻引用（冷钩子章节 2-4、18、21-22）并在此整合：

  1. **RPC 有 TCP 式语义**。假设 “请求成功” 来自 “响应到达” 的代码，遗漏了 “请求在服务端已成功但响应丢失” 的情况。

  2. **网络可靠**。Deutsch 的第一谬误。没有 timeout、retry、idempotency 的代码。

  3. **机器时钟说真话**。跨机器比较时间戳的代码。

  4. **朴素分布式锁有效**。没有 fencing token 的 Redlock。假设锁持有者唯一的代码。

  5. **部分故障罕见**。只有 happy path 的代码；不考虑 “半成功” 结果。

  6. **CAP 分类简单**。说 “我们用 CP 系统” 而不理解 PACELC、linearizability vs serializable 或 per-operation 选择的代码。

LLM 默认产出嵌入全部六个的代码。本章用实例逐一走过。
