### 24.3 SGLang 与 RadixAttention

SGLang（2023 年底由 LMSYS 发布；2025 年广泛部署）走了另一条优化路径：_RadixAttention_。vLLM 优化内存布局，SGLang 优化请求路由布局。

洞察：许多请求共享前缀结构（system prompts、chain-of-thought scaffold、function-calling 模板）。RadixAttention 按这些前缀在 radix tree 中组织 KV cache。新请求到达时，系统找到最长缓存前缀并复用；只有后缀需要重新计算。

收益：

(a) **共享前缀的巨大节省**：对具有长共享 system prompt 的工作负载（生产 LLM 应用中常见），前缀复用节省了共享部分的 prefill 成本。之前每个请求都必须 prefill 的 2000-token system prompt，现在只 prefill 一次并缓存。

(b) **结构化生成**：SGLang 原生支持结构化输出（JSON schema、regex 约束）。结构是请求规范的一部分；推理引擎知道如何处理。

(c) **函数调用**：原生支持 tool use；radix tree 跨请求缓存函数定义部分。

SGLang 在具有高前缀复用的工作负载中流行：客服机器人、结构化输出应用、agent 系统。它是 prompt 结构重复的工作负载的最佳选择。

**何时选 SGLang 而非 vLLM**：若提示 token 中显著比例跨请求共享——共同 system prompt、固定 function-calling 模板或 chain-of-thought scaffold——RadixAttention 的前缀缓存可避免重新计算这些 token。阈值大致：若平均 prompt token 中 30% 或更多来自跨请求重复固定前缀，SGLang 的缓存命中率足够高，值得切换。对每个请求都以 2000-token system prompt 开始的客服机器人，SGLang 在缓存命中时直接消除该计算，同时降低延迟和 GPU 成本。对 prompt 多样化（不同用户、不同任务、无共享前缀）的通用 API 流量，vLLM 的 PagedAttention 是更好选择——它为多样性优化内存布局，而非复用。
