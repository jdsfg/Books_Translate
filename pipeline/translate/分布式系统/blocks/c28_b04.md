### 28.2 一笔支付的旅程

追踪一笔从圣保罗 Adaeze 到拉各斯商户 Femi 的支付：

(1) Adaeze 的手机发送支付请求到 Cloudflare edge worker。Worker 验证请求（HMAC 签名；按客户计数器做速率限制检查）。5 ms。

(2) Worker 路由到 US-East 区域（Adaeze 的计算 home 区域，由 geo-DNS 决定；圣保罗到 US-East 单程约 55 ms，是 Crescent 三个区域中最近的）。60 ms 跨赤道。

(3) US-East 的 regional 负载均衡器路由到健康的 API 服务实例。实例开始支付处理。追踪上下文（OpenTelemetry W3C `traceparent`）全程传播。

(4) API 服务通过 Redis 检查幂等性键（第18章缓存模式）。若键存在，返回之前计算的结果（谎言 1 防御）。2 ms。

(5) API 服务开始 Stratus DB 事务。该事务的 coordinator 状态在 US-East 节点间经 Raft 复制（第9章）。Coordinator 获得 fencing token（第18章）。5 ms。

(6) 事务从 CockroachDB 读取 Adaeze 余额（第11/13/14章）。Adaeze 账户按地域分区到 US-East，因此读是本地；线性化（从领导者读；使用 HLC，第3章）。8 ms。

(7) 事务通过 Continuum LLM 推理检查欺诈（第24-26章）。欺诈模型在 p50 80 ms 内返回分数（sub-100-ms p99，按 Tobias 的 SLO）；分数低于阈值；支付继续。

(8) 事务写入 TigerBeetle（账本）：借记 Adaeze，贷记 Femi。TigerBeetle 的 5 副本 Viewstamped Replication 在 30 ms 内提交。

(9) 事务在 CockroachDB 中提交：更新 Adaeze 余额（US-East shard），更新 Femi 余额（EU-West shard，拉各斯商户），更新 merchant_day_rollup。跨 shard、跨区域事务，带 HLC 时间戳；为可串行化一致性做 commit-wait。95 ms（受第6章所说的最坏情况跨区域法定人数物理限制）。

(10) 事务的 coordinator（Stratus DB）用 fencing token 记录完成；银行下游 endpoint 验证 token（谎言 4 防御）。5 ms。

(11) API 服务向 Kafka 发布 “payment.completed” 事件。下游服务（通知、分析、账本对账）异步消费。5 ms。

(12) API 服务通过 Cloudflare 返回成功给 Adaeze 的手机。60 ms 跨赤道 + 5 ms 最后一公里。

总计：端到端 p50 约 360 ms。p99 约 580 ms（欺诈检测 LLM 尾部更宽，且跨区域提交跳每跳付出约 95 ms 的最坏情况 Raft 法定人数物理代价）。远低于 Crescent 产品团队为跨区域支付地理正确性协商的 750-ms p99 SLO。

Trace（第20章）捕获整个旅程。47 个跨度，分布在 6 个服务。Trace 作为取证记录保存 7 年（合规要求）。
