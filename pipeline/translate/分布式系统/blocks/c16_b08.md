#### 应用问题

**Q1.** Yuki 的 Glide 团队想添加 “实时在线状态”（显示其他用户光标）。如何用 Yjs 实现？

提示

光标位置不是持久状态；是 awareness 数据。Yjs 有独立于文档 CRDT 的 awareness 协议。

**答案：** Yjs 区分 _持久状态_（文档内容，必须在断连后保留）和 _awareness 状态_（临时信息如光标位置、在线状态、选择，只对连接中的用户有意义）。

Awareness 协议：

(a) 每个客户端将其 awareness 状态（一个 JSON 对象：光标位置、用户名、颜色、当前选择）发布到 awareness 通道。

(b) awareness 状态通过同一个 WebSocket 传播给所有连接客户端，但存储在独立的 Yjs Awareness 对象中。

(c) 客户端根据收到的 awareness 状态渲染在线状态指示。

(d) 客户端断开连接后，其 awareness 状态从其他客户端视图中移除（通常在短超时后）。

实现：


    const awareness = doc.getAwareness()

    // 光标移动时：
    awareness.setLocalStateField('cursor', { x: ..., y: ..., position: ... })

    // 渲染他人光标：
    awareness.on('change', (changes) => {
      for (const [clientId, state] of awareness.getStates()) {
        renderPresence(clientId, state)
      }
    })


awareness 状态 _不是_ 严格意义上的 CRDT（不需要跨副本合并；每个客户端的状态是权威的）。它是临时信息的独立通道。

这种分离是有意的设计：把光标位置存到文档 CRDT 会让文档因临时数据膨胀，并产生不想要的历史（每次光标移动都是一次文档编辑）。Awareness 协议是 “临时协作状态” 的正确架构。

**Q2.** 一个团队要构建协作文档表格。他们考虑��单元格值使用 CRDT。该用什么 CRDT 结构，有哪些坑？

提示

表格：cell ID 到值的映射。简单情况用 LWW-Map；同一单元格并发编辑是坑。公式更难。

**答案：** 基本结构：LWW-Map（或 OR-Map），键是 cell ID（如 “A1”、“B2”），值是单元格内容。

对简单单元格值（文本、数字），带 HLC 时间戳的 LWW-Map 可用。两个用户并发编辑 A1 时，HLC 更高的写胜出。

坑：

(a) **公式**。单元格包含 `=SUM(A1:A10)` 时依赖其他单元格。若用户添加行使 A10 变成 A11，公式必须重新解释。CRDT 能表示公式文本，但不能在没有应用逻辑的情况下解决 “公式含义是什么”。Google Sheets 在协作公式语义上投入了数十年；这不只是 CRDT 问题。

(b) **范围操作**。“排序 A 列” 或 “删除 3-5 行” 影响很多单元格。用 CRDT 表示这些操作需要 (i) 记录为单一 op 并让所有副本一致应用（op-based CRDT，注意顺序），或 (ii) 分解为单个单元格 op（丢失语义意图）。

(c) **Schema 变更**。新增列、修改单元格类型、定义命名范围。这些是 CRDT 必须支持的结构操作。
