**答案：** RDMA 把网络延迟从 ~50 微秒（kernel-bypass TCP）降到 ~1-2 微秒（RDMA over RoCE）。对总请求延迟 ~10 ms 的应用，这只省 ~0.5% 预算——不值部署 RDMA fabric 的运维复杂度。

对分布式 LLM 推理，prefill 与 decode 节点之间每次 token 都要移动 KV cache，每个 token 必须在 ~10-50 ms 内生成。一次 50 微秒网络跳占预算 5-25%；降到 2 微秒是预算内与超出的差别。高频率和紧预算让 RDMA 值得运维成本。

同样理由适用于 ML 训练（每步梯度交换）和分布式内存数据库（关键路径远程内存访问）。对延迟预算为毫秒级或更高的通用应用服务，kernel-bypass + TCP 已足够。
