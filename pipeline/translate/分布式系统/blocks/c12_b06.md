#### 概念检测

**Q1.** 区分哈希分片与范围分片。各举一个适合的工作负载。

提示

哈希分散负载但无法范围查询；范围支持扫描但顺序键有热点风险。

**答案：** 哈希分片对每个键哈希；哈希决定分区。负载均匀、路由简单、不支持范围查询。

范围分片对键排序；每个分区拥有连续范围。范围查询高效、相关键局部性好、顺序写热点风险。

哈希适合：用户会话键值存储，每个会话按 ID 访问且无范围查询。示例：Redis 集群、DynamoDB。

范围适合：时序数据库常查询“T1 到 T2 之间的所有事件”。按时间戳范围分片使该查询成为单分区扫描。示例：HBase、ClickHouse、TimescaleDB。

许多现代系统每表提供两者：CockroachDB 默认范围但支持哈希分片表；Cassandra 哈希分片但允许同一 partition 内按聚类列排序做局部范围查询。

**Q2.** 为什么一致哈希比分布式键值存储中的 “哈希 mod N” 更好？

提示

hash-mod-N 增删节点会移动大部分数据；一致哈希只移动约 1/N。

**答案：** hash-mod-N 分片中，每个键的分区由 `hash(key) mod N` 决定。若 N 变化（增删节点），几乎所有键会映射到不同分区。$N=12 \to 13$ 时，12/13 的键会换分区；几乎所有数据都要移动。

一致哈希中，键和节点放在环上；每个键由环上顺时针方向下一个节点拥有。增加节点时把它插入环；只需移动新节点与其顺时针邻居之间的键。$N=12 \to 13$ 时，约 1/13 的数据移动（新节点拥有的那段弧）。

运维含义：一致哈希下集群扩缩容可行（移动 8% 数据），hash-mod-N 不可行（移动 92% 数据）。每个现代分布式键值系统都使用某种形式的一致哈希或其衍生。

虚拟节点（vnodes）进一步完善：每个物理节点拥有多个 vnode 散布在环上。这带来更均匀负载分布，并把重平衡成本分散到多个邻居。

**Q3.** 描述 LSM-tree 的写路径。为什么它比 B+树写更快？

提示

LSM：先写 WAL（顺序），再写 memtable（内存）。B+树：读页、修改、写回（随机 I/O）。

**答案：** LSM 写路径：

  1. 写追加到磁盘 WAL（预写日志（WAL））。这是顺序写。
  2. 写插入 memtable（内存有序结构）。这很快。
  3. memtable 满时，刷盘成不可变 SSTable。
  4. 定期通过 compaction 合并多个 SSTable。

用户可见写在第 1、2 步后完成；后续 compaction 异步。

B+树写路径：

  1. 写必须更新相关叶页（磁盘上 4-16 KB）。
  2. 若页未缓存，先读（随机 I/O）。
  3. 在内存中修改页。
  4. 写回（又一次 I/O）。
  5. 若页满，页分裂，需更新父节点（可能直到根）。
