Tobias 的集群 GPU 利用率为 60%。Continuum CTO 把目标定为 80%。2026 年实现这一目标的架构变化：分离式预填充/解码（预填充/解码分离）。

这个洞察事后看很明显：预填充（处理提示）和解码（生成 token）的计算特征非常不同。预填充是 compute-bound；解码是 memory-bound。在同一张 GPU 上同时运行两者是次优默认；把它们放到针对不同阶段优化的不同 GPU 上，可解锁显著收益。

本章是工作流 12：一个 vLLM 集群加分离式预填充/解码，以及跨节点的 KV 缓存 sharding。该技术在 2023-2024 年成为经典研究（Splitwise、DistServe）；生产部署在 2025-2026 年成熟。


### 25.1 预填充/解码不对称性

对单个 LLM 推理请求：

**预填充阶段**：处理整个输入提示。对 1000-token 提示，GPU 计算所有 1000 个 token 的注意力。这是矩阵-矩阵乘法；瓶颈是 GPU 计算（TFLOPs）。内存带宽很少是限制；延迟随提示长度缩放。

**解码阶段**：逐 token 生成输出。对每个 token，GPU 读取整个上下文（提示 + 已生成 token）的 KV 缓存，计算注意力，采样下一个 token。这是矩阵-向量乘法；瓶颈是内存带宽（加载 KV 缓存）。

不对称性：

| 阶段 | 计算模式 | 瓶颈 | Latency 每个 token | 内存使用 |
|---|---|---|---|---|
| 预填充 | Matrix-matrix 乘法 | GPU TFLOPs | ~0.1-1 ms | Allocates KV 缓存 |
| 解码 | Matrix-vector 乘法 | 内存bandwidth | ~10-50 ms | 读取 KV 缓存 |

一张 GPU 同时运行两个阶段，可能只用到 50% 计算和 50% 内存带宽：从未饱和任一。浪费巨大。

Microsoft Research 2023 年的 Splitwise 论文和 UCSD 2024 年的 DistServe 提出：把两个阶段分离到不同 GPU。每个 GPU 针对自己的阶段优化。预填充完成后，KV 缓存从预填充 GPU 传输到解码 GPU。
