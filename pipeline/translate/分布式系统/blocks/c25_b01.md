Tobias 的集群 GPU 利用率为 60%。Continuum CTO 把目标定为 80%。2026 年实现这一目标的架构变化：disaggregated prefill/decode（prefill/decode 分离）。

这个洞察事后看很明显：prefill（处理提示）和 decode（生成 token）的计算特征非常不同。Prefill 是 compute-bound；decode 是 memory-bound。在同一张 GPU 上同时运行两者是次优默认；把它们放到针对不同阶段优化的不同 GPU 上，可解锁显著收益。

本章是工作流 12：一个 vLLM 集群加 disaggregated prefill/decode，以及跨节点的 KV cache sharding。该技术在 2023-2024 年成为经典研究（Splitwise、DistServe）；生产部署在 2025-2026 年成熟。


### 25.1 Prefill/Decode 不对称性

对单个 LLM 推理请求：

**Prefill 阶段**：处理整个输入提示。对 1000-token 提示，GPU 计算所有 1000 个 token 的 attention。这是矩阵-矩阵乘法；瓶颈是 GPU 计算（TFLOPs）。内存带宽很少是限制；延迟随提示长度缩放。

**Decode 阶段**：逐 token 生成输出。对每个 token，GPU 读取整个上下文（提示 + 已生成 token）的 KV cache，计算 attention，采样下一个 token。这是矩阵-向量乘法；瓶颈是内存带宽（加载 KV cache）。

不对称性：

| Phase | Compute pattern | Bottleneck | Latency per token | Memory usage |
|---|---|---|---|---|
| Prefill | Matrix-matrix mul | GPU TFLOPs | ~0.1-1 ms | Allocates KV cache |
| Decode | Matrix-vector mul | Memory bandwidth | ~10-50 ms | Reads KV cache |

一张 GPU 同时运行两个阶段，可能只用到 50% 计算和 50% 内存带宽：从未饱和任一。浪费巨大。

Microsoft Research 2023 年的 Splitwise 论文和 UCSD 2024 年的 DistServe 提出：把两个阶段分离到不同 GPU。每个 GPU 针对自己的阶段优化。Prefill 完成后，KV cache 从 prefill GPU 传输到 decode GPU。
