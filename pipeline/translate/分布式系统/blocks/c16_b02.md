### 16.2 典型 CRDT


#### G-Counter（只增计数器）

最简单的非平凡 CRDT。每个副本有一个向量 \(V[1..N]\)，\(V[i]\) 是副本 \(i\) 贡献的递增次数。

* 在副本 \(j\) 递增：\(V[j] \leftarrow V[j] + 1\)。
* 值：\(\sum_i V[i]\)。
* 合并两个 G-Counter：\(V_{\text{merged}}[i] = \max(V_1[i], V_2[i])\)。

逐元素 max 合并满足交换律、结合律、幂等。值（总和）定义良好且单调递增。

G-Counter 只能递增；PN-Counter 扩展为支持递减。


#### PN-Counter（正负计数器）

两个 G-Counter：\(P[1..N]\) 记录正向递增，\(N[1..N]\) 记录负向递增。

* 在副本 \(j\) 递增：\(P[j] \leftarrow P[j] + 1\)。
* 在副本 \(j\) 递减：\(N[j] \leftarrow N[j] + 1\)。
* 值：\(\sum_i P[i] - \sum_i N[i]\)。
* 合并：对 \(P\) 和 \(N\) 分别逐元素 max。

PN-Counter 可表达任意整数值。它不强制 “值绝不低于零”，因此不能替代库存（第15章）。


#### LWW-Register（Last-Write-Wins 寄存器）

每个值带时间戳（通常用 HLC）。寄存器保存时间戳最高的值。

* 在副本 \(j\) 用值 \(v\) 和时间戳 \(t\) 写入：若 \(t > \text{current timestamp}\)，替换。
* 合并：选时间戳更高的值；平票按副本 ID 打破。

LWW-Register 继承 LWW 的所有问题：时钟偏移可导致 “逻辑上更晚” 的写输掉。适合 “最后更新胜出” 语义正确的字段；不适合必须保留每次更新的字段。


#### MV-Register（Multi-Value 寄存器）

不选赢家，而是保留所有并发写。每次写带版本向量；并发写（版本向量互不支配）作为 siblings 保留。

* 在副本 \(j\) 用值 \(v\) 和版本 \(V\) 写入：将寄存器设为 \(\{(v,V)\}\)；任何版本被 \(V\) 支配的现有条目被移除。
* 合并：保留所有版本不被任何其他版本支配的条目。

MV-Register 把冲突抛给应用：读返回所有存活值，应用选择（或合并）。Dynamo 和 Riak 使用。


#### OR-Set（Observed-Remove Set）

典型的集合 CRDT。挑战：如何支持能正确收敛的 add 和 remove 操作。

朴素方法（带 remove 的 G-Set）失败：若 A 添加元素 \(x\)，B 并发移除 \(x\)，合并结果必须决定谁赢。使用 tombstone（被移除元素被标记而非删除）有帮助，但产生 “remove-before-add” 问题：若 B 的 remove 在 A 的 add 到达某副本前先到达，add 会被静默丢失。

OR-Set 的解决方案：每次 add 打一个唯一 ID（一个 “dot”）。remove 针对特定 dot。若任何 add 的 dot 未被 tombstone，元素就在集合中。

* 在副本 \(j\) **add element x**：生成新唯一 dot \(d\)；将 \((x,d)\) 加入 pair 集合。
* **Remove element x**：找到集合中所有 \((x,d)\)；将 \(d\) 记入 tombstone 集合。
* **集合值**：若存在某个 \((x,d)\) 的 \(d\) 未被 tombstone，则 \(x\) 在集合中。
* 合并：pair 集合取并集，tombstone 集合取并集；然后排除 dot 在 tombstone 中的 pair。

OR-Set 干净地处理 add-remove 并发。代价：tombstone 累积。生产 OR-Set 实现会在 tombstone 全局已知后做垃圾回收。


#### LWW-Map / OR-Map

由每键寄存器构建的映射（键到值）。LWW-Map：每个值是 LWW-Register。OR-Map：每个键对应一个值的集合（类似 OR-Set）。

对协作文辑，相关的 CRDT 是 _list_（或数组、序列），允许在任意位置插入删除。这是难的。
