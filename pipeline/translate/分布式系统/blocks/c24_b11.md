更深观察：“搭建推理集群” 答案空间很广。最小答案（基础部署）适合原型；完整答案（生产级）需要理解工作负载、运维要求和成本约束。给出最小答案的 LLM 产出的是原型级代码，对原型合适但对生产不足。

对 Continuum 部署，上述每个缺失特性都很重要。遵循 LLM 最小答案的团队会构建脆弱、不可观测、昂贵的集群。正确路径是逐步成熟：先用最小答案做原型，再随工作负载需求添加生产特性。


### 本章总结

分布式 LLM 推理是 2026 年分布式系统的一个子学科。与典型微服务舰队的关键差异：GPU 是单元；两阶段计算（prefill + decode）；KV cache 是中心状态；严格 per-token 延迟预算；突发工作负载模式。

vLLM 的 PagedAttention 把 KV cache 分成固定大小块；消除碎片；GPU 内存利用率从 30-50% 提升到 70-90%。2026 年基线开源推理引擎。

SGLang 的 RadixAttention 按前缀组织 KV cache；对共享 system prompt 工作负载节省巨大。最适合客服机器人、agent 框架、结构化输出。

NVIDIA NIM 是企业部署平台：容器化微服务、多引擎支持、硬件优化、企业特性。企业团队的标准部署表面。

Continuous batching 是吞吐模式：GPU 并行处理多个请求；请求持续加入和离开 batch；相比 static batching 提升 2-5 倍。现代引擎标准。

Tobias 的 Continuum 集群：50 节点、400 GPU、每月 120 万美元、60% 利用率。优化空间巨大；每个百分点利用率约每月 2 万美元。

第25章进入 2025-2026 架构突破：disaggregated prefill/decode。把 compute-bound prefill 与 memory-bound decode 分离，让每个阶段使用最优硬件。本章将走工作流 12：vLLM 集群加 disaggregated prefill/decode + KV cache sharding 图。
