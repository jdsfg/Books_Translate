#### 概念检测

**Q1.** 说出 LLM 关于分布式系统的六个谎言。

提示

RPC 语义、网络可靠性、时钟、锁、部分故障、CAP 简单。

**答案：**

  1. **RPC 有 TCP 式语义**：代码假设响应表示请求结果；不处理 “服务端成功但响应丢失”。

  2. **网络可靠**：代码没有 timeout、retry、circuit breaker、idempotency。

  3. **机器时钟说真话**：代码跨机器比较物理时钟时间戳做排序。

  4. **朴素分布式锁有效**：Redlock 风格代码假设锁持有者唯一；缺少 fencing token。

  5. **部分故障罕见**：代码只有 happy path；不考虑 “半成功” 结果；无 saga、无补偿动作。

  6. **CAP 分类简单**：代码说 “我们用 CP 系统” 或 “我们用 AP 系统”，而不理解 per-operation 一致性选择、PACELC、linearizable vs serializable。

LLM 默认产出嵌入这些谎言的代码，因为训练数据过度代表简单模式（单机假设），而不足代表处理这些故障模式的分布式系统纪律。

**Q2.** 每个谎言给出一个 LLM 生成代码嵌入的例子。

提示

例子在 §27.2-27.7。

**答案：**

（谎言 1）`result = service.call(req); if result.success: handle()`。无幂等；重试造成重复工作。

（谎言 2）`result = http.get(url)`。无 timeout、retry、circuit breaker；挂起级联。

（谎言 3）`sorted(events, key=lambda e: e.timestamp)`。跨机器物理时钟排序；时钟偏移破坏排序。

（谎言 4）`if redis.set(key, "1", nx=True, ex=30): do_critical_work()`。无 fencing token 的 Redlock；并发持有者造成污染。

（谎言 5）`db.update(user); cache.update(user); notify(user)`。部分失败使系统不一致。

（谎言 6）`# CockroachDB is CP, so this is consistent` 后接未指定的读。口号级 CAP，缺少 per-operation 一致性选择。

每个模式都在训练数据中，且常大量出现。LLM 把它们作为默认产出；识别它们是 bug 的工程纪律需要分布式系统训练。

**Q3.** 为什么单元测试不足以捕获 LLM 生成分布式代码中的分布式系统 bug？

提示

单元测试不演练分布式故障模式（网络分区、并发重试、操作期间领导者切换）。

**答案：** 单元测试通常：

(a) 在受控环境的单机上运行。(b) mock 或 stub 网络调用；不演练真实网络行为。(c) 不引入时间相关故障（时钟偏移、GC 暂停、重试以异常顺序到达）。(d) 不测试多副本场景（split-brain、partition、failover）。

分布式系统 bug 需要：

(a) 真实或带真实故障注入的模拟网络（Toxiproxy、Chaos Mesh，第23章）。(b) 多进程（或多副本）加真实时序。(c) 对抗性调度（Jepsen 风格测试，第23章）。(d) 可变条件下的长时间运行测试。

单元测试遗漏的 bug：

* 网络抖动 + 重试下的重复扣款。
* 分区下的 split-brain。
* 领导者 failover 下的丢失写。
* 网络恢复后的 stale read。
* 负载下的级联故障。
