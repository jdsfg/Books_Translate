使这成为可能的数学是 CRDT（Conflict-free Replicated Data Types，无冲突复制数据类型）。Yuki 使用的实现是 Yjs（团队主要选择）和 Automerge（用于部分子产品）。本章是 Yuki 的工作流 9：用 CRDT 实现 Glide 协作文档编辑器。

CRDT 是过去十年分布式状态系统中最具运维重要性的进展。CRDT 出现前，“协作编辑” 需要复杂的 Operational Transformation（OT）算法，出了名的难实现正确（Google Docs 有 10 万行 OT 实现）。CRDT 出现后，数学处理冲突解决；实现小一个数量级。


### 16.1 CRDT 是什么

Conflict-free Replicated Data Type 是这样设计的数据类型：来自不同副本的并发更新可被确定性合并，无论合并顺序如何都产生相同结果。“无冲突” 是结构属性：数据类型的设计从构造上消除冲突。

形式上，设计 CRDT 有两种等价方式：

(a) **基于状态的 CRDT（CvRDT）** ：每个副本持有完整状态。合并时，合并函数取两个状态并产生新状态。合并必须满足：

* **交换律** ：\(\text{merge}(a,b) = \text{merge}(b,a)\)
* **结合律** ：\(\text{merge}(\text{merge}(a,b),c) = \text{merge}(a,\text{merge}(b,c))\)
* **幂等律** ：\(\text{merge}(a,a) = a\)

这三条性质使状态在合并下形成一个 join-semilattice。任意合并序列都会收敛到所有已见状态的最小上界。

(b) **基于操作的 CRDT（CmRDT）** ：每个副本广播操作。广播必须保证投递（可靠广播，第4章）。操作必须可交换：不同顺序应用操作产生相同结果。

两种表述表达能力等价；选择是运维性的。基于状态的更易实现（只需算合并）但状态可能变大。Op-基于更高效（只发 diff）但要求广播层保证投递。
