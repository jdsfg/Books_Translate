### 14.3 CockroachDB

Cockroach Labs 的开源 NewSQL。有时被描述为 “Spanner for the rest of us”，因为它提供类似保证而无 GCP 锁定。

关键属性：

* 每 range 使用 Raft 复制。
* HLC-based MVCC，NTP 偏移上界（默认 500 ms）。
* Postgres 线缆兼容。
* 多区域部署，支持 per-table 区域配置。
* 开源核心（CockroachDB Community）；企业版附加高级功能。

优势：

* 可跑在任何云或本地。
* Postgres 兼容性意味着现有工具（psql、驱动、ORM）可用。
* Per-table 多区域配置（global、regional、follower reads）。
* 默认可串行化。

劣势：

* 运维成本高于单节点 Postgres。
* 某些 Postgres 扩展和功能不支持。
* HLC-based MVCC 需要严格的 NTP 纪律。

CockroachDB 适合：不能接受 Spanner GCP 锁定的多区域 Postgres 工作负载。生产示例：众多 fintech（DoorDash、Comcast 部分工作负载、若干大型银行）。


### 14.4 TiDB

PingCAP 的 NewSQL；兼容 MySQL 线缆。

关键属性：

* TiKV 存储层（每 region/tablet 使用 Raft；Percolator-based 事务）。
* TiDB 计算层（无状态 SQL 前端；可独立于 TiKV 扩展）。
* 兼容 MySQL 线缆。
* 通过 TiFlash（列式存储引擎用于分析查询）支持 HTAP。

优势：

* MySQL 兼容性（庞大现有生态）。
* HTAP via TiFlash：同一数据上 OLTP 和 OLAP 无需 ETL。
* 运维成熟（在中国科技规模下久经考验：微信、阿里巴巴等）。

劣势：

* 英语社区比 CockroachDB 小。
* 多组件架构复杂（PD + TiDB + TiKV + TiFlash）；运维学习曲线。

TiDB 适合：已超出单节点规模、需要 HTAP 能力的 MySQL 工作负载。生产示例：许多中国科技公司、部分美国公司（Square 历史上）。


### 14.5 YugabyteDB

兼容 Postgres 的 NewSQL；CockroachDB 的近亲。

关键属性：

* 每分片使用 Raft 复制。
* HLC-based 时间戳。
* 兼容 Postgres 线缆（直接使用 Postgres 解析器和计划器）。
* 多区域部署。

优势：

* 比 CockroachDB 更接近 Postgres 兼容（使用 Postgres 自身代码）。
* 除 Postgres API 外还提供 Cassandra 兼容 API（YCQL）。

劣势：

* 生产 track record 比 CockroachDB 小。
* 多区域配置复杂（与 CockroachDB 类似）。

YugabyteDB 和 CockroachDB 是画像相似的竞争者。选择常归结为具体功能需求和生态偏好。
