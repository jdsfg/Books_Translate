#### 概念检测

**Q1.** 是什么让分布式 LLM 推理在结构上与典型微服务舰队不同？

提示

GPU 作为单元、两阶段计算、KV cache 作为状态、严格的 per-token 延迟、突发模式。

**答案：** 五个结构差异：

(a) **GPU 是单元，而非节点**。昂贵资源是 GPU 内存和计算。一个节点有 8 张 GPU；工作负载在 GPU 之间移动不亚于在节点之间。微服务舰队关注节点；推理关注 GPU。

(b) **每个请求的两阶段计算**。Prefill（处理 prompt，compute-bound）和 decode（生成 token，memory-bound）有不同最优硬件/软件 profile。独立优化每个阶段是 2025-2026 架构突破。

(c) **KV cache 作为中心状态**。KV cache 是 per-request 工作内存（1-100 GB），短命，是内存和吞吐瓶颈。微服务 per-request 状态小；推理 per-request 状态大。

(d) **严格的 per-token 延迟预算**。每个生成 token 必须在 10-50 ms 内完成。网络跳数超过几毫秒会显著影响吞吐。微服务 per-request 预算更宽松；推理有 per-token 预算。

(e) **突发工作负载模式**。请求从单次问答到大文档分析不等。集群必须处理混合而无线头阻塞。微服务通常 per-request profile 更均匀。

这些差异证明把分布式 LLM 推理视为独立子学科。协议（PagedAttention、RadixAttention）、原语（KV cache、prefill、decode）和部署模式（disaggregation、sharding）都是推理专用。

**Q2.** 描述 PagedAttention。它解决什么问题？

提示

受 OS 分页启发。KV cache 分固定大小块；不连续；消除碎片。

**答案：** PagedAttention（vLLM，2023）把 KV cache 分成固定大小块（如每块 16 个 token）。每个请求的 KV cache 是块列表，不必在内存中连续。块可独立分配和释放。

它解决的问题：经典 KV cache 管理为每个请求预留连续内存。若请求需要 4 GB，系统预留 4 GB；请求结束后释放。久而久之内存碎片化；即使总空闲内存大，也没有足够大的连续块给新请求。GPU 内存利用率差（典型 30-50%）。

PagedAttention 收益：

* **更高内存利用率**：70-90% GPU 内存用于 KV cache，相比朴素系统 30-50%。
* **每张 GPU 更多并发请求**：更好内存利用率意味着更多请求 fit；每张 GPU 吞吐上升。
* **前缀共享**：共享 prompt 的请求共享前缀的 KV cache 块。对具有共同 system prompt 的聊天工作负载，内存节省巨大。

灵感来自操作系统虚拟内存：页让进程无需连续物理地址即可使用内存。PagedAttention 把同样思想用于 KV cache。

2026 年，vLLM（及 PagedAttention 衍生系统）是最广泛部署的开源推理引擎。该技术是基线；进一步优化（RadixAttention、disaggregation、KV cache sharding）在此基础上构建。
