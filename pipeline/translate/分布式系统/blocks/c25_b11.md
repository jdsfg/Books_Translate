* 对某些工作负载用更小模型（质量可接受处）。
* 用 task-specific fine-tunes（针对特定任务调优的小模型可媲美大通用模型）。
* 用 MoE（Mixture-of-Experts）模型：总参数量很大，但每 token 只激活部分；成本低于 dense 大模型。

(f) **运维优化**：

* 根据观测利用率合理调整规模集群。
* 用自动扩缩匹配需求。
* 多租户调度以最大化利用率。

LLM 的 “用更小模型” 答案最多带来 10-20% 成本降低（有时有质量损失）。以上完整答案可实现 50-80% 成本降低且无质量损失。任何特定团队的最优答案取决于他们已应用哪些优化。

更深观察：2026 年推理成本优化是深度专业领域。给出单句答案的 LLM 遗漏了领域实际深度。正确答案应是：“推理成本优化有很多杠杆。最大杠杆是 [列表]。你的集群在每个上处于什么位置？我们针对你的具体 setup 确定下一步最高杠杆。”


### 本章总结

分离式预填充/解码是 2025-2026 架构突破。预填充是 compute-bound（矩阵-矩阵乘法）；解码是 memory-bound（矩阵-向量乘法）。分离到不同 GPU 让每个阶段使用最优硬件；相同延迟下吞吐提升 2-4 倍。

Splitwise（Microsoft Research）和 DistServe（UCSD）是经典研究；生产系统（Mooncake、LMCache）实现这些模式。采用阈值：约 50+ 节点集群，效率收益超过运维复杂度。

KV 缓存 sharding 把每个请求 KV 缓存跨多张 GPU 和节点分布。超长上下文（1M+ token）必需；实现跨请求前缀复用。Mooncake（商业）和 LMCache（开源）是 2026 实现。

Tobias 的工作流 12：30 预填充节点 + 30 解码节点 + 10 缓存节点；高带宽 RDMA 网络；6 个月迁移；利用率从 60% 到 85%；年节省 400-500 万美元。投入巨大；ROI 巨大。

延迟成本：首 token 延迟增加约 50 ms（KV 缓存传输）。对交互式工作负载可感知；缓解措施（同机箱 NVLink、预取、前缀缓存）使其接近 co-located 性能。

第26章结束第八部分，讲负载均衡和投机解码作为分布式协议。Anyscale/Together/Fireworks 路由问题；投机解码（草稿模型 + 验证模型）作为多机协议；长度预测和 KV缓存感知路由。
