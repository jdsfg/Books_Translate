#### 概念检测

**Q1.** 计算以下单程光速下限：(a) Chicago 到 São Paulo，(b) Tokyo 到 Mumbai，(c) 赤道上相距 180 度的任意两点。

提示

光纤中光速约 200,000 km/s。地球周长约 40,000 km。

**答案：**

(a) Chicago 到 São Paulo：大圆距离约 8,500 km。按直线光纤 200,000 km/s 计算，下限 8,500 / 200,000 = 42.5 ms。真实电缆绕行加勒比和巴西海岸，有效距离约 10,000 km，即 50 ms 单程。

(b) Tokyo 到 Mumbai：大圆约 6,750 km。下限：34 ms。真实电缆经香港、新加坡，距离增加；预计单程 50-60 ms。

(c) 赤道上相距 180 度两点：赤道周长的一半，20,000 km。下限：100 ms 单程，200 ms 往返。这是对跖点下限；地球上不可能更远。

这些是极限。因此没有任何协议能让纽约到东京往返低于 50 ms p99，无论工程多强。承诺跨太平洋操作 30 ms p99 的团队在承诺不可能。

**Q2.** 用 2-3 句话描述 leaf-spine 拓扑。它为何取代三层网络？

提示

Leaf-spine 中每个 leaf 连到每个 spine；经典三层中 aggregation 交换机成为带宽瓶颈。

**答案：** Leaf-spine 有两层：leaf 交换机连接服务器，每个 leaf 都连到每个 spine 交换机。任意两台服务器间流量只经过一个 spine hop，ECMP 跨 spine 路径做负载均衡。它取代三层（core、aggregation、access），因为三层的 aggregation 交换机对东西向（服务器到服务器）流量成为瓶颈，而现代分布式工作负载以东西向为主；leaf-spine 提供任意服务器间扁平、低超额订阅的带宽。

**Q3.** 一个团队的多区域数据库部署在 US-East、US-West、Frankfurt。他们希望 Raft 法定人数在 80 ms 内提交。可行吗？若不可行，如何改？

提示

Raft 法定人数需要多数。三节点时法定人数是任意 2。计算每对往返下限。

**答案：** 三副本 Raft 需 2 of 3 ack。相关成对往返延迟：

* US-East 到 US-West：~80 ms。
* US-East 到 Frankfurt：~90 ms。
* US-West 到 Frankfurt：~160 ms（最差一对）。

US-East 发起的写等待第二个 ack；US-West 和 Frankfurt 中先响应者约 80-90 ms 往返。因此 US-East 发起的写约 85 ms 往返提交，刚超 80 ms 预算。

预算勉强可行但很紧。选项：

(a) 把一个副本移近（如 Frankfurt 换 US-Central 或 US-West 换 Toronto），把第二快往返压到 80 ms 以下。

(b) 用 Spanner 风格按区域 leaderless 写，按区域法定人数加全局提交时间戳，特定工作负载可更快。

(c) 接受 85 ms 并调整预算。对人类可见操作，5 ms 通常不重要。

(d) 读操作用跟随者读（无需法定人数），让写保持法定人数成本，但减少读的感知多区域延迟。

**Q4.** 为什么 RDMA 用于分布式 LLM 推理却很少用于应用层微服务？

提示

RDMA 的延迟收益在亚毫秒级有意义。应用服务延迟预算大得多。

**答案：** RDMA 把网络延迟从 ~50 微秒（kernel-bypass TCP）降到 ~1-2 微秒（RoCE 上的 RDMA）。对总请求延迟 ~10 ms 的应用，这只省 ~0.5% 预算——不值部署 RDMA fabric 的运维复杂度。

对分布式 LLM 推理，prefill 与 decode 节点之间每次 token 都要移动 KV cache，每个 token 必须在 ~10-50 ms 内生成。一次 50 微秒网络跳占预算 5-25%；降到 2 微秒是 budget 内与超出的差别。高频率和紧预算让 RDMA 值得运维成本。

同样理由适用于 ML 训练（每步梯度交换）和分布式内存数据库（关键路径远程内存访问）。对延迟预算为毫秒级或更高的通用应用服务，kernel-bypass + TCP 已足够。
