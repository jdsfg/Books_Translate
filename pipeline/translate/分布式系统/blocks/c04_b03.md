### 4.4 一致可靠广播（Uniform Reliable Broadcast）

再上一层修复“发送者崩溃后只有一个接收者收到消息”缺口。一致可靠广播新增：_若任一进程（正确或已故障）交付了一条消息，则所有正确进程都交付它。_

从“任一正确接收者交付”加强到“任何进程交付”迫使系统保证，即使最初收到消息的接收者在重广播前崩溃，消息仍会被送达。

简单实现：一个进程只有在确认多数进程已经 _收到_ 该消息后才向上层交付。ack 往返增加延迟，但确保如果消息消失（发送者崩溃、某个接收者崩溃），仍有存活的正确进程持有它并重广播。


    on 广播(msg):
        for 对等节点 in all_processes:
            发送(对等节点, msg)

    on 接收(msg, sender):
        if msg not in 已接收:
            received.add(msg)
            for 对等节点 in all_processes:
                发送(对等节点, ACK(msg))

    on 接收(ACK(msg), sender):
        acks[msg].add(sender)
        if len(acks[msg]) > N/2 and msg not in 已投递:
            delivered.add(msg)
            upper_layer.deliver(msg)


性质（在可靠广播之外）：

* **统一性** ：若 _任何_ 进程交付了一条消息（正确或故障），所有正确进程都交付它。

这就是防止普通可靠广播中“唯一接收者崩溃”失败模式的性质。


### 4.5 因果广播（Causal Broadcast）

可靠广播不保序。因果广播新增：_若消息 m_1 在 happens-before 关系下先于 m_2 广播（即广播(m_1) \to 广播(m_2)），则任何正确进程都不会在 m_1 之前交付 m_2。_

标准实现使用向量时钟（第3章）。每次广播携带发送者的向量，接收者延迟交付消息，直到所有因果上先于它的消息都已交付。


    # 每个进程维护 V[1..N]，初始全零。
    on 广播(msg):
        V[self] += 1
        send_to_all(msg, V)

    on 接收(msg, V_msg, sender):
        buffer.add((msg, V_msg, sender))
        try_deliver_from_buffer()

    def try_deliver_from_buffer():
        while True:
            deliverable = None
            for (msg, V_msg, sender) in 缓冲区:
                # 当所有因果上先于它的消息都已交付时才可交付。
                if V_msg[sender] == V[sender] + 1 and all(V_msg[i] <= V[i] for i in others):
                    deliverable = (msg, V_msg, sender)
                    break
            if deliverable is None:
                return
            # 交付
            buffer.remove(deliverable)
            V[deliverable.sender] += 1
            upper_layer.deliver(deliverable.msg)


性质（在可靠广播之外）：

* **因果顺序** ：若广播(m_1) \to 广播(m_2)，则每个正确进程先交付 m_1 再交付 m_2。

代价：每次广播携带一个 N 项向量。与向量时钟一样，大 N 时扩展性差。对固定小 N（3 节点 Raft 集群、5 节点 Cassandra 协调组）成本可忽略。对 10,000 节点舰队需要压缩方案。
