### 25.3 为什么分离获胜

两个复合收益：

(a) **每阶段硬件利用率更好**。Prefill 节点饱和 GPU 计算（只做计算重的工作）。Decode 节点饱和内存带宽（只做内存重的工作）。集群整体利用率远高于未分离情况。

(b) **独立扩缩**。Prefill 容量（计算）和 decode 容量（内存+内存带宽）可根据工作负载独立扩缩。对长 prompt 短输出的工作负载，多扩 prefill；对相反情况，多扩 decode。

Splitwise 公布数字：在相同延迟下，相比 co-located prefill/decode，成本效率提升 2 倍。DistServe 数字：吞吐提升 2-4 倍。

成本：架构复杂度。两种节点类型；KV cache 传输逻辑；集群拓扑更复杂。对小集群，复杂度不值得；对大集群，收益值得。

2026 阈值：大约 50+ 节点是分离开始划算的地方。低于此，运维开销超过效率收益。


### 25.4 跨节点 KV Cache Sharding

一个独立但相关的技术：对超长上下文，把 KV cache 分布到多个 decode 节点。

对 1M token 上下文（2026 年正在成为常见工作负载），单个请求的 KV cache 可达数十 GB。没有单张 GPU 内存足够；KV cache 必须跨多张 GPU（可能跨多个节点）分片。

Mooncake，Moonshot AI 在 2024 年论文中描述的推理系统，是 2026 年的典型实现。KV cache 以块形式（PagedAttention 风格）分布在集群级缓存层。Decode 节点需要某块时，从对应 shard 读取。

LMCache（UC Berkeley，2024）是开源等价物。为 vLLM 集成设计；提供集群级 KV cache，任何 decode 节点都可读取。

架构模式：KV cache 成为集群的独立 tier，而不只是 per-node 资源。Decode 节点无状态（按需从缓存层读取 KV cache）；KV cache 在许多 decode 节点间共享。

收益：许多并发请求共享缓存层；KV cache 复用（同一 prompt 前缀被许多请求使用）被摊销；超长上下文无需单节点内存达到最大尺寸。

成本：缓存层网络带宽成为瓶颈；每 token 的 KV cache 传输必须非常快（100+ tokens/sec 需亚毫秒）。RDMA + 精心预取是让这可行的技术。
