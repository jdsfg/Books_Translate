#### 应用问题

**Q1.** 任选你使用过或读过的生产分布式系统。应用诊断方法（第11章）并指出三个谎言姿态（第1章）。

提示

选系统；回答四个诊断问题；指出它如何防御时间、身份、故障。

**答案：** 以 Postgres + Patroni 高可用部署为例：

_诊断方法（第11章）_：

* **复制协议**：Postgres 逻辑复制；默认异步；Patroni 通过 etcd 管理 failover。
* **故障恢复**：Patroni 通过基于 etcd 的 leader 选举检测主库故障；提升 standby；耗时 30-60 秒。split-brain 可能需要人工干预。
* **一致性模型**：事务内快照隔离；副本读最终一致。
* **分区行为**：CP——少数派无法在 etcd 获得 leadership，拒绝写。

PACELC：PC/EL（分区时一致；正常操作时低延迟，因异步复制）。

_三个谎言姿态_：

* **时间**：Postgres 使用 wall-clock 时间戳；事务按事务开始时间排序，非 wall clock。跨副本顺序由复制决定；单副本内部不受时钟偏移影响。
* **身份**：Patroni + etcd 提供 leader 唯一性；etcd 的 Raft 确保一次只有一个主库。Fencing token 未原生使用；etcd revision 在编排层起类似作用。
* **故障**：异步复制可能丢失主库传播前最近写入。团队必须接受某 RPO；可通过 `synchronous_commit = remote_apply` 收紧。

优势：成熟、文档丰富、SQL 强大。劣势：failover 不可用窗口；异步复制 RPO。

对 Crescent：Postgres + Patroni 不满足多 region 需求；CockroachDB 是正确选择。对单 region OLTP 工作负载，Postgres + Patroni 运维简洁且工作良好。

这个练习说明：诊断方法适用于任何系统；三个谎言姿态揭示防御（或缺失）；两者让工程师无需通读每页文档就能评估系统。

**Q2.** Olamide 正在指导新工程师。工程师问：“分布式系统最重要的是学什么？” 构造 Olamide 的回答。

提示

心智模型、纪律、愿意假设最坏情况。

**答案：** Olamide 可能的回答：

"最重要学会的是心智动作：假设每个组件都在时间、身份、故障上说谎。然后问有什么防御。然后用混沌工程验证防御。

"这就是全部。其余——具体共识算法、具体数据库、具体模式——都是那个心智动作的实现细节。

"你会随着时间学会算法。你会通过阅读文档并在生产运行系统来学习具体系统。你会通过写代码和审查 PR 学习模式。你无法潜移默化学会的是 _姿态_：愿意假设代码中每次交互、架构中每个连接、系统中每个操作的最坏情况。

"没有这种姿态的工程师构建出测试通过、生产失败的系统。有这种姿态的工程师构建出 Crescent 这样的系统。区别不在于知识；而在于不信任的纪律。
