#### 应用问题

**Q1.** 把诊断方法用于 TigerBeetle。充分阅读其文档以回答四个问题，并产出一页阅读。

提示

TigerBeetle 是面向确定性模拟测试和 TigerStyle 编程范式的金融级账本数据库。找其复制协议、故障模型、一致性和分区行为。

**答案：** TigerBeetle 阅读：

Question | Answer
---|---
Replication protocol | 自定义 Viewstamped Replication 变体；5 副本部署是经典；集群范围写排序
Failure-recovery | 亚秒级 view-change；面向确定性模拟测试（每个可达状态都被显式枚举和演练）
Consistency model | 复式记账事务的 strict serializability；每次转账 linearizable
Partition behavior | CP——少数侧拒绝写；法定人数为副本多数
PACELC | PC / EC；优化金融 OLTP 吞吐（benchmark 宣称每秒 100 万+ 转账）
Strengths | 金融级正确性模型（确定性模拟测试 + TigerStyle 编程）；确定性执行；易于调试
Weaknesses | 专用于复式记账（非通用）；生态小
Right for | 银行账本、支付系统、金融 OLTP，且 schema 符合 TigerBeetle 的会计模型

TigerBeetle 作为领域特定设计的研究很有趣：通过限制数据模型（仅复式记账），系统可比通用数据库快得多且更可验证。2026 年金融系统中真实架构模式是：Crescent 的支付账本实际转账记录可用 TigerBeetle（schema 合适），而用户可见元数据仍用 CockroachDB。

**Q2.** 一个团队为新微服务评估 MongoDB。他们问：“MongoDB 一致吗？”用诊断方法给出精确、可辩护的答案。

提示

MongoDB 的一致性取决于配置：writeConcern、readConcern、replica set vs sharded。默认与最强可用不同。

**答案：** MongoDB 的一致性高度依赖配置。精确答案必须说明哪种操作、哪种配置。

副本集（典型 3 节点）：

* _默认写_ ：`writeConcern: 1`（单节点 ack）。复制最终一致；若主库在复制前崩溃可能丢失。
* _Majority 写_ ：`writeConcern: majority`。写在被 ack 前已持久化到多数；主库故障后存活。
* _默认读_ ：`readConcern: local` 从主库读。主库读线性化，从 secondary 读则最终一致（MongoDB 客户端默认 `readPreference: secondary` 时）。
* _Majority 读_ ：`readConcern: majority` 返回已被多数 ack 的数据。
* _Linearizable 读_ ：`readConcern: linearizable` 提供线性化读。自 MongoDB 3.4 起可用。

分片集群：每个分片是一个副本集；上述按分片适用。跨分片事务可用（MongoDB 4.0+），跨分片提供快照隔离。
