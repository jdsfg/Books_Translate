### 27.2 谎言 1：RPC 有 TCP 式语义

> 本章每个 LLM 生成代码块都是说明性伪代码。重点是 _缺失的结构防御_，而非语法。

LLM 生成代码：


    def submit_payment(payment):
        result = payment_service.charge(payment)
        if result.success:
            db.insert(payment.id, 状态='completed')
        else:
            db.insert(payment.id, 状态='已失败')


谎言：代码假设 `payment_service.charge()` 要么成功（返回成功），要么失败（返回故障）。第三种选项（RPC 在服务端已处理但响应丢失）未被处理。

现实：网络不可靠。HTTP 调用可能在服务端已处理后从客户端超时。客户端看到失败；服务端已扣款。重试造成重复扣款。

修复：幂等性。每笔支付必须携带幂等键。服务端检查：我之前见过这个键吗？若见过，返回之前计算的结果。重试安全。

### 27.3 谎言 2：网络可靠

LLM 生成代码：


    def get_user_profile(user_id):
        return profile_service.get(user_id)


谎言：没有超时、没有重试、没有断路器、没有回退。代码假设调用最终会返回。

现实：网络会抖动。下游有时慢。下游有时会失败。没有防御，这一行可能让调用服务无限挂起，促成级联故障，造成 p99 延迟灾难。

修复：每个网络调用应有超时、重试预算、断路器，以及（若可能）回退。


    @circuit_breaker(阈值=0.5, 超时=30)
    @重试(max_retries=3, 预算=0.1)
    @超时(秒=2)
    def get_user_profile(user_id):
        try:
            return profile_service.get(user_id)
        except CircuitBreakerOpen:
            return cached_profile_or_default(user_id)


装饰器栈反映纪律。LLM 产出裸调用是因为训练数据充满裸调用；“每个网络调用都需要防御” 的工程智慧在代码生成训练中没有强体现。
