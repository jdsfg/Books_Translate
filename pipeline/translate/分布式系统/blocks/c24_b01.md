### 24.1 为什么分布式 LLM 推理不同

单机上推理大模型（Llama 3 70B、Mistral Large、Claude 3 Opus 级别）需要的内存超过任何单张 GPU。模型权重 alone 就是数十 GB；每个请求的 KV cache 又增加更多。推理必须跨 GPU 分布。

但分布式推理不是 “以 LLM 为负载的分布式系统”。它有与典型微服务舰队结构不同的属性：

(a) **GPU 是单元，而非节点**。昂贵资源是 GPU 内存和计算。一个节点可能有 8 张 GPU；推理工作负载在 GPU 之间移动，不亚于在节点之间。

(b) **每个请求的两阶段计算**。Prefill（处理提示）和 decode（逐 token 生成）的计算特征非常不同。Prefill 是 compute-bound；decode 是 memory-bound。独立优化每个阶段是 2025-2026 的突破。

(c) **KV cache 作为中心状态**。KV cache 是让模型逐 token 解码的工作内存。它很大（每个活跃请求 1-100 GB），短命（请求结束即释放），并且是内存和吞吐瓶颈。

(d) **严格的延迟预算**。每个 token 生成延迟 10-50 ms。在此预算内，系统必须读取 KV cache、计算 next-token logits、采样、推进状态。超过几毫秒的网络跳数都很重要。

(e) **突发工作负载模式**。有的请求短（单次问答），有的长（大文档分析），有的突发（多轮并发对话）。集群必须处理这种混合而没有队头阻塞。

2026 年处理这些挑战的系统：vLLM、SGLang、NVIDIA NIM。每种有不同优化；适合不同工作负载。
