#### 概念检测

**Q1.** 什么是 “NewSQL”？它与传统 SQL 和 NoSQL 有何不同？

提示

NewSQL：SQL + ACID + 水平扩展。传统 SQL：单节点或少数节点。NoSQL：水平扩展但历史上放弃 ACID。

**答案：** NewSQL 是在水平扩展的同时保留 SQL 和 ACID 事务的分布式数据库类别。约 2011 年出现，介于两者之间：

* **传统 SQL**（PostgreSQL、MySQL、Oracle）：ACID、完整 SQL，但单节点或主从架构，纵向扩展。
* **NoSQL**（Cassandra、DynamoDB、MongoDB）：水平扩展，但历史上放弃部分 ACID、SQL 或事务一致性。

NewSQL 系统（Spanner、CockroachDB、TiDB、YugabyteDB、Aurora DSQL）提供：

* SQL（通常兼容 Postgres 或 MySQL 线缆）。
* 可串行化或线性化事务的 ACID。
* 跨分片/range 水平扩展。
* 多区域部署下的一致事务。

代价：比单节点 Postgres 更高的每写延迟（共识往返）；更多运维复杂度（分片、多区域调优）。

**Q2.** 用诊断方法比较 CockroachDB 和 Spanner。

提示

两者都是 PC/EC NewSQL。差异：TrueTime vs HLC、仅限 GCP vs 任何云、专有 SQL vs Postgres 兼容。

**答案：**

Question | Spanner | CockroachDB
---|---|----
Replication protocol | 每 tablet Paxos | 每 range Raft
Failure-recovery | Paxos leader 切换（~数秒） | Raft leader 切换（~数秒）
Consistency model | Linearizable；提供过期读 | Serializable；提供 follower reads
Partition behavior | CP——少数侧拒绝写 | CP——少数侧拒绝写
Timestamp source | TrueTime（GPS + 原子钟） | HLC + NTP 偏移上界
PACELC | PC / EC（每次写 commit-wait） | PC / EC（不确定性的可变成本）
SQL 兼容性 | Spanner SQL（专有） | 兼容 Postgres 线缆
部署 | 仅限 GCP | 任何云、本地
成熟度 | 2012 年生产；2017 年对外 | ~2019 年生产

两者都是 PC/EC NewSQL，高层保证相似。关键差异：Spanner 有 TrueTime 优势（一致延迟、无疑虑性重启）但仅限 GCP；CockroachDB 有 Postgres 兼容优势且可跑在任何地方，但争用下付可变成本。

新工作负载选择：若在 GCP 且成本可接受，选 Spanner；若需要多云、本地或 Postgres 兼容，选 CockroachDB。

**Q3.** NewSQL 数据库与分布式查询处理器（如 Trino 或 Snowflake）有何不同？

提示

NewSQL：OLTP。分布式查询处理器：OLAP。访问模式、成本模型不同。

**答案：** NewSQL 数据库（Spanner、CockroachDB）面向 OLTP（在线事务处理）：大量小读/写操作、每操作低延迟、强一致。优化目标是低延迟下的高事务吞吐，通常每次操作亚 100 ms。

分布式查询处理器（Trino、Snowflake、BigQuery）面向 OLAP（在线分析处理）：少量但扫描 TB-PB 数据的大查询、每查询频率低、复杂聚合和 join。优化目标是大扫描上的查询吞吐，通常每查询数秒到数分钟。
