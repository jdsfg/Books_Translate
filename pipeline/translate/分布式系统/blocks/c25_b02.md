预填充节点：

* 针对计算优化（TFLOPs 最高的最新 GPU）。
* 并行处理大量 incoming 提示。
* 输出：每个提示的 KV 缓存。
* 计算完预填充后，将 KV 缓存传输到分配的解码节点。

解码节点：

* 针对内存带宽和容量优化（HBM3、大内存）。
* 保存大量活跃解码请求的 KV 缓存。
* 为每个请求逐 token 生成。
* 瓶颈是内存带宽（每 token 读取 KV 缓存）；GPU 为此调优。

KV 缓存传输：

* 预填充完成后，预填充节点把 KV 缓存发送给解码节点。
* 通过 RDMA（第6章）或 NVLink（同机箱内）传输。
* 大小：每个请求通常 1-10 GB（取决于提示长度和模型）。
* 时间：~10-100 ms（通过 200 Gbit/s NVLink 或 InfiniBand 的 RDMA）。

KV 缓存传输是新的运维关注点：它消耗网络带宽并增加首 token 时间。处理得当，整体吞吐收益占主导。
