Prefill 节点：

* 针对计算优化（TFLOPs 最高的最新 GPU）。
* 并行处理大量 incoming prompt。
* 输出：每个 prompt 的 KV cache。
* 计算完 prefill 后，将 KV cache 传输到分配的 decode 节点。

Decode 节点：

* 针对内存带宽和容量优化（HBM3、大内存）。
* 保存大量活跃 decode 请求的 KV cache。
* 为每个请求逐 token 生成。
* 瓶颈是内存带宽（每 token 读取 KV cache）；GPU 为此调优。

KV cache 传输：

* Prefill 完成后，prefill 节点把 KV cache 发送给 decode 节点。
* 通过 RDMA（第6章）或 NVLink（同 chassis 内）传输。
* 大小：每个请求通常 1-10 GB（取决于 prompt 长度和模型）。
* 时间：~10-100 ms（通过 200 Gbit/s NVLink 或 InfiniBand 的 RDMA）。

KV cache 传输是新的运维关注点：它消耗网络带宽并增加首 token 时间。处理得当，整体吞吐收益占主导。
