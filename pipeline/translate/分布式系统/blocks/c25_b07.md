对首 token 延迟敏感的工作负载（用户看到流式输出的交互式聊天），50 ms 惩罚是真实的。对批处理工作负载（文档分析、agent 运行），惩罚不可见（用户只看到最终输出）。

减少首 token 延迟的优化：

(a) **KV cache 预取**：prefill 快完成时，开始把早期块传输到 decode 节点。(b) **节点内 NVLink**：把 prefill 和 decode 放在同一 physical chassis；NVLink 传输比跨节点 RDMA 快得多。(c) **共享前缀缓存**：若提示有已缓存前缀（来自之前请求），跳过该部分 prefill。

Tobias 的部署使用 (a) 和 (c)；典型首 token 延迟约 150 ms，接近 co-located 性能。
