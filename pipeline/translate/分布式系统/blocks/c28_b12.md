#### 概念检测

**Q1.** 用自己的话重述本书的中心论点。

提示

系统在时间、身份、故障上撒谎。工程纪律：组合会说真话的原语。

**答案：** 分布式系统以三种特定方式本质上不可靠：它们在时间上说谎（各机器时钟不完全一致）、在身份上说谎（每个节点自视为唯一扮演其角色，而其他节点可能不同意）、在故障上说谎（部分故障是默认模式，不是例外）。

分布式系统工程纪律是假设这些谎言正在发生，识别系统每个部分易受哪些谎言影响，并组合防御这些谎言的原语（时间用 HLC、身份用 fencing token、故障用重试/超时/熔断器/saga）。

工作工程师的姿态：对每个组件、每个连接、每个操作都假设最坏情况，直到被验证。这种姿态区分了构建健壮分布式系统的工程师与不断被故障惊到的工程师。

本书路径：从第1章引入三个谎言，经过协议（共识、复制、事务、CRDT），经过运维纪律（追踪、级联故障、混沌工程），到第27章回顾为什么 LLM 不擅长这个，以及第28章的综合。内化纪律的读者能构建 Crescent 这样的系统；没有内化的读者产出有 bug 的系统。

**Q2.** 指出下列原语分别由哪一章引入：HLC、fencing token、Raft、原子广播、CRDT、重试预算、混沌工程、KV-cache-aware 路由。

提示

各章大致按顺序引入原语；查看目录。

**答案：**

* **HLC**：第3章（时间、序与说谎的时钟）。
* **Fencing token**：第18章（分布式锁）。
* **Raft**：第9章（实现友好的共识）。
* **Atomic broadcast**：第4章（广播层级）。
* **CRDT**：第16章（CRDTs in production）。
* **重试预算**：第21章（级联故障）。
* **混沌工程**：第23章（混沌作为学科）。
* **KV-cache-aware 路由**：第26章（LLM 推理负载均衡）。

每个原语解决三个谎言某一类表现。HLC 防御时间谎言；fencing token 防御身份谎言；带预算的重试防御故障谎言的放大。完整防御需要多个原语共同使用。

第28章的 Crescent 系统使用了所有上述原语。本书路径就是积累工具包；综合就是一起使用工具包。
