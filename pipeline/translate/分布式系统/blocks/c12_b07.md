(a) LSM 写是 _顺序_ 的（WAL 追加；把整个 memtable 刷成新 SSTable）。传统存储上顺序写比随机写快 10-100 倍；在 SSD 上也快（但差距没这么大）。

(b) LSM 批量磁盘 I/O：很多写先在 memtable 累积，再一起刷盘。B+ tree 每次页更新都要触碰磁盘。

(c) LSM 把 compaction 成本摊销：合并异步发生，不在用户写路径上。

对持续高写吞吐，LSM 结构上优于 B+ tree。点查方面，B+ tree 延迟更低（一次 I/O）；LSM 需要检查多个 SSTable（Bloom filter 有帮助）。

**Q4.** 为什么 Cassandra 默认每个物理节点 256 个 vnode？它解决了什么问题？

提示

负载分布。没有 vnode 时，单个物理节点可能落在环上稀疏区域，从而承担不成比例负载。

**答案：** 朴素一致哈希（每个物理节点一个位置）中，每个节点的负载等于它在环上的“弧”（从它到下一个顺时针节点）。随机放置意味着某些节点的弧远大于其他节点；弧大 2 倍的节点得到 2 倍查询，带来磁盘和 CPU 压力。

12 个随机放置节点中，最大弧通常是平均值的 2-3 倍。即最忙节点 QPS 是平均节点的 2-3 倍，对应磁盘和 CPU 压力。

每个物理节点 256 个 vnode 时，每个物理节点在环上有 256 个随机位置。一个物理节点拥有的总弧是 256 个随机弧之和；依大数定律，它接近期望值（环的 1/N）。负载分布均匀得多。

第二个好处：新物理节点加入时，从多个现有物理节点取 vnode（因为新节点的 256 个 vnode 分散）。数据移动分散到整个集群，不集中在少数邻居。这使再平衡更快、更平缓。

256 是参数；合适值取决于集群规模。大集群可每节点少 vnode（100 节点集群用 1024 vnode 每节点即每节点 10 个 vnode，通常足够）。小集群需要更多 vnode 每节点以获得好分布。Cassandra 默认 256 是因为它在典型集群规模下平衡了均匀性与令牌管理开销。
