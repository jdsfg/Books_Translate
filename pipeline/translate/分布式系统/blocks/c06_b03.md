### 6.4 CLOS 与 Leaf-Spine 拓扑

现代数据中心内部，网络不是交换机树，而是 _CLOS 网络_（以 Charles Clos 命名，1953），2026 年实现为 _leaf-spine_。

结构：

* **Spine switches** ：顶部少量高带宽交换机。
* **Leaf switches** ：许多低成本交换机，每个都连接到每个 spine。
* **Servers** ：连接到 leaf；每台服务器有多个 leaf 以提供冗余。

性质：

* **Any-to-any bandwidth** ：任意服务器到另一服务器的流量只经过一个 spine hop。任意划分服务器之间的 bisection bandwidth 远高于经典树形拓扑。
* **无超额订阅**（理想版）：leaf 到 spine 的总上行带宽与 leaf 到服务器的总下行带宽匹配。
* **Equal-cost multi-path（ECMP）** ：一台服务器到另一台服务器的流量可走多条 spine 路径之一，网络在它们之间做负载均衡。

Leaf-spine 取代经典三层网络（core、aggregation、access），因为三层的超额订阅模式在 core 产生带宽瓶颈，限制了东西向（服务器到服务器）流量，而这正是分布式系统产生的。

对分布式系统工程师的实践含义：

* 同数据中心 RPC 延迟由序列化和排队主导，而非网络。在 CLOS 内，延迟下限是微秒级。
* 网络 bisection bandwidth 很少是瓶颈。磁盘 I/O、CPU 和应用层协调通常是。
* 跨机架与同机架 RPC 延迟相近（差几微秒）。网络局部性不如应用设计重要。


### 6.5 RDMA

Remote Direct Memory Access 让一台服务器的 NIC 直接写入另一台服务器的内存，无需目标 CPU 参与。数据中心两种实现：

* **RoCE（RDMA over Converged Ethernet）** ：2026 年最常见；跑在以太网上，用 PFC（Priority Flow Control）保证无损交付。
* **iWARP** ：基于 TCP 的 RDMA；较少见，但因容忍有损网络而更容易部署。

性能：RDMA 延迟约 1-2 微秒（同数据中心），而 kernel-bypass TCP 约 50-100 微秒。内核不参与其中；NIC 处理数据移动。

用途：

* **分布式内存数据库**（Microsoft FaRM，曾是 Azure Cosmos DB 的基础）用 RDMA 以类似内存的延迟做跨节点内存访问。
* **ML 分布式训练** 用 InfiniBand 或 RoCE 上的 RDMA 跨节点移动 GPU 梯度。
* **分布式 LLM 推理**（第24-26章）用 RDMA 在 prefill 与 decode 节点之间移动 KV cache。

RDMA 不是银弹。它需要精心网络配置（无损保证、PFC 调优）、应用必须使用 RDMA 原语（one-sided puts 和 gets），且失败模式与 TCP 不同。对大多数应用层分布式系统，RDMA 过度；它存在于存储和 ML 层，那里的延迟提升 justify 运维成本。
