正确答案应讨论前缀索引方法、缓存新鲜度跟踪、负载感知，以及若有缓存层如何集成。单行 “hash-and-route” 是原型级答案；生产需要更多。

更深观察：推理集群优化是 2026 专业领域。给出原型级答案的 LLM 遗漏了领域深度。正确 LLM 回应应问：“你的提示结构是什么？多少租户？有缓存层吗？当前缓存命中率多少？我可以基于这些 specifics 设计路由策略。”

对 Continuum 部署，路由逻辑是数千行手写代码，为工作负载精细调优。LLM 生成的朴素实现会低 50% 以上。在正确路由实现上的投资通过效率收益回报。


### 本章总结

LLM 请求路由与 Web 请求路由有结构差异：KV 缓存局部性、长度相关放置、模型可用性、更宽的尾部延迟。LLM 专用路由优化（KV缓存感知、长度预测）带来显著效率收益。

KV缓存感知路由：负载均衡器维护缓存 KV 缓存的前缀索引；把请求路由到有缓存的节点。对前缀重工作负载（系统提示、代理 scaffold、function-calling 模板）的重大收益。

长度预测路由：预测请求输出长度；长输出请求路由到专用 “sustained” 节点；短请求去 “burst” 节点。防止长请求阻塞短请求导致尾部延迟放大。

投机解码：小草稿模型提出 K 个 token；大验证模型并行检查 K 个；接受前缀输出。在验证模型层面 2-3 倍吞吐。分布式变体（草稿在便宜硬件，验证在大 GPU）独立扩缩；适合大集群。

多租户公平性：加权公平调度按客户权重分配 GPU 时间。防止饥饿；支持 SLA 层级。Continuum 使用分层加权公平调度。

Tobias 的完整优化栈：disaggregation + KV 缓存 sharding + KV缓存感知路由 + 长度预测路由 + 分布式投机解码 + 加权公平调度 + 按引擎选择（vLLM/SGLang）。结果：集群利用率 85%（从 60%）、每请求成本降低 40%、年节省 500-600 万美元。
