#### 概念检测

**Q1.** 什么是分布式追踪？每个跨度携带哪些信息？

提示

追踪是跨度树。每个跨度携带追踪 ID、跨度 ID、parent 跨度 ID、时间戳、状态、属性。

**答案：** 分布式追踪是单个分布式请求的因果记录：请求触发的跨服务工作链。它结构化为跨度的树（或 DAG）；每个跨度代表一个工作单元。

每个跨度携带：

* **追踪 ID**：该追踪内所有跨度共享；全局标识追踪。
* **跨度 ID**：该跨度唯一。
* **Parent 跨度 ID**：标识该跨度的父节点；根跨度为 null。
* **服务名称和操作名称**：哪个服务、哪个操作。
* **开始时间和持续时间**：跨度何时开始、持续多久。
* **状态**：成功、错误，可带错误码。
* **属性**：自定义键值对（HTTP 状态、数据库查询、应用自定义元数据）。
* **事件**：跨度内的时间戳日志条目（状态变化、错误、里程碑）。

单个追踪的所有跨度通过追踪和 parent-跨度 ID 组装，形成可视化显示的树结构。

**Q2.** 为什么跨服务边界传播追踪上下文至关重要？

提示

没有传播，子跨度无法链接到父跨度；追踪会碎片化。

**答案：** 追踪上下文（追踪 ID、parent 跨度 ID、采样决策）是父跨度和子跨度之间的链接。没有传播：

* 接收请求的服务不知道请求属于哪个追踪。它创建新的追踪 ID；工作看起来与原始请求是分开的追踪。
* 父子关系丢失；追踪树碎片化。
* 采样决策不传播；子跨度可能未被采样而父跨度被采样（或相反），导致不完整追踪。

结果：不是一条展示完整因果链（原始请求和所有下游工作）的追踪，而是许多断开的片段。调试变得不可能，因为你无法跟随请求路径。

传播通常通过 HTTP 头部（W3C 标准的 `traceparent`）或消息队列元数据（Kafka 头部、AWS SQS 属性）。OpenTelemetry 库对常见框架自动处理；自定义协议需要显式传播逻辑。

纪律：每次跨服务交互都必须传播追踪上下文。异步交接（队列、定时任务）需要通过异步机制显式传播上下文。没有这种纪律，分布式追踪产生碎片化的追踪，误导性大于帮助。

**Q3.** 什么是基于头部的采样与基于尾部的采样？各自何时适用？

提示

基于头部的：在根处决策；传播决策。基于尾部的：缓冲跨度，追踪完成后决策。

**答案：** _基于头部的 sampling_ ：采样决策在追踪起点（根跨度）做出。决策（是否采样）通过追踪上下文传播给所有子跨度。要么追踪所有跨度都被采样，要么都没有。
