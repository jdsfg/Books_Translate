### 12.1 哈希 vs 范围分片

把键映射到节点有两种根本不同的方式。


#### 哈希分片

每个键被哈希；哈希值决定分区（即节点）。哈希函数固定；键到分区的映射是确定性的。

优点：

* **负载均匀分布** ：好的哈希函数把键均匀分散到分区，无视键倾斜。
* **路由简单** ：任何节点都能算出“哪个分区拥有此键”，无需查表。
* **无顺序键热点** ：即使键是顺序的（自增用户 ID），哈希也会打散。

缺点：

* **不支持范围查询** ：“给我 A 到 Z 之间所有键”需要咨询每个分区。
* **无范围扫描局部性** ：逻辑相关的键（同一用户的数据）可能落到不同分区。

用于：Dynamo、Cassandra（默认 partitioner：Murmur3Partitioner）、Redis Cluster。


#### 范围分片

键排序；每个分区拥有一个连续范围。分区边界存在元数据里（协调者、路由表）。

优点：

* **范围查询高效** ：范围查询只触及覆盖该范围的几个分区。
* **局部性** ：逻辑相关的键（按用户 ID 排序）落在同一分区。

缺点：

* **顺序键热点** ：自增 ID 都落到最新分区；该分区在分裂前承担所有写。
* **路由需要元数据查找** ：客户端必须知道每个分区持有哪个范围；元数据必须复制并保持最新。

用于：HBase（HBase 的存在理由就是对宽行做范围扫描）、CockroachDB（默认）、Spanner（per-tablet）、TiKV。


#### 2026 年混合方案

现代系统常同时提供两者。CockroachDB 默认范围分片，但表可显式按 `crdb_internal` shard key 哈希分片。Cassandra 是哈希分片，但提供 partition key + clustering columns，使同一 partition 内数据有序（在哈希 partition 内实现局部范围查询）。

选择取决于工作负载：纯 OLTP 点查偏向哈希；分析扫描偏向范围；混合工作负载需要通过 per-table 配置获得两者。
