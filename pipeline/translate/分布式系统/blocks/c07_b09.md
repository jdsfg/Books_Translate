BFT _是_ 正确选择时：区块链系统（不信任的验证者）、云厂商在威胁模型内的公有云系统、有监管要求必须具备拜占庭韧性的金融系统。

2026 现实：BFT 主要与区块链相关（Aptos、Sui、Diem 后代、Cosmos via Tendermint）。对传统分布式系统用例（配置存储、数据库、协调），Raft 仍是运维默认。

**Q3.** 为一个 2 进程共识示例走一遍 FLP 不可能性证明直觉。证明中对手起什么作用？

提示

对手控制消息交付。在纯异步中，对手可无限延迟一条消息。证明存在“二价”状态，协议无法决定。

**答案：** 两个进程 P1 和 P2 各提议一个值。P1 提议 0；P2 提议 1。协议必须决定 0 或 1。

对手控制消息交付。协议执行取决于消息交付顺序。_二价_ 状态是指协议仍可决定 0 或 1，取决于未来调度。

初始状态是二价的（协议尚未收到任何消息；两种决定都可能）。证明表明：从任何二价状态出发，都存在某种调度到达另一个二价状态，永不到达 _一价_ 状态（决定被强制）。

关键论证：协议正要从二价过渡到一价（即将承诺决定）时，该过渡由某条特定消息触发。对手无限延迟该消息。协议必须等待，而等待期间可能收到其他消息使状态重新二价。

对手的威力在于任意延迟。纯异步中对手有无限延迟。协议无法区分“P1 已崩溃”和“P1 消息被永远延迟”，因此不能在没有 P1 输入的情况下安全决定。但等 P1 可能永远等不到。

逃脱：部分同步中 GST 后对手有界。协议可在超时后声明怀疑某进程并无需它做出决定；超时是有界的，因此终止有保证。
