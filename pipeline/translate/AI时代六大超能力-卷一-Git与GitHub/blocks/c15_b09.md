#### 深入思考

**Q1.** 有人坚持说：“Git 是程序员的工具。历史学家**能**用它，并不表示她**应该**用它——她用普通文字处理器加上小心备份会更好。”这个人在哪些地方有一部分道理，又在哪些地方错了？

提示

他们这个说法最强的版本，谈的是摩擦和习惯，不是能力。把“它能不能帮上忙”和“对这个人来说，新增的结构值不值得”分开看。

**讨论：** 要把这个反对意见按它最强的形态来理解，因为一张隐藏沼泽的地图会让人迷路。这个人**说对了**的是，这个工具不是免费的：它增加了 1 个习惯（做快照、写说明、按分支思考），而对于非常小或很短命的项目，这种结构的成本可能高过它带来的回报。1 封 3 页信不需要相册。他们也说对了：对于 14.5 中的 2 个泥潭，这个工具确实是**错误**选择；如果某人的“项目”主要是巨大的图片，那么文字处理器加备份可能正是正确答案。但在 Dr. Okonkwo 的情形上，他们错在关键处：1 个 400 页、历时 3 年、根据导师反馈不断修订的东西，正是那种“文件夹里一堆副本”的做法会悄悄失效的场景：版本被覆盖，理由被遗忘，大胆的重构从未尝试，因为它可能毁掉当前草稿。“小心备份”不会给你分支，不会给你一段可读的**为什么**的历史，也不会阻止覆盖灾难；它只会给你更多副本，让你淹没其中。诚实的立场就是本章始终坚持的立场：收益来自**工作的形状**（庞大、长期、经常修订、有时协作、由文本或小文件构成），而不是制作者会不会写代码。让工具匹配工作的形状，而不是匹配职业。

#### 对你的 AI 这样说

本章安静的胜利在这里：**没有新的请求需要学习。** 回头看看从第 2 章以来你收集的每一个白话请求：“做一个我能回来的快照”，“开一个单独的分支，让我尝试一次有风险的重组”，“把它合并回来，并告诉我有没有东西相撞”，“把两个版本都给我看，让我选择”，“把今天的快照发布到我们的共享副本”，“在我批准前，用白话带我看清这次改动实际改变了什么。”它们中的每 1 个，都可以原封不动地用在 Dr. Okonkwo 的论文、Rosa 的价目表、食谱盒、你的网站上。你不会因为项目是散文而不是代码，就换一种说法。你说完全相同的话，你的智能体做完全相同的工作。这就是本章的全部证明，而你已经拥有它。

本章退场的恐惧，是本书里最古老的那个恐惧，也是让你一路读下来时心里仍怀疑“这一切其实是给别人用的”的那个声音：**“这只适用于代码。这是给专家的。不是给我做的东西用的。”** 这不是真的，而现在你知道它为什么不是真的：工具不在乎文件里是什么；它只在乎工作的形状。你现在可以敢于拿起你制作的最重要的东西，那份手稿、价目表、合同、你一直过分小心对待的收藏，把它放到这张地图下面，让智能体做你的双手，然后终于不再害怕触碰那些已经能运转的东西。唯一诚实的提醒，仍沿用 14.5：在涉水前认清那 2 个泥潭，这样你就会把工具指向它真正擅长的工作。
