### 8.3 什么是备份，什么不是

现在说清楚那个诚实的边界，而且它足够重要，所以我们要说得直白一点。

把你的项目放在一个仓库里（一本相册，在你的一台机器上），**不是备份。** 它从来都不是。仓库保护你免受你在工作**内部**犯下的错误：糟糕的编辑、后悔的删除、失败的重组。这些它处理得很漂亮。第 4 章就是完整演示。但它对机器本身死亡这件事完全无能为力。如果硬盘坏了，而相册一直只在那块硬盘上，相册就会和它一起死掉，连同所有快照。那段历史就和第 1 章里 Maya 的三段文字一样彻底消失。死盘上的一个快照，就是烧毁房子里的一张照片。

把它说成一条你能握住的规则：

> **一个仓库只有生活在第二个地方时，才是备份。**

“丢了一台笔记本什么也不会丢”的魔力，不是仓库里的魔力。它是**第二个地方**里的魔力。一台机器上的一本完整相册，离遗忘只差一杯洒出的咖啡。两台机器上的两本完整相册，或者一台机器和互联网上一个工作间里的两本完整相册，就是一个能在失去任意一边时存活下来的项目。真正重要的数字，不是你的版本控制有多好。而是多少个独立地方保存着一份完整副本。一个地方不是备份。两个地方才是备份的开始。

这就是为什么第 3 章悄悄提醒你，相册“还不是备份”，并指向这里。现在你可以看到完整的形状了。版本控制给你一段历史。远程给这段历史第二个家。只有第二个家才让它成为备份。两半都必要；单独任何一半都不够。

所以，当你设置一个项目时，普通话请求有两部分，你永远不该把它们分开：**保留一段历史**（第 2 章的相册）和**把它保存在不止一个地方**（本章的远程）。只在一个地方的历史珍贵而脆弱。在两个地方的历史珍贵而安全。
