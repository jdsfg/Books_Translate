#### 概念检查

**Q1.** 不回看 §16.2，说出 3 个预检问题，并为每一个描述 Maya 和 Theo 这个贯穿示例中的一个时刻，说明提出它如何改变了结果。

提示

这 3 个问题分别关于**改变**、**可逆性**和**共享**。其中一个最戏剧性的使用，是第 15 章的险些出事。

**答案：** 这些问题是 (1) **到底会改变什么？**，(2) **我们能回去吗？**，以及 (3) **这段历史已经被共享了吗？** 对应时刻：第 1 个问题在 Maya 批准陌生人的修正之前阅读 diff 的每一次都被训练，她用白话询问拟议改动实际改变了什么，然后才点头。第 2 个问题让她从最早的快照开始就能勇敢地删段落：答案可靠地是能，所以删改不再可怕。第 3 个问题抓住了那次险些出事：智能体正要改写已经发布到共享工作坊的历史，而“这被共享了吗？”这个问题正是把一场安静灾难变成一次停止的原因。如果你能说出 3 个问题，并能给每一个连上一个时刻，你就拥有了判断层；这比任何命令都更有价值。

#### 应用题

**Q1.** 拿一个你自己的真实项目，不是指南，而是你的项目；它现在可能只是一些散文件或一个单独文档。用白话让它走完整张地图，从什么都没有到第一次外部贡献。每一步都说出你会给智能体的请求。从“我从未给它做过快照”开始，到“一个我从未见过的人提出了改进，而我已经审阅它”为止。

提示

顺序大致就是本书的顺序：第 1 个快照，然后历史，然后为大胆改动开的分支，然后第 2 个地方，然后工作坊，然后 issue，然后你审阅的一项拟议改动。§16.2 里已经有那 14 句话；这个练习就是为**你的**东西选择哪些句子、按什么顺序使用。

**答案：** 一个好的走法是这样。首先：“做一个我能回来的快照，并说明它的用途”，现在这个项目有了一个永远不会跌破的起点。然后，几次工作之后：“把历史按列表显示给我，用白话说明”，相册就存在了。当一个大胆改动诱惑你时：“开一个单独的分支，让我尝试这个，而不碰那个能运转的版本”，之后再说“把它合并回来，并告诉我有没有东西相撞。”当你想要安全和第 2 个地方时：“把今天的快照发布到我们的共享副本，但保持私有。”当你准备好面向世界时：“把这个放进工作坊，先设为私有。”当读者发现问题时：“为它开一个 issue”，然后，当他们提出修复时：“在我批准之前，带我看清这项拟议改动实际改变了什么。”准确句子没有你能否生成它们重要；重要的是你现在能看着任何你在乎的项目，看见从散文件到活着的、可修正的、共享工作的整条安全路径。如果你能为自己的项目按合理顺序说出这些请求，你就已经完成了本书唯一要求你做的事。
