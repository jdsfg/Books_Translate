### 章节总结

Núria 的修正到来时，不是作为一封需要重新输入的邮件，而是作为一个等在指南里的拟议变更；需要 Maya 做的是决定，而不是打字。她请自己的智能体用白话带她看一遍，而她原本以为会迎来的那堵符号墙，最后变成了一句普通的话：删掉一家已经关门的咖啡馆，加入一家新咖啡馆，修正一个错字，其他地方都没动。这种白话阅读就是 **diff**：**用白话说，就是发生了什么变化**，也就是项目现在的样子和变更进入后项目会变成的样子之间的精确差别，不多也不少。它比任何描述都更诚实，因为它不是对变更的总结；它就是变更本身。

Maya 把 3 个预检问题指向别人的工作，而它们顺畅地翻译了过来：**到底会改变什么**，就是用白话读 diff；**我们能回得去吗**，就是确认批准也只是另一个可以追溯的快照；**这段历史有没有分享出去**，让她安全地站在追加而不是改写的一边。然后她做了那件把 审阅 和机械盖章区分开的事：她问了一个温暖、清楚的问题（新咖啡馆真的在 Alfama 吗？），而这个变更变得比对话开始时的任何一个版本都**更好**。这就是本章建立其上的真相：审阅 不是找错，而它最好的结果也不是拒绝。它是一场让工作变好、让理解扩散的对话；一个项目的质量存在于这场对话里，而不是存在于它的行数里。

这里点名、并将在第 15 章回头讨论的危险，是批准你没有读过的东西；这种诱惑会随着信任而变得**更强**，因为朋友的名字出现在提案上，会让阅读看起来没有必要，而这正是在阅读最重要的时候。你的 同意 认可的是变更，不是这个人；它会把你的理解带进历史，不管你到底有没有理解。所以每一次都要读 diff；它只花一分钟，而且这就是整份工作。当你是被 审阅 的那个人时，也要把澄清问题当成它本来的样子来接收：一份“第二份判断”的礼物，回答“抓得好”，而不是防卫。

你进入本章时担心，读别人的变更需要你并不具备的专业知识；离开时你知道，它只要求你用白话询问变更内容，并思考你读到的东西。你现在敢做的，是说出一个真正的 同意：一个确实属于你的批准，一个基于理解而不是基于侥幸点头的批准。接下来，在第 12 章，变更开始来自不止一位朋友：我们会看一起工作的各种**形态**，从你和你的智能体，到一个小团队，再到开源里的那个动作：一个陌生人拿走你作品的一份自己的副本，改进它，再把它交回来。
