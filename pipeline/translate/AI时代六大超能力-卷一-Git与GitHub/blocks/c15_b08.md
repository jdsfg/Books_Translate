#### 应用题

**Q1.** 一个以剪辑婚礼视频为生的朋友听说你对这一切很兴奋，于是说：“太好了，我终于可以把我十年的 raw 素材放进版本控制了。”你会温和地告诉他们什么？对于同一个朋友也保存的**脚本和分镜清单**，你又会告诉他们什么？

提示

来自 14.5 的两个不同文件类型，有两个不同答案。把素材和文字分开。

**答案：** 温和地说，不行；素材不行。Raw 视频正是第一片沼泽：巨大的二进制文件，没有可比较的行，所以工具无法显示它们内部“改了什么”，也无法在快照之间便宜地共享未改变部分。十年的 raw 素材放进 Git 相册，会膨胀到接近存储许多份近乎完整的巨大文件，而相册会变得又慢又痛苦。那是错误的工具，而且确实有专门为大型媒体资产做版本管理的工具。**但是**脚本、分镜清单、客户合同、剪辑笔记，这些全都是文本，也都很小，非常适合放进相册。你的朋友可以给有风险的重剪计划创建分支，保留每一版合同的清晰历史，再也不覆盖掉分镜清单。诚实的答案不是“是”或“不是”；而是“素材不行，但描述素材的文字绝对可以。”这种精确性就是 14.5 的完整教训。

**Q2.** 轮到你了。选一个你自己的、与代码**毫无关系**的真实项目——比如一份手稿、一门你教授的课程、一组法律模板、一个花园计划、一份共享家庭预算。把它走一遍这张地图：你会先做哪个快照？有什么你一直害怕尝试的大胆更改现在可以创建分支？里面有没有一个两个人的碰撞，是冲突可以替你保护的？

提示

在那个大胆更改上使用三个起飞前检查问题：到底会改变什么？能回来吗？这段历史已经共享出去了吗？如果三个问题都有答案，你就被允许勇敢。

**答案：** 没有唯一正确答案，因为这个练习之所以有效，正是因为它是**你的**；但一个好的答案包含三部分。第一，一个**第一个快照**：项目今天的状态，带一句诚实说明（“state before the big revision”），仅此就能消除你可能会丢掉现有内容的恐惧。第二，一个**你会创建分支的大胆更改**：那个重构、重写、实验；你一直避免它，**正是因为它可能毁掉能用的版本**，而现在你认识到分支让尝试它变得免费，因为安全版本只差平静的一步。第三，如果还有别人会碰这个项目，一个**冲突会保护你的碰撞**：你和共同作者可能编辑同一行的那个时刻，在那里工具停下来请你选择是一种善意，不是失败。如果你能为一个自己真正关心的项目填满这三项，你就完成了这本书存在的理由：你已经把一张围绕一对伴侣的指南书搭建的地图，独立地走进了你自己的生活。而你没有用到任何一个命令。
