#### 应用题

**Q1.** 一位好心的贡献者 fork 了你的指南，并打开了一个拟议变更；它在同一个包里：(a) 添加一个屋顶酒吧小节，(b) 用你不喜欢的声音重写你的开头段，(c) 修正一个确实错误的电车号码。用白话、不使用任何命令，你会对他们说什么？本章的礼仪暗示他们本该怎么做？

提示

这 3 件事里，有 2 件你可能想要；有 1 件你不想要；而它们全都焊在一起，所以你不能只拿其中一件而不拿其他件。如果这位贡献者遵守了哪一条礼仪规则，事情本来会变得很容易？

**答案：** 他们打破的礼仪规则是**保持每个变更小而聚焦**，每个提案只放一个想法。因为他们把 3 件无关的事情捆在一起，你就无法接受电车修正（这显然是好的）而不同时吞下引言重写（这是你不想要的），这会迫使你拒绝整个东西，或者开始一场协商。一条体面的回复，既尊重维护者的决定权，也尊重贡献者的努力，可以像这样：“谢谢你；电车修正确实是对的，我很希望单独接收它；屋顶酒吧小节很有意思，我们可以分开谈；引言我会保留现在的版本，但真的很感谢你花时间做这些。”然后你会请他们（或请你的智能体）把好的部分拆成各自聚焦的提案。注意，整个混乱本来都可以避免：3 个分开的小提案，每一个都能得到清楚、快速的 同意 或 拒绝。这正是为什么“小而聚焦”是第一条规则——这是对必须做决定的那个人的一种体贴。

**Q2.** 你发现了一个小型公共项目——一份社区无障碍徒步路线清单，其中有一个错误细节：它把一条路线列为轮椅可通行，但路线中途有一段楼梯。你以前从未给任何人的项目做过贡献。用意图层面的白话走一遍你会使用的三步循环，并说明你会在“为什么”说明里写什么。

提示

这个循环是 fork → 修改 → 提回。你不是在请求访问他们的项目；你先拿走自己的一份副本。而“为什么”说明是你让维护者容易说 同意 的地方：如果你是他们，你会想知道什么？

**答案：** 用白话说，这个循环是：第一，拿走他们项目的一份完整副本，这样你可以编辑它而不碰到他们的项目（fork）；第二，在你的副本里修正那一个错误细节（修改）；第三，把这个修正作为一个他们可以 审阅 并接受的拟议变更，提回给原项目（提回）。你的“为什么”说明应该短、具体，并带有证据，因为它承担着所有说服工作：“这条路线被标为轮椅可通行，但在中途的人行桥那里有大约 10 级台阶；我上周日走过。建议把标签改成‘部分无障碍’，并加一条关于楼梯的说明。”这条说明给了维护者有把握说 同意 所需的一切：哪里错了，你怎么知道，以及你具体提议改成什么。还要注意，勇气阶梯在这里转动起来：给一个陌生人的公共项目做一行修正，“真正的项目是给专家的”这种恐惧，消解成了 5 分钟的普通善意行动。
