### 7.4 同一个故事，不以一对搭档为前提

这里没有任何东西只属于写作搭档，只属于一本指南，甚至只属于两个人。冲突只是这样一种情况：两个独立的改动伸手去碰同一个东西，而这个东西正被一个版本工具看管。值得在离 Maya 和 Theo 很远的地方看看这个形状，这样你才会相信，重要的是形状，而不是故事。

想象一篇博士论文的两位共同作者；一个是学生——Dr. Okonkwo，我们之后会花真正的时间谈她的论文——另一个是她的导师。导师在自己的分支上阅读时，把论文的中心论点改得更谨慎。学生在她的分支上，把完全相同的句子改得更有力，因为有了新的数据。当他们的工作被编织到一起时，工具发现，对整篇文档中最重要的那个句子，出现了两种不同的重写。它不会在“谨慎”和“有力”之间选择，因为那正是这篇论文的整个智识问题，而工具看见边界标记时，知道那是一条边界。它停下来，展示两边，并让两个人去谈。这正是应该发生的事。冲突并没有阻碍他们的学术工作；它**迫使他们进行学术本来就需要的对话。**

或者想象 Rosa 的面包店，Rosa 和她的合伙人 Ana 在同一个下午都更新了价格表：Rosa 把酸面包提高一欧元，她的合伙人则修改同一行来添加批量折扣。两次编辑，一个价格。工具停下来并发问。现在花十秒钟问一句，比印出一份写着两个人都没想表达的内容的菜单要好得多。

在每一种情况下，模式都完全一样。两个改动，一个位置，一次诚实的停顿，一个人的选择。工具从不决定你的工作应该说什么。它只保证，当两只手相遇时，会由一个人来决定，而且没有任何人的手会被悄悄拨开。


### 7.5 练习

这些问题会请你预测工具如何行动，并在你真正接触它之前，推理它为什么那样行动。认真想一想每个问题，然后阅读讨论。


#### 概念检查

**Q1.** 用你自己的话说，为什么一个好的版本工具会在冲突处**停下**，而不是直接选择一个版本然后继续？如果它“聪明”到总能替你选择，你会失去什么？

提示

想一想工具知道什么、不知道什么。它知道两个版本意见不一致。它知道哪一个**对你的项目更好**吗？谁知道？

**答案：** 工具停下来，是因为它碰到了一个它确实没有能力回答的问题：两个相互冲突的改动中，哪一个**对你的工作**是正确的。它知道文本不一致；它不知道你的书、你的论证，或你的意图。如果它“聪明”到总能选择，它就不得不猜，而每一次猜错，都会悄悄删除你真正想要的那个版本，没有警告，也没有痕迹。你会失去的是最重要的一件事：保证任何人的任何一部分工作，都不会在没有人类先看到的情况下消失。一个从不产生冲突的工具并不更聪明；它更危险，因为它已经悄悄任命自己为某些决定的裁判，而那些决定它并不能理解。暂停不是工具愚笨。暂停是工具诚实地承认自己能力的边界。
