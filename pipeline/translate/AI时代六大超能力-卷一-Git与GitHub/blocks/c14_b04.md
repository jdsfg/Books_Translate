### 13.4 这个项目还活着吗？阅读生命体征

阅读陌生人的项目寻找答案，以及向它们贡献，都会在你抵达某个项目的那一刻提出一个实际问题：**我应该信任它吗？有人在家吗？**一个开放中的项目可能被用心维护着，也可能是一座美丽的废墟，四年前就被人遗弃了。你需要能够快速判断，而且不需要阅读它内容中的一行，就能做出第一层估计。工作坊里的每个项目都会把生命体征戴在外面。

其中三个承担了大部分工作。

**星标。**星标就像书签加点赞；人们点击它，是在说“这个值得记住”。很高的星标数是一个粗略的人气信号，意味着很多人觉得它有用。它不是质量证明，也很容易被过度解读，但一个被成千上万人收藏的项目至少不算冷僻。把它看成围观人群的规模，而不是评委的裁决。

**开放议题。**记住，议题是被报告的问题或请求。一大堆议题并不自动是坏事，因为忙碌、受欢迎的项目会吸引很多议题。你要读的是**模式**：议题有没有被回答和关闭，还是有几百个在无人回复的情况下放了多年？维护者会出现并回应的议题列表，是项目活着的迹象。一片被忽视报告的墓地，则是警告。

**最后提交日期。**这是最有说明力的单一迹象，也是最容易检查的。最后一次添加快照是什么时候？如果答案是“上周”，就有人在照料它。如果答案是“三年前”，你看到的很可能是某个被遗弃的东西：也许仍然有用，但没有人会来修你的问题，或审阅你的贡献。对“它还活着吗？”这个问题来说，最近一次 commit 的日期就是脉搏。

你要把这些放在一起读，而不是一次只看一个。一个有 40,000 个星标、但四年没有 commit、并且有 900 个无人回应议题的项目，是一座著名废墟：曾经出色，现在成了博物馆。一个有 400 个星标、最后一次 commit 是昨天、维护者会在一天内回应议题的项目，则更有生命力，也更适合你发送第一份贡献，因为真的会有人看见它。那个陌生人选择修正 **Rainy-Day Lisbon** 时，也是在以自己的方式阅读它的生命体征：一份本月更新过、作者显然仍在照料的指南，是值得修正的指南。死掉的指南，他就会放着不管。

你可以让你的智能体阅读这些迹象，并用一句话总结，比如“这个项目上一次被触碰是在两年前，而且有一长串无人回应的议题；它看起来已经被遗弃了”。这正是你在依赖某个人的工作，或准备一份没人会读的贡献之前想要得到的朴素判断。
