#### 应用题

**Q1.** 一位协作者给你们的共享项目提出了一个变更，你的智能体用白话这样总结 diff：**“这会删除引言的后半部分，大约六句话，并在最后一节新增一个结尾段。它还修改了价格表里的 3 个价格。”** 你原本只期待引言里有一个小小的措辞修正。读到这个 diff，你会在批准前问什么，为什么？

提示

把 diff 显示的内容和你原本期待的内容相比较。两者之间的差距，就是你的问题所在。应用“到底会改变什么？”

**答案：** 你会询问那些你没有预料到的部分，也就是其中的大多数。你期待的是一个小小的措辞修正；diff 显示的是引言后半段被删除、一个全新的结尾段被加入，以及 3 个价格被修改。每一项都值得提出合理的问题：**“我原本以为只是调整一下措辞，所以你能带我看一下为什么要删掉引言的后半部分吗？”** 另外还要单独问：**“这 3 个价格变更不是我们讨论过的内容——这些数字是从哪里来的？”** 价格变更尤其需要核对，因为错误的价格会对真实读者造成具体伤害。这个练习的重点在于一种纪律：你读了 diff，把它和自己的预期相比较，而**两者之间的差距**正是好的澄清问题所在。如果你跳过阅读，只根据“小改引言”的描述就批准，那么你从未同意过的 3 个价格现在已经进入项目了。这就是第一个预检问题，**到底会改变什么？**，在别人的变更上发挥作用。

**Q2.** 练习这条回复。一位朋友发来了一个确实有帮助的拟议变更，但其中一部分让某一节的长度翻了一倍，而你不确定这些额外内容是否值得占据这个位置。写下你会留在这个提案上的那一条消息，就像 Maya 写给 Núria 的那样。

提示

先表达温暖，再提出一个清楚的问题，并把它和作者能够评估的理由联系起来，同时让决定保持开放。这不是判决，而是一次对话。

**答案：** 可以是这样的形状：**“这确实是一个改进，谢谢你——有一件事我想一起想清楚：这里的博物馆小节长度大约翻了一倍，而我一直想让每一节都短到适合边走路边在手机上读。有没有一种版本可以保留最好的两个新增点、删掉其余部分，或者你觉得完整长度确实值得保留？我真心对两种方向都开放。”** 注意这些部分。开头是真诚的温暖，因为对方帮了你的忙。它提出**一个**关切，而不是散弹式的一串意见。它把关切和作者能够实际权衡的理由联系起来，也就是“短到适合边走路边在手机上读”，而不是赤裸裸的个人偏好。它还让决定保持协作，邀请一个更好的版本，而不是命令对方照做。这就是作为对话的 审阅：最可能的结果既不是你的版本，也不是对方的版本，而是你们一起走到的第三个、更好的版本。
