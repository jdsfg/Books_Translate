#### 应用题

**Q1.** Maya 想要拿回一段被删掉的段落，但她的第一反应是说“把整个引言还原到上周二”。如果她真的这么做，会出什么问题？把她的请求改写成她实际想要的、更安全的说法。

提示

从上周二到今天之间发生了一整周的编辑。把**整个**引言还原，会把所有这些编辑一视同仁。她想保留的是哪些？

**答案：** 把整个引言还原到上周二，会把整个部分往回拖一周：银色光线那段是恢复了，没错，但她从那以后对引言做的其他每一处改进也会一起被撤销。她会找回一个段落，同时失去七天无关的打磨。（她并不会**永远**失去它们；它们仍然待在链条里，可以恢复。但她会制造一个不必要的烂摊子，之后还得清理。）更安全的请求就是她真正想要的那个：**“带我回到上周二引言的样子，让我看看，但不要丢掉今天的工作；我只是想把一个段落带到现在。”** 这是访问加取回，不是还原。它有每个安全请求都具备的两部分形状：要去拿什么，以及不要失去什么。

#### 深入思考

**Q1.** 本章说，日常“撤销”的方式是**添加**一个新快照，而不是抹掉那些你后悔的快照，所以你的错误会永远留在历史里。有些人的第一反应是，这听起来更糟，而不是更好：谁想永久记录每一次走错的路？请为只追加历史为什么是一项功能提出最有力的论证，同时也诚实说明它真正的一个代价。

提示

想想“抹掉你的错误”也会抹掉什么。也想想 4.5 中，改写历史的能力是在什么时刻变成危险之物的。

**讨论：** 最有力的论证是：一段你不能偷偷改写的历史，是一段你可以**信任**的历史。如果撤销真的抹掉了过去，那么过去就是可编辑的；而一个可编辑的过去，是你永远无法完全依赖的过去：你永远无法确定相册展示的就是实际发生过的事，因为某个人（也许是上个月很累的你）可能已经悄悄改写了它。只追加给你买来的是确定性：记录是真的，因为它只能增长；修正一个错误意味着添加一条诚实的新记录，而不是篡改旧记录。正是这种确定性，让**回到过去**变得平静。你访问上周二，而且你可以相信你看到的东西，因为没有什么能伸手进去改动它。那些看得见的错误转弯，是一份可信记录的代价，而这笔交易很划算；没人给你的历史打分，真正重要的读者只有未来的你，而未来的你会感激这条路径完整而诚实，而不是被修整成讨人喜欢的虚构。唯一真正的代价，就是 4.5 标出来的那个：正因为一段真实、永久的历史如此有价值，那些**能够**改写它的操作也相应危险，值得第 15 章给予的特别谨慎。这个功能和它的锋利边缘，是同一个事实的两面。
