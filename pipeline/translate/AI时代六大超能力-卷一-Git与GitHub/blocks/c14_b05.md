### 13.5 做出你自己的第一份贡献

陌生人的修正通过展示它可以有多小，教会你自己的第一步。你不需要会构建任何东西。你需要能够注意到某件事不对，并以公地共同认可的礼貌方式提议修正。

这个形态是你在前几章已经认识的，只是现在指向了整个世界。你找到一个你使用并依赖的项目。你发现了某件事：说明里的错别字、一个坏链接、过时的步骤、错误的电车号码。你拿一份自己的副本（也就是 fork），在里面做那一个小修正，然后把它作为可审阅的修改提议回原项目。维护者阅读你的提议修改，然后接受它，或提出问题，或拒绝。如果他们接受它，你的修正现在就成了全世界陌生人都会使用的东西的一部分。你为公地添加了内容。

那段话里所有机械性的事情，都是你的智能体的工作。你用朴素的话告诉它你注意到了什么、想提议什么，它会处理复制、修改和提议。但有两件事仍然属于你，而它们正是你读这本书而不是读一本手册的全部理由。第一是**注意到**：除非有一个真正坐过那趟电车的人说出来，否则没有智能体能知道电车是 28 路而不是 12 路。第二是**发送前的判断**：阅读你自己的提议修改，确认它表达的是你的意思；当你向别人的项目提出贡献时，先看一眼许可证，确保你知道自己是在你理解的条款下贡献。向一个活着的项目提出一行文档修正，就是一份完整而体面的第一份贡献。几乎每个人都是从这里开始的。就从这里开始。


### 13.6 练习

这些练习是用来思考和预测的，不是用来计算的。读完每一题，静静想一想，然后再读讨论。


#### 概念检查

**Q1.** 一位朋友说：“我在开放中找到了一个很棒的项目。我能读到它的每一行，所以我把整个东西复制进自己的产品并发布了。”这个推理的缺陷是什么？

提示

把两件事分开：能够**看见**作品，和被允许**复用**作品。“我能读到每一行”证明的是哪一个？

**答案：**能够阅读一个项目，只能说明它是可见的，并不能说明你可以自由复用它。复用由许可证决定，而不是由可见性决定；一个附带**没有**许可证的项目，是受限制的情况，而不是自由的情况，因为许可从未真正被授予。在把任何东西复制进自己的产品之前，你的朋友需要检查许可证，并确认它允许这种使用。如果它是宽松型（类似 MIT）许可证，只要保留所要求的声明，它很可能允许。如果它是相同方式共享（类似 GPL）许可证，把它装进封闭产品并发布，可能会违反条款。“我能看见它”回答的是另一个问题，不是“我是否被允许拿走它”；把两者混为一谈，是最常见的开源错误。
