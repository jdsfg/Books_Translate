#### 常见误解

**“太好了，所以现在我已经学会 Git 了。”**

并不完全是；这个差别很重要，因为它正是本书能够守住承诺的原因。

你没有记住一个工具。你获得了一张**地图**和一种**请求方式**，这比任何工具都更持久，因为工具会变化。你今天使用的具体智能体会被替换。触发快照的准确措辞会漂移。工作坊的网站会重新设计按钮。GitHub 本身，作为 2026 年最大的工作坊，也不能保证 10 年后仍然最大；本书曾经提到 GitLab 和 Codeberg 一次，并且没有忠诚地绑定任何一方，正是因为地图不等于地图上的某一个地址。

不会改变的是你真正学到的东西：快照是你整个项目的一张照片，并带有说明为什么的备注；分支是平行宇宙，绝不是副本；历史一旦被共享，就不能悄悄改写；一项拟议改动是 diff 加对话加决定；在批准任何东西之前，你要问会改变什么、能不能回去，以及这段历史是否已经被共享。这些不是命令。它们是一种看法，而当你交谈的智能体和你对它说的话都变得面目全非时，它们仍然为真。如果你忘掉上面账本中的每一句具体话，但保留那个**形状**——你想要什么，以及你绝不能失去什么——你就可以通过提问重建整份账本。这就是价值。丢掉命令不会让你损失什么。丢掉地图，才会让你失去工作。

### 16.3 永远带着这 3 个问题

这份账本底下有一个小习惯，值得最后一次命名，因为它是你在合上书后带走的部分。任何让你迟疑的改动之前，问 3 个问题：

  1. **到底会改变什么？** 不是“相信我，没事的”，而是用白话说明这个动作实际改变了什么。如果你的智能体说不清，或者你听不懂答案，那就是该慢下来的信号，而不是点头的信号。
  2. **我们能回去吗？** 几乎总是能，因为历史是一条可以重访的链，而回去会添加一个新快照，不会擦掉旧快照。少数诚实答案是**不能**的时候——改写历史，或覆盖发布别人的工作——正是这个问题存在的目的。
  3. **这段历史已经被共享了吗？** 这是整本书里最重要的单一问题，因为它是“我的私人实验，我可以自由改写”和“我们的共享记录，别人现在正建立在它之上，我不能在他们脚下悄悄改变它”之间的分界线。第 15 章的险些出事，归根结底就是这个问题没有被问出口。

Maya 不再把这些看作清单。它们只是她现在看待改动的方式，就像一个谨慎司机会检查后视镜，却不必把动作念出来。目标正是这样：不是你遵守的一条规则，而是你拥有的一种本能。当它变成自动反应，你就拥有了判断层，而判断层是这里没有任何智能体能替你完成的部分。智能体拥有词汇。你拥有这 3 个问题。这个分工就是整个安排。
