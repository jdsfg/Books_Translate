上一章里，Theo 大胆的重组回到了家。他花了一周时间，把指南从按天气组织改成按街区组织；这件事发生在他自己的平行版本里，在那里，他做的任何事都碰不到正在工作的那本书。等它准备好后，智能体把他这一周的工作编织回主指南，而那个下午最令人惊讶的，是几乎什么都没发生。没有戏剧性场面，没有手工调和，也没有 Theo 从第 1 章起就害怕的“两份版本都坏掉”的噩梦。智能体读了两条工作线，看到它们碰到的是书中不同的部分，然后把它们缝合成一份。当两条线穿过不同位置时，编织是自动的。你几乎注意不到它。

有一种情况不是自动的。那就是两个并行工作的人伸手去改同一个句子。它也是分支故事的最后一块，终于让本书里最古老的恐惧安静下来。

Maya 和 Theo 在一个星期二遇到了它，地点是指南的第一行。


### 7.1 同一个句子，两种写法

《雨天里斯本》的开头那一行一直不太对，他们两个人都知道。所以他们两个人，在没有告诉对方的情况下，都决定去修它。

Maya 在她的分支上，把它改得温暖而亲近：**“当天空转灰时，我们行走的就是这样的里斯本。”** Theo 在他的分支上，把同一行改得简洁而充满承诺：**“潮湿午后里的四十种小乐趣。”** 谁也不知道对方碰过它。每个人都以为自己在改善一行没人正在处理的文字。两个人对于自己的版本都是对的。两个人都让这本书朝着自己的方向更好了一点。

然后他们请智能体把两个分支编织到一起。

现在请你站到工具的位置上想一想，因为这就是整章的核心。在书的其他地方，两组编辑碰到的是不同的句子，所以编织它们很明显：拿 Maya 的新咖啡馆段落，拿 Theo 重新排序后的章节，两者都保留，完成。但在这里，在这一行上，出现了对**完全相同的词句**的两种不同重写。工具不能两者都保留，因为一个句子不能同时说两件不同的事。它也没有办法知道 Maya 和 Theo 更喜欢哪一个。它不了解这本书。它不知道他们已经围绕语气争论了好几个星期。它只知道，在它期待一个答案的地方，它找到了两个，而且它们不一致。

所以它做了唯一诚实的事。**它停下来，并发问。**

它不会因为 Maya 编辑得更近就选她的那一行。它不会因为 Theo 的分支更大就选他的那一行。它不会把两者平均成某种既不温暖也不简洁的糊状东西。它不会悄悄保留一个、默默丢掉另一个，直到书印出来才有人注意到。它拒绝猜测。它并排呈现两个版本，标出它们意见不一致的确切位置，并把决定交给人，因为这个决定从来就不是机械决定。它是关于这本书应该**听起来是什么样**的决定，而只有知道这本书用途的人，才能做出这个决定。

这种“停下来并发问”的行为，有一个专门的名字。
