#### 应用题

**Q1.** 你和一位合作者没有提前协调，却都重命名了共享文档里的同一个小节：你把它叫作“Getting Around”，对方把它叫作“Transport”。你的智能体开始把你们两个版本编织到一起。用普通话预测一下会发生什么。智能体会回来告诉你什么？

提示

同一个位置，被朝两个不同方向改了两次。这和 Maya 与 Theo 那句开头有什么不同吗？

**答案：** 这是一个冲突，智能体不会替你选择。它会报告说其余部分都顺利编织到一起了，但这一个小节标题同时被重命名成了两种不同写法；它会把“Getting Around”和“Transport”都展示给你，然后等待。没有东西坏掉；两个名字都被安全地保留下来，文件在那个位置会暂时同时带着两者，并用标记隔开，直到有人做决定。你会像 Maya 那样解决它：选一个，或者写第三个（比如“Getting Around Lisbon”），然后告诉智能体选哪一个。这里最重要的预测是：智能体回来是在**询问**，不是在**宣布出了错误**。它没有失败，你也没有失败。它只是发现你们两个人对同一个标题意见不一致，并且拒绝自己打破这个平局。如果你预测的是“智能体悄悄保留其中一个”，请重读 7.1：冲突存在的目的，正是防止这种悄悄保留带来的灾难。

**Q2.** 你的智能体完成了两个分支的编织，并报告：“Everything merged cleanly, no conflicts.” 一个朋友听到后说：“看吧？冲突就是 bug；一个表现良好的工具永远不会有冲突。”你朋友的推理错在哪里？

提示

“这次没有冲突”说明了**这几处具体编辑**的某个事实。它能说明工具质量如何吗？

**答案：** “没有冲突”并不表示工具表现良好；它表示这两组编辑刚好没有碰到同一个位置，所以把它们编织起来没有歧义。这是关于**编辑**的事实，不是关于工具的事实。只要两处改动真的重叠，同一个工具立刻就会提出冲突，而这正是你希望它做的事。你的朋友把事情想反了：冲突不是工具有时会犯的 bug，而是工具在需要的时候专门启用的一项安全功能。一个“不管你扔给它什么都永远没有冲突”的工具，只能靠悄悄丢弃每个重叠处的一边来做到这一点，而这恰恰是你最该害怕的行为。干净的合并和冲突，是同一台诚实机器的两种正确结果：没有重叠时干净合并，有重叠时报告冲突。
