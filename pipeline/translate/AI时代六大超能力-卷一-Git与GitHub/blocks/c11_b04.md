### 10.3 为什么说这是伟大的社会发明

我答应过要配得上这个说法，所以这里给出完整论证。

人与人之间在没有完全信任彼此时遇到的每个重要协作问题，归根结底都落在同一种张力上。你想得到别人工作的好处，也想保持对自己工作的控制。这两个愿望会彼此拉扯。打开门，你就失去控制；把门关上，你就失去帮助。人类制度花了几个世纪建造复杂的机器（编辑、委员会、签核程序、审批链）来管理这种确切的张力，而所有这些都很慢，其中大多数也很沉重。

对于人们正在创造的一大类事物，而且这一类还在扩大，拉取请求用一个干净的动作解决了这种张力。它通过让更改变得**具体**，让对话**与更改待在一起**，并让接受成为一个**有意做出的决定**，而不是一次无声的覆盖。把这三个性质逐一来看，因为每一个都在真正发挥作用。

**具体。** 因为提议是精确的 diff，而不是含糊的建议，所有者可以在几分钟内审阅它，并准确知道自己将同意什么。没有歧义需要解决，没有“她指的是第三个项目还是第四个项目”。更改**就是**它自己的说明。这正是让你能够接受从未谋面之人贡献的原因：你不是在信任这个人，而是在检查这个更改，而更改会把一切都告诉你。

**对话与更改待在一起。** 因为讨论附着在相关的精确行上，建议就没有缝隙可以掉进去。理由、问题、“其实我们就用 Núria 建议的那家吧”，以及最后的同意，全都永久地一起存放在它们所谈论的东西旁边。一年以后，这份记录会自己解释自己。拿它和埋在某个谁也找不到的邮件线程里的决定相比。

**接受是有意做出的决定。** 因为什么都不会改变，直到所有者说“是”，所以无论有多少陌生人提出东西，所有者都不会失去控制。默认状态是**没有更改**。改进需要某个有权限的人主动、有意识地说“是”。这种反转，也就是无事发生是安全的，而改变需要一个决定，正是你为了把作品开放给不认识的人所需要的安全性。

把这三者放在一起，你就解决了人类创造中一大片古老的问题：陌生人如何在既不彼此信任、也不淹没于摩擦的情况下改善彼此的工作。这就是为什么现在有数亿人每天都在这样做，也为什么这个数字还在持续上升。它不是一个编程功能。它是一种人类协作的方式，三十年前几乎不存在，如今却像水一样自然。Maya 和 Theo 正在写的指南从来没有一行代码，而这项发明完全适用于他们。
