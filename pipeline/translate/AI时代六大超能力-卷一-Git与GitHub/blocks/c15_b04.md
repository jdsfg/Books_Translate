#### 常见误解

**“版本控制是程序员的东西。只有带代码的文本真正受益；电子表格或合同不一样。”**

这正是整章要消除的信念，所以让我们精确地拆开它。

这个误解来自**人们最初遇见这个工具的地方**。几乎所有人都是在编程语境里听说 Git，所以他们很自然地得出结论：这个工具是**给**编程用的，就像你可能因为看到拿着钉枪的是屋顶工，就断定钉枪是给屋顶工用的一样。但这个工具并不知道，也不在乎文件里面是什么。它给一个项目拍照，追踪它随时间怎样变化，让你创建分支、合并、看到哪里不同。一篇论文会随时间变化。一张价格表会随时间变化。一份合同、一个网站、一部小说、一套家规：它们全都是人在时间中制作、放在文件里的东西，而人们害怕碰到已经能用的部分。它们每一个都能从同样四个动作中受益。

那么**真正的**限制在哪里？不是你是不是会写代码。它在两个具体东西上：**文件类型**和**工作流程**，而这两者才是整个工具诚实的边界。我们会在 14.5 转向它们，它们远比“代码”和“非代码”之间任何想象出来的界线重要。牛角面包并不在乎 Rosa 不会编程。Git 也不在乎。

### 14.3 家庭食谱集：夫妻共同编辑

Priya 和 Sam 多年来一直在整理一套家庭食谱集：Priya 祖母的菜、Sam 母亲的菜，还有他们自己的孩子现在会点名要吃的那些东西。这是他们两人最私人的项目，而且他们一起编辑它，就坐在同一张厨房桌边，用两台笔记本。

这是最小可能的团队：两个彼此相爱、但会争论 dal 是否需要第二根辣椒的人。而从结构上说，它正是你在 Chapters 5 through 11 学到的同一种协作，只是更温柔。

他们把这套食谱集放在一个相册里，活在不止一个地方，所以洒了一杯茶也不会丢东西。当 Sam 想试着把整个“工作日晚餐”部分重做成“按你有多累来分”，这是一次大胆重组，Priya 还不确定时，他不会在抽象层面为它争辩。他给它创建**分支**，在一个平行宇宙里搭出“疲劳程度版”，再把完成后的东西给她看。她可以在他们任何一个人都没有冒险碰到能用版本之前，看见它的整体。如果她喜欢，他们就把它合并进来。如果她不喜欢，他就离开那个分支，而食谱集和原来一模一样。大胆想法不再变成争吵，而变成你可以看一看的实验。

而关于辣椒的分歧——两个人在同一个晚上编辑同一道 dal 食谱——就是一个冲突，解决方式和所有冲突一样：两个版本被显示出来，由人类做选择；这一次伴随着笑声，而不是恐慌，因为他们现在都明白，工具停下来询问是一种**善意**。它是在保护他们各自写下的版本。没有人的祖母会被覆盖掉。

我把这个例子放进来，是因为它是本章最朴素的项目，却最有力地证明了这一点。如果夫妻共同编辑一个食谱盒也能从分支和冲突解决中受益，而它显然可以，那么“这个工具是给程序员的”这个想法就完全是错的。它适合任何和别人一起制作任何东西的人。
