#### 对你的智能体这样说

这里是一个清单里的第一条；这个清单会随着一章章推进，长成一页可以直接对你的智能体说的白话。每一条都是一个**想要**，用普通话说出来。它们都不是要你背下来的命令。命令智能体知道；你的工作是知道自己想要什么，并检查它带回来了什么。

* **“在你改任何东西之前，先做一个我能回来的快照，并记下它是做什么用的。”**

这句话让我们在第 1 章点名的那种害怕退休了：害怕碰坏已经能用的东西。你不再需要一文件夹让人紧张的副本，也不再需要因为怕出事而不去尝试那个大胆的改动。你可以用白话标出一个干净的落脚点，然后再往前走。你现在敢做的事很小，但它是一切的转轴：你可以**不用先做副本就开始编辑**，因为你有了比副本更好的东西，而且你知道怎么开口要它。


### 2.5 练习

和第 1 章一样，这里没有机械训练。这些问题会请你预测工具会做什么，用白话读懂一个情境，并练习把一个想要变成一次请求。先和每一道题待一会儿，再去读后面的讨论。


#### 概念检查

**Q1.** Maya 在写完引言后给这本指南做了一个快照。一个小时后，她把引言彻底重写了一遍，又做了第二个快照。有人对你说：“所以现在第一个快照只记得那篇引言，第二个快照也只记得新的引言。”这句话到底错在哪里？

提示

回头看看定义。快照拍下的是你正在编辑的那个文件，还是更大的东西？

**答案：** 错在“只”这个意思上，而且错了两次。每一个快照记住的是那个时刻的**整个项目**，不是只记住 Maya 碰巧正在编辑的引言。第一个快照保存的是带有第一版引言的整本指南；第二个快照保存的是带有重写引言的整本指南，也包括她从未碰过的每一章、每条图注和每张照片。这不是技术细枝末节。正因为如此，她以后才能回到“一个小时前的整个项目”，并发现一切彼此一致，而不是只把某一个文件孤零零地恢复回来。快照永远是项目的快照，从来不是某一个文件的快照。
