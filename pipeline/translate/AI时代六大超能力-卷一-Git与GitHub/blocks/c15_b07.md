#### 沼泽二：实时共同编辑，就像共享文档

想象 Priya 和 Sam 在**同一瞬间**编辑同一道食谱，看着彼此的光标移动，每一次敲键都实时出现在两块屏幕上。共享在线文档做的就是这个：那种你们两个人在同一秒里往同一个页面里打字，而它持续地、一个字母一个字母地合并，没有快照，也不询问。

Git 不是这样工作的，也没有试图这样工作。它的整个设计正相反：你工作，你决定**这是一个有意义的时刻**，你做快照，发布它，别人获取它。它是刻意的、轮流的，围绕经过考虑的检查点构建，而不是连续的实时打字。正是这种刻意，让它适合论文或合同，因为在那里你想要一段由认真版本组成的清晰历史，也想要当两个更改碰撞时有人类在场。对于实时一起头脑风暴一个段落来说，它又正好是**错误的**，因为在那里你想要摩擦消失，光标跳舞。

这些是不同工作的不同工具，没有哪个是另一个的低配版。如果你想要的是两个人实时在同一个页面里打字，那就使用为此打造的共享文档工具。如果你想要的是有意义版本的认真历史、给大胆实验创建分支的自由，以及当两个更改真正冲突时由人类选择，那就是这个工具，而且没有别的工具能像它一样做好。错误不在于选择其中一个。错误在于期待其中任何一个变成另一个。

注意，这两片沼泽都不是“你必须是程序员”。两者都关乎**文件类型**（文本和小东西，好；巨大二进制文件，差）以及**工作流程**（经过考虑的检查点，好；连续实时共同输入，错误工具）。这才是边界的真实形状，而且它对程序员和 Rosa 都一样。

### 14.6 练习


#### 概念检查

**Q1.** Dr. Okonkwo、Rosa、Priya-and-Sam，以及网站制作人，大多使用了**同样**四五个动作。不要回头看，说出至少在四个场景中的三个里出现过的核心动作，并用朋友能理解的一句话说明每个动作是**用来做什么的**。

提示

不要列命令。列想法：那张照片、那个平行版本、那次合并、需要人类选择的时刻、工作活在不止一个地方。

**答案：** 反复出现的动作有：**快照**（给整个项目拍一张照片，并附上为什么的说明，这样没有任何版本真正丢失）、**分支**（一个平行宇宙，让你尝试大胆的东西，而不碰已经能用的版本）、**合并**（把成功的实验带回主版本）、**冲突**（当两个人编辑同一行时，工具拒绝默默选赢家，于是由人类选择），以及活在**不止一个地方**（所以掉落的笔记本或洒出的茶不会造成损失）。这个练习的重点，是感受到这些不是四个项目的四套工具；它们是**同一张**地图，形状不变地适配了一篇论文、一张价格表、一个食谱盒和一个网站。如果你能说出每一个是**用来做什么的**，你就已经拥有了 Chapter 1 里那个酸性测试所要求的东西；即使明天忘掉每一个命令，你仍然会拥有它。
