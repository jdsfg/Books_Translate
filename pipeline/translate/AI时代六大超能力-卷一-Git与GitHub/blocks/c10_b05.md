#### 定义：Issue（议题）

**Issue 是附在项目上的一条单独、可追踪的备注，它说的是“这里有件事需要处理”（一个 bug、一个问题、一个请求、一个想法），并且被放在工作所在的地方，所以不会丢失。**

Issue 不是对项目的修改。它不会改变文件里的任何东西。它是一场**有主题行、有归属位置的对话**。它有一个标题（“Alfama 咖啡馆条目过时了，那家店已经关门”），有一段描述，Núria 在里面说明她看到了什么、什么时候看到的；更关键的是，它就放在**指南自己的页面上**，出现在未处理 issue 的列表里，直到有人把它标记为完成。它不依赖任何人记得一条短信。它被记录在案，就在它所关心的工作旁边。

有三件事让 issue 不同于一条短信，而且每件事都很重要。

它**附在工作上。**关于那家关门咖啡馆的备注存在于指南页面上，而不是在 Maya 可能一周都不会打开的聊天应用里。任何有访问权限的人都能一眼看到未处理的 issue：这些就是这个项目仍然需要处理的事情。

它是**结构化的。**Issue 有标题、正文、作者、日期和状态：未处理或已解决。你可以在它下面进行对话，一条评论接一条评论，而整段对话都会跟着这个 issue 留在那里。六个月后，“我们为什么删掉了那家 Alfama 咖啡馆？”这个问题的答案就在原处。

而且它**不是修复本身。**这是微妙但重要的一点。Núria 的 issue **报告**了问题；它并没有**解决**问题。打开一个 issue，是在说“应该有人看看这里”，这和真正修改指南是清楚分开的两个动作。这种分离是一种特性。它意味着任何人都可以提出关切，而不需要知道怎么修复；Núria 不必碰指南的文件，就能告诉 Maya 有地方不对。她只需要描述自己看到了什么。修复的工作在之后发生，而且那是另一种动作。

Maya 在指南页面上看到这个 issue 出现时，感觉到一种微小而新鲜的东西。一个项目之外的人（好吧，是朋友，但不是正在写它的人）伸手进入共享的工作坊，把一张备注准确地留在了它该在的地方，并且以一种她不会弄丢的形式留下。这个指南因为有了读者而变得更好了。而这一切是通过工作坊发生的，不是在工作坊之外绕着发生的。
