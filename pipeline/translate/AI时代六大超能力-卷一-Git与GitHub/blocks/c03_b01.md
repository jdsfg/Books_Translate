在那个丢掉的星期六过去几周后，Maya 坐下来打开那份指南，完全出于习惯，她的手先伸向了自己总是最先做的那件事。保存一个副本。重命名。`rainy-day-lisbon_before_edits.docx`，这样不管她接下来一小时把什么东西弄坏，工作版本都会还在那里，没被碰过，像一份防备自己的小保险。

然后她停住了，因为 Theo 前一晚给她看过一种做法，而她想试试他的方法。

她不打算制作副本。她要改为拍一张快照。这听起来像是同一件事换了个词，最初几分钟也确实感觉像同一件事。但它不是同一件事。它是一种全新工作方式的开始，而到本章结束时，你会在自己的手上感觉到这种差异。


### 2.1 副本与照片

想想文件夹里的一个副本到底是什么。它是你的文件的第二个完整版本，放在第一个旁边，占着自己的空间，顶着一个你匆忙发明出来的名字（`before_edits`、`v2`、`use_this_one`），而一个月后你根本不会知道它是什么意思。它没有带着任何说明，解释你**为什么**制作它。它不知道自己和其他文件有关。它只是一团相同字节，挂着一个紧张兮兮的名字；它全部的工作，就是在灾难发生时存在着。

快照是另一种对象。当 Maya 为指南拍一张快照时，她并不是制作第二份指南。她是在请求工具**记住此刻整个项目的准确样子**——每一章、每一条图片说明、每一张照片、这份工作的完整状态——并把这份记忆归档，同时附上两样东西：精确时间，以及一小段她用自己的话写下的说明，说明这个时刻**是什么**。“完成了引言的新语气。”“加入了 Alfama 咖啡馆，还需要 Theo 的照片。”“在我尝试删掉博物馆那一节之前。”

这条说明不是装饰。这条说明才是整个重点，也是文件夹里的副本永远给不了她的东西。

原因在这里。六个月后，Maya 的副本文件夹什么也不会告诉她：七个叫 `FINAL` 的文件，不知道哪个是哪个，也不知道它们之间改了什么，又不敢删掉任何一个。但一串快照读起来像这份工作的日记：**完成引言。加入咖啡馆。删掉博物馆那一节，然后第二天又放了回来。**她可以用自己写给未来自己的普通句子，读完整个指南如何变成指南的故事，并落到她想去的任何一个时刻。副本是一堆东西。快照是一条叙事。
