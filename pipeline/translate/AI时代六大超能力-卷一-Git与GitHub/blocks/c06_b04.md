### 5.4 在安全的东西旁边尝试大胆的东西

模型理顺之后，再看 Theo 的周末实际会变成什么样。

周五晚上，他让智能体为街区重组开一个分支。它瞬间完成；主指南没有被碰。整个周末，他都完全在那个平行宇宙里工作：重新分组步行路线，把天气建议折进每个街区，重写章节标题。他一路创建快照，并写下诚实的说明：**把 Alfama 和 Graça 重组进同一个街区章节；把雨天博物馆推荐移到每个街区内部。** 与此同时，Maya 在 main 上修复一个坏掉的图片说明，并把引言打磨得更锋利。他们谁都没有踩到谁。两个宇宙，一个周末。

周日，Theo 从头到尾读了一遍重组后的版本。现在，他**知道**了自己之前只是怀疑的事：它更好。街区骨架让整本指南感觉像是由一个站在你身边的街头向导写出来的。他是对的，而且他花一个周末建出了答案，而不是花一个周末担心它。

或者，假设他错了。假设街区版读起来更差，步行路线被切得零碎，天气逻辑丢失了。那么周日晚上，他只要走回 main，停止再想这个分支。主指南还是周五时的样子，因为它从来没有被碰过。不是受损后修复。**从来没有被碰过。** 失败的实验不会留下疤痕。他不是在一次代价高昂的绕路之后“回到起点”；从 main 的角度看，那次绕路从未发生。

这种不对称就是礼物。一个成功的分支给你一本更好的书。一个失败的分支只花掉你尝试时投入的时间，除此之外没有任何代价：没有清理，没有对齐，没有一个受伤的 main 版本需要护理回健康。当尝试的下行风险只是“我花掉的尝试时间”时，大胆实验就不再是勇气之举，而变成普通好奇心的举动。人们说分支让他们可以无畏工作，意思就是这个。那不是虚张声势；那是算术。

这也不是代码专属的事。一个小说家想试着把自己的书从第三人称改成第一人称，这个改动会触碰每一页，可能大获成功，也可能彻底失败。到目前为止，她面对的正是 Theo 的困境：改写真正的手稿并冒着毁掉它的风险，或者复制整份手稿，手动管理两个逐渐漂移的版本。分支也是她的出路。她打开手稿的一个平行宇宙，用一周时间把它改成第一人称，读一遍，然后要么把新的声音带回家，要么转身离开，而她的第三人称小说完好无损。工具不知道，也不在乎它保存的是一部小说，而不是一本指南。任何你能创建快照的项目，你都能创建分支。
