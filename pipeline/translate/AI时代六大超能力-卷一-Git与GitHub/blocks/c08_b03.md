### 7.2 Maya 实际看到的内容

当 Maya 请她的智能体把两个分支编织到一起时，智能体带回来的不是一本完成的书，而是一份小而平静的报告：**“这些内容已经干净地编织到一起，只有一个地方例外。你和 Theo 都用不同方式重写了开头那一行。我不会替你选择。它们在这里。”**

然后它把那一行的两个版本展示给她。她的版本，热情迎接。Theo 的版本，利落明快。书的其余部分，几百处编辑，他的整个重组，她的新段落，都已经毫无阻碍地编织在一起。整个指南里，冲突只有一个句子。

在下面的实际文件中，工具会用一点脚手架式的标记来标出有争议的位置：一些符号把“这里是 Maya 的版本”和“这里是 Theo 的版本”围起来并分隔开，让分歧的确切边界不会弄错。你不需要记住这些标记长什么样，也几乎永远不需要自己输入它们。重要的是这个东西的形状：文件在发生冲突的位置，会暂时同时保存**两个**候选版本，并清楚地分开，等待某个人保留一个、保留另一个，或者写出一个同时吸收两者的新版本。你的智能体可以像 Maya 的智能体那样，用普通语言把这些展示给你，所以你很少会看到原始的脚手架标记。脚手架标记是工具在说：**你们两个人正是在这里意见不一致，而我已经把两边都保留下来，好让你决定。**

Maya 读了两行。然后她做了一件工具永远做不到的事：她思考了这本书。Theo 的那一行在承诺；她的那一行在欢迎。她决定第一句话应该欢迎，**第二句**应该承诺，于是她决定用一种解决方式：先用她温暖的那一行开头，再让 Theo 简洁的那一句紧随其后，作为后续推进。她告诉智能体：“两句都保留：我的在前，然后他的作为第二句。”智能体把这个选择记录为一个快照，并附上一条说明原因的备注，冲突就结束了。现在，这本书有了一个比他们任何一个人单独写出的版本都更好的开头。

这就是解决冲突的意思：一个人阅读两个版本，然后做出决定。有时你保留自己的。有时保留他们的。有时，像 Maya 那样，你写出一个尊重两者的新版本。工具的全部贡献，就是确保你能睁着眼睛做这个选择，而不是三周之后才发现某个人一半的工作已经消失了。
