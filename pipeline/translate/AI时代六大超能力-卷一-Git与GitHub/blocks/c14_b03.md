#### 定义：开源许可证（要点层面）

**开源许可证**是附在项目上的标准法律文件，它授予陌生人在明示条件下使用、复制、修改和分享作品的许可。你会遇到的大多数许可证，都属于两个宽泛家族：

* **宽松型（类似 MIT 的形态）。**要点是：**几乎可以用它做任何事。使用它、修改它、在它之上构建，甚至把它放进你出售的东西里；只要保留原始声明，不要声称是你写的。**它要求的回报很少。它是公地里“请自便”的一端。

* **相同方式共享 / copyleft（类似 GPL 的形态）。**要点是：**你可以自由使用和修改它，但如果你分发自己修改后的版本，它必须在同样条款下继续保持开放。**改进会回到公地，而不是消失在封闭产品里。它是“把善意继续传下去”的一端。

两者都是真正开放的。它们的差别在一个问题上：**当你基于它继续创作并把作品传给别人时，你的版本也必须继续开放吗？**宽松型说不用，由你选择。相同方式共享说要，保持开放。其他一切都是实际文本里的细节；再次说明，真正算数的是实际文本，而 choosealicense.com 会带你看懂它。

对于 **Rainy-Day Lisbon**，Maya 和 Theo 像讨论任何共同决定一样把这件事谈清楚。他们希望人们阅读它、修正它、翻译它，并自由分享它。他们并不特别介意有人在它之上做出自己的东西。他们想要的是得到署名，并让这本指南在名称上仍然属于他们。宽松型许可证适合这一点，于是他们告诉自己的智能体添加一个，并先把它的朴素语言摘要指给他们看，让他们明白自己正在同意什么。陌生人的修正现在有了清楚的落脚之地：他一直被允许复制和提议，现在这件事被写下来了。


#### 常见误解

**“开源意味着没有规则；只要是公开的，任何人都可以对它做任何事。”**

这个想法会让人栽跟头，而且它错了两次。

第一，**公开可读**并不等于**可以自由做任何事**。一个你能看到的项目，不会自动成为一个你能复制、销售或并入自己作品的项目。事实上，一个发布出来但**没有**附带许可证的项目，默认情况下是最受限制的情况，而不是最自由的情况：没有明示许可，通常就意味着许可并未被授予，哪怕你能看见每一行。开放是由许可证创造的，不是由可见性创造的。

第二，即使是最宽松的许可证也有条款：保留声明，不要歪曲作者身份。公地并非无法无天；它依靠一组很小、很清楚、每个人都可以预先阅读的规则运转。这正是它能在数亿人的规模上运作的原因。“没有规则”不会成为公地。那会变成一个没有人能够安全贡献的地方。许可证让开放变得可信。
