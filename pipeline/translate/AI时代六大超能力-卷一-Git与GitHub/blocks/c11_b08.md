### 本章小结

朋友的咖啡馆修正，起初是第 9 章里的一个 issue，后来变成了一个拉取请求：对指南提出的一项更改，连同它会改动什么的精确说明、围绕它的讨论，以及是否接受它的决定，全都放在同一个地方。这种打包就是它的发明。它让一个人可以把一项改进完整做完并交给别人审阅，同时所有者仍然保有接受或拒绝的唯一权力；它也解决了一个古老的张力：既想得到别人的帮助，又想保持对自己作品的控制。

最应该记住的一点是：拉取请求本身什么都不会改变。它只是提出建议。真正的项目会原封不动地保持原样，直到有权限的人有意接受它；提出与接受之间的这种分离，正是让你可以放心向陌生人开放作品而不冒风险的安全性。拉取请求是具体的（一个精确的差异，而不是含糊的建议），它的对话和更改放在一起（建议不会掉进缝隙里），接受也是一个有意识的决定（默认是不改变）。这三个性质合在一起，正是为什么如今数以亿计的人用这种方式改进彼此的作品，也正是为什么它配得上被称为这个时代伟大的社会发明：一种人类协作的新形状，既适用于城市指南，也适用于任何程序。最重要的是，拉取请求是一场对话，而不只是被丢进盒子里的一段代码。

接下来，在第 11 章，Maya 会做最重要的那一部分：她阅读朋友提出的更改，用白话准确理解它改了什么，提出一个澄清问题，然后作出决定。阅读一项更改并妥善决定是否接受它，本身就是一种技能，也是一种文化；所有共同创作之物的质量，最终正是从这里产生的。
