### 本章小结

这本指南放在互联网之外的第三份副本，结果不只是一个安全措施。它给了项目一张脸和一个地址，也改变了这个项目可能成为的样子：它不再只是两个人小心保存的私人物品，而成了一个读者可以伸手进来、让它变得更好的地方。

这个地方就是工作坊；截至 2026 年，其中最大的一类是 GitHub：它是若干建筑中的一座（GitLab 和 Codeberg 也在其中），它们都依循同样的原则，所以你正在学习的地图可以迁移。最关键的区别，也正是多数人搞错的地方是：GitHub 不是 Git。Git 是工具，也是一门技能，属于你，而且可以离线使用；它诞生于 2005 年，当时 Linus Torvalds 的项目失去了对另一个工具的访问权，于是他用大约十天写出了 Git。GitHub 是建立在 Git 之上的工作坊，由 Tom Preston-Werner、Chris Wanstrath 和 PJ Hyett 于 2008 年创立，后来在 2018 年被 Microsoft 以 75 亿美元收购。这些日期是确定的历史；至于规模，则像天气一样，需要你去查当下的数字。

项目在工作坊中的页面，就是它面向公众的脸：可以浏览的文件、一份欢迎文档，以及贯穿其中、用于对话的结构化位置。其中最重要的是 **议题**：一条附着在工作上的、被追踪的单独记录，意思是“这里有件事需要处理”；它被保存在项目所在的地方，因此不会丢失。当 Núria 发现 Alfama 那家咖啡馆已经关门时，她没有发一条可能丢失的短信；她打开了一个议题，把它正式记录在案，放在工作旁边。议题报告问题；它明确地**不是**修正本身。

本章让你放下的恐惧是：被别人看见就意味着失去控制。事实并非如此；私人的工作台只会向你选择的人展示，而议题是一张按你的条件留下的便条。你现在可以大胆去做的是：把未完成的工作展示给一个可信的读者，并把他们的更正视为落在正确位置的礼物。

接下来，在第 10 章，Núria 又向前迈出一步。她不只是报告那家关门的咖啡馆；她写出了更好的段落，并把它作为一个具体、可审阅的更改提议回来，让 Maya 可以阅读、接受或质疑。这个提议有一个名字，也有一种安静的重要性：拉取请求，正是这项发明让世界学会了一起建造东西。
