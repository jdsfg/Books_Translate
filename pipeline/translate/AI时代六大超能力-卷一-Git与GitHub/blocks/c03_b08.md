#### 深入想一想

**Q1.** 在旧的“把副本放进文件夹”的世界里，合理的直觉是：副本昂贵，还会把生活弄乱，所以只有在你真的要冒险时才做一个。本章说，有了快照之后，正确的直觉正好反过来：要**经常**做快照，甚至可以慷慨一点。为什么建议会翻转？有没有可能因为快照做得太多，反而把快照做坏了？

提示

旧世界和新世界之间有两件不同的事变了：一个快照要花多少存储空间，以及什么会让一个快照**以后读起来有用**。分别想一想。

**讨论：** 建议会翻转，是因为让副本显得昂贵的那个东西消失了。文件夹副本是完整的第二坨字节，还带着一个没什么用的名字，所以做一百个副本确实浪费，也确实让人困惑。一个快照几乎不花什么空间，因为没变过的材料不会被重新复制，只会被指回原处；一个轻度编辑的项目做一百个快照，占用的空间大概也只是一个项目多一点。于是，反对频繁做快照的**存储**理由就蒸发了，而频繁的快照反而变成礼物：一条细密、标好名字的路径，你可以一步一步沿着它走回去。但确实有一种把快照做坏的方式；问题不在数量，而在**连贯性**。一个快照如果把四十个互不相关的改动捆在一起，再写一句“做了些事”，那不管你多么少做快照，它都是坏快照，因为这条说明把一团模糊说成了历史。纪律不是“少做快照”，而是“每个快照都是一个连贯、有名字的想法”。每当你完成了一个值得命名的想法，就做一个快照。如果你的说明读起来像一份诚实的工作日记，那你就做对了；今天是三个快照还是三十个，都可以。

**Q2.** 三个改动前检查问题里的第一个是“到底会改什么？”本章说，做快照是最安全的动作，因为诚实的答案是“什么都不会改”。用你自己的话解释，为什么记录某个东西并不会改变它。再想一个你**最**想要这种保证的时刻。

提示

给房间拍照不会移动家具。**记录**一个状态和**改变**它之间有什么区别？

**讨论：** 快照只是读取并记住；它不碰东西。给你的项目拍一张照片，会让项目保持原样，就像给房间拍照不会碰到房间一样。所以，对“到底会改什么？”这个问题，真实答案就是：你当前的工作什么也不会变。这也是为什么它是你永远都可以毫不犹豫先做的一步。你最想要这种保证的时刻，正是冒险之前：在一次大胆重组、一次大删减、一次也许行不通的实验之前。也正因为如此，最有价值的快照往往是在危险**之前**做的，而不是之后。它们不花什么，不改变什么，却把“我可能会把这个弄坏”变成“我有一扇标好的门可以走回来”。实际上，你是在还没需要它之前，就先把第二个改动前检查问题“我们能回来吗？”的答案存成了一个“能”。整门手艺就在这里：先做那一步免费又安全的动作，于是后面那步有风险的动作也变安全了。
