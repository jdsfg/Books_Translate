#### 应用题

**Q1.** 你的智能体告诉你，它已经准备好把你的实验合并回主版本，并询问是否应该继续。你正准备带入一周的编辑。在你说可以之前，本章说你必须问的一个问题是什么？用普通话说，你要让智能体做什么？

提示

这是三个起飞前问题中的第一个。而这个请求关乎**看见**，不是**执行**。

**答案：** 这个问题是 **“到底会改变什么？”** 用普通话提出的请求可以是这样：**在你合并之前，给我看它会把哪些东西带进主版本：什么会移动，什么是新的，尤其是有没有什么会被删除。** 只有在你确实读过那份摘要，并且它符合你认为自己做过的事之后，你才批准。之所以要在合并时特别坚持这一点，是因为合并会一次性送来大量改动，而这正是无意编辑最容易藏起来的条件。在说可以之前花十秒查看，就是把冷静的合并和糟糕的惊喜区分开的习惯。注意，这并不是不信任智能体；这是读者保留本就属于自己的判断。

#### 深入思考

**Q1.** 假设工具在两条线以不同方式编辑了同一句话时**不会**停下来。假设它总是直接保留较新的编辑，并悄悄丢弃较旧的编辑，于是每一次合并都是“自动”的，永远没有冲突。这听起来更方便。为什么它实际上会比会停下来询问的工具危险得多？

提示

想一想，“悄悄丢弃”对落败的编辑意味着什么，以及写下它的人是否会知道。把它和 Chapter 1 里的灾难比较一下。

**讨论：** 一个总是悄悄挑出赢家的工具，只是 Chapter 1 的覆盖换上了更体面的衣服。危险不在于做出了选择；选择总是必须要做的。危险在于这个选择是**悄悄**做出的，于是那个认真改写却被丢弃的人永远不会发现。Maya 花了一个晚上打磨开头句；合并悄悄放弃了它，改用 Theo 的版本，只因为他的编辑碰巧晚了几分钟；他们两个人都不知道这个损失发生过，直到几周后，书读起来比 Maya 记忆中更差，却没有人说得清为什么。那比响亮的冲突更具腐蚀性，因为响亮的冲突会被**解决**：一个人查看两边，并有意地做出选择。安静的版本在感觉顺滑的同时摧毁工作。这就是为什么“它停下来问我”是工具值得信任，而不是工具难用。版本工具能做出的最重要承诺是：**我绝不会悄悄扔掉一个人的意图**；而合并冲突初看像麻烦，实际上正是它守住这个承诺的方式。Chapter 7 会近距离展示这个承诺。
