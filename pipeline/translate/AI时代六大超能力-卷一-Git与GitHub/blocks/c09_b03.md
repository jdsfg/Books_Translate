#### 定义：克隆

**克隆**是一份项目相册的完整副本（整个历史、每一个快照、每一个分支、每一条备注），而不只是当前文件。当你克隆一个项目时，你不是在下载“最新版本”。你是在拿到整本相册，所以你的机器现在保存着一份完整、独立的历史；即使其他每一份副本都消失，你也可以从这里继续工作。

这就是为什么丢了一台笔记本什么也不会丢。Maya 的笔记本电脑是一份克隆。共享副本实际上也是一份克隆。Theo 那台死掉的笔记本电脑曾经也是一份克隆。三本完整的相册，保持同步。摧毁其中任何一本，项目仍然完整地存在于另外两本里。不存在一个“主原件”，一旦丢失就会把历史一起带走。每一份副本都是完整的。这就是这一切底下那个深刻、也有点令人惊讶的事实：在一个正确分布式的项目里，没有任何一个地方的死亡会是致命的，因为没有任何一个地方保存着其他地方没有的东西。


#### 常见误解

**“共享工作间里的那份副本只是最新版本，是当前文件的一份快照，被上传了。如果我需要历史，那历史在我的笔记本电脑上；远程更像是今天的一份备份。”**

不是。共享位置里的副本是一份**完整克隆**，是整本相册，连同历史和全部内容，和你自己机器上的副本完全一样。它不是今天文件的扁平上传。它以你的本地相册保存它们的同样形式，保存着你曾经发布过的每一个快照、每一个分支、每一条备注。这正是为什么 Theo 的新笔记本电脑可以把**整个**项目拉取下来并拥有全部内容：因为远程存的不是“今天的文件”，它存的是完整历史，随时准备把一份完整克隆交给任何提出请求的机器。

每个人一开始都带着那个旧心智模型：**上传**和**下载**。我上传当前文件，我下载当前文件，云端保存当前文件。把它放下吧。在你的机器和远程之间移动的不是文件。是快照，被添加进一本相册。每个地方保存的不是当前版本。是整个历史。一旦你把远程看作“相册的另一份完整副本”，而不是“云端里的一个文件夹”，协作的其余部分就不再神秘了。
