### 章节总结

走出囤副本的世界，这一步看起来没有那么大，感觉上却比你想的更重要：在编辑前，你不再保存另一个让人紧张的副本，而是做一个**快照**。快照，正式叫作 **commit**，是你的**整个项目**在某一刻的一张照片，并配上一条用你自己的话写下的简短说明，说明这一刻是什么。它不是你正在编辑的那一个文件的超级保存；它一次性记录所有东西，并且彼此保持一致。所以，任何一个你做了快照的时刻，都是一整个房间，你以后可以重新走进去。

快照很便宜，因为没有变化的材料会被指回原处，而不是重新复制。这意味着旧直觉正好反了：你应该**经常**做快照，而不是省着做。一个好的快照应该小（一个完成的想法）、有目的（在某个有意义的时刻做，常常是在风险之前），并且说明清楚（一个陌生人也能读懂的说明）。同样的纪律可以服务于一篇学位论文、一家面包店的价格表，或者一套食谱收藏，就像服务一本旅行指南一样好；这些都不是关于代码的事。

实际操作时，你不需要亲手操控这一切。你用白话说：“在你改任何东西之前，先做一个我能回来的快照，并记下它是做什么用的。”然后你的智能体会完成机械工作并向你汇报。你也开始把三个小小的改动前检查问题带进每一次值得认真想想的改动里：**到底会改什么？我们能回来吗？这段历史已经分享出去了吗？** 做快照，就是你第一次练习这些问题的地方，而且是在最安全的动作上练习。

接下来，在第 3 章里，这些单独的快照会开始累积起来。一张照片有用；一条按顺序排列、带着说明的照片**链条**，则是更多东西：一段可读的历史，一个记录工作如何成为它自己的完整相册，你可以像翻日记一样打开浏览。我们会见到这个相册所在的地方，并学习如何沿着项目的照片往回走，读出它的故事。
