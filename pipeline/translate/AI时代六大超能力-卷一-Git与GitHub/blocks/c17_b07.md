#### 深入思考

**Q1.** 本书从第 1 章起就坚持，有价值的技能不是命令，而是地图：知道该请求什么、该检查什么。现在你已经拥有整张地图，请论证相反观点：如果有人像 Maya 那样使用它，什么时候，如果有的话，仍然**需要**理解比地图更多的东西？这个承诺的诚实边界在哪里？

**讨论：** 诚实边界是真实存在的，假装没有边界会背叛整个项目。地图足以支撑 Maya 做的工作：她制作的东西的个人和小团队版本管理，由智能体负责机械操作，由她负责决定。它在一个巨大的范围内仍然足够：书籍、论文、价目表、网站、给陌生人项目的文档贡献。它开始吃力的地方，是本书已经小心而诚实命名过的边界。当一次改写真正会丢失历史时，“我们能回去吗？”需要你理解答案为什么是不能，而不只是听见它。当你深入一个有几十位贡献者的大型共享项目时，礼仪和失败模式会比 1 页请求能容纳的内容更微妙。还有一条更低的地板，地图无法保护你：如果你批准了自己实际上没有阅读或理解的改动，没有任何词汇能救你，因为你已经交出了唯一属于你的东西：判断。所以诚实承诺不是“你永远不需要知道更多”。它是“你需要的是地图，不是手册，而地图足以应付人们实际制作的大多数东西。”当你发现自己想要更多时，你会拥有能承接深入材料的概念：因为你理解分支、共享历史和合并**是什么**，更深的内容就有地方落脚。本书从来不是你会读的最后一本书。它是让下一本书变得可读的那本书。
