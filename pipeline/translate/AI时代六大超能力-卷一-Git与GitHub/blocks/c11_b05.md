### 10.4 拉取请求是一场对话，不只是代码

“拉取请求”这个短语里有一个陷阱，值得我们有意绕开，因为它会塑造你如何**使用**这个东西。

“请求”这个词，以及 diff 和接受这一整套装置，会让人把拉取请求想象成一个纯机械的对象：一些新文字放进一个框里，一个按钮被按下，文字被盖章纳入项目。冷冰冰、技术化、交易式。它确实可以被这样冷冰冰地使用，而一旦如此，结果就会更差。

真正让项目变好的拉取请求，是人们把它当作**对话**来对待的那些。朋友不是丢下一段编辑然后消失。她解释了自己看到的情况，给出理由，标明自己的不确定之处（“如果有更好的，随时替换”），并把门敞开。第 11 章里，Maya 也不会只是点击是或否。她会回复，问一个小问题，也许建议一种措辞，然后她们两个人会一起抵达一个比任何一方单独写出的版本都更好的版本。最后进入项目的更改，是这场对话的**结果**，不是最初被提出的那个东西。

这就是为什么拉取请求是一项社会发明，而不只是技术发明。这个对象确实容纳了一个拟议更改，但它把这个更改放在一个为人们交谈、温和分歧、打磨和达成一致而建的空间里。世界上最好的贡献，正是沿着这种形状流动的：有人提出，其他人用心阅读并回应，提出者调整，最后由一个人做出决定。代码、段落，或咖啡馆修正，几乎是其中最小的部分。慷慨、审阅和决定，才是质量真正来自的地方。

这也正是把你交给下一章的完美位置。因为 Maya 仍然必须完成最困难、也最有意思的部分：她必须**读懂**朋友提出的更改，准确理解它改变了什么，决定它是否让指南变得更好，并优雅地说“是”或优雅地说“还不太行”。阅读一个更改并对它做出决定，这本身就是一种技能，也是一种文化，而它正是第 11 章的全部主题。


### 10.5 练习

这些练习会要求你预测这个对象如何运作，并感受它的形状为什么重要。读每一道题，停下来想一想，然后再读讨论。推理会完整写出来。


#### 概念检查

**Q1.** 朋友刚刚打开了她的拉取请求，提议修正那家咖啡馆。Maya 睡着了，两天后才会看到它。在这两天里，**实际的指南**，也就是读者可以买到的那一本，看起来是什么样：已经修好，还是仍然显示那家关门的咖啡馆？

提示

拉取请求是一个提议。按照定义，一个提议还没有做过的那件事是什么？

**答案：** 仍然显示那家关门的咖啡馆。拟议更改完全待在自己的空间里，等待着；它还没有触碰真正的指南，也不会触碰，直到某个有权限的人接受它。这是整章的核心事实，值得你感受其中那一点轻微的不适：修正**存在**，已经完整写好，然而它修正的问题**仍然在线**，因为提出和接受是两个分开的动作。“已写好”和“已进入”之间的这道缝隙不是缺陷。它是安全机制。正是它让朋友能完成工作，而 Maya 不会失去控制；也正因为它，Maya 才能毫无恐惧地向任何人开放她的指南，接受更正。
