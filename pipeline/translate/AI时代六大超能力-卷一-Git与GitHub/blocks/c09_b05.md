### 8.4 先私有，以后再公开

当你的工作移动到互联网上的共享位置时，还有一件事要决定，而且这个决定带着一点令人紧张的边缘：**谁能看到它？**

对大多数项目来说，开始时诚实的答案是**除了我们没人能看**。Maya 和 Theo 还没有准备好向全世界展示一份半成品指南，里面有占位说明，还有一个他们拿不准的咖啡馆小节。他们想要第二个地方带来的安全，想要那种死一台笔记本也能幸存的平静，但不想暴露在开放互联网面前。而这完全是一件正常且受支持的事。

互联网上的共享工作间允许仓库是**私有**的（只有你和你明确邀请的人可见），或者是**公开**的，对任何人可见。私有给你本章的所有好处（第二个家、丢笔记本时的平静、你和 Theo 能在两台笔记本之间同步），却没有任何暴露。等作品准备好被看见时，你可以通过一个有意为之的步骤，把它切换为公开。

这里有一条实用的当前事实；因为这类事实会变化，我会给它盖上时间戳，并把你指向后续查看的地方，而不是假装它永恒不变。**截至 2026 年，主要的共享工作间都允许你在其免费层级上免费保留私有仓库。** 私有不是付费奢侈品；普通人可以免费把一个私有项目放在第二个地方。我不会印一张价格表，因为价格表会在一句话写下和被读到之间就变旧，而一本交给你过期价格的书，就交给了你一个小谎言。持久的是这个形状：私有仓库存在，截至写作时通常可以免费使用，而当前细节保存在工作间自己的文档里；当这件事重要时，你（或你的智能体）应该去那里核对。地图会告诉你**私有是可能的，而且通常免费**；由运行工作间的人保持更新的手册，会告诉你今天的条款究竟是什么。

因此，普通话请求里的安全半边不是事后补充。当你告诉智能体把你的工作发布到共享副本时，你几乎总是想补上一句：**先不要把它公开。** 得到第二个家是胜利。至于世界什么时候可以看见，则要单独、慎重地决定；那是你应该保留控制权的事。下一章我们会走过他们最终为全世界发布它的那个时刻，以及那会打开什么。
