#### 应用题

**Q1.** 你的智能体说：“我可以把上周那些混乱的小快照整理成 1 个干净的；要我做吗？”在回答之前，最重要的单一问题是什么？为什么答案会改变一切？

提示

这是第 3 个预检问题。改写历史的危险完全取决于关于那段历史的 1 个事实。

**答案：** 问题是：**“这段历史已经被共享了吗？”** 如果那些混乱快照仍然是私有的，只在你的机器上，没人见过，那么整理它们完全安全，而且确实有用；可以做。如果那段历史已经发布到共享副本，或者已经在别人机器上，那么改写它可能会覆盖别人工作所建立的地基；没有真实理由、也没有每个人都知情时，你不该继续。同一个请求，答案相反；唯一让答案翻转的，是历史是否已经共享。这就是为什么给智能体的长期指令是：**在你改写任何共享历史或覆盖发布别人的工作之前，停下来问我。**

**Q2.** 你发现 3 个快照前，你不小心提交了一个包含有效密码的文件，而且项目已经与 2 位合作者共享。一步步说出你实际会做什么，以及你会对智能体说什么。

提示

从今天的版本里删除它，并不会把它从历史中移除。完全在你控制之内的可靠修复是什么？在任何历史手术之前，从那里开始。

**答案：** 第一且最重要：**把密码视为已经泄露，并立刻更改它。** 它一直待在共享历史里，你的合作者，以及任何有访问权限的人，都可能看见过。轮换它（签发新密码，让旧密码失效）完全可靠，完全在你的控制之内，而且不依赖任何棘手的历史操作。永远先做这件事。之后，你才考虑是否把旧密码从历史中擦掉。因为项目已经共享，清理就是一次共享历史改写操作，带有 15.1 节中的所有危险，所以你要谨慎地把它交给智能体，让合作者知情，而不是尝试一个半记得的教程。可以这样说：**这个文件的历史里有一个有效密码；我已经更改了密码，现在帮我理解从共享历史中移除它的选项，并标出在别人也有副本的情况下这样做有什么风险。** 往后，你把那个文件加入忽略列表，让它再也不会被拍进快照。
