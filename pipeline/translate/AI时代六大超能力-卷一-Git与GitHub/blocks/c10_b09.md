#### 深入思考

**Q1.** 本章坚持说 GitHub 不是 Git，并称这种混淆是人们最常犯的混淆。你认为为什么这种混淆如此常见？把它澄清以后，你能理解哪些之前无法理解的事？

提示

想一想大多数人最先是怎样**遇到**这些东西的。他们看到的是哪一个？哪一个是看不见的？

**讨论：**这种混淆很常见，是因为人们通常遇到这两样东西的顺序。多数新手先遇到 GitHub：它是一个有面孔的网站，你能看见它、点击它、注册它。底下的工具 Git 则是看不见的：它安静地运行，屏幕上没有它的标志，并在背景中完成自己的工作。所以人们很自然地把整个概念都附着到那个可见的东西上，就像如果你从未看过任何人写书，你可能会以为“图书馆”就是书**来自**的地方。名字也没有帮忙；“GitHub”里含有“Git”，这让人以为它们是同一个产品，而不是一个工具和一个建立在它之上的地方。

把这件事澄清，会同时打开几件事。第一，它解释了为什么你可以完全离线工作：Git 不需要工作坊，所以相册、分支、快照全都能在一台没有互联网的笔记本电脑上运作；如果你以为 GitHub **就是**那个工具，这个事实会令人困惑。第二，它解释了为什么地图可以迁移：因为技能是 Git，而工作坊可以替换，所以在这里学会的动作，意味着你走进 GitLab 或 Codeberg 时也能认出一切，只是摆放方式不同。第三，也是最让人自由的一点：它把**你正在建立的技能**（它是你的、长期的、不属于任何公司）和**你碰巧存放东西的地方**（这是一个你可以改变的选择）分开了。你不是在学习“如何使用 GitHub”。你是在学习 Git，并且暂时选择一个工作坊来保存它。正是这种区别，让你感觉自己是掌舵的人，而不是依赖房东的租客。工具是你的。工作坊是一个决定。
