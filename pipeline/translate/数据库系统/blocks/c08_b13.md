#### 概念检查

**Q1.** 用叙事 A 的大学 Schema，把下列查询写成关系代数：(a) 所有三年级学生。 (b) 办公室在 'Building A' 的教师姓名。 (c) 所有成绩为 'A'、'A+' 或 'A-' 的选课。 (d) 成绩为 null 的选课对应的（学生姓名，课程标题）对。

提示

使用 \sigma 过滤、\pi 投影、\bowtie 连接。

**答案：** (a) \sigma_{\text{year} = 3}(\text{Students})

(b) \pi_{\text{name}}(\sigma_{\text{office LIKE 'Building A\%'}}(\text{Instructors}))

(c) \sigma_{\text{grade} \in \{'A', 'A+', 'A-'\}}(\text{Enrollments})

(d) \pi_{\text{s.name}, \text{c.title}}(\sigma_{\text{grade IS NULL}}(\text{Students} \bowtie_{\text{s.id=e.student\_id}} \text{Enrollments} \bowtie_{\text{e.course\_id=c.id}} \text{Courses}))

**Q2.** 如果条件 \theta 同时引用 R 和 S 的属性，\sigma_\theta(R) \bowtie S 可能产生与 \sigma_\theta(R \bowtie S) 不同的什么结果？

**答案：** 当 \theta 同时引用两侧属性时，这两个表达式不等价——因为 \sigma_\theta(R) 连 \theta 都无法求值，它只有 R 的属性。选择下推等价规则（等价规则 2）只在 \theta 只引用一侧时适用。若 \theta 引用两侧，选择必须在连接之后应用。

下推失败的例子：\sigma_{\text{s.name = i.name}}(\text{Students} \bowtie \text{Instructors}) —— 找姓名与教师相同的学生。你无法只在 Students 上求这个选择；必须先连接两侧。

当选择下推适用时，优化器总会用它；这个重写只会赢、不会输。

**Q3.** 解释为什么 \pi_{\text{credits}}(\text{Courses}) 与 `SELECT credits FROM Courses` 可能产生不同结果。哪个“正确”？

**答案：** 在严格关系代数中，投影会消除重复——结果是不同值的集合。对值 {3, 3, 4, 4, 4, 6}，\pi_{\text{credits}}(\text{Courses}) 返回 {3, 4, 6}。

在 SQL 中，`SELECT credits FROM Courses` 保留重复——结果是 bag：[3, 3, 4, 4, 4, 6]。要得到代数行为，写 `SELECT DISTINCT credits FROM Courses`。

两者没有哪个“正确”——它们都内部自洽。SQL 选择 bag，因为多数查询确实想要保留重复（`SUM`、`AVG` 依赖重复计数；`COUNT(*)` 度量 bag 大小）。纯代数为数学简洁选择集合。真实优化器在扩展的 bag 代数中工作，如 7.5 节所述。
