### 4.8 事务：初次品尝

第 13 章是完整的事务章节；这里是你到那之前需要的预览。**事务（transaction）**把多条 SQL 语句组织成一个全有或全无的单元——要么每条都生效，要么都不生效。

    BEGIN;
      UPDATE Accounts SET balance = balance - 100 WHERE id = 1;
      UPDATE Accounts SET balance = balance + 100 WHERE id = 2;
    COMMIT;

如果服务器在两个 `UPDATE` 之间崩溃，恢复后两者都不可见。如果两者都成功并 `COMMIT`，两者原子地变得可见。你也可以按需回滚：

    BEGIN;
      DELETE FROM Enrollments WHERE grade = 'F';
      -- 等等，我是这个意思吗？让我检查一下。
      SELECT COUNT(*) FROM Enrollments WHERE grade = 'F';
      -- 啊，这会删掉 4000 行，不是我想要的。
    ROLLBACK;

`DELETE` 被“撤销”——对其他会话从未可见，现在被完全还原。

**保存点（Savepoints）** 在事务内提供更细粒度的回滚：`SAVEPOINT before_x;` 标记一个点，`ROLLBACK TO SAVEPOINT before_x;` 只撤销该点之后的语句，同时保留之前的工作直到最终 `COMMIT`。

第 13 章会深入得多——隔离、并发、ACID。现在的要点是：事务是原子单元，而自动提交模式已经无声地摧毁了大量生产数据。


### 4.9 索引：初次品尝

索引有自己的专章（第 10 章），但你现在需要一个工作心智模型。**索引（index）**是 DBMS 在某一列（或多列）上维护的独立数据结构，用于加速 `WHERE` 子句和连接中的查找。

    CREATE INDEX idx_enrollments_student ON Enrollments(student_id);

现在 `WHERE student_id = 1001` 会使用索引而不是扫描整个 `Enrollments`。在 80,000 行上，这会把 625 页读取（全表扫描，第 2 章）变成大约 4 页读取（B+ 树遍历，第 10 章）。

> **关于全书出现的数字说明。** 叙事 A 提到若干页读取数字；它们并不矛盾，而是指*不同查询*：
>
>   * **625 页**（第 2 章 2.1 节）：扫描整个 Enrollments——朴素的单表扫描。
>   * **4 页**（本节）：一次索引查找某个学生的选课（仅 B+ 树下降）。
>   * **8,200 页**（第 9 章 9.4 节）：*无索引*下完整的“找出 Alice 的课程及其标题和教师姓名”多表查询——每个学生行都重新扫描 Enrollments 的多表嵌套循环。
>   * **32 页**（第 10 章 10.9 节）：在 `Students(name)`、`Enrollments(student_id)` 以及 `Courses` 和 `Instructors` 主键上都有索引时，同一个完整多表查询。
>
> 每个数字都是设计不同点上不同问题的代价。比较时请把范围弄清楚。

两个注意：索引不是免费的——每一个都会拖慢 `INSERT`/`UPDATE`/`DELETE`，因为索引必须和表一起维护。而且并非每个查询都能使用索引（例如 `WHERE email LIKE '%@uni.edu'` 无法使用 `email` 上的索引；第 10 章会讲规则）。经验法则：每个外键以及 `WHERE` 或 `ORDER BY` 中频繁使用的列都加索引；第 10 章会细化这条。
