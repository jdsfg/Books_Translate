1. **Loans 上的引用完整性：**

         Loans(
           book_isbn   VARCHAR(20) NOT NULL REFERENCES Books(isbn),
           borrower_id INTEGER     NOT NULL REFERENCES Borrowers(id),
           ...
         )

     没有它：一笔借阅可以引用一本不存在的书——一笔 phantom 借阅。图书馆的“在借书目”报表会包含不在目录中的书。

  2. **copies_available 非负：**

         Books(
           ...
           copies_available INTEGER NOT NULL CHECK (copies_available >= 0)
         )

     没有它：应用“借出”逻辑中的 bug 可能把 `copies_available` 减到零以下——于是图书馆声称某本书有 -2 本。CHECK 约束让这在数据库层面结构上不可能，即使有 bug 的借出脚本也无法破坏计数。

其他值得考虑的约束：

* 插入时 `due_date > CURRENT_DATE`（通常由应用强制执行——涉及 `CURRENT_DATE` 的 CHECK 约束比较棘手，因为约束在插入/更新时求值，但行在 `due_date` 过期后仍然“有效”）。
* 把 `copies_available` 与当前活跃借阅数关联起来的一致性约束——这不容易表达为简单约束，通常由触发器或应用借出/归还逻辑维护。

**Q3.** 考虑以下 SQL 片段：

    SELECT COUNT(*)     FROM Enrollments;  -- 返回 80,000
    SELECT COUNT(grade) FROM Enrollments;  -- 返回 62,000

这两个结果告诉你什么？写一个查询，找出所有至少有一门选课尚未给出成绩的学生。

**答案：** `COUNT(*)` 统计 `Enrollments` 的每一行，而 `COUNT(grade)` 只统计 `grade IS NOT NULL` 的行。差值（18,000）是 grade 为 null 的选课数——最可能的是当前进行中学期的选课，成绩尚未给出。

尚未给出成绩的学生：

    SELECT DISTINCT s.id, s.name
    FROM Students s
    JOIN Enrollments e ON s.id = e.student_id
    WHERE e.grade IS NULL;

**跨章联系：** 这里使用 `IS NULL`（而不是 `= NULL`）是第 3.6 节三值逻辑的实际应用。第 11 章我们会重新审视这条查询如何执行——`DISTINCT` 子句常常会改变优化器选择的计划。
