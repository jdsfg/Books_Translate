#### 三套术语

你会遇到三套并行词汇表达相同概念。文献中它们经常互换使用，所以都值得掌握：

| 数学 | 逻辑/SQL | 物理（文件系统时代） |
|---|---|---|
| Relation | Table | File |
| Tuple | Row | Record |
| Attribute | Column | Field |
| Domain | Type | Field type |
| Relation schema | Table schema | File format |
| Relation instance | Table contents | File contents |

左栏是形式化（数学）词汇。中栏是 SQL 使用的。右栏是数据库出现之前同一概念的叫法。读 1972 年的数据库论文，会遇到右栏；读 1995 年的教材，会遇到中栏；读 2026 年的理论论文，会遇到左栏。


#### 属性与域

每个属性的值都来自一个**域（domain）**——一个被命名的允许值集合。例如，`Courses` 关系的 `credits` 属性的域可能是 `INTEGER`（或者更严格地，`INTEGER IN [1, 12]`，如果注册员想强制没有单门课程超过一个学期的学分）。

域有两个作用：

  1. 它们在插入时**类型检查**数据。DBMS 会拒绝给 `INTEGER` 列插入 `'four'`。
  2. 它们**约束查询**。SQL 引擎知道比较两个 `INTEGER` 列的 `<` 是有意义的，但比较 `INTEGER` 和 `VARCHAR` 则根据严格性设置被强制转换或禁止。

大多数 SQL 数据库提供一组内置域（INTEGER、VARCHAR、TEXT、BOOLEAN、DATE、TIMESTAMP、NUMERIC(p,s)），并提供扩展机制（ENUM 类型、CHECK 约束、用户定义类型）。PostgreSQL 的类型系统以丰富著称；SQLite 的类型系统以宽松著称。
