### 4.4 连接（Join）

Join 是 SQL 真正发挥作用的地方。关系模型_依赖_外键来构建结构（第 3 章），而连接就是沿这些引用前行的机制。

我们的叙事 A 问题：“Alice Wong 选了哪些课程？”

    SELECT c.title, c.credits
    FROM Students s
    JOIN Enrollments e ON s.id = e.student_id
    JOIN Courses     c ON e.course_id = c.id
    WHERE s.name = 'Alice Wong';

我们跟随了两条外键引用：`Enrollments.student_id → Students.id`，以及 `Enrollments.course_id → Courses.id`。三张表连接生成的行中，包含 Alice 的*所有*选课以及每门课的信息。


#### 五种连接类型

SQL 有五种连接类型。它们的区别在于如何处理*不匹配*的行。

设两个样本表：

`A` 包含行：`(1), (2), (3)`；`B` 包含行：`(2), (3), (4)`

| 连接类型 | 语义 | 对 `A JOIN B ON A.x = B.y` 的结果 |
|---|---|---|
| `INNER JOIN` | 只保留满足连接条件的行 | `(2,2), (3,3)` |
| `LEFT OUTER JOIN` | 保留 A 的所有行；A 中不匹配的行在 B 列上补 NULL | `(1,NULL), (2,2), (3,3)` |
| `RIGHT OUTER JOIN` | 保留 B 的所有行；B 中不匹配的行在 A 列上补 NULL | `(2,2), (3,3), (NULL,4)` |
| `FULL OUTER JOIN` | 保留双方所有行；不匹配处补 NULL | `(1,NULL), (2,2), (3,3), (NULL,4)` |
| `CROSS JOIN` | A 和 B 的笛卡尔积；无条件 | `(1,2), (1,3), (1,4), (2,2), (2,3), (2,4), ...`（9 行） |

SQL 语法：

    SELECT * FROM A INNER JOIN B ON A.x = B.y;
    SELECT * FROM A LEFT JOIN  B ON A.x = B.y;  -- "OUTER" 可省略
    SELECT * FROM A FULL JOIN  B ON A.x = B.y;
    SELECT * FROM A CROSS JOIN B;

`INNER` 和 `OUTER` 常被省略：`JOIN` 单独出现即 `INNER JOIN`，`LEFT JOIN` 即 `LEFT OUTER JOIN`。正式名称有助于在心智上区分它们。
