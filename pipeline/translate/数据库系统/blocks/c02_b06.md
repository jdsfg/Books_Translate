#### 概念检查

**Q1.** 用你自己的话说，_database_ 和 _DBMS_ 有什么区别？在行业交流中，“database”通常指哪一个？

提示

回到 1.1 节的定义。数据本身是软件吗？

**答案：** **数据库（database）**是有组织的数据集合。**DBMS**（数据库管理系统）是管理这些数据的软件——解析查询、强制约束、处理并发、保证崩溃恢复，等等。严格地说，当有人说“我们用 PostgreSQL 作为数据库”时，他们的意思是“我们用 PostgreSQL DBMS 管理我们的数据”。在随意的行业交流中，“database” routinely 被用来指 DBMS。大多数对话中这种歧义无害，但在 distinction 重要时请明确说“DBMS”（例如，同事说“数据库很慢”——他们几乎总是指 DBMS 软件及其配置，而不是磁盘上的比特）。

**Q2.** 存储层次列出 CPU 寄存器约 0.3 ns，HDD 约 10 ms。CPU 从 HDD 读一个页的时间里，大约能执行多少次寄存器操作？请展示计算过程。

提示

把两个时间换算成相同单位再相除。

**答案：** 换算成秒：0.3 ns = 3 \times 10^{-10} s；10 ms = 10^{-2} s。比值为

\frac{10^{-2}}{3 \times 10^{-10}} \approx 3.3 \times 10^{7}

——即每次 HDD 页读取约 3300 万次寄存器操作。即使在 SSD 上（假设 50 µs = 5 \times 10^{-5} s），比值仍然约为 16.7 万次寄存器操作每次页读取。这就是为什么数据库代价模型数 I/O 次数，而不是 CPU 周期。

**Q3.** 说出 DBMS 做出的、文件系统无法做出的四项承诺。每一项用一句话举例说明没有它会出什么问题。

**答案：**

  1. **查询语言。** 没有它，每个临时数据问题都要写新的命令式代码；类 SQL 系统让你用声明式方式提问，并由引擎决定怎么做。
  2. **并发控制。** 没有它，两个用户同时编辑同一数据会悄悄覆盖对方改动——经典的“丢失更新（lost update）”。
  3. **崩溃恢复。** 没有它，一次断电导致事务写到一半（半写行、孤立引用），没有自动回滚机制。
  4. **完整性保证。** 没有它，输入错误、被删除的父记录、缺失的外键会悄悄腐蚀数据，直到数月后有人发现报表 nonsense。

**Q4.** 以下哪一项**不是**现代数据库使用自己的缓冲池而非依赖操作系统页缓存的原因？

* (a) 数据库比操作系统更了解访问模式。
* (b) 数据库的替换策略可以针对工作负载定制（例如，OLTP 缓冲池的 LRU-K 或 2Q，在索引密集型工作负载上优于 OS 页缓存的简单 LRU）。
* (c) 操作系统页缓存根本不能存储任何数据。
* (d) 写入必须与 WAL 协调，DBMS 自己管理缓冲更容易做到这一点。
