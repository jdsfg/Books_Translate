### 4.6 `DISTINCT` 与袋语义 vs 集合语义

第 3 章指出严格关系是集合，但 SQL 使用袋语义（允许重复）。`DISTINCT` 把它们折叠：

    SELECT student_id FROM Enrollments;           -- 1001 可能出现 8 次
    SELECT DISTINCT student_id FROM Enrollments;  -- 每个 id 最多一次

`DISTINCT` 不是免费的——它强制排序或哈希以检测重复。当你只需要“是否存在匹配？”时，`EXISTS`（第 8 章）通常更快：

    SELECT s.id, s.name FROM Students s
    WHERE EXISTS (SELECT 1 FROM Enrollments e WHERE e.student_id = s.id);


### 4.7 叙事 A 完整示例：“谁和 Alice 一起上数据库课？”

让我们走一遍一个真实的多连接查询，把英文问题一步步翻译成 SQL。

英文问题：“列出所有选了 Chen 博士的 Introduction to Databases 课程的学生的姓名和邮箱，按姓氏排序。”

步骤 1：需要哪些表？Students（姓名和邮箱）、Enrollments（谁选了课）、Courses（确定具体课程）、Instructors（按 Chen 博士过滤）。

步骤 2：表如何连接？Students ↔ Enrollments 在 student_id；Enrollments ↔ Courses 在 course_id；Courses ↔ Instructors 在 instructor_id。

步骤 3：过滤条件？`Instructors.name = 'Dr. Chen'` 和 `Courses.title = 'Introduction to Databases'`。

步骤 4：输出？`Students.name, Students.email`。

步骤 5：排序？姓氏——但 Schema 存的是全名。为简单起见，假设我们可以按整个 `name` 字符串字母排序（真实系统会把名/姓分开）。

写出来：

    SELECT s.name, s.email
    FROM Students s
    JOIN Enrollments e ON s.id = e.student_id
    JOIN Courses     c ON e.course_id = c.id
    JOIN Instructors i ON c.instructor_id = i.id
    WHERE i.name = 'Dr. Chen'
      AND c.title = 'Introduction to Databases'
    ORDER BY s.name;

这是典型的操作型查询：四表连接、两个过滤、简单排序。你会写数百条类似查询。注意这种纪律——每张表都有别名，每个连接都有显式 `ON`，每一列都用表别名限定——这让查询可读且可维护。

**叙事 A 里程碑：** 我们现在可以用一条 SQL 语句回答“Alice 选了哪些课？”以及它的许多变体。回想第 2 章，这每个问题都要一个定制 Python 脚本。这就是 SQL 的回报。

**叙事 B 预告：** 同样的连接会出现在第 7 章我们将遇到的 20 分钟查询中——`SELECT s.name, c.title, i.name FROM Students s JOIN Enrollments e JOIN Courses c JOIN Instructors i WHERE s.year = 4`。*查询*结构相似；后续章节变化的是*物理执行*及其性能含义。在没有索引的 10 万行数据上，这个连接结构要花 20 分钟。
