#### 应用问题

**Q1.** 写出 SQL 实现：“对每门课程，计算已被评分学生的平均 GPA（按 4.0 制）。忽略未评分选课。只包含至少 5 个评分选股的课程。”

使用以下成绩到 GPA 的映射（你可以把它硬编码在 `CASE` 表达式中）：

    A+=4.0, A=4.0, A-=3.7, B+=3.3, B=3.0, B-=2.7,
    C+=2.3, C=2.0, C-=1.7, D+=1.3, D=1.0, D-=0.7, F=0.0

提示

在 `AVG` 里用 `CASE`。用 `HAVING` 处理“至少 5 个”过滤。

**答案：**

    SELECT
      c.id,
      c.title,
      AVG(CASE e.grade
            WHEN 'A+' THEN 4.0 WHEN 'A'  THEN 4.0 WHEN 'A-' THEN 3.7
            WHEN 'B+' THEN 3.3 WHEN 'B'  THEN 3.0 WHEN 'B-' THEN 2.7
            WHEN 'C+' THEN 2.3 WHEN 'C'  THEN 2.0 WHEN 'C-' THEN 1.7
            WHEN 'D+' THEN 1.3 WHEN 'D'  THEN 1.0 WHEN 'D-' THEN 0.7
            WHEN 'F'  THEN 0.0
          END) AS avg_gpa,
      COUNT(e.grade) AS n_graded
    FROM Courses c
    JOIN Enrollments e ON e.course_id = c.id
    WHERE e.grade IS NOT NULL
    GROUP BY c.id, c.title
    HAVING COUNT(e.grade) >= 5
    ORDER BY avg_gpa DESC;

说明：

* `AVG` 自动跳过 NULL，所以即使没有显式 `WHERE e.grade IS NOT NULL`，未评分选课也不会影响平均分。但 `WHERE` 同时把它们排除在 `COUNT(e.grade)` 之外——实际上 `COUNT(e.grade)` 本来就跳过 null，所以 `WHERE` 在这里是可选的。包含它没有坏处，也让意图更清晰。
* `CASE` 表达式是把一个小的查找表内联的常见方法。对于大的查找表，应放进真正的表（例如 `GradePoints(grade, points)`）并 `JOIN`。
* 真实系统会把 GPA 映射抽成视图或正经表，以免跨查询重复。第 8 章会讲视图。

**跨章联系：** 这条查询用了叙事 A 的三个表。在规模化（80,000 条选课、500 门课程）且无索引的情况下，查询会对连接结果做哈希聚合——大约 80,000 次哈希探测加 500 个输出分组。第 11 章会揭示执行计划。

**Q2.** 大学想要一份名册：“对 Chen 博士的 'Introduction to Databases' 课程，列出所有已选课学生及其成绩（如果成绩为 null 则显示 `(pending)`）。按学生姓名排序。”

提示

`COALESCE` 把 null 替换成给定值。

**答案：**

    SELECT s.name, s.email, COALESCE(e.grade, '(pending)') AS grade
    FROM Students s
    JOIN Enrollments e ON s.id = e.student_id
    JOIN Courses     c ON e.course_id = c.id
    JOIN Instructors i ON c.instructor_id = i.id
    WHERE i.name = 'Dr. Chen'
      AND c.title = 'Introduction to Databases'
    ORDER BY s.name;

这和 4.7 节的例子几乎完全相同——唯一变化是多加了一个带 `COALESCE` 的输出列，并且选课连接现在提供成绩。`COALESCE(x, y, z)` 返回 `x, y, z` 中第一个非 null 的值；两个参数时就是“x 非 null 则 x，否则 y”。
