#### 引用动作

当被引用行被删除（或其主键被更新）时，数据库可以被告知执行以下操作之一：

* **RESTRICT / NO ACTION（默认）。** 如果还有子行引用父行，则拒绝删除。这是最安全的默认：你必须在删除父行之前显式清理依赖数据。
* **CASCADE。** 删除父行时同时删除所有引用它的子行。适用于子行离开父行就没有意义的场景（例如删除订单时删除其订单明细）。
* **SET NULL。** 子行的外键设为 `NULL`，表示“曾经存在但不再指向”。要求该外键列允许 null。
* **SET DEFAULT。** 子行的外键设为一个默认值（例如“已删除用户”占位符）。

在这些动作中选择是设计决策，而且往往是 Schema 中最有后果的决策。示例：

    Enrollments(
      student_id INTEGER NOT NULL
        REFERENCES Students(id) ON DELETE RESTRICT,
      course_id INTEGER NOT NULL
        REFERENCES Courses(id) ON DELETE RESTRICT,
      ...
    )

这里我们在说：“如果学生还有选课，就不允许删除该学生；如果课程还有选课，就不允许删除该课程。” 注册员必须先显式清理选课。这防止了意外数据丢失，但要求使用者自律。

对比：

    OrderLineItems(
      order_id INTEGER NOT NULL
        REFERENCES Orders(id) ON DELETE CASCADE,
      ...
    )

订单被删除时，其明细行没有意义，因此级联删除。这是安全的，因为明细行没有独立身份——它们只作为订单的一部分存在。

> ### 定义：引用完整性

**引用完整性（referential integrity）**是数据库中每个外键值都匹配被引用关系中的某个主键值（或允许为 `NULL`）的性质。DBMS 在每次插入、更新和删除时自动强制执行引用完整性——通过拒绝变更或应用声明的引用动作。

通俗地说，引用完整性意味着“没有悬空指针，系统永远保证，而不是靠程序员自律”。

这就是对第 1 章第四项 DBMS 承诺的回答。CSV 版本（第 2 章）无法强制引用完整性；关系型 DBMS 通过 Schema 中的外键声明自动做到。
