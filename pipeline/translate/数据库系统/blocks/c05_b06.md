### 4.5 `GROUP BY` 与聚合

聚合把多行汇总成单个值。五种基本聚合：

* `COUNT(*)` — 行数。
* `COUNT(expr)` — `expr` 非 null 的行数。
* `SUM(expr)` — 非 null 值之和。
* `AVG(expr)` — 非 null 值的平均值。
* `MIN(expr)` / `MAX(expr)` — 非 null 值的极值。

还有一些不太常见但重要的：

* `COUNT(DISTINCT expr)` — 不同非 null 值的数量。
* `STRING_AGG(expr, separator)` / `ARRAY_AGG(expr)` — 连接或收集成列表。

全表汇总：

    SELECT COUNT(*), AVG(credits), MAX(credits)
    FROM Courses;
    -- 500, 3.42, 6

按组汇总：

    SELECT instructor_id, COUNT(*), AVG(credits)
    FROM Courses
    GROUP BY instructor_id;

每个不同的 `instructor_id` 一行，每行汇总该教师所教课程。


#### `GROUP BY` 规则

在带 `GROUP BY` 的查询中，`SELECT` 列表中的每一列必须是：

* `GROUP BY` 中列出的列，或
* 在聚合函数内部。

为什么？因为分组后，输出的每一行对应*多条*输入行。“选 `title`”没有意义——组里有很多 title，用哪个？“选 `COUNT(title)`”或“选 `MAX(title)`”有意义——聚合把它们折叠成一个值。

大多数数据库会拒绝违反该规则的查询。历史 MySQL 不会——它静默挑选某随机行的值，产生臭名昭著的 bug；现代 MySQL 默认强制执行。


#### `HAVING`：过滤分组

`WHERE` 在分组*前*过滤行；`HAVING` 在分组*后*过滤分组。

    -- 教至少 5 门课且平均学分 >= 3 的教师
    SELECT instructor_id, COUNT(*) AS n_courses, AVG(credits) AS avg_credits
    FROM Courses
    GROUP BY instructor_id
    HAVING COUNT(*) >= 5 AND AVG(credits) >= 3;

`HAVING` 可以引用聚合；`WHERE` 不能，因为 `WHERE` 运行时聚合尚未计算。这两条子句真正看到的东西不同——比较：

    -- "教过至少一门 >= 4 学分课程的教师"
    -- （先过滤单行：只保留 4+ 学分课程；再按组计数）
    SELECT instructor_id, COUNT(*)
    FROM Courses
    WHERE credits >= 4
    GROUP BY instructor_id;

    -- "所教课程平均学分 >= 4 的教师"
    -- （先分组；再按聚合过滤分组）
    SELECT instructor_id, AVG(credits)
    FROM Courses
    GROUP BY instructor_id
    HAVING AVG(credits) >= 4;

这两个查询回答的是截然不同的问题；选对那个需要几次踩坑才能培养的技能。


#### 常见误解

工程师常写：

    SELECT s.name, e.course_id
    FROM Students s JOIN Enrollments e ON s.id = e.student_id
    GROUP BY s.name;

然后收到错误，或在宽松的 MySQL 上得到非确定性输出。问题是歧义的——“每个名字对应的 course_id 是哪个？”——SQL 正确拒绝猜测。如果你想要“每个名字一个 course_id”，必须告诉查询是*哪一个*：`MAX(e.course_id)`、`MIN(e.course_id)`，或以其他方式聚合。这条规则迫使 SQL 作者显式说明“分组”的含义。
