#### 权衡：读速度 vs 新鲜度 vs 写速度

* **普通视图**：零存储开销，无陈旧问题，但每次查询都重新计算。适合小/便宜查询。
* **物化视图**：读快、可建索引，但在刷新前陈旧。一些引擎（Oracle、SQL Server 索引视图）在每次底层写入时热切刷新，代价是每次写都要支付刷新税。

当底层查询昂贵、陈旧可容忍、且读远多于写时，使用物化视图。展示昨日 Top 10 课程的仪表板：完美。支撑实时预订系统的视图：危险。


### 8.7 窗口函数

**窗口函数（window function）**在一组与当前行相关的行上计算值，而不会把结果折叠成单条聚合行。

对比普通聚合：

    SELECT dept_id, AVG(gpa) FROM Students GROUP BY dept_id;

与窗口聚合：

    SELECT id, name, dept_id, gpa,
           AVG(gpa) OVER (PARTITION BY dept_id) AS dept_avg
    FROM Students;

第二个查询返回**每名学生一行**（没有折叠），并把该院系平均 GPA 附到每一行。这正是本章开篇问题的最干净答案。


#### OVER 的 anatomy

`OVER` 有三个可选子句：

    function(args) OVER (
      PARTITION BY col1, col2, ...   -- 把行分成组
      ORDER BY col3, col4 [ASC|DESC] -- 在每个分区内排序
      ROWS BETWEEN ... AND ...       -- 定义 frame
    )

* **PARTITION BY** 类似 GROUP BY，但不折叠行。每个窗口求值只在各自分区内进行。
* **ORDER BY** 定义分区内的行顺序——`RANK`、`ROW_NUMBER`、`LAG`、运行总和都需要它。
* **ROWS BETWEEN** 定义**frame**：函数看到的、相对于当前行的那些行。默认值取决于是否带 ORDER BY。


#### 常见窗口函数

* **排名**：`ROW_NUMBER()`、`RANK()`、`DENSE_RANK()`、`NTILE(n)`。
* **聚合**：`SUM()`、`AVG()`、`COUNT()`、`MIN()`、`MAX()` —— 都可以作为窗口函数。
* **偏移**：`LAG(expr, n)` 和 `LEAD(expr, n)` 返回分区内当前行前/后第 n 行的 `expr`。


#### 示例：费用累计

    SELECT student_id, term, amount,
           SUM(amount) OVER (PARTITION BY student_id ORDER BY term) AS balance
    FROM Fees;

对每名学生，`balance` 列显示到该学期为止的累计费用。无需自连接、无需相关子查询。


#### 示例：每院系 Top 3

    SELECT id, name, dept_id, gpa
    FROM (
      SELECT id, name, dept_id, gpa,
             RANK() OVER (PARTITION BY dept_id ORDER BY gpa DESC) AS r
      FROM Students
    ) t
    WHERE r <= 3;

没有窗口函数时，这个查询写起来很痛苦（相关子查询去数同院系里更高 GPA 的行，或者自连接，都不可扩展）。用了窗口函数，三行即可。

> **窗口函数不允许出现在 WHERE 或 HAVING 中。** 原因是求值顺序：`WHERE` 在窗口计算之前过滤行。要按窗口函数结果过滤，就把查询包进子查询或 CTE，再在外层用 `WHERE`，如上所示。
