### 7.2 把 SQL 写成关系代数

我们把几个 SQL 查询翻译成代数。

**示例 1.** `SELECT name FROM Students WHERE year = 4;`

代数：\pi_{\text{name}}(\sigma_{\text{year} = 4}(\text{Students}))

从内向外读：先把 Students 过滤到大四，再投影 name 列。

**示例 2.** 叙事 A 的查询——“Alice 选的课程”：

    SELECT c.title
    FROM Students s JOIN Enrollments e ON s.id = e.student_id
                    JOIN Courses c     ON e.course_id = c.id
    WHERE s.name = 'Alice';

代数：\pi_{\text{c.title}}(\sigma_{\text{s.name = 'Alice'}}(\text{Students} \bowtie_{\text{s.id=e.student\_id}} \text{Enrollments} \bowtie_{\text{e.course\_id=c.id}} \text{Courses}))

从内向外读：连接三张表，过滤出 Alice 的行，投影 title。

**示例 3.** 叙事 B 的查询——“大四学生的姓名、课程标题和教师姓名”：

    SELECT s.name, c.title, i.name
    FROM Students s
    JOIN Enrollments e ON s.id = e.student_id
    JOIN Courses c     ON e.course_id = c.id
    JOIN Instructors i ON c.instructor_id = i.id
    WHERE s.year = 4;

代数：\pi_{\text{s.name, c.title, i.name}}(\sigma_{\text{s.year}=4}(S \bowtie E \bowtie C \bowtie I))

其中连接带有合适的谓词（例如 s.id = e.student_id、e.course_id = c.id、c.instructor_id = i.id）。

这是一个四路连接。代数表达式很紧凑——四个算子：一个投影、一个选择、三个连接（合并写在大连接里）。但*执行*这个表达式才是一切有趣的地方。不同连接顺序、不同算法、不同过滤位置可以让运行时间相差三个数量级。我们会在第 12 章仔细展开。


#### 叙事 B：那个 20 分钟的查询

这个查询就是我们的叙事 B。我们会在第 10、11、12、19 章再次见到它。上面的代数是它的逻辑规约——查询“是什么意思”。同一个代数的不同*物理*执行在代价上天差地别。

先把场景说在前面（免得第 11 章重复）：

* Students：100,000 行（id, name, email, year）。
* Enrollments：800,000 行（student_id, course_id, grade）——平均每名学生 8 条选课。
* Courses：500 行（id, title, credits, instructor_id）。
* Instructors：100 行（id, name, office, phone）。

除主键外无索引。

运行查询。耗时 20 分钟。第 11 章会解释原因。本章的任务是给我们*讨论*为什么的代数词汇。


### 7.3 代数等价规则

关系代数不可或缺的核心想法就在这里：同一个查询可以有**多个等价的代数表达式**，而优化器的自由度就在于选择其中最好的一个执行。
