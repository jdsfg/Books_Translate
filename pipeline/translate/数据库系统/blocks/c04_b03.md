### 3.2 注册员的 Schema，正本清源

让我们在关系模型中重建第 2 章的大学选课系统。第 2 章的异常源于无关事实被共存；关系模型的解法就是把每种事实放进自己的关系。

    Students(
      id       INTEGER     PRIMARY KEY,
      name     VARCHAR(100) NOT NULL,
      email    VARCHAR(100) UNIQUE NOT NULL
    )

    Instructors(
      id       INTEGER      PRIMARY KEY,
      name     VARCHAR(100) NOT NULL,
      office   VARCHAR(50),
      phone    VARCHAR(20)
    )

    Courses(
      id            INTEGER     PRIMARY KEY,
      title         VARCHAR(200) NOT NULL,
      credits       INTEGER      NOT NULL CHECK (credits BETWEEN 1 AND 12),
      instructor_id INTEGER      NOT NULL REFERENCES Instructors(id)
    )

    Enrollments(
      student_id INTEGER NOT NULL REFERENCES Students(id),
      course_id  INTEGER NOT NULL REFERENCES Courses(id),
      grade      VARCHAR(3),
      PRIMARY KEY (student_id, course_id)
    )

这个 Schema 在它的结构本身中编码了对第 2 章三种异常的治愈：

* **更新异常治愈。** Park 博士的名字只存在于 `Instructors` 的一行里。改名字只需一次 `UPDATE`。
* **删除异常治愈。** 删除课程不会触及 instructors 表。删除 Bob 的选课不会触及 courses 或 instructors 表。
* **插入异常治愈。** 没有学生选的新课程可以简单地 `INSERT` 到 `Courses` 中——选课是独立的问题。
* **引用完整性。** `INSERT INTO Enrollments (student_id, course_id) VALUES (1099, 109)` 这种 typo 会在数据库层面失败，因为没有学生 1099，也没有课程 109。

我们将在 3.3 到 3.6 节逐一走过这些构造——键、引用、约束。
