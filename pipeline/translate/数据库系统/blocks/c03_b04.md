#### 常见误解

学生有时认为 NULL 只是“数据库里的一种东西”，除了占一个存储位外没有成本。错。NULL 以三值方式与查询逻辑交互——与 NULL 比较的表达式结果是 `UNKNOWN`，而不是 `TRUE` 或 `FALSE`。这意味着当 NULL 存在时，聚合函数、连接和 `WHERE` 子句都可能以反直觉的方式表现。第 3 章会形式化这一点；现在先注意，注册员被迫在上面 invented 的那个 NULL 携带了真实的语义伤害：“实际选课学生数”和“enrollment 行数”现在相差 1。

三种异常——更新、删除、插入——不是三种不同的 bug。它们是**同一种病的三种症状**：由把无关事实塞进同一行的冗余 Schema 驱动的数据冗余。治愈这种病（通过把事实拆到多个表中，第 3 章会做），三种症状会同时消失。


### 2.5 没有 DBMS 的引用完整性

到目前为止，我们的例子都关于修改数据。现在考虑一种更 subtle 的故障。

注册员匆忙输入一条选课记录：


    1099,Alice Wong,109,Advanced Cryptography,Dr. Boerner,4,


根本没有学生 1099（Alice 是 1001），也没有课程 109。两者都是输入错误。在关系型 DBMS 中，这一行会在插入时被*拒绝*——`enrollments.student_id` 到 `students.id` 以及 `enrollments.course_id` 到 `courses.id` 的外键会阻止写入。

CSV 文件没有这种守卫。这一行进入了文件。明天，当一份报表拉取“Alice 选的所有课程”时，它会发现她选了根本不存在的课程 109——一条**悬空引用（dangling reference）**。报表要么默默丢弃她，要么报错，要么把 “Advanced Cryptography” 显示为一门真课，尽管系统没有其他关于它的记录。

> ### 定义：引用完整性

**引用完整性（referential integrity）**是指数据库中的每个引用都指向真实存在的行。当表 T 的外键引用表 U 时，引用完整性意味着：对 T 的每一行，U 中被引用的行都存在、未被删除、不是 typo。

通俗地说，引用完整性就是“没有悬空引用”——每个指针都真正指向某处。DBMS 通过外键约束自动强制执行（第 3 章）；文件系统做不到，因为它一开始就没有表达这种约束的语言。

引用完整性是第 1 章第四项 DBMS 承诺的具体化。CSV 文件无法做出这个承诺，因为它不知道什么是引用。DBMS 知道。
