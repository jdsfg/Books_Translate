#### 概念检查

**Q1.** 对下列每一项，判断它是否是第 3 章大学 Schema 中的函数依赖，并简要说明理由。

(a) \{Students.id\} \rightarrow \{Students.name\}

(b) \{Students.name\} \rightarrow \{Students.id\}

(c) \{Students.email\} \rightarrow \{Students.id\}

(d) \{Enrollments.student\_id\} \rightarrow \{Enrollments.grade\}

**答案：** (a) **是。** 每个学生 id 对应一个学生，该学生只有一个名字。 (b) **否。** 两个学生可以同名。 (c) **是。** Email 声明为 UNIQUE NOT NULL，所以每个 email 至多对应一个学生，从而决定 id。 (d) **否。** 一名学生（如 id = 1001）可能在不同课程有多条选课，每条成绩可能不同。`student\_id` 单独不能决定 `grade`；决定 grade 的是组合 `(student\_id, course\_id)`。

**Q2.** 对 R(A, B, C, D)，FD 集合 F = \{A \rightarrow B, B \rightarrow C, C \rightarrow D\}，计算 \{A\}^+。

**答案：** 起始：\{A\}。A \rightarrow B：A 在集合中，加入 B，得 \{A, B\}。  
B \rightarrow C：B 在集合中，加入 C，得 \{A, B, C\}。  
C \rightarrow D：C 在集合中，加入 D，得 \{A, B, C, D\}。没有 FD 再适用。

\{A\}^+ = \{A, B, C, D\}。所以 A 是超键（实际上也是候选键，因为没有真子集能决定全部）。

**Q3.** 给出 2NF、3NF、BCNF 的定义，并对每个用一句话说明它消除何种冗余。

**答案：**

* **2NF：** 满足 1NF，且每个非键属性完全依赖于整个主键（不存在复合键上的部分依赖）。_消除“非键属性只依赖复合主键一部分”导致的冗余。_
* **3NF：** 满足 2NF，且每个非平凡 FD X \rightarrow A 要么 X 是超键，要么 A 是主属性。_消除传递依赖（非键 → 非键）导致的冗余。_
* **BCNF：** 每个非平凡 FD X \rightarrow A 的 X 都是超键。_消除所有“非超键决定其他属性”的冗余——比 3NF 更强。_

**Q4.** 一个关系有 FD \{A \rightarrow B, B \rightarrow C, C \rightarrow A\}。它的候选键是什么？它是否满足 BCNF？

**答案：** 先计算单属性的闭包：

* \{A\}^+ = \{A, B, C\}，通过 A \rightarrow B、B \rightarrow C。
* \{B\}^+ = \{A, B, C\}，通过 B \rightarrow C、C \rightarrow A。
* \{C\}^+ = \{A, B, C\}，通过 C \rightarrow A、A \rightarrow B。

三个单属性都是超键，且都最小（已经是单属性，无法再缩小）。因此有三个**候选键**：\{A\}、\{B\}、\{C\}。

BCNF：每个非平凡 FD 的左侧必须是超键。

* A \rightarrow B：左侧 A 是超键。✓
* B \rightarrow C：左侧 B 是超键。✓
* C \rightarrow A：左侧 C 是超键。✓

所有 FD 的左侧都是超键。该关系满足**BCNF**。
