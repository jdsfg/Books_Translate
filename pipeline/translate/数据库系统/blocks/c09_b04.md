### 8.4 EXISTS vs IN vs JOIN —— NULL 雷区

表达“学生至少有一条选课”有三种常见方式：

    -- A: EXISTS
    SELECT s.* FROM Students s
    WHERE EXISTS (SELECT 1 FROM Enrollments e WHERE e.student_id = s.id);

    -- B: IN
    SELECT s.* FROM Students s
    WHERE s.id IN (SELECT student_id FROM Enrollments);

    -- C: JOIN + DISTINCT
    SELECT DISTINCT s.* FROM Students s JOIN Enrollments e ON e.student_id = s.id;

当 `Enrollments.student_id` 声明为 NOT NULL 且外键指向 `Students` 时，三种写法在优化后返回相同结果和相同计划。但 NULL 可能存在时，它们会分道扬镳——有时结果惊人。


#### NOT IN 里的 NULL 陷阱

假设 `Enrollments.student_id` 可以为 NULL（Schema 不好，但有人会发布这样的系统）。考虑：

    SELECT s.* FROM Students s
    WHERE s.id NOT IN (SELECT student_id FROM Enrollments);

如果 `Enrollments` 里*任何一行*的 `student_id = NULL`，该查询返回**零行**。不是“没有选课的学生”——是零。原因是三值逻辑（第 3 章）：`s.id NOT IN (..., NULL, ...)` 归约为 `s.id <> NULL AND ...`，而任何与 NULL 的比较都产生 UNKNOWN，WHERE 子句把 UNKNOWN 视为 false。

NOT EXISTS 没有这个陷阱：

    SELECT s.* FROM Students s
    WHERE NOT EXISTS (SELECT 1 FROM Enrollments e WHERE e.student_id = s.id);

EXISTS 检查是否存在行；不执行 NULL 比较。


#### 定义：经验法则

用 **EXISTS / NOT EXISTS** 做存在性检查。它们对 NULL 安全，且几乎总是被优化为半连接。用 **IN** 检查成员资格时，仅用于有限且无 NULL 的列表。仅在确实需要从被连接表取列时，才用 **JOIN + DISTINCT**。


#### 权衡

EXISTS 一旦找到第一个匹配行即可停止（半连接）。JOIN 必须构建完整连接结果然后去重。对外部行有大量匹配行的表，EXISTS 通常更便宜。优化器通常会在它们之间转换，但通过惯用语法给它提示总没坏处。


### 8.5 公用表表达式（CTE）

**公用表表达式（Common Table Expression, CTE）**是出现在查询顶部的命名子查询。

    WITH dept_avg AS (
      SELECT dept_id, AVG(gpa) AS gpa FROM Students GROUP BY dept_id
    )
    SELECT s.id, s.name, s.gpa, d.gpa AS dept_gpa
    FROM Students s JOIN dept_avg d ON s.dept_id = d.dept_id
    WHERE s.gpa > d.gpa;

CTE 提高可读性。它们让你给中间结果命名，并在一条语句中多次使用。它们还支持**递归**，而普通子查询无法表达。


#### 定义：递归 CTE

**递归 CTE** 计算一个不动点：从基例开始，反复应用递归例，直到不再产生新行。

    -- 先修链：课程 → 其先修 → 其先修的先修 → ...
    WITH RECURSIVE prereq_chain(course_id, prereq_id, depth) AS (
        SELECT course_id, prereq_id, 1
        FROM Prerequisites
      UNION ALL
        SELECT p.course_id, pr.prereq_id, c.depth + 1
        FROM prereq_chain c JOIN Prerequisites p ON c.prereq_id = p.course_id
    )
    SELECT * FROM prereq_chain;

当 `Prerequisites` 没有更多祖先可贡献时，递归停止。图遍历、组织架构、物料清单展开——都天然适合这里表达。
