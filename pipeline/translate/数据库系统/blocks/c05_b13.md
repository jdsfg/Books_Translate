`student_id` 上的外键约束在插入 1099 行时触发。批量中的其余行会怎样？

**答案：** `Enrollments.student_id` 上的外键约束拒绝 1099 行。在大多数 SQL 数据库中，多行 `INSERT` 是*单条语句*，因此要么全部成功，要么全部失败——没有部分结果。1099 行失败，整条 `INSERT` 失败，其余四行也不会被插入。

因为我们处于 `BEGIN ... COMMIT` 事务中，失败会回滚整个事务——没有行被添加。如果我们随后 `COMMIT`，该提交是 no-op（或某些客户端会在“失败语句后提交”时报错；PostgreSQL 会报错）。

如果我们去掉 `BEGIN ... COMMIT` 在自动提交模式下运行：每条语句是自己的事务，所以 `INSERT` 仍在 1099 行上原子失败，仍然没有任何行被插入。

如果我们发出五条*单独*的 `INSERT` 语句，答案会改变：

    INSERT INTO Enrollments VALUES (1001, 201, NULL);
    INSERT INTO Enrollments VALUES (1002, 201, NULL);
    INSERT INTO Enrollments VALUES (1003, 201, NULL);
    INSERT INTO Enrollments VALUES (1099, 201, NULL);  -- 失败
    INSERT INTO Enrollments VALUES (1005, 201, NULL);

在自动提交模式下，前三条成功，第四条失败，第五条成功。此时 `Enrollments` 表新增了四行。

在显式事务中，如果我们捕获错误并继续，模式也一样——但 `COMMIT` 时会提交那四行。如果我们让错误传播并以 `ROLLBACK` 结束，则不提交任何行。

更深层的点：事务边界很重要，“原子批量插入”与“逐条插入”是真正的设计决策。第 13 章会把原子性故事讲精确。
