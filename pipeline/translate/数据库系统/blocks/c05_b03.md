### 4.3 `SELECT`：SQL 的核心

`SELECT` 是你花最多时间的 SQL 部分。其完整结构：

    SELECT   [DISTINCT] select_expressions
    FROM     table_expression
    WHERE    filter_expression
    GROUP BY grouping_expressions
    HAVING   group_filter_expression
    ORDER BY ordering_expressions
    LIMIT    n
    OFFSET   m

你很少同时用全部七个，但知道它们存在及其求值顺序，是写出不会悄悄做错的 SQL 的基础。


#### 逻辑求值顺序

SQL 文本上是自顶向下读，但*求值*顺序不同。大致如下：

  1. **FROM** — 决定哪些表和连接提供行全集。
  2. **WHERE** — 过滤行。
  3. **GROUP BY** — 把存活下来的行分组。
  4. **HAVING** — 过滤分组。
  5. **SELECT** — 为每行或每组计算输出列。
  6. **DISTINCT** — 去除重复输出行。
  7. **ORDER BY** — 对输出排序。
  8. **LIMIT / OFFSET** — 裁剪输出。

这是*逻辑*顺序；真实查询计划可能看起来完全不同（第 11 章）。但逻辑顺序决定*正确性*。例如：

* 你不能在 `WHERE` 子句中使用 `SELECT` 列表别名，因为 `WHERE` 在 `SELECT` 计算别名之前求值。
* 除非某列在 `GROUP BY` 中，否则不能在 `SELECT` 中把非聚合列和 `GROUP BY` 一起使用——因为此时行身份已经丢失。
* `ORDER BY` *可以*使用 `SELECT` 列表别名，因为它在 `SELECT` 之后求值。


#### `FROM` 与简单 `SELECT`

    SELECT id, name, email FROM Students;
    SELECT * FROM Students;

`*` 表示“所有列”——在即席查询中方便，在生产环境危险：Schema 变化可能破坏应用代码或返回意料之外的列。任何会活得比你终端更久的查询，都应显式命名列。


#### `WHERE`：过滤

    SELECT name FROM Students WHERE id = 1001;
    SELECT name FROM Students WHERE name LIKE 'A%';
    SELECT * FROM Courses WHERE credits > 3 AND credits <= 6;
    SELECT * FROM Enrollments WHERE grade IS NULL;

四种模式：精确匹配（`= 1001`）、模式匹配（`LIKE`，`_` 代表一个字符、`%` 代表任意序列）、范围（用 `AND`/`OR` 组合比较）、空值测试（`IS NULL`/`IS NOT NULL`，绝不用 `= NULL`）。


#### `ORDER BY` 与 `LIMIT`

    SELECT name, email FROM Students
    ORDER BY name ASC
    LIMIT 10;

`ASC` 是默认；`DESC` 反转。按多列排序（`ORDER BY last_name, first_name`）以便在第一列相同时用第二列打破平局。没有 `ORDER BY` 的 `LIMIT` 给出“某十行，天知道是哪十行”——关系是集合，没有固有顺序。

    SELECT name FROM Students ORDER BY id LIMIT 20 OFFSET 40;

这是每页 20 条的第三页。`OFFSET` 分页扩展性不好（引擎仍然要扫描并丢弃前 `OFFSET` 行）；第 8 章会讨论键集分页作为替代。
