### 2.8 为什么查询语言重要

让我们回到第 1 章的一个问题：“Chen 博士教的课程中，所有选课学生的平均成绩是多少？”

在正确的关系型数据库中，这是一句话：

    SELECT AVG(e.grade)
    FROM enrollments e
    JOIN courses c ON e.course_id = c.id
    WHERE c.instructor = 'Dr. Chen';

在 CSV 世界里，过程是：

  1. 写一个脚本（Python、awk、电子表格）读取 `courses.csv`，过滤出 Chen 博士的课程。
  2. 拿到对应的 `course_id`，再过滤 `enrollments.csv`。
  3. 计算平均成绩——但成绩是字母成绩，需要先转换成数字分制，这又需要另一张表（`grade_points.csv`？还不存在）。
  4. 返回数字。

每一步都可行，但需要描述*如何*计算答案的*命令式代码*。每个新问题都要一个新脚本。

关系模型加 SQL 是**声明式（declarative）**的：你描述想要*什么*答案，引擎决定*如何*得到它。这是从文件切换到数据库的最大收获。它让 DBMS 感觉像一门数据的编程语言，而不是一个存储系统。


#### 常见误解

有些工程师（尤其是有深厚命令式编程经验后才学 SQL 的人）认为声明式查询“只是方便”——“我用 Python 也能写，只是长一点”。这低估了收益。优化器（第 12 章）利用声明性带来的*自由度*，选择有时比最明显的 Python 写法快 1000 倍的计划。你*原则上*可以在 Python 里实现同样的计划，但你需要为每个查询、每次数据规模变化、每个新索引重新推导一次。声明性不是生活质量提升；它是让引擎完成人类无法规模化完成的优化工作的接口。
