#### 应用问题

**Q1.** 为一个博客平台做正向工程。领域描述：

> “用户撰写帖子。每个帖子有标题、正文、发布日期和一名作者。用户可以对任何帖子发表评论。评论有正文、日期和评论者。评论可以回复其他评论（ threaded）。用户可以对帖子‘点赞’。帖子有标签（自由格式字符串）。”

产出：(a) 实体及其属性列表；(b) 关系及其基数、属性列表；(c) 最终关系 Schema（DDL 级草图——列名、主键、外键）。

提示

Threaded comments 是一元（自引用）关系。Tags 最初是“自由格式字符串”，但可能有歧义。

**答案：**

**(a) 实体：**

* `User` (id*, name, email, joined_date)
* `Post` (id*, title, body, published_at)
* `Comment` (id*, body, commented_at)
* `Like` — 实体还是关系？User 与 Post 之间的 M:N，除了“是否点赞”外无其他属性。建模为连接表。
* `Tag` — 自由格式字符串最初是 Post 的属性。但如果标签可以列表、排序或加属性，就提升为实体。

**(b) 关系：**

* `User writes Post` — User 到 Post 的 1:N。每篇帖子恰好有一个作者（Post 侧全参与）。
* `User comments on Post` — 如果每条 Comment 有一个评论者和一个帖子，则是 1:N。但 Comment 是带自身属性的实体，因此表达为两个 1:N 关系：_User commented_ 和 _Post has comment_。
* `Comment is reply to Comment` — 一元，1:N（每条评论最多有一个父评论）。
* `User likes Post` — M:N，无属性。
* `Post has Tag` — M:N，无属性（如果标签是自由格式字符串，则没有 Tag 实体；而是 Post 上的多值属性）。

**(c) Schema：**

    Users (
      id INTEGER PRIMARY KEY,
      name VARCHAR NOT NULL,
      email VARCHAR UNIQUE NOT NULL,
      joined_date DATE NOT NULL
    );

    Posts (
      id INTEGER PRIMARY KEY,
      author_id INTEGER NOT NULL REFERENCES Users(id),
      title VARCHAR NOT NULL,
      body TEXT NOT NULL,
      published_at TIMESTAMP NOT NULL
    );

    Comments (
      id INTEGER PRIMARY KEY,
      post_id INTEGER NOT NULL REFERENCES Posts(id) ON DELETE CASCADE,
      commenter_id INTEGER NOT NULL REFERENCES Users(id),
      parent_comment_id INTEGER REFERENCES Comments(id),  -- 顶层为 NULL
      body TEXT NOT NULL,
      commented_at TIMESTAMP NOT NULL
    );

    Likes (
      user_id INTEGER NOT NULL REFERENCES Users(id) ON DELETE CASCADE,
      post_id INTEGER NOT NULL REFERENCES Posts(id) ON DELETE CASCADE,
      PRIMARY KEY (user_id, post_id)
    );

    PostTags (
      post_id INTEGER NOT NULL REFERENCES Posts(id) ON DELETE CASCADE,
      tag VARCHAR NOT NULL,
      PRIMARY KEY (post_id, tag)
    );

说明：

* `Comments.parent_comment_id` 是自引用。第 7、8 章会讲如何查询递归结构（公用表表达式 / 递归查询）。
* `PostTags` 把多值标签属性拆成单独表（规则 2）。如果以后想让标签有属性（颜色、关注者数），就增加 `Tags` 实体表，并把 `PostTags.tag` 改成 `PostTags.tag_id REFERENCES Tags(id)`。
* 所有“子级”关系在子级离开父级无意义的地方都使用 `ON DELETE CASCADE`。
