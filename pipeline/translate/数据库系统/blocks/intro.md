大多数数据库课程只教 SQL 怎么用。本书则教你数据库“为什么”这样工作——以及换一种方式为什么会更糟。当你面对一条无法解释原因的慢查询、一个在高并发下悄悄丢失数据的事务，或者一个在一万行时运行良好、在一千万行时崩溃的 Schema 时，这种区别才真正重要。

全书 23 章贯穿三条叙事线：一个大学选课系统，它会以各种富有教学意义的方式不断崩溃；一个四表 JOIN 查询，随着你逐步添加索引、更新统计信息并理解优化器，它的运行时间逐章减少 99%；以及一个余额 1000 USD 的银行账户，因两个并发事务同时读取同一余额而被重复取款。这些例子都不是人为编造的——读到最后，你会发现它们正是你生产系统将要遇到的真实问题。

本书对失败模式异常坦诚。每个“常见误解（Common Misconception）”框都记录了一个工程师真实会犯的错误，而不是稻草人。事务与 MVCC 相关章节尤其不留情面：仅仅写下 BEGIN / COMMIT 并不够，错误的隔离级别即使在结构良好的事务中也会让异常钻进来。规范化章节解释了“故意不做规范化”的场景。最后一章则给出了一套真实 AI 学习平台的完整数据架构——Schema、索引、隔离级别、缓存、复制、分析管道、GDPR 删除——并要求你逐条捍卫每一项选择、每一个权衡。

到最后一章，开篇那条耗时 20 分钟的查询将不再是谜。你会确切知道它为什么慢、优化器到底做错了什么，以及关于存储、索引、统计信息和连接算法的哪些事实最终促成了加速。这种理解可以迁移到任何关系型引擎——以及此后你遇到的任何新引擎。

**目标读者**：计算机专业高年级本科生；用过 ORM 和 SQL 但从未理解其底层原理的软件工程师；希望自信地分析数据库性能的后端工程师。

**先修要求**：具备基础编程能力；熟悉数据结构（数组、树、哈希表）。有 SQL 基础会更有帮助，但不是必需——第 4 章会从零讲起。

**学习时长**：90–110 小时（约每章 4 小时，外加习题）。如果深入做练习和苏格拉底式对话，应预留 110 小时以上。
