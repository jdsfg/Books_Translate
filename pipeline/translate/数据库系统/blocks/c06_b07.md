### 5.5 ER 到关系映射规则

现在进入机械部分。有五条标准规则。始终如一地应用它们，就能把 ER 模型变成关系 Schema，而不再需要在这个阶段做设计判断——所有判断已经在 ER 建模阶段完成。


#### 规则 1：每个强实体变成一张表

对每个强实体，创建一个表，每个简单属性对应一列。主键属性成为表的主键。复合属性分解（如果你希望各部分可查询）或存为单列（如果你想把它们视为不透明）。派生属性省略。

从我们的 ER 模型：

    Students    (id, name, email)
    Instructors (id, name, office, phone)
    Courses     (id, title, credits)

各表主键均为 `id`。


#### 规则 2：多值属性变成自己的表

多值属性不能存在单列中。创建新表：

* 指向拥有实体的外键。
* 多值属性值的一列。
* 主键为 (owner_key, value)。

我们当前领域没有多值属性，但如果一门 Course 可以有多个 `keyword` 标签：

    CourseKeywords (course_id REFERENCES Courses(id), keyword, PRIMARY KEY (course_id, keyword))


#### 规则 3：1:N 关系在“N”侧加外键

对 A 与 B 之间的 1:N 关系（每个 A 对应多个 B），在 B 中加一个外键引用 A 的主键。关系上的任何属性也放进 B。

从我们的 ER 模型：Teaches 是 Instructor 到 Course 的 1:N。所以我们在 Courses 中加 `instructor_id`：

    Courses (id, title, credits, instructor_id REFERENCES Instructors(id))

如果 Teaches 有 `since` 属性（教师首次教该课的日期），也放进 Courses 表：

    Courses (id, title, credits, instructor_id, since)

Course 侧的全参与（每门课必须有教师）→ `instructor_id` 为 `NOT NULL`。


#### 规则 4：M:N 关系变成自己的表

对 A 与 B 之间的 M:N 关系，创建一张新表——称为_连接表_或_关联表_。其列为：

* 指向 A 主键的外键。
* 指向 B 主键的外键。
* 关系自身的所有属性。

主键是两个外键的组合（或扩展键，如果关系可能重复，例如跨多个学期的选课）。

从我们的 ER 模型：Enrolls 是 Student 与 Course 之间的 M:N，属性为 `grade`：

    Enrollments (
      student_id REFERENCES Students(id),
      course_id  REFERENCES Courses(id),
      grade,
      PRIMARY KEY (student_id, course_id)
    )

这就是为什么选课是一张表，而不是一列。关系的 M:N 性质决定了这一点。
