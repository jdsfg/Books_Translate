#### 概念检查

**Q1.** 把下列每一项改写成 SQL：(a) 统计恰好 4 学分的课程数量。(b) 找出 id 号最大的学生。(c) 找出所有尚未给出成绩的选课。(d) 找出名字以 'B' 或 'C' 开头的所有学生。

提示

(c) 需要 null-aware 测试。(d) 用 OR 连接两个条件，或用模式匹配。

**答案：** (a) `SELECT COUNT(*) FROM Courses WHERE credits = 4;` (b) `SELECT * FROM Students ORDER BY id DESC LIMIT 1;` (c) `SELECT * FROM Enrollments WHERE grade IS NULL;` (d) `SELECT * FROM Students WHERE name LIKE 'B%' OR name LIKE 'C%';` —— 或等价地 `WHERE substring(name, 1, 1) IN ('B', 'C');`。两者都对；第一种通常能用索引，第二种很少能。

**Q2.** 下面两个查询有什么区别？哪个可能返回更多行？

    -- 查询 A
    SELECT s.name FROM Students s JOIN Enrollments e ON s.id = e.student_id;

    -- 查询 B
    SELECT s.name FROM Students s LEFT JOIN Enrollments e ON s.id = e.student_id;

提示

零选课的学生在每种情况下会怎样？

**答案：** 查询 A 返回每个选课一行——所以一名学生选 5 门课就出现 5 次，零选课学生根本不出现。查询 B 返回每个选课一行*加上*每个零选课学生一行（其 `e` 列为 null）。查询 B 至少和查询 A 一样大——只要有零选课学生，它就严格更大。

哪一个“对”取决于问题。对于“选了某些课的学生姓名”，对查询 A 用 DISTINCT。对于“学生姓名，无论是否选课”，用查询 B。对于“每个学生的选课数”，你几乎肯定想要查询 B 外面包一层 `GROUP BY + COUNT`。

**Q3.** 这个查询为什么失败？

    SELECT student_id, course_id, COUNT(*)
    FROM Enrollments
    GROUP BY student_id;

**答案：** `course_id` 既不在 `GROUP BY` 里，也不在聚合函数里。单独按 `student_id` 分组后，输出的每一行对应一个学生——而该学生有很多课程。SQL 不知道返回哪个 course_id，所以拒绝查询。

修复，取决于意图：

* 如果你想统计每个学生的选课数：去掉 `course_id`。`SELECT student_id, COUNT(*) FROM Enrollments GROUP BY student_id;`
* 如果你想按（学生，课程）计数：把 `course_id` 加进 `GROUP BY`。（这等价于 enrollments 表本身，因为 (student_id, course_id) 是主键——所以 `COUNT(*)` 恒为 1。）
* 如果你想要每个学生的*一个代表性* course_id：`SELECT student_id, MAX(course_id), COUNT(*) FROM Enrollments GROUP BY student_id;`

**Q4.** 在第 3 章习题 3.9 Q1 的 `Orders` Schema 中：

    Customers, Items, Orders, OrderItems

写出 SQL 实现：“对每个客户，计算其订单总价值，按总价降序排列”。总价值 = 每个订单明细中 (price_snapshot × quantity) 之和。

**答案：**

    SELECT c.id, c.name, SUM(oi.price_snapshot * oi.quantity) AS total_value
    FROM Customers c
    JOIN Orders o     ON o.customer_id = c.id
    JOIN OrderItems oi ON oi.order_id = o.id
    GROUP BY c.id, c.name
    ORDER BY total_value DESC;
