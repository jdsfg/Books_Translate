第 3 章给了我们数据的形状：关系、元组、键、引用。本章给我们针对这种形状提问和改变它的语言。SQL（Structured Query Language）是每种主流关系型数据库都说的一门*通用语*——尽管有方言差异——并且自 1974 年以来比任何竞争查询语言都活得更久。

这不是 SQL 参考手册。到本章结束时，你应该能读写处理 90% 真实操作型查询的 SQL，并理解**SQL 为什么被塑造成这样**——逻辑求值顺序、连接类型、`NULL` 行为——好到以后再遇到任何 SQL 结构都不觉得随意。每个例子都锚定在叙事 A（第 2–3 章的大学选课系统）：

    Students(id, name, email)
    Instructors(id, name, office, phone)
    Courses(id, title, credits, instructor_id → Instructors)
    Enrollments(student_id → Students, course_id → Courses, grade)


### 4.1 SQL 的两半：DDL 与 DML

SQL 有两个层面。**DDL——数据定义语言**（`CREATE TABLE`、`ALTER TABLE`、`DROP TABLE`、`CREATE INDEX`、`CREATE VIEW`）定义 Schema，其中 `CREATE INDEX` 用于创建索引（index）。**DML——数据操作语言**（`SELECT`、`INSERT`、`UPDATE`、`DELETE`）操作内容。日常工作大多是 DML，但即使 schema  sloppy，一个细心的 `SELECT` 也会出错。


#### DDL — 创建 Schema

我们大学选课系统的完整 DDL，采用自底向上构建，使外键引用可满足：

    CREATE TABLE Students (
      id    INTEGER PRIMARY KEY,
      name  VARCHAR(100) NOT NULL,
      email VARCHAR(100) UNIQUE NOT NULL
    );

    CREATE TABLE Instructors (
      id     INTEGER PRIMARY KEY,
      name   VARCHAR(100) NOT NULL,
      office VARCHAR(50),
      phone  VARCHAR(20)
    );

    CREATE TABLE Courses (
      id            INTEGER PRIMARY KEY,
      title         VARCHAR(200) NOT NULL,
      credits       INTEGER      NOT NULL CHECK (credits BETWEEN 1 AND 12),
      instructor_id INTEGER      NOT NULL REFERENCES Instructors(id)
    );

    CREATE TABLE Enrollments (
      student_id INTEGER NOT NULL REFERENCES Students(id) ON DELETE RESTRICT,
      course_id  INTEGER NOT NULL REFERENCES Courses(id)  ON DELETE RESTRICT,
      grade      VARCHAR(3),
      CHECK (grade IS NULL OR grade IN
             ('A+','A','A-','B+','B','B-','C+','C','C-','D+','D','D-','F')),
      PRIMARY KEY (student_id, course_id)
    );

这份 DDL 中有几点值得注意：

* `REFERENCES Instructors(id)` 创建外键。大多数数据库中删除默认动作是 RESTRICT，但我们在 `Enrollments` 上显式写出，以求清晰。
* `CHECK (credits BETWEEN 1 AND 12)` 把业务规则（“一门课值 1–12 学分”）直接编码进 Schema。应用的任何 bug 都无法插入一门 800 学分的课。
* `CHECK (grade IS NULL OR grade IN (...))` 利用了第 3.6 节的三值逻辑：我们允许 `NULL`（未评分）_或_ 一个来自合法集合的成绩。
* `PRIMARY KEY (student_id, course_id)` 是复合主键。每个（学生，课程）对恰好一行。
