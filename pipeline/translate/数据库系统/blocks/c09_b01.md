### 8.1 为什么 SELECT-FROM-WHERE 还不够

考虑注册主任可能会问的三个问题：

  1. “列出 GPA 高于其所在院系平均 GPA 的每位学生。”
  2. “对每门课，显示上学期选课人数与本学期选课人数。”
  3. “按 GPA 给出每个院系前三名学生。”

只用第 4 章的词汇尝试写第一个。你需要按院系计算平均 GPA（一个 GROUP BY 聚合），然后再把每个学生的 GPA 与该聚合值比较。但 GROUP BY 会折叠行——如果按院系分组，你就会丢失具体学生；不分组，又无法计算院系平均。你被困住了。

SQL 对这类问题的答案是允许查询*嵌套*在另一个查询内部。这个内部查询——**子查询**——就是我们要先建造的。


#### 常见误解

初学者常认为子查询总是比“等价”的 JOIN 更贵。在某些方言中成立，在另一些中不成立。PostgreSQL、MySQL 8、SQL Server 都经常在优化期间把子查询展平为连接。`WHERE id IN (SELECT ...)` 与 `INNER JOIN (...)` 在规划器处理完后，代价差异往往为零。不要基于 folklore 选语法；去读 `EXPLAIN`。
