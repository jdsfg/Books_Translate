**Q3.** 回想第 1 章中的神秘登录 bug——有些用户即使密码正确也无法登录。调试这个问题时，哪些偏差可能会让你走偏？一个具有偏差意识的调查会是什么样子？

**讨论：** 登录 bug 的潜在偏差陷阱：

**锚定在“密码”上：** bug 报告说“密码正确但登录失败”。你可能会锚定在密码比较逻辑上，花几个小时阅读认证代码，即使比较可能完全正常——问题可能出在密码如何被_传输_，而不是如何被_比较_。

**可得性——“我刚处理过 auth”：** 如果你最近碰过认证代码，你会怀疑自己的改动，可能因此漏掉这个 bug 早于你的工作存在。

**对编码的确认偏差：** 如果有人提到“也许是 Unicode 问题”，你可能会用 Unicode 字符测试并发现一些怪异之处——但实际原因完全是别的东西（比如特殊字符的 URL 编码，我们将在第 8 章探讨）。

**对“特殊字符”的过早闭合：** 你可能发现密码中带特殊字符的用户受到影响，并立刻得出结论：“特殊字符没有被正确处理”——但哪些特殊字符？为什么？具体机制很重要。

一个具有偏差意识的调查：(1) 观察——收集受影响与未受影响用户的数据，并在不预设模式的情况下寻找模式。(2) 生成多个假设——编码、比较、传输、哈希、字符集、浏览器差异。(3) 先测试信息量最大的假设——那个无论结果如何都能缩小最多可能性的假设。(4) 抵制闭合，直到你能解释精确机制，而不只是类别。


### 本章总结

你的大脑自带一些内置捷径，它们经常破坏调试：确认偏差让你看见自己预期的东西，锚定把你锁在第一个想法上，可得性启发让你怀疑记忆中新鲜的东西，过早闭合让你停止得太早，而沉没成本谬误让你在错误方向上走得太久。这些偏差不是缺陷——它们是人类认知的特性，只是碰巧在系统性调查中适得其反。

第 2 章的调试循环，其核心是一个偏差校正框架。每一步都强制执行一种纪律，而某种特定偏差正试图颠覆它。但意识是终极防线：当你能捕捉到自己在想“我确信是 X”，并立刻追问自己为什么_确信_时，你就把调试中最危险的时刻（未经检查的假设）转化成了最有成效的时刻（诚实评估的时刻）。

在第 4 章，我们会处理最简单却最被低估的调试技巧：真正_阅读错误消息_。这听起来微不足道。并不是。大多数程序员看到错误后会立刻开始猜测，落入我们刚刚讨论过的那些偏差——而答案往往就在那里，显示在屏幕上。
