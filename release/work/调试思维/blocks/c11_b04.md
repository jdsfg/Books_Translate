#### 定义：竞态

当程序行为取决于事件（例如两个线程或两个异步操作）的相对时序，而这些事件并不保证按特定顺序执行时，就会发生竞态。“竞争”发生在这些事件之间——哪个先完成，就决定了行为。

用直白的话说：两件事同时发生，结果取决于哪一件先完成。有时它能正常工作。有时不能。你无法预测是哪一种。
    
    
    // 竞态：两个请求更新同一个账户余额
    // 线程 1：读取余额（$100），加 $50，写入余额（$150）
    // 线程 2：读取余额（$100），减 $30，写入余额（$70）
    // 如果两者都在任何一方写入之前读取了 $100：
    // 线程 1 写入 $150，线程 2 用 $70 覆盖
    // 预期：$120（$100 + $50 - $30）。实际：$70 或 $150。
    

**为什么竞态很难处理：**

  1. **不可复现**：它们依赖时序，所以运行同一段代码两次可能产生不同结果。调试工具（打印语句、调试器）会改变时序，可能把缺陷隐藏起来。
  2. **依赖环境**：竞态可能从不在你快速的开发机器上表现出来，却在较慢的生产服务器上稳定出现（或反过来）。
  3. **间歇出现**：缺陷可能每 1000 次才出现 1 次，使得确认修复很困难。

**竞态的诊断模式：**

* **没有明确原因的间歇失败**——同一段代码有时有效，有时失败
* **“在我机器上能跑”**——不同硬件速度改变了时序
* **一调试缺陷就消失**（第 10 章的海森堡缺陷）——调试器暂停改变了时序
* **缺陷报告中出现“有时”这个词**——“它有时显示陈旧数据”或“它偶尔崩溃”

**调查方法：**

  1. **寻找共享可变状态**——任何可被多个线程/进程/异步操作读写的数据
  2. **寻找缺失的同步**——缺少锁、缺少 `await`、缺少事务边界
  3. **增加压力测试**——运行大量并发操作，提高竞态表现出来的概率
  4. **使用线程安全分析工具**——使用 ThreadSanitizer（C/C++）、`go vet -race`（Go）或 Java 的 `FindBugs` 等竞态检测器

Therac-25 放射治疗机器（第 14 章）曾因竞态导致患者死亡。安全关键系统中的竞态可能致命。这就是并发编程需要极端谨慎，以及 Rust 这类语言在设计上让数据竞争不可能发生的原因。


### 11.7 断言与不变量：及早捕捉缺陷

**断言**是代码中的一条语句，用来声明某件事在某个特定点应该始终为真。如果断言失败，程序会立即停止，并准确告诉你出了什么问题以及发生在哪里。
    
    
    def withdraw(account, amount):
        assert amount > 0, f"Withdrawal amount must be positive, got {amount}"
        assert account.balance >= amount, f"Insufficient funds: {account.balance} < {amount}"
        
        account.balance -= amount
        
        assert account.balance >= 0, f"Balance went negative: {account.balance}"
        return account.balance
    

断言是内建在代码中的调试基础设施。它们就像绊线——正常运行时看不见，但当某些东西违反你的假设时，会立刻提醒你。
