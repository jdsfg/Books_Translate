#### 定义：不变量

不变量是在程序的某个点上必须始终为真的条件。例如："账户余额永远不为负"、"列表始终已排序"，或"所有条目的总和等于总计"。

用直白的话说：不变量是你的代码承诺遵守的规则。断言检查这项承诺。

**在哪里放置断言：**

* 在函数入口：验证输入（"这个金额必须为正"）
* 在函数出口：验证输出（"返回的列表必须已排序"）
* 在关键操作之后：确认状态（"提现之后，余额非负"）
* 在循环不变量点：验证循环的契约（"每次迭代之后，数组直到索引 i 的部分都是已排序的"）

断言在生产环境中几乎没有成本（大多数语言都允许你禁用它们），并且会在缺陷发生的瞬间捕捉它们，而不是让它们在系统中传播并在别处表现为晦涩症状，从而节省大量调试时间。


### 11.8 调试谜题：消失的投票

**调试谜题：为什么投票会丢失票数？**

一个投票应用允许用户在投票中投票。一个有 3 个选项的投票显示：Option A: 42 votes, Option B: 37 votes, Option C: 21 votes。Total: 100 votes。一个新用户给 Option A 投票。预期：A=43, total=101。实际：A=43, B=36, total=100。

**线索 1：** 当 Option A 增加一票时，Option B _丢失_了一票。总数保持不变。

**线索 2：** 投票函数：
    
    
    function vote(poll, optionId) {
        const total = poll.options.reduce((sum, o) => sum + o.votes, 0);
        poll.options.find(o => o.id === optionId).votes += 1;
        // Recalculate percentages and normalize to keep total consistent
        const newTotal = total + 1;
        poll.options.forEach(o => {
            o.votes = Math.round(o.votes / newTotal * total);
        });
    }
    

**你的任务：** 发生了什么？为什么给 A 加一票会从 B 减一票？

**解答：** 这个函数先增加正确选项的票数，然后把所有票数_归一化_，以保持总数与之前相同。归一化这一行 `Math.round(o.votes / newTotal * total)` 会把所有票数缩放到旧总数（100），而不是新总数（101）。这意味着新增的一票实际上按比例分摊到了所有选项中，而舍入导致某些选项丢失了一票。

开发者的意图很可能是重新计算显示用的_百分比_，而不是实际票数。他们把"把百分比归一化到合计 100%"和"把票数归一化到旧总数"混淆了。修复方法：存储原始票数，只在显示时计算百分比，永远不要修改实际投票数据。

**本可以捕捉这个问题的断言：** 在归一化之后写 `assert newTotal === poll.options.reduce((sum, o) => sum + o.votes, 0)`。这个不变量（"投票之后的总票数应比之前多一"）会立即失败，指向归一化是罪魁祸首。
