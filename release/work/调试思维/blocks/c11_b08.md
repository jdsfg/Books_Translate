#### 应用题

**Q1.** 下面这个函数本应返回数组中的第二大数字。它有一个缺陷。找到它并解释修复方法。
    
    
    def second_largest(numbers):
        if len(numbers) < 2:
            return None
        first = second = float('-inf')
        for n in numbers:
            if n > first:
                second = first
                first = n
            elif n > second:
                second = n
        return second
    

用这个测试：`second_largest([5, 5, 5])`——它会返回什么？

提示

当所有数字都相同时会发生什么？[5, 3, 5] 呢？

**答案：** 对于 `[5, 5, 5]`：第一次迭代：`n=5 > -inf`，所以 `second=-inf, first=5`。第二次迭代：`n=5`，`5 > 5` 为 false，`5 > -inf` 为 true，所以 `second=5`。第三次迭代：同样，`second` 保持 5。返回 `5`。

这种行为是否是缺陷取决于需求。如果"第二大"意味着"第二大的不同值"，那么 `[5, 5, 5]` 应该返回 `None`（不存在第二个不同值）。当前代码返回 5，因为它把重复值视为有效。

更微妙的缺陷：`second_largest([5, 3, 5])` 返回 5（先 second=3，然后在第三个元素处因为 5 > 3 而 second=5）。这对于"第二大值"是正确的，但对于"第二大的不同值"是错误的。

如果需要不同值，修改 `elif` 条件：`elif n > second and n != first`。这样 `[5, 5, 5]` 会返回 `-inf`（可以检查它并返回 `None`），而 `[5, 3, 5]` 会返回 3。

**调试经验教训：** 这个缺陷只会在特定输入（重复值）下出现。用 `[3, 7, 1, 9, 4]` 测试会显示正确行为，并完全漏掉这个缺陷。边界情况（所有值相同、两个相同最大值）正是差一错误和边界缺陷隐藏的地方。

如果两个来自同一账户的转账同时运行，会发生什么？

**答案：** **竞态场景：** 两笔各 50 USD 的转账同时从一个余额为 80 USD 的账户运行。

  1. 转账 A 读取余额：80 USD。检查：80 USD >= 50 USD ✓
  2. 转账 B 读取余额：80 USD（尚未更新）。检查：80 USD >= 50 USD ✓
  3. 转账 A 写入新余额：80 USD - 50 USD = 30 USD
  4. 转账 B 写入新余额：80 USD - 50 USD = 30 USD（覆盖了 A 的写入！）
