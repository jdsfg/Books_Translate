### 9.4 Git Diff 是调试超能力

`git diff` 是最没有被充分利用的调试工具之一。除了简单回答"改了什么"，它还能回答具体的调试问题：
    
    
    # What changed in a specific file since it last worked?
    git diff abc1234..HEAD -- src/api/auth.js
    
    # What changes touched authentication-related files?
    git log --oneline --all -- '**/auth*'
    
    # Who last changed this specific line?
    git blame src/api/auth.js
    
    # Show me the full diff for a specific commit
    git show def5678
    
    # What changed between two releases?
    git diff v2.3.0..v2.4.0
    

**用 `git blame` 生成假设：** 当你已经把缺陷范围缩小到某一块代码时，`git blame` 会显示每一行最后是谁在什么时候修改的。这个上下文常常会提示原因："这一行是 3 天前改的——正好是缺陷开始的时候。让我看看这个提交是在做什么。"

**用 `git log -p` 识别模式：** `git log -p -- filename` 会显示一个文件随时间发生的每一次变化。滚动浏览这些变化可能揭示模式："每次有人碰这个函数，他们都会忘记更新下面的验证逻辑。"


### 9.5 超越代码：对比环境

当相同代码在一个环境中能工作、在另一个环境中不能工作时，版本对比适用于_环境_：
    
    
    Working environment vs. Broken environment
    What's different?
    

常见差异：

类别 | 开发环境（正常） | 生产环境（故障）  
---|---|---  
Node 版本 | 18.17.0 | 18.12.0  
数据库 | 本地 PostgreSQL 15 | AWS RDS PostgreSQL 14.6  
OS | macOS 14 | Ubuntu 22.04  
内存 | 16 GB | 512 MB container  
网络 | localhost，无延迟 | 跨区域，50ms 延迟  
数据量 | 100 条测试记录 | 5 百万条真实记录  
文件系统 | 大小写不敏感 | 大小写敏感  
  
每一个差异都是潜在原因。把它们作为假设来调查，先测试最可能的那些。

文件系统大小写敏感性的差异值得特别说明：macOS 和 Windows 默认使用大小写不敏感的文件系统，而 Linux（最常见的服务器 OS）区分大小写。这意味着当文件实际命名为 `UserService.js` 时，`import UserService from './userService'` 在本地可以工作，但在服务器上会失败。这是最常见的"本地能跑，生产坏掉"缺陷之一。
