#### 发生了什么

Cloudflare 的边缘服务器会解析 HTML，以应用各种转换（压缩、注入分析代码、电子邮件混淆）。这个解析器由 Ragel（一种状态机编译器）生成的语言编写，逐字符处理 HTML。

关键 bug 是：在一个由畸形 HTML 触发的特定代码路径中，解析器用 `==` 检查当前指针是否已经到达缓冲区末尾，而本应使用 `>=`。这看起来只是微不足道的区别，却造成了灾难性后果：

在正常情况下，指针每一步递增 1，刚好命中缓冲区的精确末尾，等值检查 `p == pe` 会正确停止。但当某些畸形 HTML 触发特定代码路径时，指针可能会 _跳过_ 缓冲区边界——落在 `p = pe + 2`，而不是 `pe + 1`。使用 `==` 时，检查会失败（指针已经越过末尾，并不 _等于_ 末尾），解析器于是继续读取缓冲区之外的内存——这些内存可能包含其他客户请求中的数据。

所谓“某些畸形 HTML”，是指页面上启用了三个特定功能（电子邮件混淆、服务器端包含排除，以及自动 HTTPS 重写），再加上损坏的 HTML 标签（例如未完成的属性：`<script type=`）这一特定组合。


#### 调试视角

**通过历史做二分查找（第 5 章）：** bug 报告后，Cloudflare 团队需要确定它已经发生了多久。他们在部署日志中做二分查找，发现这个 bug 是在解析器从一个代码生成器迁移到另一个代码生成器时引入的。这次迁移已经过去数月，也就是说这个 bug 已经泄露数据数月。

**最小可复现示例（第 6 章）：** 这个 bug 需要三个特定功能启用，并且需要畸形 HTML。在处理的数以百万计的页面中，只有极小一部分具备这个精确组合。这使得该 bug 极难通过测试发现——你必须正好测试到正确的功能组合和 HTML，才会触发它。这个 bug 的最小可复现示例会是：一个带有特定损坏标签的单个 HTML 页面，在三个特定功能启用的情况下被处理。

**可观测性（第 10 章）：** 这次泄露对 Cloudflare 的监控来说是不可见的，因为泄露的数据看起来只是正常 HTML 响应的一部分。从外部看，响应只是“一个 HTML 页面”——没有错误、没有崩溃、指标中没有异常。检测它的唯一办法，是注意到 HTML 中包含了不该存在的内容——这需要 _理解预期内容_，而不只是监控响应码。
