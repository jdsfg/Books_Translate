### 7.2 为什么这有效——认知科学

小黄鸭调试法不只是一个可爱的小技巧。它之所以有效，是因为一些被充分研究过的认知现象：

**语言处理会激活不同于默想的认知通路。** 当你默默思考时，你使用的是压缩的、速记式的表征——你会跳过步骤，因为“你知道自己是什么意思”。当你说出来（或写下来）时，你必须把这些捷径解压成带有逻辑连接的完整句子。这种解压会迫使你走过每一步，包括那些默想时一直被你略过的步骤。

**解释效应。** 认知心理学研究表明，向另一个人解释某件事会显著加深你自己的理解。这种现象也称为“受教者效应”或“以教促学”，它之所以起作用，是因为解释要求你组织信息、识别因果关系，并发现自己理解中的缺口。

**假设浮出水面。** 当你深陷一个问题时，会形成盲点——一些看起来显然为真、以至于你不会质疑的假设。“查找表当然是正确的”或“用户 ID 当然是整数”。解释问题会迫使你把这些假设明确说出来，从而让它们可以被测试。还记得第 3 章的认知偏差吗——小黄鸭调试法同时是对它们的反制手段，因为表达会穿透默想所维持的偏差过滤器。

**对连贯性的社交压力。** 即使“听众”只是一只橡皮鸭，想让自己的解释讲得通这种社交习惯，也会推动你比独自思考时更严谨。当有人（或某物）在“看着”你时，你更不容易含糊带过或跳过步骤。


### 7.3 有效解释的技巧

并不是所有解释都同样有效。下面这些做法能最大化小黄鸭调试法的调试能力：

**先解释预期行为。** 在描述 bug 之前，先解释代码本来应该做什么。“这个函数应该接收一个订单列表并返回总收入。” 这会建立一个基线，bug 会在这个基线之上显现出来。

**沿着数据流走。** 不要解释代码结构——解释数据如何移动。“用户的点击会发送一个带有这个 payload 的请求。服务器收到它，并把 payload 传给这个函数。函数提取 user ID 并查询数据库……” 跟随数据，而不是跟随架构。

**明确说出你的假设。** “我假设 user ID 总是存在于请求中，因为它由认证中间件设置。” 当你把假设大声说出来时，会突然意识到其中一些可能是错的。

**当你到达 bug 时，不要停——继续解释。** 有时你发现的第一个异常只是症状，不是根因。继续往下讲。“好，所以这里缺少 user ID。这意味着认证中间件没有设置它。但为什么？这个中间件会在所有路由上运行……哦，除了这条刚新增的路由，它没有使用这个中间件。”

**如果大声说话感觉奇怪，就写下来。** 有些人会觉得对着橡皮鸭说话很傻。没关系——改成写下解释。把它写成一份详细的 bug 报告，给一个从没见过你代码的人看。写作过程提供的认知收益与开口解释相同。
