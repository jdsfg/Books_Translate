### 16.7 调试谜题：编码灾难

**调试谜题：带重音符号的名字变成乱码**

一个 Web 应用在个人资料页面上能正确显示用户姓名，但在管理员报表中显示乱码字符（比如 `JosÃ©` 而不是 `José`）。

**线索 1：** 个人资料页面从 API 读取，API 返回带有 `Content-Type: application/json; charset=utf-8` 的 JSON。姓名显示正确。

**线索 2：** 管理员报表从一个由独立报表服务生成的 CSV 导出读取。CSV 文件在文本编辑器中打开时，会显示乱码字符。

**线索 3：** 报表服务使用以下方式生成 CSV：
    
    
    with open('report.csv', 'w') as f:
        writer = csv.writer(f)
        for user in users:
            writer.writerow([user.name, user.email])
    

**你的任务：** 编码在哪里出错了？

**答案：** 报表服务写入 CSV 时没有指定编码。在 Python 3 中，默认编码取决于系统 locale——在许多 Linux 服务器上是 UTF-8，但在某些配置中可能是 ASCII 或 Latin-1。即使 UTF-8 是默认值，CSV 文件也没有编码声明（不像 JSON，按规范默认是 UTF-8）。当管理员打开 CSV 时，他们的软件（例如 Excel）可能会错误猜测编码，把 UTF-8 字节解释成 Latin-1，从而产生乱码。

**修复：** 显式指定 UTF-8 编码，并添加一个 BOM（Byte Order Mark），告诉 Excel 使用 UTF-8：
    
    
    with open('report.csv', 'w', encoding='utf-8-sig') as f:
        writer = csv.writer(f)
        for user in users:
            writer.writerow([user.name, user.email])
    

`utf-8-sig` 编码会在文件开头写入 BOM，Excel 会把它识别为 UTF-8 指示符。
