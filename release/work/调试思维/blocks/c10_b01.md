有一种情况应该让你感到害怕：你的应用正在生产环境中运行，一个用户报告了缺陷，而你完全不知道发生了什么。没有日志，没有指标，没有追踪。应用是一个黑盒——数据进去，里面出了问题，错误的数据出来。你唯一的选择是尝试在本地复现这个缺陷，并希望它以同样的方式表现。

现在看相反的情况：用户报告同一个缺陷，而你在 30 秒内就能调出确切的请求，看到它触碰过的每一个函数，阅读它发出的数据库查询，观察它生成的响应，并定位数据出错的确切步骤。这个缺陷几分钟内就解决了。

这两个场景之间的差异就是**可观测性**——你通过检查系统输出理解系统内部发生了什么的程度。构建可观测系统不只是良好的工程实践；它是调试中最大的单一力量倍增器。


### 10.1 什么是可观测性？

#### 定义：可观测性

可观测性是通过检查系统的外部输出——日志、指标和追踪——来理解系统内部状态的能力。当你无需修改系统或部署新代码，就能回答关于系统正在做什么或曾经做过什么的任何问题时，这个系统就是"可观测的"。

用直白的话说：可观测性意味着你能_看到_系统正在做什么。当某个东西出错时，你不必猜——你可以查看证据并理解发生了什么。

可观测性建立在三大支柱之上：

  1. **日志**：离散事件——"在这个时间，这件事发生了。"日志告诉你发生了_什么_。
  2. **指标**：随时间变化的数值测量——"请求延迟是 200ms，错误率是 0.5%。"指标告诉你系统表现_如何_。
  3. **追踪**：请求在系统中经过的路径——"这个请求经过了服务 A，然后是 B，再然后是 C。"追踪告诉你系统中的_哪里_发生了某件事。


### 10.2 Print 语句：有效的原始工具

让我们从最朴素的可观测性工具开始：`print` 语句。
    
    
    def process_order(order):
        print(f"Processing order {order.id}")
        validated = validate(order)
        print(f"Validation result: {validated}")
        total = calculate_total(validated)
        print(f"Total: {total}")
        result = charge_payment(total)
        print(f"Payment result: {result}")
        return result
    

Print 语句具有这些特点：

* **通用**：适用于每种语言、每个平台
* **零依赖**：不用安装库，不用配置服务
* **即时**：添加、运行、看到输出
* **出人意料地有效**：对于本地调试，它们能解决大多数缺陷

它们也有这些问题：

* **嘈杂**：充满调试 print 的生产日志很难阅读
* **非结构化**：自由文本输出很难搜索或过滤
* **临时**：你添加它们、调试，然后删除它们，从而丢失了仪表化
* **手动**：在你知道缺陷在哪里之前，你就必须知道该把它们放在哪里

当你在本地调试、对缺陷位置有大致判断，并且需要查看几个值时，print 语句是正确工具。当你需要理解生产系统、监控持续行为，或者处理你尚未预料到的缺陷时，它们就是错误工具。
