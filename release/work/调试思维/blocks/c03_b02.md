### 3.2 锚定——第一个想法会粘住

一位同事顺口提到：“我们上周遇到过一些 DNS 问题。”一小时后，你正在调试一个连接超时。你的大脑立刻抓住：“一定是 DNS。”

也许确实是 DNS。但你之所以在考虑 DNS，并不是因为证据指向那里——而是因为 DNS 是最近被提到的概念。你的第一个想法已经变成了锚，后续所有思考都围绕它运行。


#### 定义：锚定偏差

锚定是指在做决定时过度依赖遇到的第一条信息（“锚”）的倾向。随后的判断是从这个锚开始调整得出的，这会让最终结果偏向初始值。

用直白的话说：你最先想到的东西往往会主导你的思考，即使后来出现了更好的信息。第一个假设仅仅因为它是第一个，就获得了不公平的权重。

调试中的锚定常常来自：

**外部建议：** 有人说“检查防火墙”，然后你就无法停止想着防火墙，即使没有证据指向那里。

**过去经验：** 你上次看到这个症状时，原因是 X。所以 X 变成了你的锚，即使这次是不同的上下文。

**错误消息：** 如果错误显示 “connection refused”，你就会锚定在网络问题上——即使实际原因是服务器进程崩溃了，端口上根本没有任何东西在监听。


#### 对策

  1. **在测试任何假设之前，先生成多个假设。** 不要停在第一个想法上。在开始调查之前，强迫自己列出至少三个可能原因。这会削弱锚的力量。

  2. **明确标记你的锚。** 对自己说：“我想到 DNS 是因为 Bob 提到了 DNS，不是因为证据。让我先把它放到一边，看看实际数据。”意识到这种偏差会降低它的影响。

  3. **在多个假设之间交替。** 不要把所有时间都花在假设 #1 上，等 #1 失败才检查 #2。交错进行：在 #1 上花 5 分钟，然后在 #2 上花 5 分钟。这能防止你在任何单一理论中陷得太深。


### 3.3 可得性启发——怀疑记忆中最新鲜的东西

你整个上午都在处理认证模块。下午，有人报告结账流程里有一个 bug。你的第一个念头？“也许我在认证里改的东西影响了结账。”

可能是这样。也可能和认证毫无关系。但认证在你的记忆中是_可得的_——它新鲜、生动，并且就在脑海最前面。因此你的大脑把它标记为可能的嫌疑对象，不是因为证据，而是因为它最近。
