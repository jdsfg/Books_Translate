### 10.9 调试谜题：慢性毒药

**调试谜题：为什么应用每天都会变慢？**

一个 Web 应用的 p95 延迟在周一早晨是 200ms，到周三变成 500ms，到周五变成 2000ms。周一重启应用会让它回到 200ms。这个模式每周重复。

**线索 1：** CPU 和网络指标整周保持平稳。内存使用量从周一的 200MB 稳步增长到周五的 3.5GB。

**线索 2：** 应用使用内存缓存保存用户会话。这个缓存没有淘汰策略——条目会被添加，但从不移除。
**线索 3：** 到周五有 50,000 个活跃会话时，Node.js 垃圾收集器运行得更频繁、耗时更长，导致延迟尖峰。

**你的任务：** 内存增长如何导致延迟增加？

**解答：** 内存中的会话缓存持续增长，因为会话会被创建，但从不过期或淘汰。当缓存增长到数百万条目时，两个效应会叠加：(1) 缓存查找会变慢，因为数据结构更大（不过这通常是对数级，所以影响较小）。(2) 更关键的是，垃圾收集器必须扫描更多对象。Node.js 使用 mark-and-sweep GC，它在 major collection 期间会暂停所有执行。当对象达到 3.5GB 时，GC 暂停会变得频繁且漫长——每次暂停都会给当时正在进行的请求增加延迟。

**本可以立即捕获这一点的可观测性：** 内存使用指标（线索 1）结合 GC 暂停指标（未提及，但大多数运行时都可用）。如果团队一直监控这些指标，他们会看到内存增长，并看到 GC 暂停与延迟相关——这是清晰、直接的诊断。没有指标时，团队可能会花几天调查代码变化、API 调用和数据库查询，却从未怀疑应用自身的内存管理。
