#### 应用题

**Q1.** 一个 React 应用有一个缺陷：表单校验消息在页面加载时立即出现，而不是等到用户提交表单后才出现。这个应用有 40 个组件、Redux 状态管理、自定义钩子，以及一个 CSS-in-JS 库。请逐步描述你会如何使用减法构建这个缺陷的最小可复现示例。

提示

先识别哪些内容肯定无关。这个缺陷关乎表单校验的时机——你可以立即排除什么？

**答案：** 逐步构建最小可复现示例：

  1. **移除所有非表单页面/路由。** 缺陷在表单中——另外 35 个页面无关。测试：只保留表单页面时，缺陷是否仍然存在？几乎可以肯定是的。

  2. **移除无关服务。** 身份认证、分析、通知——这些都不会影响表单校验的渲染。把它们全部移除。

  3. **简化表单。** 如果表单有 15 个字段，就减少到 2 个——一个带有校验，另一个不带校验。测试：校验消息是否仍然会在加载时出现？

  4. **移除 CSS-in-JS。** 用普通 HTML 替换带样式的组件。如果缺陷仍然存在，CSS 就没有参与其中。

  5. **简化状态管理。** 用本地组件状态（`useState`）替换 Redux。如果缺陷仍然存在，Redux 就不是原因。如果缺陷消失了，那么 Redux 状态初始化就参与其中。

  6. **移除自定义钩子。** 如果表单使用 `useFormValidation()`，就把它的逻辑直接内联展开。这会暴露校验触发逻辑。

  7. **检查剩下的内容。** 到这一步，你很可能只剩下：一个组件、一个表单字段、一个校验规则和本地状态。缺陷现在位于大约 30 行代码中。最可能的原因：校验是在渲染时触发的（例如在没有正确依赖数组的 `useEffect` 中，或者初始状态已经包含校验错误），而不是在提交时触发。

**Q2.** 你正试图在 StackOverflow 上就一个缺陷求助：你的 Python 脚本在读取某个特定 CSV 文件时崩溃。这个 CSV 是来自生产数据库的 50MB 文件，包含 200,000 行和 45 列。你会如何创建一个适合公开发布的最小可复现示例？除了最小化之外，你还需要处理哪些顾虑？

**答案：** 从生产数据创建公开的最小可复现示例需要几个步骤：

**步骤 1 — 最小化数据：**

* 从完整 CSV 开始。只用前 100 行时缺陷是否会出现？10 行呢？1 行呢？
* 一旦找到最小行数，就检查：只保留相关列时缺陷是否会出现？不断移除列，直到只剩必要的列。
* 目标：得到一个可能只有 3 行和 3 列、但仍然能显示该缺陷的 CSV。

**步骤 2 — 匿名化/合成数据：**

* 绝不要公开发布生产数据。用具有相同特征的合成值替换真实值。如果缺陷是由姓名字段中的某个特殊字符导致的，就创建一个带有该字符的假姓名。
* 确保合成数据仍然能够复现该缺陷。

**步骤 3 — 最小化代码：**

* 将脚本精简到只保留 CSV 读取和失败操作。移除所有与崩溃无关的业务逻辑、错误处理和输出格式化。

**步骤 4 — 使其完整：**

* 内联包含 CSV 数据（将其嵌入为字符串或多行变量），使最小可复现示例自包含——读者不应该需要下载文件。
* 包含确切的 Python 版本和库版本。
* 包含确切的错误消息和堆栈跟踪。
