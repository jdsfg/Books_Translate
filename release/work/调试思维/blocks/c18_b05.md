#### 概念检查

**Q1.** 什么是苏格拉底式调试，为什么它比简单告诉别人答案更有利于长期技能发展？

**答案：** 苏格拉底式调试通过提问引导某人完成调试调查，让他们自己发现答案，而不是直接告诉他们。它更有利于长期技能发展，因为：(1) 学习者练习的是调查过程，而不只是修复方式。他们学会如何找到缺陷，而不只是这个缺陷的具体答案。(2) 自己发现的答案比被告知的答案更容易记住（认知心理学中的生成效应）。(3) 学习者会建立对自己调试能力的信心。(4) 这个过程教会他们独立应用调试循环，形成一种自我维持的技能，可以用于未来那些你不在场帮忙的缺陷。

**Q2.** 什么时候应该给出直接答案，而不是使用苏格拉底式方法？

**答案：** 在以下情况下给出直接答案：(1) **存在紧迫性**——生产环境宕机，客户受影响，教学可以等到灭火之后。(2) **学习者缺少知识**——他们不知道某个工具（git bisect）、某个概念（URL 编码），或某个领域约定（认证服务如何返回错误）。再多提问也无法产生他们没有的知识。(3) **学习者已经精疲力尽**——在 4 小时调试毫无进展之后，一个提示或直接答案可能比继续提问更人道、更有生产力。混合方法（直接教授概念，然后用苏格拉底式方法引导其应用）结合了两者的好处。

**Q3.** 为什么“你试过 X 吗？”是伪装成问题的指令，而不是真正的苏格拉底式问题？

提示

想想这个问题向学习者传达了什么信息。

**答案：** “你试过 X 吗？”传达的是“我认为 X 会解决你的问题”——它本质上是在用问题形式告诉他们答案。学习者没有学会自己生成 X；他们学会的是跟随你的建议。真正的苏格拉底式问题会是“你考虑过哪些方法？”——它提示学习者思考自己的策略，并可能自己生成 X（以及其他想法）。或者“什么能帮助你缩小缺陷位于哪一半代码中？”——这会教授二分查找思维，而不指定具体技术。

**Q4.** 什么让事后复盘成为“无责”的，为什么无责性对调试文化很重要？

**答案：** 无责事后复盘关注系统性原因（流程、工具、架构），而不是个人错误。它不会说“Bob 部署了坏代码”，而是问“我们的部署流程中有什么使坏代码能够进入生产环境？” 无责性重要，因为：(1) 如果人们害怕被责备，他们会隐藏错误，使缺陷更难被发现和学习。(2) 责备个人会阻止系统性改进——即使 Bob 被“惩罚”，流程缺陷仍然存在，另一个人还会犯同样的错误。(3) 责备会制造恐惧文化，阻碍冒险、实验和部署——而这些都是软件开发所必需的。(4) 几乎每次事故都涉及一连串系统性因素，而不是某一个人的单一错误。责备一个人会忽略更深层的原因。
