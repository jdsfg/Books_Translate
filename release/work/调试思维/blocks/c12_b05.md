### 12.7 调试谜题：幽灵权限

**调试谜题：除生产环境外处处可用的上传**

文件上传在开发、预发布和 QA 环境中都能工作。在生产环境中，它们静默失败——上传端点返回 200（成功），但文件从未写入磁盘。

**线索 1：** 应用代码把文件写入 `/data/uploads/`。这个目录存在于所有环境中。

**线索 2：** 在生产中，应用以用户 `app` 的身份运行在 Docker 容器内部。`/data/uploads/` 目录是一个由 `root` 拥有的挂载卷。

**线索 3：** 在容器中添加 `ls -la /data/` 显示：`drwxr-xr-x root root uploads`。

**你的任务：** 为什么上传会静默失败？

**解答：** 目录权限 `drwxr-xr-x` 意味着：所有者（root）可以读/写/执行，组和其他用户只能读和执行——不能写。应用用户 `app` 属于 "others"，无法写入这个目录。上传失败是因为写操作被拒绝。

但为什么是静默的？应用代码很可能捕获了权限错误，并在不记录日志的情况下处理（或吞掉）它。在开发环境中，开发者以 root 或目录所有者身份运行，所以权限问题从未出现。

修复：`chmod 777 /data/uploads/`（快速但不安全），或者更好的是 `chown app:app /data/uploads/`（正确的所有权）。预防：Dockerfile 应在镜像构建期间用正确所有权创建上传目录。

**环境比较角度：** 工作环境和损坏环境之间的差异不是代码、配置或数据——而是文件_所有权_。这不会出现在任何应用文件 diff 中。
