#### 定义：差异（Diff）

**差异（diff）**就是**用白话说明改了什么**：它精确说明项目现在的样子，和如果一个拟议更改进入之后项目会变成的样子，两者之间有什么不同。不是整个文件。不是整本书。只包括那些会**不同**的部分：删除了什么、添加了什么，以及在哪里。

这个词来自 “difference” 的缩写。工具可以用一种充满标记和符号的技术形式展示 diff，但你完全不必那样阅读。你的智能体可以把任何 diff 呈现成白话摘要：**这一行删掉，这一行加上，这个词修正，其他一切保持不变。**当本书说“阅读差异”时，指的正是这种白话阅读。技能不在于解码符号。技能在于用日常句子理解到底会有什么变得不同，这样当你批准时，你批准的就是一个真实、已知的东西，而不是一个附着友好备注的谜团。

差异比描述更诚实。Núria 可以写“对 Alfama 部分做了一些小修正”，这句话也是真的，但 Maya 仍然不知道自己到底在同意什么。差异会展示**全部**不同，不多也不少。它不能把更改藏在含糊摘要后面，因为它不是摘要。它就是更改本身，被摊开供人阅读。


#### 常见误解

**“审阅一个更改，就是检查它有没有错误；我的工作是抓出错误并拒绝糟糕的更改。”**

这是人们最常见的审阅图像，也是真正审阅的一种狭小、令人难过的版本。

如果审阅只是抓错误，那么最好的审阅就会是拒绝最多更改的审阅，而一次以“是的，这很好，谢谢你”结束的审阅，反而会让人感觉像是你没能找出问题。相信这种图像的审阅者会变成守门人，守着门口；而给他们带来更改的人会学会少带一些，并且下意识畏缩。

更真实的图像是这样：**审阅是一场让作品变得更好、也传播理解的对话。**更改来了；你阅读它；你理解它；很多时候你会看到一种让它**更好**的方式：一个更清楚的句子，一个值得再核对的事实，或者一个作者在自己的编辑内部看不到的小东西。一次审阅最好的结果，常常不是拒绝，也不是沉默地说可以。它是一个**比刚到来时更好的更改**，由两个人一起抵达，并且两个人都比独自一人时更深入地理解了作品。

抓到错误有时是其中的一部分。但如果你走进去时只寻找错误，你就会错过你真正要做的那件更大的事：成为让作品变得更好的第二个头脑，并让带来更改的人觉得，带来它是值得的。一个项目的质量不住在它的代码或文字里。它住在每个更改周围的**对话**里。你正在加入的，正是这场对话。
