#### 应用题

**Q1.** 想想旧方式：朋友给你发邮件，建议你修正自己写过的某个东西。现在具体列出，从她发来邮件到修正真正出现在你的作品中，中间必须发生的每一件事，以及每一步可能出错的地方。然后说明拉取请求移除了其中哪些步骤。

提示

按字面一步步走：她写下描述更改的文字；你读这些文字；你定位到那个位置；你解释她的意思；你写出编辑；你希望自己理解对了。缝隙在哪里？

**答案：** 在邮件世界里，这条链又长又漏。她用散文描述更改。你必须自己找到正确的位置。你必须解释她的话，而这些话可能含糊不清。实际编辑由你来做，所以其中任何错误现在都成了你的错误。建议（在你的收件箱里）和编辑（在你的手里）从未在物理上相遇，因此没有一份单一记录能说明当初提出了什么、最终做了什么。大多数修正都会死在这条链的某处，因为它所需的工作量超过了它的价值。拉取请求几乎把这一切都压缩掉了：**她**找到位置，**她**写出精确的编辑，而提议和编辑是同一个对象，所以不需要解释，不需要重新定位，也没有让建议掉进去的缝隙。你保留下来的，只有那个本来就应该属于你、也只属于你的一步：是否接受的决定。这就是全部收益，用一句话说就是：拉取请求把劳动移给提出者，并让所有者只剩下一项工作——决定。
