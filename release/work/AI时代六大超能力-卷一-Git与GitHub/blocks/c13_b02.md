### 12.2 fork（分叉副本）

还记得相册、仓库、那个保存项目完整历史的家吗？Maya 和 Theo 为这份指南拥有一个。它保存着他们拍下过的每一个快照，一直回到那个被覆盖的星期六。

想添加博物馆小节的那位家长，不需要进入那本相册。他们需要自己的相册。

#### 定义：fork

**fork 是你对别人相册拥有的一份完整副本；你可以自由修改它，然后把你的变更提回给原项目。**

当那位家长 fork 这份指南时，工具会为他们制作整个项目的一份完整、独立的副本：每一个快照、完整历史、所有内容，和第 8 章里 clone 给 Theo 笔记本电脑上一份完整副本的方式一样。区别在于它住在哪里，以及它属于谁。这份副本是**他们自己的**。它在工作坊里挂在他们自己的名字下面。他们可以添加博物馆小节，改写一段文字，拍快照，弄得一团糟，从头再来，而这一切都不会碰到 Maya 和 Theo 的原项目，连一个逗号都碰不到。现在，这两本相册已经是两个分开的家。

这种独立性就是全部重点。那位家长可以平静地做自己的工作，不需要许可，不需要等待，也没有任何办法损坏他们欣赏的东西。与此同时，Maya 和 Theo 什么也不会察觉；他们的指南原样待在那里。fork 对那位家长没有成本，对原项目所有者也没有成本，并且移除了让陌生人帮忙时唯一真正的摩擦：害怕把陌生人放进来。

而这里，这个形态闭合成了一个循环。一旦那位家长在自己的副本里起草好博物馆小节，他们就做你已经从第 10 章认识的动作。他们打开一个拉取请求（一个拟议变更、一份 diff、一场对话、一个决定），从**他们的副本指回原项目**。“这是我写的一节。你愿意把它放进你的指南吗？”Maya 像读朋友修正咖啡馆那次一样，用白话读 diff。她可以问问题。她可以接受它，然后这一节流入原项目。她也可以拒绝它。选择权在她手里，因为这是她的指南。

fork，制作你自己的副本。自由修改它。把变更提回去。这个三步循环，**fork、修改、提回**，就是数以百万计的陌生人每天改进彼此作品的方式，而你现在已经理解了其中的每一步。
