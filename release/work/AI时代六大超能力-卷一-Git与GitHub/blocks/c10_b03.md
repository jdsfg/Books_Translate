### 9.2 工作坊从何而来

简短地知道这座建筑是怎样出现的，是值得的，因为这个故事解释了它为什么以现在这种方式运作，也因为其中两个事实离奇到值得随身带着。

底下的工具 Git，是 Linus Torvalds 在 2005 年写的；他也是十四年前启动 Linux 操作系统的同一个人。他一开始并不是要建造一个会运行全世界软件的工具。他写它，是因为自己的项目遇到了一场危机。Linux 内核一直由另一个版本控制工具管理，而在 2005 年，使用那个工具的免费安排破裂了。突然之间，地球上最大的协作项目之一，没有了追踪自身历史的好办法。

于是 Torvalds 写了自己的工具。了不起的是时间线：第一个可工作的版本大约十天就拼了出来。开发始于 2005 年 4 月初，几天之内，它就已经在追踪自己的源代码；这个工具几乎立刻就在管理它自己诞生过程的历史。它很快，能很好地处理相册和分支模型，而且任何人都可以免费使用。它传播开来。

但 Git 本身只是你自己机器上的一个工具。三年后，把它变成世界协作之地的是 GitHub。2008 年，三个人（Tom Preston-Werner、Chris Wanstrath 和 PJ Hyett）创立了 GitHub。他们的想法就是那个满是工作台的房间：拿 Git 这个让人们保存相册的工具，建一个网站，让这些相册拥有地址、面孔，以及人们谈论彼此工作的方式。这个组合，工具加上公共工作坊，就是现在大多数人谈到“把某个东西放到 GitHub 上”时的意思。

它变得巨大。2018 年，Microsoft 以 7.5 亿美元 收购 GitHub；交易在那年 6 月宣布，并在那年 10 月完成。截至 2026 年，按相当大的优势，它是同类工作坊中最大的一个：根据平台自己的年度报告，大约有 180 百万 名开发者和数亿个项目。

注意哪些事实是持久的，哪些会漂移。Git 写于 2005 年，GitHub 创立于 2008 年，Microsoft 在 2018 年以 7.5 亿美元 买下它：这些事情发生过，并且会一直为真。规模数字则性质不同。“180 百万” 是一个运动中事物的快照；等你读到这里时，它会更大，如果你想知道当前数字，就去查。这是整本书要求你养成的习惯：把已经定下来的事说清楚，把仍在移动的事当作需要核查、而不是需要背诵的东西。日期是历史。人数是天气。
