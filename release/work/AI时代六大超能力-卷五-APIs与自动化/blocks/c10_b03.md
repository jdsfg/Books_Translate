#### 常见误解

_“我需要彻底理解一个服务的文档，才能使用它。”_

你需要理解的是它的_能力_，也就是快速的顶层读取，而不是它的_参考资料_，后者才是缓慢、细致的那一种。人们会想象，自己必须把整本密密麻麻的手册从头到尾读完，才“被允许”做任何事；也正是这个信念，让他们还没开始就放弃了，因为参考层确实令人精疲力竭，而且对于一个不负责打字的人来说，基本无关紧要。真相正好相反：你快速扫描这个服务_能做什么_，决定你想要什么，然后_到那时_，在委托构建的时候，才有人（通常是你的助手）需要你选中的那一件具体事情的精确参考细节。你不会为了点早餐就吃完整张菜单。为了能力而读，做出选择，然后让细节恰好及时到来。


### 9.4 转折：从服务是什么，到拿它做什么

请注意，这一章处在一个铰链上。前八章讲的是服务_是什么_，以及它们如何行动：柜台窗口、JSON、发问与回答、拒绝、密钥、礼节、门铃。现在你已经握住了那张地图。能力扫描这项技能，让你可以把那张地图指向_任何_服务，包括那些你我都从未听说过的服务，并且迅速学会它的形状。

这就完成了本书的 API 半部。从这里开始，问题改变了。它不再是“这个服务是什么，它如何行动？”而是“既然我现在能查明任何服务可以做什么，_这些能力中哪些值得接起来，哪些应该留在我自己手里？_”那就是本书的自动化半部，也是在那里，判断力会从背景走到前景。能力扫描是一座桥：它既是“理解服务”这一半的最后一项技能，也是“委托构建自动化”这一半的第一件工具，因为你若不能迅速勘察什么是可能的，就无法判断什么值得自动化。

所以，结束这一章的那个请求，恰如其分地，也正是你以后会构建的每一条自动化的开场请求：在决定要做什么之前，先弄清楚能做什么。


### 9.5 练习

读取答案。

#### 对你的 AI 这么说（排练）

**Q1.** Mara 想知道她的邮件名单服务能不能按买家购买的系列给他们打标签，这样她以后就可以给这些分组发送消息。请用你自己的话，写出她应该向助手提出的普通语言请求，并说出那个她绝不能跳过的追问。

提示

她想要一份用普通语言写成的能力勘察，而且她要能够信任它。

**答案：** 一个好的请求大致可以是：“读取我的邮件名单服务的文档，用普通语言告诉我，它能不能按买家购买的系列给他们打标签或分组，以及沿着这个方向它还能做些什么。不要设置任何东西；我只是想知道什么是可能的。”她绝不能跳过的追问是：“文档里的哪里真的这么说？”第二个问题，就是能力扫描和一厢情愿之间的全部区别，因为它迫使助手的报告回到这个服务真实、可核查的文本上，而不是停留在一个听起来合理的猜测上。读得快，是助手的天赋；核实它读到的东西真的在那里，是 Mara 的工作，而这是一件很小、回报很大的工作。
