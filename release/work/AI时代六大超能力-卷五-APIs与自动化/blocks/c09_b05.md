### 本章小结

得知某事已经发生，有两种方式：**敲门**（你的管道每隔一段时间去问柜台，这是新鲜程度和礼貌之间的妥协），以及**被按响门铃**（服务在事件发生的那一刻主动联系你）。第二种就是 **Webhook**，一只门铃：你登记一个地址和一列事件，服务就会无需提示地按响你，常常递过来一只关于发生了什么的小 JSON 盒子。这个名字可以追溯到 2007 年和工程师 Jeff Lindsay，但你只需要那幅图景。门铃化解了新鲜程度与礼貌之间的张力，但有一个诚实的代价：为了让服务在任何时刻_按响_你，你需要某个始终醒着、在固定地址上监听的东西，而这正是第四卷所讲的始终开启的存在。一台合上的笔记本电脑接不到门铃。

在敲门（**轮询**）和被按响门铃（**推送**）之间选择，是一种判断，不是一条教义：只有在你真的需要_马上_知道时，才伸手去拿门铃；当_马上_并不重要时，就按日程敲门，因为每周任务想要的是时钟，不是始终开启的监听者，而过度建造更花哨的东西是一种常见错误。Mara 最终两者都会用：为她每周的汇总安排定时敲门，为不能等待的加急委托准备门铃。这一章建立在第 7 章“问一次，然后记住”之上（门铃是不再过度发问的终极版本），也伸进了第四卷的疆域。下一章，第 9 章，会转向一种让每个服务都变得可亲近的技能：用地图方式读取它的文档，扫描它_能做什么_，而不是记住该怎么做；这也是从 API 地图转向自动化地图的枢纽。
