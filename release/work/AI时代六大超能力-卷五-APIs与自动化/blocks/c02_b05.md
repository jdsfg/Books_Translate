#### 预判形状

**Q2.** 在 Mara 的四件周一任务里，哪些是*读取*，哪些是*发送*？为何这个区分重要到我们要在第一章就标出来？

**答案：** 任务 1（读订单）和任务 2（更新库存表）本质上是*读取*：它们拉取信息并记录下来，误做两遍也不会造成伤害。任务 3（给每位买家发邮件）和任务 4（发到邮件列表）是*发送*：它们把东西推到外面世界，别人会收到，出错也无法「取消发送」。这个区分之所以重要，是因为我们后面关于信任与安全的全部处理都挂在它上面。我们会让助手尽早、自由地读取，因为读取可逆。在发送之前，我们会让它停下、起草、等一句人的「可以」，因为发送不可逆。若读者离开本章时只带走「读取廉价，发送昂贵」，就已经握住了本书一根承重梁。


#### 对你的 AI 这么说

每章结尾你会找到一两句眼下就能对助手说的白话。它们是累积的：后面的倚靠前面的。大声说出来；若听起来说得出口，它们就是说得出口的。

本章的请求是一次勘察，不是一次行动——因为自动化任何东西的第一步，是把管道看清楚：

> *「这些是我每周用的在线工具：[把它们说出来]。对每一个，用白话告诉我：它有没有一扇『柜台窗口』，能让另一个程序透过它提问。先什么都别搭。我只想知道，原则上哪些工具可以被自动交谈。」*

注意这个请求的三点——它们是此后所有请求的模板。它是**意图层**的：说的是你想知道什么，不是该按哪些按钮。它是**安全**的：明确只要信息，禁止任何改动。它是**老实的第一步**：在自动化任何东西之前，先弄清什么*能*被自动化。你是在画地图，然后再修路。


### 本章小结

你就是那段管道。你用的每个服务都擅长一件活，住在自己的房间里；你整天在从未连通的房间之间搬运信息，一件信使差事接一件。这本书讲的是那些房间造好时留下的第二扇门——为机器造的那扇：**柜台窗口**。在互联网的大半辈子里，那扇门只给工程师，而且这话曾经老实；改变的是你现在有了一个 AI 助手，能替你走上前去提问，于是你需要的技能不再是旧式程序员的手艺，而是一种新的：知道该要什么、该检查什么，以及什么绝不能想都不想就交出去。那就是**地图**，而这是一本地图书。

我们遇见了 **Mara**——一位陶工，她的周一仪式（读订单、更新库存、给买家发邮件、发到邮件列表）将是全书贯穿的例子；我们也注意到了后面会统领一切的那个区分：*读取*廉价且可逆，*发送*则不然。第2章我们打开柜台窗口，看看 API 究竟是什么，好让「店铺可以被询问」不再只是承诺，而变成你能想象的东西。更后面，在综合项目里，我们会站在 Mara 那套已完成、已完全理解的管道前，用本系列教过的每一种工具把它走通。但一切从这里开始：一杯茶旁的一句承认。
