#### 读盒子

**Q1.** 下面是一个虚构天气服务透过柜台窗口递回来的响应：
    
    
    {
      "location": "Porto",
      "today": { "high_c": 24, "low_c": 17, "summary": "clear" },
      "tomorrow": { "high_c": 19, "low_c": 15, "summary": "rain" }
    }
    

Mara 的助手说：「明天波尔图会下雨，最高 19 度。」只读盒子，助手对吗？它必须打开哪些标签才能作答？

提示

有两个内盒。确认助手读的是对的那一个。

**答案：** 助手是对的。要作答，它必须打开 `tomorrow` 盒子（不是 `today`——容易搞错），并读里面的两个标签：`summary` 是 `rain`，`high_c` 是 `19`。注意：核对这件事完全不需要技术技能；你打开声称所关于的贴签盒子，确认两条事实。这就是读 JSON 的全部技艺，也是监督替你读它的助手的全部技艺。若助手说「最高 24」，你就会抓住它误读了 `today` 盒子。


#### 预判服务

**Q2.** 回头看 3.2 节那托盘三笔订单。Mara 对助手说：「给这周末买了东西的每个人发一封感谢信。」若助手一字不差照做，谁会收到*不该*收到的邮件？哪一个贴签盒子本可以防止这个错误？

**答案：** Lena Fischer 还不该收到「感谢购买」信，因为她的订单显示 `paid: false`；她其实还没完成购买。防止错误的那条贴签事实，就是每笔订单上的 `paid` 盒子。小心的请求会是「给订单显示 paid 为 true 的每个人发感谢信」——用贴签盒子来过滤。这是一个大主题的小预告：自动化的安全，往往藏在一条匆忙版本会直接略过的贴签事实里。读盒子不是瞎忙；错误就藏在那里。


#### 对你的 AI 这么说

你已经勘察了哪些工具有柜台窗口，并整理了它们的读取与更改能力。迈出下一个老实的一步：让助手真正取回某样东西，并*把原始贴签盒子给你看*，好开始读真实答案。

> *「从[我的日历 / 一个公开天气服务 / 我店铺的测试数据]读取[一件无害、低风险的东西]，把实际响应以贴签盒形式给我看，不要只给摘要。然后带我走一遍：哪个标签装着我在乎的东西，还回来了哪些我该知道存在的其他标签？只读；什么都别改。」*

这个请求把整章付诸工作。它让你严格停在读取（安全、可逆），要求看见盒子而不只是助手的转述（好让你手握方向盘），并把助手变成耐心的向导，带你穿过它自己的标签。你读过的原始响应越多，这一切就越不像墙，你也越擅长一眼找到那个要紧的盒子。
