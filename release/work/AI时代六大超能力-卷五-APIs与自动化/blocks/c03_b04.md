#### 预判服务

**Q1.** 你对助手说：「给我看看支票账户的余额。」想象这会拜访哪扇柜台窗口。助手填的是*读取*表还是*更改*表？那张表几乎肯定需要填上的那一栏是什么？

提示

问一问：银行在作答之前必须知道什么？你的钱是否真的发生了任何移动。

**答案：** 这是一张*读取*表。账户没有任何变化；你只是请银行告诉你一个它已经知道的数字，问两遍也无害。表需要填上的空白是*哪个账户*（以及看不见却至关重要的*证明你有权询问它*——那是第6章的主题）。要带走的课：即便最简单的请求也有形状，服务在作答前必须填好特定空白。当你的助手「只是查一下余额」时，它正安静地替你填那张表。


#### 读地图

**Q2.** Mara 的店铺既有前门（顾客购物的网站），也有柜台窗口（API）。一位朋友对她说：「每周一让助手读你店铺的网站拿订单就行，跟你用眼睛做的一样。」在读答案之前，用你自己的一句话说明：为什么柜台窗口是更好的路径？

**答案：** 柜台窗口更好，因为它以约定格式、为机器准备的朴素贴签事实交出订单；而网站交出的是机器必须眯眼猜透的装饰，所以读网站更慢、更脆、也更容易抓错东西。还有更深一层理由，留给第13章：网站是给*人*的前门，悄悄让机器费力去读，是绕开了服务本意的路径；柜台窗口才是服务真正为此建造的门。先伸手去够那扇老实的、为机器造的门——这个直觉现在就值得养成。


#### 对你的 AI 这么说

上一章你勘察了哪些工具有柜台窗口。现在挑一个——那个你最想甩掉周一早晨苦差的——再往下走一步。仍然不做任何改动；仍然只是在看。

> *「拿[我的店铺 / 我的日历 / 我的银行]来说。透过它的柜台窗口，哪些事可以*被请求读取*，哪些事可以*被请求更改*？用白话把读取能力与更改能力分开列出。先一件都别做。我想先弄清这扇柜台能做什么、不能做什么，再向它要任何东西。」*

这个请求直接建立在上一个之上。它只用了本书目前教过的词（柜台窗口、读取与更改），严格停在「看」而非「做」，并请助手把服务的能力分进安全的一堆（读取）和需小心的一堆（更改）。你在学习信任之前先读懂服务的形状——而这正是第9章将炼成超能力的习惯。
